28.1 ทำไมต้องมี Method

ภาษา C# ให้คุณสร้างแอปพลิเคชันที่แข็งแกร่งได้หลากหลายรูปแบบ สมมติคุณต้องเขียนโค้ดที่ทำงานกับ input ของผู้ใช้ซึ่งคาดเดาไม่ได้ คุณอาจต้องเพิ่มตรรกะจัดการ input ที่ผิดพลาด แปลง input ให้อยู่ ในรูปแบบที่ใช้งานได้ และทำการดำเนินการที่ถูกต้อง เมื่อแอปของคุณใหญ่ขึ้นเรื่อยๆ การติดตามโค้ด ของคุณอาจกลายเป็นเรื่องท้าทายอย่างรวดเร็ว

method (เรียกอีกอย่างว่า function) เป็นส่วนสำคัญที่ช่วยให้โค้ดมีโครงสร้าง มี ประสิทธิภาพ และอ่านง่าย method คือหน่วยโค้ดแบบโมดูล (modular) และเป็นแนวคิดพื้นฐานของการเขียน โปรแกรม method มักถูกออกแบบให้ทำงานเฉพาะอย่างหนึ่ง และมีโค้ดที่ทำงานนั้นอยู่ข้างใน ชื่อของ method ควรสะท้อนงานของมันอย่างชัดเจน ซึ่งช่วยเพิ่มความอ่านง่ายของโค้ด การเรียนรู้วิธีใช้ method จะช่วยให้คุณสร้างแอปพลิเคชันที่มีฟีเจอร์มากมายได้เร็วขึ้น

ในบทนี้ คุณจะเรียนสร้าง method ของตัวเองเพื่อทำงานเฉพาะอย่าง คุณจะเรียนว่า method ช่วยลด ความซับซ้อนและย่นย่อโค้ดได้ยังไง รวมถึงช่วยให้ทุกอย่างเป็นระเบียบและหาง่ายขึ้น

28.2 ไวยากรณ์ของ Method

คุณอาจคุ้นเคยกับ method บางตัวอยู่แล้ว เช่น Console.WriteLine() หรือ random.Next() คุณอาจเห็นแล้วว่า method เหล่านี้ช่วยลดความซับซ้อนของงาน และให้คุณ สร้างโค้ดได้ง่ายขึ้น ในหัวข้อนี้ คุณจะเรียนวิธีสร้าง method ของตัวเอง

Method ทำงานยังไง

กระบวนการพัฒนา method เริ่มจากสร้าง method signature — method signature ประกาศ return type, ชื่อ, และ input parameter ของ method ตัวอย่างเช่น พิจารณา method signature นี้:

syntax
void SayHello();

ชื่อ method คือ SayHello return type ของมันคือ void หมายถึง method ไม่คืนค่าข้อมูลใดๆ กลับมา อย่างไรก็ตาม method คืนค่าเป็น data type ไหนก็ได้ เช่น bool, int, double, และ array ก็ได้เช่นกัน (จะเรียน ละเอียดในบทที่ 30) parameter ของ method (ถ้ามี) ต้องอยู่ในวงเล็บ () — method รับ parameter ได้หลายตัว data type ไหนก็ได้ ในตัวอย่างนี้ method ไม่มี parameter เลย

ก่อนรัน method ได้ คุณต้องเพิ่ม method definition — method definition ใช้ปีกกา {} ครอบโค้ดที่จะทำงานตอน method ถูกเรียก ตัวอย่างเช่น:

syntax
void SayHello()
{
    Console.WriteLine("Hello World!");
}

ตอนนี้ method จะพิมพ์ Hello World! ทุกครั้งที่ถูกเรียก

การเรียกใช้ Method

เรียก method ด้วยการใช้ชื่อของมัน พร้อม argument ที่จำเป็น (ถ้ามี) พิจารณาโค้ดนี้:

syntax
Console.Write("Input!");

string "Input!" คือ argument ที่ส่งให้เมธอด Write

เรียก method ได้ทั้งก่อนหรือหลังนิยามของมัน ตัวอย่างเช่น SayHello นิยามและเรียก ด้วย syntax นี้ได้:

Program.cs 
SayHello();

void SayHello()
{
    Console.WriteLine("Hello World!");
}
Output
Hello World!

สังเกตว่าไม่จำเป็นต้องนิยาม method ก่อนเรียกใช้เลย ความยืดหยุ่นนี้ทำให้คุณจัดระเบียบโค้ดตามที่ ต้องการได้ โดยทั่วไปนิยมนิยาม method ทั้งหมดไว้ท้ายโปรแกรม ตัวอย่างเช่น:

Program.cs 
int[] a = {1,2,3,4,5};

Console.WriteLine("Contents of Array:");
PrintArray();

void PrintArray()
{
    foreach (int x in a)
    {
        Console.Write($"{x} ");
    }
    Console.WriteLine();
}
Output
Contents of Array:
1 2 3 4 5
💡 นี่คือ local function ของ top-level program สังเกตว่าตลอดทั้งเล่มนี้ เราไม่เคยเขียน class Program { static void Main() { ... } } ครอบโค้ดเลย เพราะใช้ฟีเจอร์ top-level statements ของ C# (มีมาตั้งแต่ C# 9) — method อย่าง SayHello() หรือ PrintArray() ที่นิยามในไฟล์เดียวกับโค้ดหลัก แบบนี้ เรียกว่า local function มันเข้าถึงตัวแปรที่ประกาศไว้ข้างนอกได้โดยตรง (เช่น PrintArray() เข้าถึง a ได้) ซึ่งเป็นสิ่งที่คุณจะใช้ตลอดทั้ง Part นี้

การทำงานของ Method

เมื่อคุณเรียก method โค้ดในตัว method จะถูกรัน หมายความว่า control การทำงานถูกส่งจากผู้เรียก ไปยัง method control จะกลับมาที่ผู้เรียกหลัง method ทำงานเสร็จ ตัวอย่างเช่น พิจารณาโค้ดนี้:

Program.cs 
Console.WriteLine("Before calling a method");
SayHello();
Console.WriteLine("After calling a method");

void SayHello()
{
    Console.WriteLine("Hello World!");
}
Output
Before calling a method
Hello World!
After calling a method

เมื่อ method ถูกนิยามแล้ว คุณเรียกใช้มันได้ทุกเมื่อ ซ้ำกี่ครั้งก็ได้ตามต้องการ คุณใช้ method ข้างใน if-else statement, for-loop, switch statement แม้แต่ตอน initialize ตัวแปร และอื่นๆ อีกมากมาย!

แนวปฏิบัติที่ดี (Best Practices)

ตอนเลือกชื่อ method สำคัญมากที่ต้องตั้งชื่อให้กระชับและสื่อความชัดเจนว่า method ทำงานอะไร ชื่อ method ควรเป็น Pascal case (ทบทวนจาก บทที่ 3) และโดยทั่วไป ไม่ควรขึ้นต้นด้วยตัวเลข ชื่อของ parameter ควรอธิบายว่าข้อมูลชนิดไหนที่ parameter นั้นแทน พิจารณา method signature เหล่านี้:

เทียบกัน
void ShowData(string a, int b, int c);
void DisplayDate(string month, int day, int year);

method ที่สองอธิบายชัดเจนว่าข้อมูลชนิดไหนถูกแสดง และตั้งชื่อ parameter ที่สื่อความหมายชัดเจน — ต่างจากตัวแรกที่ใช้ชื่อพารามิเตอร์ a, b, c ซึ่งไม่ บอกอะไรเลยว่าแต่ละตัวคืออะไร

ตอนนี้คุณรู้พื้นฐานแล้ว พร้อมเริ่มเขียน method ของตัวเองได้เลย!

28.3 ลงมือ: สร้าง Method แรกของคุณ

โดยทั่วไป method ถูกสร้างขึ้นเพื่อทำงานเฉพาะอย่างหนึ่ง ในแบบฝึกหัดนี้ คุณจะสร้าง method ที่ สุ่มและแสดงตัวเลข 5 ตัว

เตรียมโปรเจกต์

Terminal 
dotnet new console -o ch28-methods

สร้าง Method แสดงตัวเลขสุ่ม

ในการสร้าง method ก่อนอื่นสร้าง method signature แล้วเพิ่ม method body — สร้าง method signature ด้วยการประกาศ return type, ชื่อ method, และพารามิเตอร์ สร้าง method body ด้วย ปีกกา {} ที่มีโค้ดข้างใน

Program.cs 
void DisplayRandomNumbers();

ในกรณีนี้ method แค่ต้อง generate และแสดงข้อมูล ดังนั้น return type จึงเป็น void ตอนนี้ยังไม่ต้องมี parameter ก็ได้

ลบเซมิโคลอน ; เพื่อสร้าง method body แล้วอัปเดตโค้ดเป็นแบบนี้:

Program.cs 
void DisplayRandomNumbers()
{
    Random random = new Random();
}

ตรงนี้คุณสร้าง Random object ที่ใช้สุ่มตัวเลข เพิ่ม for loop แสดงตัวเลขจำนวนเต็มสุ่ม 5 ตัว:

Program.cs 
void DisplayRandomNumbers()
{
    Random random = new Random();

    for (int i = 0; i < 5; i++)
    {
        Console.Write($"{random.Next(1, 100)} ");
    }
}

โค้ดนี้สุ่มตัวเลขระหว่าง 1 ถึง 99 (รวมทั้งสองค่า) พร้อมเติมช่องว่างหลังพิมพ์ตัวเลขแต่ละตัว ต่อไปเพิ่มการขึ้นบรรทัดใหม่ก่อน method จบทำงาน:

Program.cs 
void DisplayRandomNumbers()
{
    Random random = new Random();

    for (int i = 0; i < 5; i++)
    {
        Console.Write($"{random.Next(1, 100)} ");
    }

    Console.WriteLine();
}

เรียกใช้ Method ของคุณ

Program.cs 
Console.WriteLine("Generating random numbers:");
DisplayRandomNumbers();

void DisplayRandomNumbers()
{
    Random random = new Random();

    for (int i = 0; i < 5; i++)
    {
        Console.Write($"{random.Next(1, 100)} ");
    }

    Console.WriteLine();
}
Output (ค่าสุ่ม — ตัวอย่าง)
Generating random numbers:
17 29 46 36 3

สังเกตว่าการใช้ method ทำให้โค้ดเข้าใจง่ายขึ้นมาก แทนที่จะเสียเวลาไขความหมายของ for loop ด้วยตัวเอง คุณแค่อ่านชื่อ method ก็รู้ทันทีว่าโค้ดนี้แสดงตัวเลขสุ่ม

28.4 ลงมือ: สร้าง Method ที่ใช้ซ้ำได้

เวลาพัฒนาแอปพลิเคชัน คุณอาจพบว่าตัวเองเขียนโค้ดทำสิ่งเดียวกันซ้ำไปซ้ำมา แทนที่จะเขียนโค้ดซ้ำ การใช้ method ทำงานเดียวกันช่วยย่นย่อโค้ดและพัฒนาแอปได้เร็วขึ้น ในแบบฝึกหัดนี้ คุณจะระบุโค้ดที่ ซ้ำกันและแทนที่ด้วย method ที่ใช้ซ้ำได้

ระบุโค้ดที่ซ้ำกัน

มาดูแอปที่ติดตามเวลากินยาข้ามโซนเวลากัน ผู้ใช้กรอกโซนเวลาปัจจุบันและโซนเวลาปลายทาง ตารางเวลากินยาจะแสดงออกมา แล้วปรับให้ตรงกับโซนเวลาใหม่

Program.cs 
int[] times = {800, 1200, 1600, 2000};
int diff = 0;

Console.WriteLine("Enter current GMT");
int currentGMT = Convert.ToInt32(Console.ReadLine());

Console.WriteLine("Current Medicine Schedule:");

/* Format and display medicine times */
foreach (int val in times)
{
    string time = val.ToString();
    int len = time.Length;

    if (len >= 3)
    {
        time = time.Insert(len - 2, ":");
    }
    else if (len == 2)
    {
        time = time.Insert(0, "0:");
    }
    else
    {
        time = time.Insert(0, "0:0");
    }

    Console.Write($"{time} ");
}

Console.WriteLine();

Console.WriteLine("Enter new GMT");
int newGMT = Convert.ToInt32(Console.ReadLine());

if (Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12)
{
    Console.WriteLine("Invalid GMT");
}
else if (newGMT <= 0 && currentGMT <= 0 || newGMT >= 0 && currentGMT >= 0)
{
    diff = 100 * (Math.Abs(newGMT) - Math.Abs(currentGMT));

    /* Adjust the times by adding the difference, keeping the value within 24 hours */
    for (int i = 0; i < times.Length; i++)
    {
        times[i] = ((times[i] + diff)) % 2400;
    }
}
else
{
    diff = 100 * (Math.Abs(newGMT) + Math.Abs(currentGMT));

    /* Adjust the times by adding the difference, keeping the value within 24 hours */
    for (int i = 0; i < times.Length; i++)
    {
        times[i] = ((times[i] + diff)) % 2400;
    }
}

Console.WriteLine("New Medicine Schedule:");

/* Format and display medicine times */
foreach (int val in times)
{
    string time = val.ToString();
    int len = time.Length;

    if (len >= 3)
    {
        time = time.Insert(len - 2, ":");
    }
    else if (len == 2)
    {
        time = time.Insert(0, "0:");
    }
    else
    {
        time = time.Insert(0, "0:0");
    }

    Console.Write($"{time} ");
}

Console.WriteLine();

สังเกตว่ามี for-loop หลายชุดที่ซ้ำกันด้วยโค้ดเหมือนเดิมเป๊ะ — มี foreach loop 2 ชุดที่จัดรูปแบบและแสดงเวลากินยา และมี for loop อีก 2 ชุดที่ปรับเวลาตามส่วนต่างของโซนเวลา

ตอนเขียนโค้ด คุณอาจพบว่าตัวเองเขียน code block ซ้ำเพื่อทำงานเดียวกัน นั่นคือโอกาสดีที่จะรวม โค้ดเข้าด้วยกันโดยใช้ method ทำงานนั้นแทน มาลองฝึกกัน!

สร้าง Method ทำงานที่ซ้ำกัน

เพราะ foreach loop จัดรูปแบบและแสดงค่าเวลา คุณตั้งชื่อ method ให้สะท้อนงานนั้น ได้ชัดเจน ทำแบบเดียวกันกับ for loop ที่ปรับเวลาด้วย

Program.cs (เพิ่มท้ายไฟล์) 
void DisplayTimes()
{
    /* Format and display medicine times */
    foreach (int val in times)
    {
        string time = val.ToString();
        int len = time.Length;

        if (len >= 3)
        {
            time = time.Insert(len - 2, ":");
        }
        else if (len == 2)
        {
            time = time.Insert(0, "0:");
        }
        else
        {
            time = time.Insert(0, "0:0");
        }

        Console.Write($"{time} ");
    }

    Console.WriteLine();
}

void AdjustTimes()
{
    /* Adjust the times by adding the difference, keeping the value within 24 hours */
    for (int i = 0; i < times.Length; i++)
    {
        times[i] = ((times[i] + diff)) % 2400;
    }
}

ใน DisplayTimes() คุณรวมการเรียก Console.WriteLine() ท้าย method เพื่อขึ้นบรรทัดใหม่หลังแสดงเวลาเสร็จด้วย

เรียกใช้ Method แทนโค้ดที่ซ้ำ

ลบ code block ที่ซ้ำกัน แล้วแทนที่ด้วยการเรียก method ที่สร้างไว้:

Program.cs (ฉบับสมบูรณ์) 
int[] times = {800, 1200, 1600, 2000};
int diff = 0;

Console.WriteLine("Enter current GMT");
int currentGMT = Convert.ToInt32(Console.ReadLine());

Console.WriteLine("Current Medicine Schedule:");
DisplayTimes();

Console.WriteLine("Enter new GMT");
int newGMT = Convert.ToInt32(Console.ReadLine());

if (Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12)
{
    Console.WriteLine("Invalid GMT");
}
else if (newGMT <= 0 && currentGMT <= 0 || newGMT >= 0 && currentGMT >= 0)
{
    diff = 100 * (Math.Abs(newGMT) - Math.Abs(currentGMT));
    AdjustTimes();
}
else
{
    diff = 100 * (Math.Abs(newGMT) + Math.Abs(currentGMT));
    AdjustTimes();
}

Console.WriteLine("New Medicine Schedule:");
DisplayTimes();

void DisplayTimes()
{
    /* Format and display medicine times */
    foreach (int val in times)
    {
        string time = val.ToString();
        int len = time.Length;

        if (len >= 3)
        {
            time = time.Insert(len - 2, ":");
        }
        else if (len == 2)
        {
            time = time.Insert(0, "0:");
        }
        else
        {
            time = time.Insert(0, "0:0");
        }

        Console.Write($"{time} ");
    }
    Console.WriteLine();
}

void AdjustTimes()
{
    /* Adjust the times by adding the difference, keeping the value within 24 hours */
    for (int i = 0; i < times.Length; i++)
    {
        times[i] = ((times[i] + diff)) % 2400;
    }
}
Output (กรอก -6 แล้ว +6)
Enter current GMT
-6
Current Medicine Schedule:
8:00 12:00 16:00 20:00 
Enter new GMT
+6
New Medicine Schedule:

สังเกตว่าการใช้ method แทนที่ code block ขนาดใหญ่ทำให้โค้ดชัดเจนและเข้าใจง่ายขึ้นมากแค่ไหน — ทั้ง DisplayTimes() และ AdjustTimes() เข้าถึงตัวแปร times และ diff ที่ประกาศไว้นอก method ได้โดยตรง เพราะเป็น local function ในไฟล์เดียวกัน (ทบทวนจากหัวข้อ 28.2b)

28.5 ลงมือ: สร้างโค้ดด้วย Method และ Pseudo-code

method มีประโยชน์สำหรับจัดระเบียบโค้ด ใช้ซ้ำโค้ด และแก้ปัญหาอย่างมีประสิทธิภาพ คุณคิดถึง method เหมือนกล่องดำ (black box) ที่รับ input ทำงานตามชื่อที่ตั้งไว้ แล้วคืน output ได้ ด้วย สมมติฐานนี้ คุณจัดโครงสร้างโปรแกรมได้อย่างรวดเร็ว แค่ตั้งชื่องานของคุณเป็น method แล้วเติม ตรรกะทีหลัง หลังจากระบุงานที่จำเป็นทั้งหมดแล้ว

เมื่อคุณใช้ภาษาพูดธรรมดาอธิบายขั้นตอนในโค้ด โดยไม่ต้องยึดกฎ syntax เคร่งครัด คุณกำลังใช้ "pseudo-code" (รหัสจำลอง) การผสม method กับ pseudo-code เป็นวิธีที่ดีมากในการฝ่าฟัน โจทย์การเขียนโปรแกรมที่ท้าทายได้อย่างรวดเร็ว

ใช้ Method จัดโครงสร้างโค้ด

สมมติคุณเป็นผู้สมัครในการสัมภาษณ์งานเขียนโค้ด ผู้สัมภาษณ์อยากให้คุณเขียนโปรแกรมตรวจสอบว่า IPv4 address ถูกต้องหรือไม่ คุณได้รับกฎต่อไปนี้:

  • IPv4 address ที่ถูกต้องประกอบด้วยตัวเลข 4 ตัวคั่นด้วยจุด
  • แต่ละตัวเลขต้องไม่มีเลขศูนย์นำหน้า (leading zero)
  • แต่ละตัวเลขต้องอยู่ในช่วง 0 ถึง 255

1.1.1.1 และ 255.255.255.255 เป็นตัวอย่างของ IP address ที่ถูก ต้อง

IPv4 address ถูกส่งมาเป็น string คุณสมมติได้ว่ามันมีแค่ตัวเลขกับจุดเท่านั้น (ไม่มีตัวอักษรใน string ที่ให้มา) — คุณจะเข้าหางานนี้ยังไง?

แตกปัญหาออกเป็นส่วนๆ

ถ้าดูกฎให้ดี คุณจะพบว่าต้องใช้แค่ 3 ขั้นตอนในการตัดสินว่า IPv4 address ถูกต้องหรือไม่

Program.cs (pseudo-code) 
/*
if ipAddress consists of 4 numbers
and
if each ipAddress number has no leading zeroes
and
if each ipAddress number is in range 0 - 255

then ipAddress is valid

else ipAddress is invalid
*/

pseudo-code เป็นวิธีที่ดีมากในการเริ่มฝ่าฟันโจทย์ ด้วย comment block นี้ คุณเชื่อมช่องว่าง ระหว่างกฎในโจทย์กับโค้ดโปรแกรม ทำให้งานหลักที่โค้ดของคุณต้องทำชัดเจนขึ้น pseudo-code ไม่ จำเป็นต้องทำงานได้จริงหรือยึดกฎ syntax แต่ควรอธิบายชัดเจนว่าโค้ดจะทำอะไร ทีนี้มาแปลงมันเป็น โค้ดจริงกัน!

Program.cs 
if (ValidateLength() && ValidateZeroes() && ValidateRange())
{
    Console.WriteLine($"ip is a valid IPv4 address");
}
else
{
    Console.WriteLine($"ip is an invalid IPv4 address");
}

ในขั้นตอนนี้ คุณแปลง if statement จาก pseudo-code เป็น method ที่เรียกได้ และ แสดงผลลัพธ์ออกมา ยังไม่ต้องกังวลเรื่องนิยาม method ตอนนี้ สมมติไว้ก่อนว่าแต่ละ method ทำงาน ตามชื่อที่มันอธิบายไว้ คุณจะแก้ compile error และสร้างตรรกะของ method ทีหลัง แต่ตอนนี้ให้ โฟกัสที่ภาพรวมก่อน เวลาเริ่มโปรแกรมใหม่ การโฟกัสที่การออกแบบภาพรวมช่วยให้คุณจัดระเบียบและ พัฒนาแอปได้เร็วขึ้น

Program.cs (placeholder methods) 
void ValidateLength() {}
void ValidateZeroes() {}
void ValidateRange() {}

สังเกตว่าการใช้ placeholder method ทำให้คุณเข้าหาโจทย์ได้อย่างรวดเร็ว และจัดโครงสร้างโค้ดเพื่อ พัฒนา solution ได้ ตอนนี้คุณมีแผนที่มีโครงสร้างชัดเจนแล้ว คุณพัฒนาต่อได้โดยเติมโค้ดทีละชิ้น

พัฒนา Solution

ตอนนี้คุณมี placeholder method ครบสำหรับแก้โจทย์แล้ว ถึงเวลาโฟกัสที่รายละเอียดของ solution จำไว้ว่า input format ของ IPv4 address จะเป็น string ที่มีตัวเลขคั่นด้วยจุด

Program.cs (ตัวแปรตั้งต้น) 
string ipv4Input = "107.31.1.5";
bool validLength = false;
bool validZeroes = false;
bool validRange = false;
Program.cs 
ValidateLength();
ValidateZeroes();
ValidateRange();

if (validLength && validZeroes && validRange)
{
    Console.WriteLine($"ip is a valid IPv4 address");
}
else
{
    Console.WriteLine($"ip is an invalid IPv4 address");
}

อัปเดต method ValidateLength:

Program.cs 
void ValidateLength()
{
    string[] address = ipv4Input.Split(".");
    validLength = address.Length == 4;
};

กฎแรกบอกว่า IPv4 address ต้องมีตัวเลข 4 ตัว ดังนั้นในโค้ดนี้ คุณใช้ string.Split (ทบทวนจากบทที่ 23) แยกตัวเลข แล้วเช็คว่ามีครบ 4 ตัวหรือไม่

อัปเดต method ValidateZeroes:

Program.cs 
void ValidateZeroes()
{
    string[] address = ipv4Input.Split(".");

    foreach (string number in address)
    {
        if (number.Length > 1 && number.StartsWith("0"))
        {
            validZeroes = false;
            return;
        }
    }

    validZeroes = true;
}

กฎที่สองบอกว่าตัวเลขใน IPv4 address ต้องไม่มีเลขศูนย์นำหน้า ดังนั้น method ต้องเช็คตัวเลขที่ มีเลขศูนย์นำหน้า พร้อมยอมรับ 0 เดี่ยวๆ ว่าเป็นค่าที่ถูกต้อง ถ้าตัวเลขทุกตัวมี เลขศูนย์ถูกต้อง validZeroes ควรเป็น true ไม่งั้นเป็น false

⚠️ ทำความรู้จัก return Statement ถ้าสังเกตดีๆ จะเห็นว่า validZeroes ถูกตั้งเป็น true หลัง foreach loop จบเสมอ แต่คุณต้องการตั้งเป็น true เฉพาะตอนที่ไม่พบ เลขศูนย์นำหน้าที่ผิดกฎเท่านั้น — คุณแก้บั๊กนี้ได้ด้วยการตั้ง validZeroes = true ก่อน foreach loop รัน แต่ก็แก้ได้ด้วย return statement เช่นกัน — return statement หยุดการทำงานของ method แล้วส่ง control กลับไปยังผู้เรียก การเพิ่ม return หลัง validZeroes = false; ทำให้ method จบทำงานทันทีที่เจอเลข ศูนย์ที่ผิดกฎตัวแรก ถ้าไม่เจอเลขศูนย์ที่ผิดกฎเลย method จะจบหลังตั้ง validZeroes เป็น true (จะเรียนละเอียดเรื่อง return value ใน บทที่ 30)

อัปเดต method ValidateRange:

Program.cs 
void ValidateRange()
{
    string[] address = ipv4Input.Split(".");

    foreach (string number in address)
    {
        int value = int.Parse(number);
        if (value < 0 || value > 255)
        {
            validRange = false;
            return;
        }
    }
    validRange = true;
}

กฎที่สามบอกว่าแต่ละตัวเลขต้องอยู่ในช่วง 0 ถึง 255 ดังนั้นโค้ดนี้เช็คว่าแต่ละตัวเลขน้อยกว่า 255 ถ้าไม่ ให้จบการทำงานหลังตั้ง validRange เป็น false เพราะ string input มีแค่ตัวเลขกับจุด คุณไม่ต้องเช็คเลขติดลบ

แต่อาจมีบางกรณีที่ไม่มีตัวเลขอยู่ระหว่างจุดเลย เช่น "255...255" ในกรณีนี้ string.Split(".") จะคืน entry ว่างเปล่า ทำให้ int.Parse ล้มเหลว คุณป้องกันปัญหานี้ได้ด้วยการระบุ StringSplitOptions:

Program.cs 
string[] address = ipv4Input.Split(".", StringSplitOptions.RemoveEmptyEntries);

ใช้ StringSplitOptions.RemoveEmptyEntries ตัด entry ว่างเปล่าออกจาก array address และป้องกันไม่ให้พยายาม parse string ว่างเปล่า

ทำให้ Solution สมบูรณ์

ตอนนี้คุณมี method ครบสำหรับตรวจสอบ IP address แล้ว ถึงเวลากลับไปดู solution เริ่มต้น เพิ่ม ค่า input มากขึ้น และเตรียมทดสอบโค้ด

Program.cs 
string[] ipv4Input = {"107.31.1.5", "255.0.0.255", "555..0.555", "255...255"};

ตอนพัฒนา solution สำคัญมากที่ต้องทดสอบโค้ดด้วย input หลายกรณี ในโค้ดนี้ คุณให้ค่าทดสอบที่ ครอบคลุมพอสมควร ตอนนี้ต้องอัปเดตโค้ดให้ทดสอบแต่ละค่าโดยใช้ loop

Program.cs 
foreach (string ip in ipv4Input)
{
    ValidateLength();
    ValidateZeroes();
    ValidateRange();

    if (validLength && validZeroes && validRange)
    {
        Console.WriteLine($"{ip} is a valid IPv4 address");
    }
    else
    {
        Console.WriteLine($"{ip} is an invalid IPv4 address");
    }
}

สุดท้าย ต้องแก้ให้แต่ละ method ใช้ข้อมูลจากตัวแปรกลาง เพราะเปลี่ยน ipv4Input จาก string เป็น array แล้ว — เพิ่มตัวแปร address ที่แต่ละ method จะอ้างอิงถึง:

Program.cs 
string[] ipv4Input = {"107.31.1.5", "255.0.0.255", "555..0.555", "255...255"};
string[] address;
bool validLength = false;
bool validZeroes = false;
bool validRange = false;

กำหนดค่า address ด้วย string.Split:

Program.cs 
foreach (string ip in ipv4Input)
{
    address = ip.Split(".", StringSplitOptions.RemoveEmptyEntries);

ลบการอ้างอิง string.Split ออกจากแต่ละ validation method ให้ใช้ตัวแปร address กลางแทน:

Program.cs (ฉบับสมบูรณ์) 
string[] ipv4Input = {"107.31.1.5", "255.0.0.255", "555..0.555", "255...255"};
string[] address;
bool validLength = false;
bool validZeroes = false;
bool validRange = false;

foreach (string ip in ipv4Input)
{
    address = ip.Split(".", StringSplitOptions.RemoveEmptyEntries);

    ValidateLength();
    ValidateZeroes();
    ValidateRange();

    if (validLength && validZeroes && validRange)
    {
        Console.WriteLine($"{ip} is a valid IPv4 address");
    }
    else
    {
        Console.WriteLine($"{ip} is an invalid IPv4 address");
    }
}

void ValidateLength()
{
    validLength = address.Length == 4;
};

void ValidateZeroes()
{
    foreach (string number in address)
    {
        if (number.Length > 1 && number.StartsWith("0"))
        {
            validZeroes = false;
            return;
        }
    }

    validZeroes = true;
}

void ValidateRange()
{
    foreach (string number in address)
    {
        int value = int.Parse(number);
        if (value < 0 || value > 255)
        {
            validRange = false;
            return;
        }
    }
    validRange = true;
}
Output
107.31.1.5 is a valid IPv4 address
255.0.0.255 is a valid IPv4 address
555..0.555 is an invalid IPv4 address
255...255 is an invalid IPv4 address
💡 555..0.555 ผิดตรงไหน "555..0.555" แยกด้วยจุดแล้วได้ 3 ค่า (เพราะ RemoveEmptyEntries ตัดค่าว่างจากจุดคู่ทิ้ง): "555", "0", "555" — มีแค่ 3 ตัวเลข ไม่ใช่ 4 ตัว จึงไม่ผ่าน ValidateLength() ทันที (นอกจากนี้ "555" ยังเกิน 255 ด้วย จึงไม่ผ่าน ValidateRange() เช่นกัน)

28.6 ท้าทาย: หมอดูทำนายดวง

โจทย์ตามต้นฉบับ MS Learn

คุณกำลังช่วยพัฒนาเกม massive multiplayer role-playing เกมหนึ่ง ผู้เล่นแต่ละคนมีค่าสถานะ "โชค" (luck) ที่ส่งผลต่อโอกาสเจอสมบัติหายาก ทุกวัน ผู้เล่นคุยกับหมอดูในเกมที่บอกว่าค่า โชคของพวกเขาสูง ต่ำ หรือปานกลาง

เกมมีโค้ดสร้างคำทำนายของผู้เล่นอยู่แล้ว แต่ยังใช้ซ้ำไม่ได้ งานของคุณคือสร้าง method ชื่อ TellFortune ที่เรียกได้ทุกเมื่อ แล้วแทนที่ตรรกะเดิมด้วยการเรียก method นี้

ข้อมูลตั้งต้น

Console.WriteLine("A fortune teller whispers the following words:");

{
    Console.Write($"{text[i]} {fortune[i]} ");
}

อัปเดตโค้ดให้ใช้ method แสดงคำทำนาย ทดสอบด้วยการเปลี่ยนค่า luck แล้วเรียก method อีกครั้ง

28.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
compile error ตอนพยายามประกาศ method โดยไม่มีปีกกา {} เขียน void MyMethod(); (แค่ signature จบด้วยเซมิโคลอน) โดยไม่มี body — เป็น method signature เฉยๆ ไม่ใช่นิยามที่สมบูรณ์ ต้องมี { } ตามด้วยเสมอ (ถึงจะว่างเปล่าก็ต้องมี)
ตัวแปรใน method หนึ่งมองไม่เห็นค่าจาก method อีกตัว ทั้งที่คาดว่าจะแชร์กันได้ ตัวแปรที่ประกาศข้างใน method (local variable) มี scope แค่ในตัว method นั้น เท่านั้น (ทบทวนจาก บทที่ 15) ถ้าต้องการแชร์ค่าข้าม method ต้องประกาศตัวแปรนั้นไว้นอกทุก method (เหมือน times, diff, address ในบทนี้)
ลืม return; แล้วตัวแปรผลลัพธ์ถูกเขียนทับด้วยค่า default หลัง loop จบ ถ้าตั้งค่า false/true ไว้ข้างใน loop แต่ไม่ return ทันที โค้ดหลัง loop (เช่น "validZeroes = true;" ท้าย method) จะทำงานเสมอ เขียนทับค่าที่ตั้งไว้ก่อนหน้า — ต้องใส่ return หลังตั้งค่าที่ควรจบการทำงานทันที
เรียก method ก่อนนิยามแล้วกังวลว่าจะ error ไม่ใช่บั๊ก — local function ใน C# top-level program เรียกได้ทั้งก่อนและหลังนิยาม (ทบทวนหัวข้อ 28.2b) ต่างจากตัวแปรที่ต้องประกาศก่อนใช้เสมอ
ตั้งชื่อ method ว่า DoStuff(), Process(), Handle() แล้วอ่านโค้ดไม่รู้เรื่องทีหลัง ชื่อ method ที่คลุมเครือทำให้เสียประโยชน์หลักของการใช้ method (อ่านชื่อแล้วรู้ทันทีว่า ทำอะไร) — ตั้งชื่อให้เจาะจงงานจริงเสมอ เช่น DisplayTimes(), ValidateRange()

28.8 ❓ Knowledge Check

คำถามชุดนี้แปลจาก Module Assessment ของ Microsoft Learn

1. ข้อใดประกาศ method ได้อย่างถูกต้อง?

  • ADisplayNumbers();
  • Bvoid DisplayNumbers{};
  • Cvoid DisplayNumbers() { }
เฉลย: ข้อ C. ต้องมีครบ return type, ชื่อ, วงเล็บ, และปีกกา body — ข้อ A ขาด return type (เป็นการเรียก ไม่ใช่ประกาศ) ข้อ B ขาดวงเล็บ () หลังชื่อ method

2. ข้อใดเรียก method ได้อย่างถูกต้อง?

  • AGenerateID();
  • Bvoid GenerateID() {}
  • CGenerateID;
เฉลย: ข้อ A. การเรียก method ต้องมีวงเล็บ () เสมอ (ข้อ C ผิดเพราะขาดวงเล็บ) ข้อ B เป็นการประกาศ method ไม่ใช่การเรียก

3. ข้อใดถูกต้องเกี่ยวกับคีย์เวิร์ด return?

  • Aเหมือนกับคีย์เวิร์ด break ทุกประการ
  • Bมันหยุดการทำงานของ method
  • Cต้องใช้คู่กับค่าหรือ expression เสมอ
เฉลย: ข้อ B. ตรงกับที่เห็นในหัวข้อ 28.5b — return; เดี่ยวๆ (ไม่มีค่า) ใช้กับ method ชนิด void ได้ เพื่อหยุดการทำงานทันที (ข้อ C ผิด) และ break ใช้ออกจาก loop/switch เท่านั้น ไม่ได้หยุดทั้ง method เหมือน return (ข้อ A ผิด)

Program.cs

ข้อ 3กลาง

โค้ดนี้มี method 2 ตัวที่มีโค้ดซ้ำกันเกือบทั้งหมด รวมให้เหลือ method เดียว:

Program.cs (ก่อนแก้)

{

    Console.WriteLine("Good morning!");
    Console.WriteLine("=====");
}

    Console.WriteLine("=====");

💡 คำใบ้

ทั้งสอง method ต่างกันแค่ข้อความตรงกลาง — ลองนึกถึงวิธีทำให้ ข้อความนั้นเป็นตัวแปรที่ปรับได้จากภายนอก method (จะเรียนละเอียดเรื่องพารามิเตอร์ใน บทที่ 29) ถ้ายังไม่รู้จักพารามิเตอร์ ลองใช้ตัวแปร global ที่ ตั้งค่าก่อนเรียก method แทนไปก่อนได้

ดูเฉลย
Program.cs (แก้แล้ว — ใช้ตัวแปร global)
string greetingMessage = "";

greetingMessage = "Good morning!";
Greet();

greetingMessage = "Good evening!";
Greet();

void Greet()
{
    Console.WriteLine("=====");
    Console.WriteLine(greetingMessage);
    Console.WriteLine("=====");
}

รวมเหลือ method เดียวชื่อ Greet() ที่อ่านค่าจากตัวแปร greetingMessage ซึ่งตั้งค่าไว้ก่อนเรียกแต่ละครั้ง — วิธีนี้ยังไม่สวยเท่า การใช้พารามิเตอร์ (ซึ่งจะเรียนในบทถัดไป) แต่แสดงหลักการ "ลดโค้ดซ้ำ" ได้ชัดเจน

ข้อ 4กลาง

เขียน pseudo-code (แค่ comment ไม่ต้องเป็นโค้ดจริง) สำหรับโปรแกรมตรวจสอบว่ารหัสผ่านที่ กรอกเข้ามาแข็งแรงพอหรือไม่ (ต้องมีความยาวอย่างน้อย 8 ตัวอักษร มีตัวเลขอย่างน้อย 1 ตัว และมีตัวพิมพ์ใหญ่อย่างน้อย 1 ตัว) จากนั้นสร้าง placeholder method 3 ตัวตาม pseudo-code นั้น

ดูเฉลย
Program.cs
/*
if password length is at least 8 characters
and
if password contains at least one digit
and
if password contains at least one uppercase letter

then password is strong

else password is weak
*/

void ValidateLength() {}
void ValidateHasDigit() {}
void ValidateHasUppercase() {}
ข้อ 5ยาก

เติมโค้ดให้ placeholder method ทั้ง 3 ตัวจากข้อ 4 ทำงานได้จริง (ใช้ตัวแปร bool กลาง 3 ตัวเหมือนแพทเทิร์นตัวตรวจสอบ IPv4 ในหัวข้อ 28.5) ทดสอบกับรหัสผ่าน "Abc12345" (ควรผ่าน) และ "abc" (ควรไม่ผ่าน)

ดูเฉลย
Program.cs
string[] passwords = { "Abc12345", "abc" };
string password = "";
bool validLength = false;
bool hasDigit = false;
bool hasUppercase = false;

foreach (string pw in passwords)
{
    password = pw;
    ValidateLength();
    ValidateHasDigit();
    ValidateHasUppercase();

    if (validLength && hasDigit && hasUppercase)
    {
        Console.WriteLine($"{password} is strong");
    }
    else
    {
        Console.WriteLine($"{password} is weak");
    }
}

void ValidateLength()
{
    validLength = password.Length >= 8;
}

void ValidateHasDigit()
{
    foreach (char c in password)
    {
        if (char.IsDigit(c))
        {
            hasDigit = true;
            return;
        }
    }
    hasDigit = false;
}

void ValidateHasUppercase()
{
    foreach (char c in password)
    {
        if (char.IsUpper(c))
        {
            hasUppercase = true;
            return;
        }
    }
    hasUppercase = false;
}

ใช้ char.IsDigit() และ char.IsUpper() ตรวจสอบตัวอักษรแต่ละ ตัวใน string — เมธอด built-in เหล่านี้ยังไม่เคยเจอในหนังสือเล่มนี้มาก่อน แต่ทำงานตรงตัว ตามชื่อ (ทดลองใช้เมธอดใหม่ที่คาดเดาพฤติกรรมได้จากชื่อ เป็นทักษะสำคัญของนักพัฒนา)

ข้อ 6ท้าทาย

ย้อนกลับไปดูแอปยาข้ามโซนเวลาในหัวข้อ 28.4 — สร้าง method ใหม่ชื่อ ValidateGMT() ที่ย้ายตรรกะ Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12 ออกจาก if statement หลัก ให้ method คืนสถานะผ่านตัวแปร bool กลางชื่อ invalidGMT แทน

ดูเฉลย
Program.cs (ส่วนที่แก้)
bool invalidGMT = false;

ValidateGMT();

if (invalidGMT)
{
    Console.WriteLine("Invalid GMT");
}
else if (newGMT <= 0 && currentGMT <= 0 || newGMT >= 0 && currentGMT >= 0)
{
    diff = 100 * (Math.Abs(newGMT) - Math.Abs(currentGMT));
    AdjustTimes();
}
else
{
    diff = 100 * (Math.Abs(newGMT) + Math.Abs(currentGMT));
    AdjustTimes();
}

void ValidateGMT()
{
    invalidGMT = Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12;
}

แพทเทิร์นเดียวกับ ValidateLength()/ValidateRange() จาก หัวข้อ 28.5 ทุกประการ — ย้ายเงื่อนไขที่ซับซ้อนออกจาก if หลัก ไปไว้ใน method ที่ตั้งชื่อสื่อความหมาย แล้วอ่านผลผ่านตัวแปร bool กลาง

เป้าหมายของคุณคือเรียนวิธีสร้าง method ของตัวเองเพื่อทำงานเฉพาะอย่าง คุณเรียนย้ายโค้ดที่ใช้ซ้ำ ได้ไปไว้ใน method เพื่อลดการเขียนโค้ดซ้ำ คุณยังเรียนใช้ pseudo-code และ placeholder method เข้าหาโจทย์ที่ซับซ้อน ด้วยการสร้าง method เล็กๆ ที่แต่ละตัวมีหน้าที่รับผิดชอบเฉพาะเจาะจง คุณ เรียนสร้าง solution ให้โจทย์ต่างๆ ได้อย่างรวดเร็ว ด้วยโค้ดที่มีประสิทธิภาพและอ่านง่าย
