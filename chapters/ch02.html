2.1 ทำไมต้องมี Literal และ Variable

แอปพลิเคชันส่วนใหญ่ที่คุณจะสร้างด้วย C# ต้องทำงานกับข้อมูล บางครั้งข้อมูลนั้นถูก "ฝังตายตัว" ไว้ในแอป ค่าที่ฝังตายตัวแบบนี้เรียกว่า hard-coded value คือค่าคงที่ ที่ไม่เปลี่ยนแปลงตลอดการทำงานของโปรแกรม เช่น ข้อความ "สำเร็จ" ที่แสดงเมื่อผู้ใช้ทำ การบางอย่างสำเร็จ — ข้อความนี้มักจะเหมือนเดิมทุกครั้งที่โปรแกรมทำงาน ค่าแบบนี้เรียกอีกอย่างว่า constant หรือ literal value

สมมติคุณอยากแสดงข้อความที่จัดรูปแบบแล้วให้ผู้ใช้เห็น โดยมีทั้งข้อมูลชนิดต่างๆ ปนกัน ข้อความนั้นจะประกอบด้วยสตริงที่ฝังตายตัว รวมกับข้อมูลที่แอปเก็บมาจากผู้ใช้ การจะแสดงข้อความ แบบนี้ได้ คุณต้องสร้างทั้งค่าที่ฝังตายตัว และตัวแปรที่เก็บข้อมูลชนิดใดชนิดหนึ่งได้

ในบทนี้ คุณจะสร้างค่า literal ของข้อมูลหลายชนิด สร้างตัวแปรที่เก็บข้อมูลชนิดต่างๆ กำหนดค่า ให้ตัวแปรเหล่านั้น แล้วเรียกคืนค่าทีหลังในโค้ด และสุดท้ายจะได้เรียนวิธีลดงานให้คอมไพเลอร์ ช่วยแบ่งเบา

2.2 ลงมือ: พิมพ์ค่า Literal 5 ชนิด

C# มีชนิดข้อมูล (data type) เยอะมาก แต่ตอนเริ่มต้น คุณต้องรู้จักแค่ 5 ชนิดหลักก็ครอบคลุม สถานการณ์ส่วนใหญ่แล้ว

ค่า literal แบบ char

ถ้าอยากพิมพ์ตัวอักษรเดียวออกจอ ให้สร้าง char literal โดยล้อมตัวอักษรนั้นด้วยเครื่องหมาย คำพูดเดี่ยว '…' คำว่า char ย่อมาจาก character:

Program.cs 
Console.WriteLine('b');
Output
b

สังเกตว่าตัว b ถูกล้อมด้วยเครื่องหมายคำพูดเดี่ยว ต่างจาก string ที่ใช้คำพูดคู่ ถ้าใส่มากกว่า 1 ตัวอักษรในเครื่องหมายคำพูดเดี่ยว จะได้ error ทันที:

Program.cs
Console.WriteLine('Hello World!');
Output
CS1012: Too many characters in character literal

ค่า literal แบบ int

ถ้าอยากแสดงเลขจำนวนเต็ม (ไม่มีเศษทศนิยม) ให้ใช้ int literal คำว่า int ย่อมาจาก integer — ไม่ต้องใช้เครื่องหมายวรรคตอนอะไรเพิ่มเลย:

Program.cs 
Console.WriteLine(123);
Output
123

ค่า literal แบบทศนิยม (floating-point)

เลขทศนิยม เช่น 3.14159 C# มี 3 ชนิดข้อมูลรองรับ ได้แก่ float, double, และ decimal — แต่ละชนิดรองรับความละเอียด (precision) ต่างกัน:

ชนิดความละเอียด (จำนวนหลักที่แม่นยำ)
float~6–9 หลัก
double~15–17 หลัก
decimal28–29 หลัก

สร้าง float literal ด้วยการเติมตัวอักษร F ต่อท้ายตัวเลข (เรียกว่า literal suffix ใช้ f หรือ F ก็ได้):

Program.cs 
Console.WriteLine(0.25F);
Output
0.25

float เป็นชนิดที่ละเอียดน้อยที่สุด จึงเหมาะกับค่าทศนิยมคงที่ที่ไม่ต้องการความแม่นยำสูง ถัดมา สร้าง double literal แค่พิมพ์เลขทศนิยมเฉยๆ ไม่ต้องมี suffix (คอมไพเลอร์จะถือเป็น double โดยอัตโนมัติ):

Program.cs 
Console.WriteLine(2.625);
Output
2.625

สร้าง decimal literal ด้วยการเติมตัวอักษร m ต่อท้าย (m หรือ M ก็ได้):

Program.cs 
Console.WriteLine(12.39816m);
Output
12.39816

ค่า literal แบบ bool

ถ้าอยากแสดงค่า true หรือ false ให้ใช้ bool literal (ย่อมาจาก Boolean):

Program.cs 
Console.WriteLine(true);
Console.WriteLine(false);
Output
True
False
⚠️ สังเกตตัวพิมพ์ใหญ่ ในโค้ดคุณพิมพ์ true/false ตัวเล็ก แต่ผลลัพธ์ที่พิมพ์ออกจอ เป็น True/False ขึ้นต้นด้วยตัวใหญ่ — เป็นพฤติกรรมปกติของ เมธอด WriteLine ตอนแสดงค่า bool

ทำไมต้องเน้นเรื่องชนิดข้อมูล

ชนิดข้อมูล (data type) มีบทบาทสำคัญมากใน C# จริงๆ แล้วการเน้นเรื่องชนิดข้อมูลนี่แหละ คือหนึ่งในจุดเด่นที่ทำให้ C# ต่างจากภาษาอื่นอย่าง JavaScript ผู้ออกแบบ C# เชื่อว่าการ "บังคับ" ให้ใช้ชนิดข้อมูลถูกต้อง จะช่วยนักพัฒนาเลี่ยงบั๊กที่พบบ่อยได้

string กับ char ใช้สำหรับ "การแสดงผล ไม่ใช่การคำนวณ" ถ้าต้องคำนวณ ทางคณิตศาสตร์กับตัวเลข ควรใช้ int หรือ decimal เช่น เบอร์โทรศัพท์ หรือรหัสไปรษณีย์ แม้จะเป็นตัวเลข แต่ไม่ค่อยถูกนำไปคำนวณ จึงควรเก็บเป็น string แทน เช่นเดียวกับ bool — ถ้าทำงานกับคำว่า "true"/"false" ในฐานะข้อความ ให้ใช้ string แต่ถ้าทำงานกับแนวคิดจริง/เท็จเพื่อประเมินเงื่อนไข ให้ใช้ bool

ค่าที่แสดงผลอาจดูเหมือนกัน แต่ชนิดข้อมูลข้างในต่างกันโดยสิ้นเชิง:

Program.cs 
// Output: 123
Console.WriteLine("123");
// Output: 123
Console.WriteLine(123);

// Output: true
Console.WriteLine("true");
// Output: True
Console.WriteLine(true);
✅ สรุปสั้นๆ string คำ/วลี · char อักขระเดียว · int เลขเต็ม · decimal เลขทศนิยม (แนะนำให้ใช้ตัวนี้เป็นหลัก) · bool จริง/เท็จ

2.3 ประกาศตัวแปร (Declare Variables)

literal คือค่าที่ฝังตายตัว แต่แอปส่วนใหญ่ต้องทำงานกับข้อมูลที่คุณไม่รู้ล่วงหน้า เช่น ข้อมูล จากผู้ใช้ จากไฟล์ หรือจากเครือข่าย เมื่อไรที่ต้องทำงานกับข้อมูลที่ไม่ตายตัว คุณจะประกาศตัวแปร

ตัวแปรคืออะไร

ตัวแปร (variable) คือ "ภาชนะ" สำหรับเก็บค่าชนิดหนึ่ง ที่สำคัญคือค่าของมัน เปลี่ยนแปลงได้ ตลอดการทำงานของโปรแกรม — กำหนดค่า อ่านค่า และเปลี่ยนค่าได้ ชื่อตัวแปรเป็นป้ายที่มนุษย์อ่านง่าย ซึ่งคอมไพเลอร์ผูกไว้กับตำแหน่งในหน่วยความจำ พอต้องการ เก็บ/เปลี่ยน/เรียกคืนค่าที่ตำแหน่งนั้น ก็แค่ใช้ชื่อตัวแปรที่ตั้งไว้

ประกาศตัวแปร

การสร้างตัวแปรใหม่ ต้องประกาศชนิดข้อมูลก่อน แล้วค่อยตั้งชื่อ:

Program.cs 
string firstName;

บรรทัดนี้สร้างตัวแปรชนิด string ชื่อ firstName จากนี้ไป ตัวแปรนี้ เก็บได้แต่ค่าชนิด string เท่านั้น

กฎและธรรมเนียมการตั้งชื่อตัวแปร

มีนักพัฒนาเคยพูดไว้ว่า "ส่วนที่ยากที่สุดของการพัฒนาซอฟต์แวร์คือการตั้งชื่อสิ่งต่างๆ" ชื่อตัวแปรไม่ใช่แค่ต้องตรงกฎไวยากรณ์ แต่ยังต้องช่วยให้โค้ดอ่านเข้าใจง่ายด้วย

หมวดกฎ / ธรรมเนียม
กฎบังคับใช้ตัวอักษร ตัวเลข และ _ ได้เท่านั้น ห้ามใช้ #, $ ฯลฯ
กฎบังคับต้องขึ้นต้นด้วยตัวอักษรหรือ _ ห้ามขึ้นต้นด้วยตัวเลข
กฎบังคับคำนึงตัวพิมพ์เล็ก-ใหญ่ — Value กับ value คือคนละตัวแปร
กฎบังคับห้ามตั้งชื่อซ้ำกับคำสงวนของ C# เช่น decimal decimal; ทำไม่ได้
ธรรมเนียมใช้ camelCase — ตัวแรกเล็ก คำถัดไปขึ้นต้นด้วยตัวใหญ่ เช่น thisIsCamelCase
ธรรมเนียมตั้งชื่อให้สื่อความหมาย บอกได้ว่าเก็บข้อมูลอะไร
ธรรมเนียมใช้คำเต็ม ไม่ย่อ ไม่ใช้คำห้วน เพื่อให้คนอื่นอ่านเข้าใจ
ธรรมเนียมอย่าเอาชนิดข้อมูลใส่ในชื่อ เช่น strValue — วิธีนี้ล้าสมัยแล้ว

ตัวอย่าง string firstName; ทำตามกฎและธรรมเนียมครบทุกข้อ (สมมติว่าตั้งใจเก็บชื่อจริงคน) ตัวอย่างอื่นๆ:

Program.cs 
char userOption;

int gameScore;

decimal particlesPerMillion;

bool processedCustomer;

2.4 ลงมือ: Set และ Get ค่าจากตัวแปร

ตัวแปรมีไว้ให้เขียนค่าลงไปและอ่านค่าออกมา — มาลองทั้งสองอย่างกัน

สร้างตัวแปรตัวแรก

สร้างโปรเจกต์ใหม่สำหรับบทนี้ แล้วพิมพ์โค้ด:

PowerShell 
dotnet new console -o ch02-variables
cd ch02-variables
Program.cs 
string firstName;
firstName = "Bob";
ยังไม่มีผลลัพธ์ — โค้ดนี้แค่เก็บค่า ยังไม่ได้สั่งพิมพ์

การจะกำหนดค่าให้ตัวแปร คุณใช้ assignment operator คือเครื่องหมายเท่ากับตัวเดียว =

ℹ️ ศัพท์ การกำหนดค่าเรียกอีกอย่างว่า "set the variable" หรือสั้นๆ ว่า "set"

กำหนดค่าผิดลำดับ

สำคัญมาก: การกำหนดค่าทำงานจากขวาไปซ้าย คอมไพเลอร์ต้องเข้าใจค่าฝั่งขวาของ = ก่อน แล้วค่อยเอาไปกำหนดให้ตัวแปรฝั่งซ้าย ถ้าสลับด้าน คอมไพเลอร์จะงง:

Program.cs
string firstName;
"Bob" = firstName;
Output
CS0131: The left-hand side of an assignment must be a variable, property or indexer

กำหนดค่าผิดชนิดข้อมูล

C# ถูกออกแบบให้บังคับชนิดข้อมูล หมายความว่าคุณกำหนดค่าชนิดหนึ่งให้ตัวแปรที่ประกาศไว้ เป็นอีกชนิดหนึ่งไม่ได้:

Program.cs
int firstName;
firstName = "Bob";
Output
CS0029: Cannot implicitly convert type 'string' to 'int'

ข้อความ error นี้บอกใบ้ว่าคอมไพเลอร์พยายาม "แปลงโดยปริยาย (implicitly convert)" สตริง "Bob" ให้เป็น int แต่ทำไม่ได้ เพราะคำว่า "Bob" ไม่มีค่าตัวเลขเทียบเท่า (เรื่องการแปลงชนิดข้อมูลแบบ implicit/explicit จะเรียนละเอียดในบทหลังๆ)

เรียกคืนค่าจากตัวแปร

การเรียกคืนค่า แค่ใช้ชื่อตัวแปรนั้นเอง:

Program.cs 
string firstName;
firstName = "Bob";
Console.WriteLine(firstName);
Output
Bob
ℹ️ ศัพท์ การเรียกคืนค่าเรียกอีกอย่างว่า "get the variable" หรือสั้นๆ ว่า "get"

กำหนดค่าใหม่ซ้ำได้

ใช้ซ้ำและกำหนดค่าใหม่ให้ตัวแปรได้เรื่อยๆ ตามต้องการ:

Program.cs 
string firstName;
firstName = "Bob";
Console.WriteLine(firstName);
firstName = "Liem";
Console.WriteLine(firstName);
firstName = "Isabella";
Console.WriteLine(firstName);
firstName = "Yasmin";
Console.WriteLine(firstName);
Output
Bob
Liem
Isabella
Yasmin

กำหนดค่าเริ่มต้น (initialize)

คุณต้อง set ค่าให้ตัวแปรก่อน ถึงจะ get ค่านั้นได้ ไม่งั้นจะเจอ error:

Program.cs
string firstName;
Console.WriteLine(firstName);
Output
CS0165: Use of unassigned local variable 'firstName'

เพื่อเลี่ยงปัญหานี้ แนะนำให้กำหนดค่าทันทีหลังประกาศตัวแปร จริงๆ แล้วสามารถประกาศและ กำหนดค่าในบรรทัดเดียวได้เลย เทคนิคนี้เรียกว่า initializing ตัวแปร:

Program.cs 
string firstName = "Bob";
Console.WriteLine(firstName);
Output
Bob

2.5 ตัวแปรแบบอนุมานชนิดอัตโนมัติด้วย var

คอมไพเลอร์ C# ช่วยงานคุณได้อีกอย่าง — มันอนุมานชนิดข้อมูลของตัวแปรจากค่าที่กำหนดให้ได้เอง

var คืออะไร

ตัวแปรแบบอนุมานชนิดอัตโนมัติ (implicitly typed local variable) สร้างด้วยคีย์เวิร์ด var ตามด้วยการกำหนดค่าเริ่มต้น:

Program.cs 
var message = "Hello world!";

ตัวอย่างนี้สร้างตัวแปร string โดยใช้คีย์เวิร์ด var แทนคีย์เวิร์ด string — var บอกคอมไพเลอร์ว่าชนิดข้อมูลถูกอนุมานจากค่าที่กำหนดให้ พอชนิดถูกอนุมานแล้ว ตัวแปรนั้นจะทำงานเหมือนประกาศด้วยชนิดข้อมูลจริงทุกประการ var ช่วยลดการพิมพ์เมื่อชื่อชนิดข้อมูลยาวหรือชัดเจนอยู่แล้วจากบริบท

เพราะตัวแปร message ถูกกำหนดค่าเป็น string ทันที คอมไพเลอร์จึงเข้าใจเจตนา และปฏิบัติกับ message เป็น string ตลอดไป — ชนิดข้อมูลถูก "ล็อก" ไว้ตั้งแต่ ตอนประกาศ และจะไม่มีวันเปลี่ยนเป็นชนิดอื่นได้อีก:

Program.cs
var message = "Hello World!";
message = 10.703m;
Output
CS0029: Cannot implicitly convert type 'decimal' to 'string'
ℹ️ เทียบกับภาษาอื่น ภาษาอื่นอาจใช้ var ต่างออกไป แต่ใน C# ตัวแปรถูกกำหนดชนิดโดยคอมไพเลอร์เสมอ ไม่ว่าจะใช้ชื่อชนิดข้อมูลจริงหรือให้คอมไพเลอร์อนุมานก็ตาม ชนิดจะถูกล็อกตั้งแต่ตอนประกาศ และจะเก็บค่าชนิดอื่นไม่ได้อีกเลย

ตัวแปรที่ใช้ var ต้องกำหนดค่าเริ่มต้นเสมอ

var ต้องพึ่งค่าที่ใช้กำหนดตอนเริ่มต้นเสมอ ถ้าใช้ var โดยไม่กำหนดค่าเริ่มต้น จะคอมไพล์ไม่ผ่าน:

Program.cs
var message;
Output
CS0818: Implicitly-typed variables must be initialized

ทำไมต้องใช้ var

var ถูกใช้กันแพร่หลายมากในวงการ C# คุณจะเห็นมันบ่อยในตัวอย่างโค้ดจากหนังสือ หรือออนไลน์ หลายครั้งชนิดของตัวแปรก็ชัดเจนอยู่แล้วจากค่าที่กำหนดให้ตอนประกาศ ทำให้ใช้ var ได้เรียบง่ายกว่า และยังมีประโยชน์ตอนวางแผนโค้ด — ตอนเริ่มพัฒนา คุณอาจยังไม่รู้ทันทีว่าควรใช้ชนิดข้อมูลไหน การใช้ var ช่วยให้พัฒนาโซลูชันได้ ยืดหยุ่นกว่า

💡 คำแนะนำสำหรับมือใหม่ ตอนเริ่มต้น แนะนำให้ใช้ชื่อชนิดข้อมูลจริง (เช่น string, int) แทน var ไปก่อน จนกว่าจะคุ้นเคยกับการเขียนโค้ดมากขึ้น การระบุชนิดข้อมูลชัดเจน จะช่วยให้คุณตั้งใจ (purposeful) มากขึ้นตอนเขียนโค้ด

2.6 ท้าทาย: รวม Literal และ Variable เป็นข้อความเดียว

โจทย์ตามต้นฉบับ MS Learn

เก็บค่าต่อไปนี้ไว้ในตัวแปร (ตั้งชื่อให้สื่อความหมาย และเลือกชนิดข้อมูลให้ตรงกับข้อมูล):

  • Bob
  • 3
  • 34.4

แล้วผสมตัวแปรเหล่านี้เข้ากับสตริง literal ผ่านชุดคำสั่ง Console.Write() หลายครั้ง เพื่อประกอบเป็นข้อความสมบูรณ์ตามนี้:

ผลลัพธ์ที่ต้องได้
Hello, Bob! You have 3 messages in your inbox. The temperature is 34.4 celsius.
💡 ขอคำใบ้

คำใบ้ 1: คุณต้องมีตัวแปร 3 ตัว ชนิด string, int, และ decimal/float/double ตามลำดับ

คำใบ้ 2: Console.Write() รับตัวแปรเป็นพารามิเตอร์ได้โดยตรง ไม่ต้องแปลงเป็น string เอง เช่น Console.Write(ตัวแปร);

2.7 เฉลยและวิเคราะห์

Program.cs — เฉลยตัวอย่าง 
string name = "Bob";
int messages = 3;
decimal temperature = 34.4m;

Console.Write("Hello, ");
Console.Write(name);
Console.Write("! You have ");
Console.Write(messages);
Console.Write(" messages in your inbox. The temperature is ");
Console.Write(temperature);
Console.Write(" celsius.");
Output
Hello, Bob! You have 3 messages in your inbox. The temperature is 34.4 celsius.

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ อาจใช้จำนวนครั้งของ Console.Write() ต่างไปก็ได้ แต่ตามโจทย์ คุณต้องกำหนดค่าเริ่มต้นให้ตัวแปร ครบ 3 ตัว โดยใช้:

  • ตัวแปรชนิด string เก็บชื่อ "Bob"
  • ตัวแปรชนิด int เก็บจำนวนข้อความ
  • ตัวแปรชนิด decimal, float, หรือ double เก็บอุณหภูมิ

2.9 ❓ Knowledge Check

คำถามชุดนี้แปลจาก Module Assessment จริงของบทนี้ใน Microsoft Learn

1. ชื่อตัวแปรข้อใดต้องหลีกเลี่ยง (ผิดกฎ)?

  • A$DATA
  • BregistrationComplete
  • Cflag
เฉลย: ข้อ A. ชื่อตัวแปรห้ามมีอักขระพิเศษอย่าง $ — ผิดกฎ C# ทันที ข้อ B และ C เป็นชื่อที่ถูกต้องตามกฎและธรรมเนียม camelCase

2. โค้ดบรรทัดนี้ผิดตรงไหน? var message;

  • Avar ไม่ใช่ชนิดข้อมูล
  • Bใช้คีย์เวิร์ด var โดยไม่กำหนดค่าเริ่มต้นให้ตัวแปร
  • Cตัวแปรชื่อ message ต้องเป็น string เสมอ
เฉลย: ข้อ B. ตัวแปรที่ประกาศด้วย var ต้องมีค่าเริ่มต้นเสมอ เพราะคอมไพเลอร์ต้องใช้ค่านั้นอนุมานชนิดข้อมูล ไม่มีค่าก็อนุมานไม่ได้ → CS0818

3. Console.WriteLine(34.40M); ให้ผลลัพธ์อะไร?

  • A34.40M
  • B34.4
  • C34.40
เฉลย: ข้อ C. ชนิด decimal เก็บ "ความละเอียด (scale)" ของเลขไว้ด้วย เลขศูนย์ท้ายที่คุณพิมพ์ไว้ตอนสร้าง literal จึงยังคงอยู่ตอนแสดงผล (ต่างจาก float/double ที่มักตัดศูนย์ท้ายทิ้ง) — ส่วนตัวอักษร suffix M ไม่ถูกพิมพ์ออกมาด้วย เพราะมันบอกชนิดข้อมูลให้คอมไพเลอร์เท่านั้น

4. โค้ดข้อใดสร้างตัวแปรถูกต้อง?

  • Aint x = 12.3m;
  • Bdecimal x = 12.3m;
  • Cbool x = 'False';
เฉลย: ข้อ B. ชนิดตัวแปรตรงกับ suffix ของ literal พอดี ข้อ A ผิดเพราะกำหนดค่า decimal ให้ตัวแปร int ไม่ได้ ข้อ C ผิดสองต่อ — เครื่องหมายคำพูดเดี่ยว สร้างได้แค่ char ตัวเดียว (แถม 'False' มี 5 ตัวอักษรจะ error CS1012 ด้วยซ้ำ) และต่อให้เป็น char ก็กำหนดให้ตัวแปร bool ไม่ได้อยู่ดี

ข้อ 4กลาง

โค้ดนี้มี error 1 จุด (เกี่ยวกับชนิดข้อมูล) หาให้เจอและแก้ไข:

คอมไพเลอร์อนุมานชนิดข้อมูลจากค่าที่กำหนดให้ตอนประกาศ ได้ชนิดเดียวกับที่พิมพ์เอง ทุกประการ (string, int, bool ตามลำดับ)

ข้อ 6ท้าทาย

เขียนโปรแกรมเก็บข้อมูลใบเสร็จง่ายๆ ด้วยตัวแปร 4 ตัว (ชื่อสินค้า/ราคา/จำนวนชิ้น/มีส่วนลดไหม) แล้วพิมพ์ข้อความสรุปให้ตรงเป๊ะบรรทัดนี้ โดยห้ามพิมพ์ค่าตัวเลข/ข้อความจริงลงในคำสั่ง Write โดยตรง — ต้องดึงจากตัวแปรทั้งหมด:

สินค้า: หูฟังไร้สาย จำนวน: 2 ชิ้น ราคารวม: 1590 บาท มีส่วนลด: True
💡 คำใบ้

ต้องมีตัวแปรอย่างน้อย: string ชื่อสินค้า, int จำนวนชิ้น, decimal ราคารวม, bool มีส่วนลด แล้วผสมกับสตริง literal ผ่าน Console.Write() หลายครั้งเหมือนหัวข้อ 2.7

ดูเฉลย
Program.cs

decimal totalPrice = 1590;

Console.Write("สินค้า: ");
Console.Write(productName);
Console.Write(" จำนวน: ");
Console.Write(quantity);
Console.Write(" ชิ้น ราคารวม: ");
Console.Write(totalPrice);
Console.Write(" บาท มีส่วนลด: ");
Console.Write(hasDiscount);
