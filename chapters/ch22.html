22.1 สถานการณ์: ฟอร์มรับผู้ป่วยทางการแพทย์

สมมติคุณเป็นนักพัฒนาซอฟต์แวร์ในทีมที่ทำงานเกี่ยวกับระบบอัตโนมัติสำหรับฟอร์มรับผู้ป่วยทาง การแพทย์ คุณได้รับมอบหมายให้ส่งมอบฟีเจอร์ของแอปสำหรับเก็บข้อมูลที่เจ้าหน้าที่การแพทย์กรอกก่อน ที่แพทย์จะพบผู้ป่วย เจ้าหน้าที่ใช้แอปบันทึกวันที่และเวลา อายุผู้ป่วย ส่วนสูง น้ำหนัก ชีพจร และความดันโลหิต แอปยังมีช่องข้อความสำหรับข้อมูลอื่นๆ เช่น เหตุผลที่มาพบแพทย์ ยาที่กำลังใช้อยู่ และรายการอื่นๆ คุณต้องทำงานกับข้อมูลที่มี data type ผสมกันหลายแบบ สำหรับต้นแบบ (prototype) คุณจะสร้าง console application แล้วรับ input ทั้งหมดเป็น string

เพราะ input เริ่มต้นถูกกรอกมาเป็น string คุณจึงต้องเปลี่ยนค่าจาก data type หนึ่งไปเป็นอีก ชนิดในโค้ดเป็นครั้งคราว ตัวอย่างง่ายๆ คือการดำเนินการทางคณิตศาสตร์ใดๆ ที่คุณต้องการทำกับข้อมูล string — คุณต้องเปลี่ยนค่าเป็น numeric data type อย่าง int ก่อน ถึงจะดำเนินการ ได้ หรือในทางกลับกัน คุณอาจต้องการจัดรูปแบบและแสดงค่าตัวเลขสำหรับรายงานสรุปด้วย string interpolation

คุณจะใช้เทคนิคต่างกันในการเปลี่ยน data type เมื่อจำเป็น คุณจะเรียนว่าเมื่อไรควรใช้เทคนิคไหน และเมื่อไรที่เทคนิคหนึ่งๆ อาจเสี่ยงต่อการสูญเสียข้อมูล

ℹ️ ตั้งค่า Culture ก่อนเริ่ม (ถ้าจำเป็น) โค้ดตัวอย่างในบทนี้ออกแบบตามการตั้งค่า culture แบบ en-US ซึ่งใช้จุด (.) เป็นตัวคั่น ทศนิยม ถ้าเครื่องคุณตั้งค่า culture ที่ใช้ตัวคั่นทศนิยมต่างออกไป (เช่น จุลภาค) ผลลัพธ์อาจไม่ ตรงกับที่แสดงในหนังสือ ถ้าเจอปัญหานี้ ให้เพิ่มโค้ดต่อไปนี้ไว้บนสุดของไฟล์ (หลัง using อื่นๆ ถ้ามี):
Program.cs (บนสุด) 
using System.Globalization;
CultureInfo.CurrentCulture = new CultureInfo("en-US");

22.2 ทำไม int + string ถึง Error แต่ string + int ทำงานได้

มีเทคนิคหลายแบบในการแปลง data type เทคนิคที่คุณเลือกขึ้นอยู่กับคำตอบของ 2 คำถามสำคัญ:

  • มีความเป็นไปได้ไหมที่ การเปลี่ยน data type ของค่านั้น อาจทำให้เกิด exception ตอนรันจริง ขึ้นอยู่กับค่านั้นๆ?
  • มีความเป็นไปได้ไหมที่ การเปลี่ยน data type ของค่านั้น จะทำให้ข้อมูลสูญหาย ขึ้นอยู่กับ ค่านั้นๆ?

ลองบวก int กับ string ดู

Program.cs 
int first = 2;
string second = "4";
int result = first + second;
Console.WriteLine(result);
Output
Program.cs(3,14): error CS0029: Cannot implicitly convert type 'string' to 'int'

ส่วนสำคัญของข้อความ error คือ Cannot implicitly convert type 'string' to 'int' บอกว่าปัญหาอยู่ที่การใช้ data type string

แต่ทำไม C# compiler ถึงจัดการ error นี้ให้ไม่ได้ ในเมื่อทำแบบตรงข้ามได้ — ต่อ (concatenate) ตัวเลขเข้ากับ string แล้วเก็บใน string variable — ลองเปลี่ยนชนิดของตัวแปร result จาก int เป็น string ดู:

Program.cs 
int first = 2;
string second = "4";
string result = first + second;
Console.WriteLine(result);
Output
24

ผลลัพธ์นี้ผิดในทางคณิตศาสตร์ แต่รันได้ เพราะรวมค่าเป็นตัวอักษร "2" กับ "4" เข้าด้วยกัน (concatenation ไม่ใช่ addition) — คำถามคือ ทำไม C# compiler ไม่ฉลาดพอที่จะรู้ว่าคุณต้องการ ปฏิบัติกับตัวแปร second ที่มีค่า 4 เป็นตัวเลข ไม่ใช่ string?

Compiler เลือกทำเฉพาะการแปลงที่ปลอดภัย

C# compiler มองเห็นปัญหาที่อาจเกิดขึ้นล่วงหน้า ตัวแปร second เป็นชนิด string ดังนั้นมันอาจถูกกำหนดค่าเป็นอย่างอื่นได้ เช่น "hello" ถ้า C# compiler พยายามแปลง "hello" เป็นตัวเลข มันจะทำให้เกิด exception ตอนรันจริง เพื่อป้องกันความเป็นไปได้นี้ C# compiler จึงไม่ทำการแปลงจาก string เป็น int ให้คุณโดยอัตโนมัติ (implicit)

จากมุมมองของ C# compiler การดำเนินการที่ปลอดภัยกว่าคือแปลง int เป็น string แล้วทำ concatenation แทน

ถ้าคุณตั้งใจจะบวกเลขโดยใช้ string จริงๆ C# compiler จะบังคับให้คุณควบคุมกระบวนการแปลง data type อย่างชัดเจนมากขึ้น พูดอีกแบบคือ มันบังคับให้คุณมีส่วนร่วมมากขึ้น เพื่อให้คุณวาง มาตรการป้องกันที่เหมาะสมสำหรับจัดการความเป็นไปได้ที่การแปลงอาจ throw exception

ถ้าคุณต้องเปลี่ยนค่าจาก data type เดิมเป็น data type ใหม่ และการเปลี่ยนนั้นอาจทำให้เกิด exception ตอนรันจริง คุณต้องทำ data conversion — มีเทคนิคหลายแบบที่ใช้ทำ data conversion ได้:

  • ใช้ helper method บนตัวแปร (เช่น myVar.ToString())
  • ใช้ helper method บน data type (เช่น int.Parse(myString))
  • ใช้เมธอดของ Convert class (เช่น Convert.ToInt32(myString))

Check ★ เทคนิคไหนดีที่สุดสำหรับแปลง decimal type เป็น int type แบบปัดเศษ (ไม่ใช่ตัดทิ้ง)?

  • AConvert
  • BNarrowing (cast operator ตรงๆ)
  • CImplicit conversion
เฉลย: ข้อ A. Convert class ปัดเศษให้ตามที่คาดหวัง ส่วน cast operator ตรงๆ (narrowing) จะตัดทศนิยมทิ้งเฉยๆ ไม่ปัด และ implicit conversion ใช้ไม่ได้ กับ narrowing conversion อยู่แล้ว (compiler ไม่ยอมทำให้อัตโนมัติ)

22.3 Widening vs Narrowing, Cast vs Convert

Widening Conversion (แปลงแบบขยาย) — ใช้ Implicit ได้

Program.cs 
int myInt = 3;
Console.WriteLine($"int: {myInt}");

decimal myDecimal = myInt;
Console.WriteLine($"decimal: {myDecimal}");
Output
int: 3
decimal: 3

บรรทัดสำคัญคือ decimal myDecimal = myInt; — เพราะค่า int ใดๆ ก็ใส่ใน decimal ได้อย่างสบาย compiler จึงทำการแปลงให้เลย

คำว่า widening conversion (แปลงแบบขยาย) หมายถึงคุณกำลังแปลงค่าจาก data type ที่เก็บข้อมูลได้น้อยกว่าไปเป็น data type ที่เก็บข้อมูลได้มากกว่า ในกรณีนี้ ค่าที่ เก็บในตัวแปรชนิด int ถูกแปลงเป็นตัวแปรชนิด decimal โดยไม่สูญเสีย ข้อมูลเลย เมื่อคุณรู้ว่ากำลังทำ widening conversion คุณพึ่งพา implicit conversion ได้เลย — compiler จัดการ implicit conversion ให้เอง

Narrowing Conversion (แปลงแบบย่อ) — ต้อง Cast เอง

Program.cs 
decimal myDecimal = 3.14m;
Console.WriteLine($"decimal: {myDecimal}");

int myInt = (int)myDecimal;
Console.WriteLine($"int: {myInt}");
Output
decimal: 3.14
int: 3

ตอนทำ cast คุณใช้ casting operator () ครอบ data type แล้ววางไว้ข้างตัวแปรที่ ต้องการแปลง (ตัวอย่าง: (int)myDecimal) คุณกำลังทำ explicit conversion ไปยัง data type ที่กำหนดไว้ (int)

บรรทัดสำคัญคือ int myInt = (int)myDecimal; — ตัวแปร myDecimal เก็บค่าที่มีความละเอียดหลังจุดทศนิยม การเพิ่มคำสั่ง cast (int) เข้าไป คือการบอก C# compiler ว่าคุณเข้าใจว่าอาจสูญเสียความละเอียดนั้น และในสถานการณ์นี้ก็ไม่เป็นไร คุณกำลัง บอก compiler ว่าคุณตั้งใจแปลงแบบนี้ — เป็น explicit conversion

คำว่า narrowing conversion (แปลงแบบย่อ) หมายถึงคุณกำลังแปลงค่าจาก data type ที่เก็บ ข้อมูลได้มากกว่าไปเป็น data type ที่เก็บข้อมูลได้น้อยกว่า คุณอาจสูญเสียข้อมูล เช่น precision (จำนวนค่าหลังจุดทศนิยม) เมื่อคุณรู้ว่ากำลังทำ narrowing conversion คุณต้องทำ cast — การ cast คือคำสั่งบอก C# compiler ว่าคุณรู้ว่า precision อาจสูญหาย แต่ยินดี ยอมรับมัน

ถ้าไม่แน่ใจว่าจะสูญเสียข้อมูลหรือไม่ ให้เขียนโค้ดทดสอบทั้งสองแบบแล้วสังเกตความเปลี่ยนแปลง นักพัฒนามักเขียน test เล็กๆ แบบนี้เพื่อเข้าใจพฤติกรรมให้ชัดขึ้น:

Program.cs 
decimal myDecimal = 1.23456789m;
float myFloat = (float)myDecimal;

Console.WriteLine($"Decimal: {myDecimal}");
Console.WriteLine($"Float  : {myFloat}");
Output
Decimal: 1.23456789
Float  : 1.2345679

สังเกตจาก output ได้ว่าการ cast decimal เป็น float เป็น narrowing conversion เพราะสูญเสียความละเอียดไปบางส่วน (ทศนิยมตำแหน่งสุดท้ายถูกปัดหายไป)

Check ★ การแปลงข้อใดปัดเศษ (round) แทนที่จะตัดทิ้ง (truncate)?

  • Aint cost = (int)3.75m;
  • Bint cost = Convert.ToInt32(3.75m);
  • Cuint cost = (uint)3.75m;
เฉลย: ข้อ B. cast operator () ตัดทศนิยมทิ้งเสมอ (truncate) ไม่ว่าจะ cast เป็น int หรือ uint ก็ตาม มีแค่ Convert.ToInt32() เท่านั้นที่ปัดเศษให้

3 เทคนิคของ Data Conversion

1) ToString() — helper method บนตัวแปร: ทุกตัวแปร data type มีเมธอด ToString() พฤติกรรมของมันขึ้นอยู่กับว่า type นั้น implement ยังไง แต่กับ primitive ส่วนใหญ่ มันทำ widening conversion แม้จะไม่จำเป็นเสมอไป (เพราะพึ่ง implicit conversion ได้ในกรณีส่วนใหญ่) แต่การเขียน ToString() ชัดๆ ช่วยสื่อสารกับนัก พัฒนาคนอื่นว่าคุณเข้าใจว่ากำลังทำอะไรและตั้งใจทำ

Program.cs 
int first = 5;
int second = 7;
string message = first.ToString() + second.ToString();
Console.WriteLine(message);
Output
57

2) Parse() — helper method บน data type: numeric data type ส่วนใหญ่มีเมธอด Parse() ที่แปลง string เป็น data type นั้นได้

Program.cs 
string first = "5";
string second = "7";
int sum = int.Parse(first) + int.Parse(second);
Console.WriteLine(sum);
Output
12
⚠️ ปัญหาที่ซ่อนอยู่ของ Parse() ลองคิดดูสักครู่ว่ามีปัญหาอะไรซ่อนอยู่ในตัวอย่างข้างบน — ถ้า first หรือ second มีค่าที่แปลงเป็น int ไม่ได้ล่ะ? จะเกิด exception ทันทีตอน รันจริง C# compiler และ runtime คาดหวังให้คุณวางแผนล่วงหน้าและป้องกัน "การแปลงที่ผิดกฎ" แบบนี้ วิธีที่ง่ายที่สุดในการบรรเทาปัญหานี้คือใช้ TryParse() ซึ่งเป็นเวอร์ชันที่ดีกว่า ของ Parse() (ดูหัวข้อ 22.4)

3) Convert class — ใช้เมธอดของ Convert class: Convert class มี helper method จำนวนมากสำหรับแปลงค่าจาก type หนึ่งเป็นอีก type

Program.cs 
string value1 = "5";
string value2 = "7";
int result = Convert.ToInt32(value1) * Convert.ToInt32(value2);
Console.WriteLine(result);
Output
35
💡 ทำไมต้องชื่อ ToInt32() ไม่ใช่ ToInt() System.Int32 คือชื่อ data type จริงใน .NET Class Library ที่ภาษา C# แมปมาเป็น คีย์เวิร์ด int (ทบทวนจาก บทที่ 21 หัวข้อ 21.2c) เพราะ Convert class เป็นส่วนหนึ่งของ .NET Class Library เช่นกัน มันถูกเรียกด้วยชื่อเต็ม ไม่ใช่ชื่อย่อของ C# — การกำหนด data type ไว้ใน .NET Class Library แบบนี้ทำให้หลายภาษาบน .NET (Visual Basic, F#, IronPython ฯลฯ) ใช้ data type และ class เดียวกันร่วมกันได้ เมธอด ToInt32() มี overload ถึง 19 แบบ รับ data type ได้แทบทุกชนิด — แต่เมื่อใช้กับ string โดยเฉพาะ ควรพิจารณาใช้ TryParse() แทนเมื่อทำได้ (ปลอดภัยกว่า)

แล้วเมื่อไรควรใช้ Convert class? Convert เหมาะที่สุดสำหรับแปลง ตัวเลขมีเศษให้เป็นจำนวนเต็ม (int) เพราะมันปัดเศษตามที่คาดหวัง

เปรียบเทียบ Cast กับ Convert ตอนแปลง decimal เป็น int

Program.cs 
int value = (int)1.5m; // casting truncates
Console.WriteLine(value);

int value2 = Convert.ToInt32(1.5m); // converting rounds up
Console.WriteLine(value2);
Output
1
2

ตอน cast int value = (int)1.5m; ค่าทศนิยมถูกตัดทิ้ง (truncate) ผลลัพธ์ จึงเป็น 1 หมายความว่าค่าหลังจุดทศนิยมถูกละเลยไปเลย ต่อให้เปลี่ยน literal เป็น 1.999m ผลลัพธ์ของการ cast ก็ยังเป็น 1 เหมือนเดิม

ตอนแปลงด้วย Convert.ToInt32() ค่า literal ถูกปัดขึ้นอย่างถูกต้องเป็น 2 ถ้าเปลี่ยนค่า literal เป็น 1.499m ผลลัพธ์จะถูกปัดลงเป็น 1

ℹ️ สรุป: cast ตัดทิ้ง, convert ปัดเศษ จำง่ายๆ: () cast operator = ตัดทิ้งเสมอ (ไม่สนใจกฎการปัดเศษใดๆ) — Convert.ToXxx() = ปัดเศษตามกฎมาตรฐาน (0.5 ขึ้นไปปัดขึ้น ต่ำกว่าปัดลง)

22.4 TryParse() และ out Parameter

เวลาทำงานกับข้อมูล บางครั้งคุณต้องแปลงข้อมูล string เป็น numeric data type อย่างที่เรียนไปใน หัวข้อก่อน เพราะ string data type เก็บค่าที่ไม่ใช่ตัวเลขได้ด้วย การแปลงจาก string เป็น numeric data type จึงอาจทำให้เกิด runtime error ได้

ตัวอย่างเช่น โค้ดนี้:

Program.cs 
string name = "Bob";
Console.WriteLine(int.Parse(name));
Output
System.FormatException: 'Input string was not in a correct format.'

ทำให้เกิด exception ตามนี้ — เพื่อหลีกเลี่ยง format exception แบบนี้ ให้ใช้เมธอด TryParse() บน data type เป้าหมายแทน

TryParse() ทำ 3 อย่างพร้อมกัน

  • พยายาม parse string เป็น numeric data type ที่กำหนด
  • ถ้าสำเร็จ เก็บค่าที่แปลงแล้วไว้ใน out parameter
  • คืนค่า bool บอกว่าการทำงานสำเร็จหรือล้มเหลว

คุณใช้ค่า Boolean ที่คืนกลับมาตัดสินใจต่อได้ (เช่น คำนวณต่อ) หรือแสดงข้อความถ้าการ parse ไม่สำเร็จ

💡 out Parameter คืออะไร เมธอดคืนค่าได้หนึ่งค่า หรือคืน "void" (ไม่คืนค่าเลย) แต่เมธอดยังคืนค่าผ่าน out parameter ได้ด้วย — นิยามคล้าย input parameter ปกติ แต่มีคีย์เวิร์ด out กำกับ เป็นกลไกที่ให้เมธอดหนึ่ง "คืนค่า" ได้มากกว่าหนึ่งทาง (ทั้ง return value ปกติ + ค่าผ่าน out parameter)

TryParse() String เป็น int

Program.cs 
string value = "102";
int result = 0;
if (int.TryParse(value, out result))
{
   Console.WriteLine($"Measurement: {result}");
}
else
{
   Console.WriteLine("Unable to report the measurement.");
}
Output
Measurement: 102

ตอนเรียกเมธอดที่มี out parameter คุณต้องใส่คีย์เวิร์ด out ไว้หน้า ตัวแปรที่จะเก็บค่า — ใน int.TryParse(value, out result) ค่าจาก out parameter ถูกกำหนดให้ตัวแปร result คุณใช้ค่าที่ result เก็บอยู่ต่อในโค้ดที่ เหลือได้เลย

int.TryParse() คืนค่า true ถ้าแปลงตัวแปร value เป็น int สำเร็จ ไม่งั้นคืน false — ครอบ statement ด้วย if แล้วจัดการตรรกะการตัดสินใจตามนั้น

ค่าที่แปลงแล้วถูกเก็บในตัวแปร int ชื่อ result — ตัวแปร result ถูกประกาศและกำหนดค่าเริ่มต้นไว้ก่อนบรรทัดนี้ จึงเข้าถึงได้ทั้ง ข้างใน code block ของ if และ else และข้างนอกทั้งสอง ด้วย

ใช้ค่าที่ Parse แล้วต่อในโค้ดถัดไป

Program.cs 
string value = "102";
int result = 0;
if (int.TryParse(value, out result))
{
   Console.WriteLine($"Measurement: {result}");
}
else
{
   Console.WriteLine("Unable to report the measurement.");
}
Console.WriteLine($"Measurement (w/ offset): {50 + result}");
Output
Measurement: 102
Measurement (w/ offset): 152

เพราะตัวแปร result ถูกประกาศไว้นอก if statement มันจึงถูกเข้าถึง ได้ต่อในโค้ดที่ตามมาทีหลัง

กรณี Parse ไม่สำเร็จ

Program.cs 
string value = "bad";
int result = 0;
if (int.TryParse(value, out result))
{
   Console.WriteLine($"Measurement: {result}");
}
else
{
   Console.WriteLine("Unable to report the measurement.");
}

if (result > 0)
   Console.WriteLine($"Measurement (w/ offset): {50 + result}");
Output
Unable to report the measurement.

เพราะ result ถูกประกาศนอก if statement จึงเข้าถึงได้จากภายนอก code block ด้วย โค้ดจึงเช็คว่า result มีค่ามากกว่าศูนย์ก่อนถึงจะยอมให้พิมพ์ค่า result + offset ออกมา การเช็คค่า result ว่ามากกว่าศูนย์แบบนี้ ป้องกันไม่ให้พิมพ์ค่า offset ต่อท้ายข้อความ "Unable to report the measurement." โดยไม่ ตั้งใจ

Check ★ ควรใช้เทคนิคไหนแปลง myInput ซึ่งเป็น string ค่า "2.71828" ให้เป็นตัวแปร decimal ชื่อ myInputDecimal?

  • Adecimal myInputDecimal = (decimal)(myInput);
  • Bdecimal myInputDecimal = myInput + 0;
  • Cdecimal.TryParse(myInput, out myInputDecimal);
เฉลย: ข้อ C. ข้อ A ไม่ compile เพราะ cast operator ใช้แปลง string เป็น decimal ตรงๆ ไม่ได้ (ไม่มี built-in cast ระหว่างสอง type นี้) ข้อ B ก็ไม่ compile ด้วยเหตุผลคล้ายกัน (บวก string กับ int ตรงๆ ไม่ได้) มีแค่ TryParse() เท่านั้นที่ใช้แปลง string เป็น decimal ได้อย่างปลอดภัยและถูกไวยากรณ์

Check ★ พิจารณาโค้ด bool success = decimal.TryParse(input, out decimal number); — ข้อใดอธิบาย return type ของ decimal.TryParse() ได้ถูกต้องที่สุด?

  • Adecimal
  • Bbool
  • Cout
เฉลย: ข้อ B. TryParse() คืนค่า bool เสมอ บอกว่าสำเร็จหรือไม่ — ค่า decimal ที่แปลงได้ถูกส่งผ่าน out parameter (พารามิเตอร์) ไม่ใช่ return value ปกติ

22.5 ท้าทาย 1: รวม String Array เป็นข้อความและตัวเลข

โจทย์ตามต้นฉบับ MS Learn

ใช้ array ตั้งต้นนี้:

ข้อมูลตั้งต้น
string[] values = { "12.3", "45", "ABC", "11", "DEF" };

สร้าง loop วนผ่านแต่ละ string ใน values แล้ว implement กฎธุรกิจต่อไปนี้:

  • กฎ 1: ถ้าค่านั้นเป็นตัวอักษร (alphabetical) ให้ต่อ (concatenate) เข้าเป็น ข้อความ
  • กฎ 2: ถ้าค่านั้นเป็นตัวเลข (numeric) ให้บวกเข้ากับผลรวม
  • กฎ 3: ผลลัพธ์ต้องตรงกับ output นี้:
Message: ABCDEF
Total: 68.3
💡 ขอคำใบ้

ทบทวนหัวข้อ 22.4 — เมธอดไหนที่บอกคุณได้ว่า string หนึ่งค่าเป็นตัวเลขหรือไม่ พร้อมแปลง ให้เสร็จในตัว โดยไม่ throw exception เวลาเจอค่าที่ไม่ใช่ตัวเลข?

🔓 ดูเฉลย (เฉลยทางการจาก Microsoft Learn)
Program.cs 
string[] values = { "12.3", "45", "ABC", "11", "DEF" };

decimal total = 0m;
string message = "";

foreach (var value in values)
{
    decimal number; // stores the TryParse "out" value
    if (decimal.TryParse(value, out number))
    {
        total += number;
    } else
    {
        message += value;
    }
}

Console.WriteLine($"Message: {message}");
Console.WriteLine($"Total: {total}");
Output
Message: ABCDEF
Total: 68.3

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ เฉลยนี้พึ่งพา TryParse() เป็นแกนหลัก — ใช้ค่า Boolean ที่คืนกลับมาตัดสินใจโดยตรงว่าจะบวกเข้าผลรวมหรือต่อเข้าข้อความ โดยไม่ต้องเขียนโค้ดตรวจสอบชนิดของอักขระเองเลย เป็นตัวอย่างที่ดีว่า TryParse() มีประโยชน์แค่ไหนเวลาข้อมูลมีชนิดปะปนกันแบบนี้

22.6 ท้าทาย 2: แสดงผลการคำนวณเป็น Type ที่กำหนด

โจทย์ตามต้นฉบับ MS Learn

ใช้ตัวแปรตั้งต้นนี้:

ข้อมูลตั้งต้น
int value1 = 11;
decimal value2 = 6.2m;
float value3 = 4.3f;

เขียนโค้ดแก้โจทย์ 3 ข้อนี้:

  • result1: เอา value1 หาร value2 แสดงผลลัพธ์เป็น int (ต้องปัดเศษเป็นจำนวนเต็มที่ใกล้ที่สุด ห้ามแค่ตัดทิ้ง)
  • result2: เอา value2 หาร value3 แสดงผลลัพธ์เป็น decimal
  • result3: เอา value3 หาร value1 แสดงผลลัพธ์เป็น float

ผลลัพธ์ที่ต้องได้:

Divide value1 by value2, display the result as an int: 2
Divide value2 by value3, display the result as a decimal: 1.4418604651162790697674418605
Divide value3 by value1, display the result as a float: 0.3909091
💡 ขอคำใบ้

result1 ต้องปัดเศษ ไม่ใช่ตัดทิ้ง — ทบทวนหัวข้อ 22.3d ว่าเทคนิคไหนปัดเศษให้ ส่วน result2 ต้องหาร decimal ด้วย float ตรงๆ ไม่ได้ (คนละ ประเภท ต้อง cast ตัวใดตัวหนึ่งก่อน) และ result3 เป็นการหาร float ด้วย int — ผลลัพธ์ที่ได้เป็น type ไหนโดย default?

🔓 ดูเฉลย (เฉลยทางการจาก Microsoft Learn)
Program.cs 
int value1 = 11;
decimal value2 = 6.2m;
float value3 = 4.3f;

// Convert class เหมาะที่สุดสำหรับแปลงตัวเลขมีเศษให้เป็นจำนวนเต็ม
// Convert.ToInt32() ปัดเศษตามที่คาดหวัง
int result1 = Convert.ToInt32(value1 / value2);
Console.WriteLine($"Divide value1 by value2, display the result as an int: {result1}");

decimal result2 = value2 / (decimal)value3;
Console.WriteLine($"Divide value2 by value3, display the result as a decimal: {result2}");

float result3 = value3 / value1;
Console.WriteLine($"Divide value3 by value1, display the result as a float: {result3}");
Output
Divide value1 by value2, display the result as an int: 2
Divide value2 by value3, display the result as a decimal: 1.4418604651162790697674418605
Divide value3 by value1, display the result as a float: 0.3909091

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ เฉลยนี้ใช้ cast หลายจุด (และเรียก convert หนึ่งครั้ง) แต่วิธีอื่นก็อาจใช้ได้ผลดีเท่ากัน ประเด็นสำคัญที่ควรสังเกต:

  • value1 / value2 คือ int หาร decimal — C# ยกระดับ (promote) int เป็น decimal โดยอัตโนมัติก่อนหาร (widening conversion) ผลลัพธ์เป็น decimal จึงต้องใช้ Convert.ToInt32() ครอบเพื่อปัดเศษเป็น int อีกที
  • value2 / (decimal)value3 — decimal กับ float หารกันตรงๆ ไม่ได้ (compile error) ต้อง cast value3 เป็น decimal ก่อนเสมอ
  • value3 / value1 คือ float หาร int — C# ยกระดับ int เป็น float ให้อัตโนมัติ ผลลัพธ์จึงเป็น float อยู่แล้วโดยไม่ต้อง cast เพิ่ม

22.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
compile error "Cannot implicitly convert type 'string' to 'int'" พยายามบวก string เข้ากับ int แล้วเก็บผลลัพธ์เป็น int ตรงๆ — ต้องแปลง string เป็น ตัวเลขก่อนด้วย Parse()/TryParse()/Convert ไม่ใช่พึ่ง implicit conversion
ผลลัพธ์การคำนวณผิดแบบ "24" แทนที่จะเป็น "6" ตัวแปรผลลัพธ์เป็น string โดยไม่ตั้งใจ ทำให้ + กลายเป็น concatenation แทน addition — เช็คชนิดของตัวแปรทุกตัวในนิพจน์คณิตศาสตร์ให้แน่ใจว่าเป็นตัวเลขทั้งหมด
System.FormatException ตอนใช้ Parse() ใช้ Parse() กับ string ที่อาจไม่ใช่ตัวเลขเสมอ (เช่น จาก user input) — เปลี่ยนไปใช้ TryParse() แทนเสมอเมื่อค่าที่รับมาไม่รับประกันความถูกต้อง
ผลลัพธ์ (int)3.99m ได้ 3 ทั้งที่คาดว่าจะได้ 4 ไม่ใช่บั๊ก — cast operator ตัดทศนิยมทิ้งเสมอ (truncate) ไม่ปัดเศษ ถ้าต้องการปัดเศษ ต้องใช้ Convert.ToInt32() แทน
compile error ตอนหาร decimal กับ float ตรงๆ C# ไม่ทำ implicit conversion ระหว่าง decimal กับ float/double ให้ (ต่างจากคู่ int↔decimal หรือ int↔float) ต้อง cast ตัวใดตัวหนึ่งให้เป็นชนิดเดียวกันก่อนเสมอ
ใช้ out parameter ผิดจุด ลืมใส่คีย์เวิร์ด out ตอนเรียก ต้องใส่ out ทั้งตอนประกาศพารามิเตอร์ในนิยามเมธอด และตอนเรียกใช้ เช่น int.TryParse(value, out result) — ขาดคีย์เวิร์ด out ตอนเรียกจะเกิด compile error

ดูเฉลย
Program.cs
string[] values = { "12.3", "45", "ABC", "11", "DEF" };

decimal oddTotal = 0m;

foreach (var value in values)
{
    decimal number;
    if (decimal.TryParse(value, out number))
    {
        int rounded = Convert.ToInt32(number);
        if (rounded % 2 == 0)
        {
            evenTotal += number;
        }
        else
        {
            oddTotal += number;
        }
    }
    else
    {
        message += value;
    }
}

Console.WriteLine($"Message: {message}");
Console.WriteLine($"Even total: {evenTotal}");
Console.WriteLine($"Odd total: {oddTotal}");

ข้อ 6ท้าทาย

อธิบายว่าทำไม decimal result = value2 / (decimal)value3; ในเฉลยท้าทาย 2 (หัวข้อ 22.6) ต้อง cast แค่ value3 (float) เป็น decimal แต่ไม่ต้อง cast value2 (ซึ่งเป็น decimal อยู่แล้ว) — แล้วถ้าเขียน (decimal)value2 / value3 แทน (cast ฝั่งซ้ายแทนฝั่งขวา) จะ compile ผ่านไหม?

ดูเฉลย

value2 เป็น decimal อยู่แล้ว ไม่ต้อง cast ซ้ำ — ปัญหาอยู่ที่ value3 ซึ่งเป็น float C# ไม่มี implicit หรือแม้แต่ built-in explicit conversion ระหว่าง float กับ decimal ที่ทำงานได้ ทั้งสองทิศทางแบบอัตโนมัติในนิพจน์เดียวกัน จึงต้อง cast operand ฝั่งใดฝั่งหนึ่งให้เป็น decimal ก่อนหารเสมอ — ส่วน (decimal)value2 / value3 จะไม่ compile ผ่าน เพราะแม้ฝั่งซ้ายจะเป็น decimal แล้ว แต่ฝั่งขวา (value3) ยังเป็น float อยู่ดี C# ยังหา decimal กับ float หารกันตรงๆ ไม่ได้อยู่ดี ต้อง cast ทั้งสองฝั่ง ให้เป็น decimal เหมือนกัน (หรืออย่างน้อยฝั่งที่ไม่ใช่ decimal ต้องถูก cast เสมอ)

📌 สรุปบทที่ 22

เป้าหมายของคุณคือใช้เทคนิคต่างๆ เปลี่ยน data type ของค่าที่กำหนด คุณใช้ implicit conversion โดยพึ่งพา C# compiler ทำ widening conversion ให้ เมื่อ compiler ทำ implicit conversion ให้ไม่ได้ คุณใช้ explicit conversion แทน คุณใช้เมธอด ToString() แปลง numeric data type เป็น string อย่างชัดเจน

เมื่อต้องทำ narrowing conversion คุณใช้เทคนิคต่างกันหลายแบบ คุณใช้ casting operator () เมื่อการแปลงทำได้อย่างปลอดภัยและยินดียอมรับการตัดทศนิยมทิ้ง และคุณใช้เมธอด Convert() เมื่อต้องการแปลงพร้อมใช้กฎการปัดเศษทั่วไปตอนทำ narrowing conversion

สุดท้าย คุณใช้เมธอด TryParse() เมื่อการแปลงจาก string เป็น numeric data type อาจทำให้เกิด data type conversion exception ได้

ถ้าไม่มีตัวเลือกเหล่านี้มากมาย การเขียนโปรแกรมในภาษาที่มีระบบ type แบบเข้มงวดจะทำได้ยากมาก โชคดีที่ระบบ type, conversion, และ casting ที่ออกแบบมาอย่างดีนี้ ช่วยให้คุณสร้างแอปพลิเคชัน ที่ปราศจากข้อผิดพลาดได้
