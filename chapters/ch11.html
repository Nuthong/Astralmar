11.1 ทำไมต้องเขียนโค้ดให้อ่านง่าย

โค้ดที่คุณเขียนควรสื่อสารเจตนาให้ทั้งคอมไพเลอร์และนักพัฒนาคนอื่นที่อาจต้องอ่านโค้ด ของคุณเข้าใจ และเพราะคุณเองคือคนที่จะอ่านโค้ดตัวเองบ่อยที่สุด — บางทีอีกหลายเดือนถัดจากวัน ที่เขียน — การเขียนโค้ดให้ชัดเจนและเข้าใจง่ายจึงเป็นผลดีกับตัวคุณเองโดยตรง จำไว้ว่า คุณอาจเขียนโค้ดครั้งเดียว แต่ต้องอ่านมันหลายครั้ง

สมมติมีคนขอให้คุณเขียนโค้ดให้ทีมนักพัฒนาอีกกลุ่ม ประชุมคุยสเปกกันจนเข้าใจตรงกัน หลังประชุม พวกเขาบอกว่าคุณจะทำงานคนเดียวระหว่างพัฒนา พอเสร็จแล้วต้องส่งมอบโค้ดให้อีกทีมดูแลต่อ — งานไม่ได้ยากเกินความสามารถ แต่คุณไม่เคยเขียนโค้ดที่คนอื่นต้องมาดูแลต่อมาก่อน ทีมบอกว่าแค่ ทำตามธรรมเนียมมาตรฐานของ C# ก็ไม่มีปัญหา

ในบทนี้ คุณจะเรียนวิธีเลือกชื่อตัวแปรที่สื่อจุดประสงค์และเจตนา เพิ่มคอมเมนต์ที่บันทึกความ ต้องการระดับสูงและแนวทางที่ใช้ในโค้ด รวมถึงสั่งให้คอมไพเลอร์ข้ามบางบรรทัดชั่วคราว และวิธีใช้ whitespace สื่อความสัมพันธ์ระหว่างบรรทัดโค้ดแต่ละบรรทัด

11.2 เลือกชื่อตัวแปรตามกฎและธรรมเนียม

มีนักพัฒนาเคยพูดไว้ว่า "ส่วนที่ยากที่สุดของการพัฒนาซอฟต์แวร์คือการตั้งชื่อสิ่งต่างๆ" ชื่อตัวแปรไม่ใช่แค่ต้องตรงกฎไวยากรณ์ แต่ยังต้องช่วยให้โค้ดอ่านเข้าใจง่ายขึ้นด้วย — เยอะมากสำหรับแค่โค้ดบรรทัดเดียว!

กฎการตั้งชื่อตัวแปร (บังคับโดยคอมไพเลอร์)

  • ใช้ตัวอักษร ตัวเลข และ underscore (_) ได้เท่านั้น ห้ามใช้อักขระพิเศษอย่าง #, -, $
  • ต้องขึ้นต้นด้วยตัวอักษรหรือ _ ห้ามขึ้นต้นด้วยตัวเลข (การขึ้นต้นด้วย underscore มักสงวนไว้สำหรับ private instance field)
  • ห้ามตั้งชื่อซ้ำกับคำสงวนของ C# เช่น float float; หรือ string string;
  • คำนึงตัวพิมพ์เล็ก-ใหญ่ — MyValue กับ myValue คือคนละตัวแปร

ธรรมเนียมการตั้งชื่อตัวแปร (ข้อตกลงของวงการ ไม่บังคับแต่ควรทำ)

ธรรมเนียมตัวอย่างที่ดีตัวอย่างที่ไม่ควรทำ
ใช้ camelCasestring thisIsCamelCase;PascalCase หรือ snake_case
สื่อความหมาย ไม่ใช่ชนิดข้อมูลbool orderComplete;bool isComplete;
ใช้คำเต็ม ไม่ย่อdecimal orderAmount;decimal odrAmt;
ไม่แปะชนิดข้อมูลในชื่อstring myValue;string strMyValue; (ล้าสมัยแล้ว)

ตัวอย่าง string firstName; ทำตามกฎและธรรมเนียมครบทุกข้อ (สมมติจะใช้เก็บชื่อจริง) ตัวอย่างอื่นๆ ที่ถูกต้อง:

ตัวอย่าง
char userOption;

int gameScore;

float particlesPerMillion;

bool processedCustomer;
ℹ️ กฎ/ธรรมเนียมนี้ใช้กับ local variable กฎและธรรมเนียมข้างต้นใช้กับ local variable — ตัวแปรที่อยู่ในขอบเขตของเมธอด หรือใน console app แบบ top-level statement (แบบที่หลักสูตรนี้ใช้มาตลอด) โครงสร้างอื่นๆ เช่นคลาส ก็มีธรรมเนียมของตัวเอง (จะเจอตอนเรียนเรื่อง class) แต่ธรรมเนียมที่เรียนตอนนี้เป็นพื้นฐาน ของกรอบการตั้งชื่อทั้งหมด

Check ★ ข้อใดคือรูปแบบ camelCase ที่ถูกต้อง?

  • AUserOption
  • Buser Option
  • CuserOption
เฉลย: ข้อ C. camelCase ต้องขึ้นต้นด้วยตัวพิมพ์เล็กเสมอ (ข้อ A ขึ้นต้นตัวใหญ่ เป็น PascalCase) และห้ามมีช่องว่างในชื่อตัวแปร (ข้อ B ผิดไวยากรณ์ทันที)

11.3 ลงมือ: เขียน Comment ที่มีประโยชน์

Code Comment คืออะไร

code comment คือคำสั่งบอกคอมไพเลอร์ให้ข้ามทุกอย่างหลังสัญลักษณ์คอมเมนต์ในบรรทัดนั้น:

ตัวอย่าง
// This is a code comment!

ฟังดูอาจไม่มีประโยชน์ในแวบแรก แต่มีประโยชน์ใน 3 สถานการณ์:

  • บันทึกเจตนา — อธิบายจุดประสงค์หรือแนวคิดของโค้ดส่วนที่ซับซ้อน ตัวคุณในอนาคตจะ ขอบคุณตัวเองแน่นอน
  • ปิดโค้ดชั่วคราว — ลบโค้ดออกไปก่อนเพื่อลองวิธีอื่น แต่ยังไม่มั่นใจว่าไอเดียใหม่ จะได้ผล คอมเมนต์โค้ดเก่าไว้ก่อน เขียนโค้ดใหม่ พอมั่นใจแล้วค่อยลบของเก่าทิ้ง
  • เพิ่มข้อความเตือน เช่น TODO ให้กลับมาดูจุดนี้ทีหลัง — ควรใช้อย่าง ระมัดระวัง แต่มีประโยชน์เวลาเจอจุดที่น่ากังวลระหว่างทำงานเรื่องอื่นอยู่
⚠️ คอมเมนต์ควรอธิบายสิ่งที่โค้ดบอกไม่ได้ หลายครั้งนักพัฒนาแก้โค้ดแต่ลืมอัปเดตคอมเมนต์ให้ตรงกัน ควรใช้คอมเมนต์อธิบายแนวคิดระดับสูง ไม่ใช่อธิบายว่าโค้ดแต่ละบรรทัดทำงานยังไง (เพราะโค้ดที่ดีควรอธิบายตัวเองอยู่แล้ว)

ใช้ /* เปิดและ */ ปิด — เร็วและง่ายที่สุดสำหรับปิดโค้ดตั้งแต่ 3 บรรทัดขึ้นไป:

ตัวอย่าง

*/

คอมเมนต์แบบไหนไม่ควรเขียน

ลองพิมพ์โค้ดนี้ (ยังไม่ต้องเข้าใจทุกบรรทัด — จุดสำคัญคือดูว่าคอมเมนต์ช่วยหรือไม่ช่วยยังไง):

Program.cs — คอมเมนต์แบบไม่ดี 
Random random = new Random();
string[] orderIDs = new string[5];
// Loop through each blank orderID
for (int i = 0; i < orderIDs.Length; i++)
{
    // Get a random value that equates to ASCII letters A through E
    int prefixValue = random.Next(65, 70);
    // Convert the random value into a char, then a string
    string prefix = Convert.ToChar(prefixValue).ToString();
    // Create a random number, pad with zeroes
    string suffix = random.Next(1, 1000).ToString("000");
    // Combine the prefix and suffix together, then assign to current OrderID
    orderIDs[i] = prefix + suffix;
}
// Print out each orderID
foreach (var orderID in orderIDs)
{
    Console.WriteLine(orderID);
}
🛑 ปัญหาของคอมเมนต์ชุดนี้ ปัญหาที่ 1: คอมเมนต์อธิบายสิ่งที่เห็นอยู่แล้วจากโค้ดแต่ละบรรทัด (low-quality) ถ้าผู้อ่านไม่คุ้นกับเมธอดพวกนี้ ก็ไปค้น learn.microsoft.com หรือใช้ IntelliSense ได้เอง ปัญหาที่ 2: คอมเมนต์ไม่ได้บอกบริบทว่าโค้ดชุดนี้มีไว้ทำอะไรในระบบใหญ่เลย (ทำไมต้องมี โค้ดชุดนี้อยู่?)

ลบคอมเมนต์รายบรรทัดทิ้ง แล้วเพิ่มคอมเมนต์บล็อกอธิบายภาพรวมแทน:

Program.cs — คอมเมนต์ที่ดีขึ้น 
/*
  The following code creates five random OrderIDs
  to test the fraud detection process.  OrderIDs 
  consist of a letter from A to E, and a three
  digit number. Ex. A123.
*/
Random random = new Random();
string[] orderIDs = new string[5];

for (int i = 0; i < orderIDs.Length; i++)
{
    int prefixValue = random.Next(65, 70);
    string prefix = Convert.ToChar(prefixValue).ToString();
    string suffix = random.Next(1, 1000).ToString("000");

    orderIDs[i] = prefix + suffix;
}

foreach (var orderID in orderIDs)
{
    Console.WriteLine(orderID);
}

คอมเมนต์บล็อกเดียวตรงหัวไฟล์บอกภาพรวมว่าทำไมโค้ดนี้ถึงมีอยู่ — มีประโยชน์กว่าคอมเมนต์ รายบรรทัดที่บอกแค่อย่างไร (ซึ่งอ่านจากโค้ดเองก็รู้อยู่แล้ว) ประโยชน์ของคอมเมนต์เป็นเรื่อง ที่ขึ้นกับดุลยพินิจ — ใช้วิจารณญาณของคุณเองว่าอะไรช่วยให้โค้ดชัดเจนขึ้นจริงๆ

ℹ️ อย่าเชื่อคอมเมนต์เสมอไป คอมเมนต์อาจไม่ตรงกับสถานะปัจจุบันของโค้ดอีกต่อไป หลังผ่านการแก้ไขหลายรอบ — เชื่อโค้ดจริง มากกว่าคอมเมนต์เสมอเวลามีข้อสงสัย

11.4 ลงมือ: ใช้ Whitespace ให้โค้ดอ่านง่าย

นักออกแบบสื่อสิ่งพิมพ์และเว็บรู้ดีว่าการยัดข้อมูลแน่นเกินไปในพื้นที่เล็กๆ ทำให้ผู้ชมสับสน จึงใช้ whitespace (พื้นที่ว่าง) แบ่งข้อมูลอย่างมีกลยุทธ์ นักพัฒนาก็ใช้หลักการเดียวกันได้ กับโค้ด

Whitespace คืออะไร

whitespace หมายถึงช่องว่างจากการกด spacebar, tab จากปุ่ม tab, และการขึ้นบรรทัดใหม่ จากปุ่ม enter — คอมไพเลอร์ C# ไม่สนใจ whitespace เลย

Program.cs 
// Example 1:
Console
.
WriteLine
(
"Hello Example 1!"
)
;

// Example 2:
string firstWord="Hello";string lastWord="Example 2";Console.WriteLine(firstWord+" "+lastWord+"!");
Output
Hello Example 1!
Hello Example 2!

ทั้งสองตัวอย่างนี้ (สุดโต่งไปคนละทาง) พิสูจน์ 2 อย่าง: whitespace ไม่มีผลต่อคอมไพเลอร์เลย — แต่ถ้าใช้อย่างเหมาะสม whitespace ช่วยให้อ่าน/เข้าใจโค้ดง่ายขึ้นมาก คุณอาจเขียนโค้ดครั้งเดียว แต่ต้องอ่านมันหลายครั้ง จึงควรให้ความสำคัญกับความอ่านง่ายของโค้ด

แนวทางเบื้องต้น:

  • แต่ละคำสั่ง (statement) ที่สมบูรณ์ควรอยู่คนละบรรทัด
  • ถ้าบรรทัดเดียวยาวเกินไป แบ่งได้ แต่อย่าแบ่งคำสั่งเดียวออกหลายบรรทัดโดยไม่มีเหตุผลดีพอ
  • เว้นวรรคทั้งซ้ายและขวาของตัวดำเนินการกำหนดค่า =

ปรับ Whitespace แนวตั้ง (บรรทัดว่าง)

ลองพิมพ์โค้ดที่ไม่มี whitespace เลย (โค้ดเกมทอยลูกเต๋าจาก บทที่ 9):

Program.cs — ก่อนปรับ
Random dice = new Random();
int roll1 = dice.Next(1, 7);
int roll2 = dice.Next(1, 7);
int roll3 = dice.Next(1, 7);
int total = roll1 + roll2 + roll3;
Console.WriteLine($"Dice roll: {roll1} + {roll2} + {roll3} = {total}");
if ((roll1 == roll2) || (roll2 == roll3) || (roll1 == roll3)) {
    if ((roll1 == roll2) && (roll2 == roll3)) {
        Console.WriteLine("You rolled triples!  +6 bonus to total!");
        total += 6; 
    } else {
        Console.WriteLine("You rolled doubles!  +2 bonus to total!");
        total += 2;
    }
}

สังเกต 2 อย่าง: ไม่มีบรรทัดว่างคั่นเลย ทุกอย่างอัดแน่นเป็นก้อนเดียว และ code block ที่ล้อม ด้วย { } ก็ชิดกันจนแยกขอบเขตด้วยสายตายาก หลักทั่วไปคือ เพิ่มบรรทัดว่างคั่น ระหว่างกลุ่มโค้ด 2-4 บรรทัดที่ทำงานคล้ายกันหรือเกี่ยวข้องกัน:

Program.cs — เพิ่มบรรทัดว่างคั่น 
Random dice = new Random();

int roll1 = dice.Next(1, 7);
int roll2 = dice.Next(1, 7);
int roll3 = dice.Next(1, 7);

int total = roll1 + roll2 + roll3;
Console.WriteLine($"Dice roll: {roll1} + {roll2} + {roll3} = {total}");

if ((roll1 == roll2) || (roll2 == roll3) || (roll1 == roll3)) {
    if ((roll1 == roll2) && (roll2 == roll3)) {
        Console.WriteLine("You rolled triples!  +6 bonus to total!");
        total += 6; 
    } else {
        Console.WriteLine("You rolled doubles!  +2 bonus to total!");
        total += 2;
    }
}

บรรทัดว่างที่ 1 แยกการประกาศ dice ออกจากการทอยลูกเต๋า — ทำให้เห็นชัดว่า dice ถูกใช้ยังไง บรรทัดว่างที่ 2 แยกกลุ่มตัวแปร roll ออกจากการประกาศ total — ตัวแปรทั้งสามชื่อคล้ายกันและรูปแบบประกาศเหมือนกัน จัดกลุ่มไว้ด้วยกัน ช่วยให้สายตาจับความคล้าย/ต่างได้ง่าย บรรทัดว่างที่ 3 แยกกลุ่มคำสั่งที่เกี่ยวข้องกันด้วย "จุดประสงค์" (ไม่ใช่แค่หน้าตา) ออกจาก if ที่ซ้อนกัน — บางคนอาจแย้งว่าควรมีบรรทัดว่างระหว่าง total กับ Console.WriteLine() ด้วย ก็แล้วแต่ดุลยพินิจของคุณ เลือกสไตล์ที่คุณว่าอ่านง่ายที่สุด แล้วใช้ให้สม่ำเสมอ

จัดวางปีกกาให้อยู่คนละบรรทัด

Random dice = new Random();

int roll1 = dice.Next(1, 7);
int roll2 = dice.Next(1, 7);
int roll3 = dice.Next(1, 7);

int total = roll1 + roll2 + roll3;
Console.WriteLine($"Dice roll: {roll1} + {roll2} + {roll3} = {total}");

if ((roll1 == roll2) || (roll2 == roll3) || (roll1 == roll3)) 
{
    if ((roll1 == roll2) && (roll2 == roll3)) 
    {
        Console.WriteLine("You rolled triples!  +6 bonus to total!");
        total += 6; 
    } 
    else 
    {
        Console.WriteLine("You rolled doubles!  +2 bonus to total!");
        total += 2;
    }
}

ย้ายปีกกาเปิด-ปิดให้อยู่บรรทัดของตัวเอง เพราะสัญลักษณ์ { และ } สร้าง code block — โครงสร้าง C# หลายแบบต้องมี code block ควรวางไว้คนละบรรทัดให้เห็นขอบเขต ชัดเจน ใช้ปุ่ม tab จัดให้ปีกกาอยู่แนวตรงกับคีย์เวิร์ดที่มันเป็นของ เช่น บรรทัด if กับ { ที่อยู่บรรทัดถัดมา ควรอยู่แนวเดียวกัน — การจัดแนวคู่กับการเยื้อง (indent) ทำให้เห็นจุดเริ่ม-จบของ code block ได้ง่าย โค้ดข้างใน code block ควรเยื้องเข้าไปเพื่อบ่งบอกว่า "เป็นของ" block นั้น

💡 นี่เป็นแนวทาง ไม่ใช่กฎตายตัว ไม่ใช่ทุกคนเห็นด้วยกับสไตล์นี้เป๊ะๆ แต่ควรใช้เป็นจุดเริ่มต้น แล้วค่อยๆ ปรับเปลี่ยนอย่างมี เหตุผลตามประสบการณ์ที่มากขึ้น

11.5 ท้าทาย: ปรับปรุงโค้ดให้อ่านง่าย

โจทย์ตามต้นฉบับ MS Learn

โค้ดนี้จัดรูปแบบและคอมเมนต์ไม่ดีเลย จุดประสงค์ระดับสูงคือ "กลับข้อความ แล้วนับว่าตัวอักษร ตัวหนึ่งปรากฏกี่ครั้ง":

Program.cs — บังคับใช้ (ปรับปรุงได้ทุกอย่าง)
string str = "The quick brown fox jumps over the lazy dog.";
// convert the message into a char array
char[] charMessage = str.ToCharArray();
// Reverse the chars
Array.Reverse(charMessage);
int x = 0;
// count the o's
foreach (char i in charMessage) { if (i == 'o') { x++; } }
// convert it back to a string
string new_message = new String(charMessage);
// print it out
Console.WriteLine(new_message);
Console.WriteLine($"'o' appears {x} times.");

ใช้เทคนิคที่เรียนในบทนี้ (ชื่อตัวแปร, คอมเมนต์, whitespace) ปรับปรุงโค้ดชุดนี้ให้อ่านง่ายขึ้น — ไม่จำเป็นต้องเข้าใจ ToCharArray() หรือ Array.Reverse() ทุกรายละเอียดก็ทำโจทย์นี้ได้

💡 ขอคำใบ้

เช็คทีละจุด: ชื่อ str, x, new_message สื่อ ความหมายพอไหม? คอมเมนต์รายบรรทัดพวกนี้อธิบายสิ่งที่เห็นอยู่แล้วหรือเปล่า? บรรทัด foreach ที่ยัดทุกอย่างไว้บรรทัดเดียวอ่านง่ายไหม?

11.6 เฉลยและวิเคราะห์

Program.cs — เฉลยตัวอย่าง 
/*
   This code reverses a message, counts the number of times 
   a particular character appears, then prints the results
   to the console window.
 */

string originalMessage = "The quick brown fox jumps over the lazy dog.";

char[] message = originalMessage.ToCharArray();
Array.Reverse(message);

int letterCount = 0;

foreach (char letter in message)
{
    if (letter == 'o')
    {
        letterCount++;
    }
}

string newMessage = new String(message);

Console.WriteLine(newMessage);
Console.WriteLine($"'o' appears {letterCount} times.");
Output
.god yzal eht revo spmuj xof nworb kciuq ehT
'o' appears 4 times.

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ ชื่อตัวแปรและระยะห่างของคุณอาจต่างไปบ้าง การเปลี่ยนแปลงหลักๆ ในเฉลยนี้คือ:

  • เพิ่มคอมเมนต์บล็อกอธิบายภาพรวมไว้ตอนต้น — ให้บริบทที่คอมเมนต์เดิมไม่มี
  • ลบคอมเมนต์รายบรรทัดทิ้ง เพราะไม่ได้ให้ข้อมูลเชิงลึกอะไรจริงๆ
  • เพิ่มบรรทัดว่างคั่นเพื่อจัดกลุ่มโค้ดที่ทำงานคล้ายกันหรือร่วมมือกันทำงานเล็กๆ ชิ้นหนึ่ง
  • เพิ่มการขึ้นบรรทัดและ tab ให้ foreach กับ if ดูดีขึ้น
  • ใช้ธรรมเนียมตั้งชื่อตัวแปรท้องถิ่น เพื่อสื่อจุดประสงค์ของแต่ละค่าให้ชัดเจนขึ้น (str→originalMessage, x→letterCount, new_message→newMessage)

11.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
ตัวแปรชื่อ x, temp, data ไม่สื่อความหมาย — เปลี่ยนเป็นชื่อที่บอกว่าเก็บอะไรจริงๆ เช่น letterCount
ตัวแปรชื่อ new_message (snake_case) C# นิยมใช้ camelCase สำหรับ local variable ไม่ใช่ snake_case (เป็นธรรมเนียมของภาษาอื่นอย่าง Python)
คอมเมนต์บอกว่า "เพิ่มค่าทีละ 1" เหนือบรรทัด count++; คอมเมนต์แบบนี้ซ้ำซ้อนกับสิ่งที่โค้ดบอกอยู่แล้ว ไม่ใช่คอมเมนต์คุณภาพดี — เก็บไว้ใช้ อธิบาย "ทำไม" แทน "ทำอะไร"
ยัดหลายคำสั่งไว้บรรทัดเดียวเพื่อ "ประหยัดบรรทัด" คอมไพเลอร์ไม่สนใจ แต่คนอ่านงงแน่นอน — แต่ละ statement ควรอยู่คนละบรรทัด
ลืมอัปเดตคอมเมนต์หลังแก้โค้ด คอมเมนต์ที่ไม่ตรงกับโค้ดจริงอันตรายกว่าไม่มีคอมเมนต์เลย — อย่าเชื่อคอมเมนต์มากกว่าโค้ดจริง

1. ข้อใดตรงตามแนวทางการตั้งชื่อตัวแปรที่แนะนำ?

  • Amy-string
  • BinitialMessage$
  • CinitialMessage
เฉลย: ข้อ C. ข้อ A มีเครื่องหมายขีดกลาง (ไม่อนุญาต) ข้อ B มี $ (ไม่อนุญาต) ข้อ C เป็น camelCase ที่ถูกต้องทั้งกฎและธรรมเนียม

2. ข้อใดคือเหตุผลที่ไม่ดีในการใช้คอมเมนต์?

  • Aอธิบายเจตนาระดับสูงของโค้ด
  • Bอธิบายว่าคีย์เวิร์ด C# ตัวใหม่ตัวหนึ่งทำงานยังไง
  • Cปิดโค้ดชั่วคราวระหว่างทดลองแนวทางอื่น
เฉลย: ข้อ B. คอมเมนต์ที่อธิบายกลไกของภาษา/เมธอดที่มีอยู่แล้วเป็น "low-quality comment" — ถ้าผู้อ่านไม่รู้ ควรไปค้น learn.microsoft.com หรือ IntelliSense เอง ไม่ใช่พึ่งคอมเมนต์ในโค้ด ข้อ A และ C เป็นการใช้คอมเมนต์ที่เหมาะสมทั้งคู่

3. ข้อความใดเกี่ยวกับการใช้ whitespace ในโค้ดถูกต้อง?

  • Aลด whitespace ให้น้อยที่สุดจะช่วยให้โปรแกรมรันเร็วขึ้น
  • Bควรเว้นบรรทัดว่างทุกๆ 2-3 บรรทัดเสมอ
  • Cควรใช้ whitespace อย่างมีวิจารณญาณ เพื่อเพิ่มความอ่านง่ายของโค้ด
เฉลย: ข้อ C. คอมไพเลอร์ไม่สนใจ whitespace เลย จึงไม่มีผลต่อความเร็ว การรัน (ข้อ A ผิด) และไม่มีกฎตายตัวว่าต้องเว้นทุกกี่บรรทัด (ข้อ B ผิด) — ขึ้นกับดุลยพินิจ ว่าอะไรช่วยให้อ่านง่ายที่สุด

ข้อ 6ท้าทาย

นำโค้ดตรวจปีอธิกสุรทินจาก บทที่ 9 แบบฝึกหัดข้อ 4 มาปรับปรุงให้ อ่านง่ายที่สุดตามหลักทั้งหมดในบทนี้: ตั้งชื่อตัวแปรสื่อความหมาย เพิ่ม comment อธิบาย กฎปีอธิกสุรทินแบบสั้นๆ ตอนต้น และจัดวาง whitespace/ปีกกาให้ถูกหลัก

ดูเฉลย
Program.cs
/*
  ปีอธิกสุรทิน: หารด้วย 4 ลงตัว และ
  (หารด้วย 100 ไม่ลงตัว หรือ หารด้วย 400 ลงตัว)
*/

int year = 2028;

bool divisibleBy4 = (year % 4 == 0);
bool divisibleBy100 = (year % 100 == 0);
bool divisibleBy400 = (year % 400 == 0);

bool isLeapYear = divisibleBy4 && (!divisibleBy100 || divisibleBy400);

if (isLeapYear)
{
    Console.WriteLine($"{year} เป็นปีอธิกสุรทิน");
}
else
{
    Console.WriteLine($"{year} ไม่ใช่ปีอธิกสุรทิน");
}

หมายเหตุ: ตัวแปร bool ย่อยช่วยให้แต่ละเงื่อนไขมีชื่อสื่อความหมายในตัวเอง อ่านง่ายกว่า expression ยาวๆ ก้อนเดียว (เครื่องหมาย ! คือ "ไม่ใช่" จะได้เรียนละเอียดในโมดูล Boolean expression ของ Part 3)

📌 สรุปบทที่ 11

เป้าหมายของบทนี้คือเขียนโค้ดที่อ่านและเข้าใจง่าย คุณใช้ธรรมเนียมการตั้งชื่อตัวแปรเพื่อเพิ่ม ความอ่านง่ายของโค้ด camelCase ช่วยให้แยก local variable ออกจากตัวระบุอื่นๆ ในโค้ดได้ และให้ วิธีใช้หลายคำอธิบายจุดประสงค์ของตัวแปรแต่ละตัวแก่ผู้อ่าน คุณใช้คอมเมนต์ปิดโค้ดที่ต้องการ เขียนใหม่ไว้ชั่วคราวก่อนลบทิ้ง และใช้คอมเมนต์เพิ่มคำอธิบายจุดประสงค์ระดับสูงของระบบให้ มีความหมายมากขึ้น สุดท้าย คุณเห็นแล้วว่าคอมไพเลอร์ไม่สนใจ whitespace ในโค้ดเลย จึงใช้ whitespace อย่างมีวิจารณญาณเพื่อช่วยเพิ่มความอ่านง่ายของโค้ด

คุณเรียนรู้ว่าคุณเขียนโค้ดครั้งเดียว แต่ต้องอ่านมันหลายครั้ง การปรับปรุงความอ่านง่ายช่วยให้ ทั้งคุณและนักพัฒนาคนอื่นดูแลรักษาโค้ดได้ในระยะยาว
