29.1 ทำไมต้องมี Parameter

method มีความสามารถทำการดำเนินการกับ input ได้ การส่งพารามิเตอร์เข้า method ทำให้คุณทำงาน เดียวกันกับค่า input ที่ต่างกันได้ การใช้พารามิเตอร์ทำให้คุณขยายโค้ดได้ในขณะที่ยังจัดระเบียบ และอ่านง่ายอยู่ ถ้าคิดว่า method เป็นกล่องดำที่รับ input แล้วทำงานอย่างเดียว คุณแบ่งปัญหาใหญ่ เป็นชิ้นเล็กๆ ที่จัดการได้ง่ายขึ้นอย่างรวดเร็ว

สมมติคุณต้องเขียนโค้ดที่ทำการดำเนินการเดียวกันกับชุด input ที่ต่างกัน คุณอาจมี array 3 ชุด และต้องแสดงเนื้อหาของแต่ละชุด คุณสร้าง method DisplayArray ที่รับ array เดียว เป็น input แล้วแสดงเนื้อหาได้ แทนที่จะเขียนโค้ดแสดงแต่ละ array แยกกัน คุณเรียก method เดียวกัน แล้วส่ง array ที่ต่างกันเป็น input ได้เลย

พารามิเตอร์ทำให้ method ของคุณแข็งแกร่งขึ้นในขณะที่ยังทำงานหลักเดิมอยู่ ในบทนี้ คุณจะเรียนรู้ การทำงานกับพารามิเตอร์เชิงลึกขึ้น และทำความเข้าใจ method ให้แน่นยิ่งขึ้น

29.2 ลงมือ: ใช้ Parameter ใน Method

ตอนสร้าง method คุณมักต้องการให้ข้อมูลบางอย่างแก่ method เพื่อใช้งาน ข้อมูลที่ method ใช้ เรียกว่า parameter (พารามิเตอร์) คุณกำหนดพารามิเตอร์ได้เท่าที่จำเป็นต่องาน หรือไม่มี เลยก็ได้

💡 Parameter กับ Argument ต่างกันยังไง คำว่า "parameter" และ "argument" มักถูกใช้แทนกันได้ แต่จริงๆ แล้วมีความหมายต่างกัน: parameter หมายถึงตัวแปรในmethod signature ส่วน argument คือค่าที่ ส่งเข้าไปตอนเรียก method — เช่น ใน void CountTo(int max) — max คือ parameter แต่ตอนเรียก CountTo(5) — 5 คือ argument

เพิ่ม Parameter ให้ Method

พารามิเตอร์ใน method ทำงานคล้ายตัวแปรมาก — parameter นิยามด้วยการระบุ data type ตามด้วยชื่อ ของพารามิเตอร์ parameter ถูกประกาศใน method signature และค่าของพารามิเตอร์ถูกให้โดยผู้เรียก method แทนที่จะ initialize ข้างในตัว method เอง พิจารณาโค้ดนี้:

Program.cs 
CountTo(5);

void CountTo(int max)
{
    for (int i = 0; i < max; i++)
    {
        Console.Write($"{i}, ");
    }
}
Output
0, 1, 2, 3, 4,

ในตัวอย่างนี้ method CountTo รับพารามิเตอร์ชนิด integer ชื่อ max — พารามิเตอร์นี้ถูกอ้างอิงใน for loop ของ method ตอนเรียก CountTo ค่า integer 5 ถูกส่งเป็น argument

ในแบบฝึกหัดนี้ คุณจะสร้าง method ที่ปรับเวลาตารางนัดให้ตรงกับโซนเวลา GMT ที่ต่างกัน method ควรรับรายการเวลา โซนเวลาปัจจุบัน และโซนเวลาใหม่

Program.cs 
int[] schedule = {800, 1200, 1600, 2000};
Program.cs 
void DisplayAdjustedTimes(int[] times, int currentGMT, int newGMT)
{

}

สังเกตว่าพารามิเตอร์ถูกประกาศคล้ายกับตอนคุณประกาศตัวแปร — ใช้ data type ตามด้วยชื่อตัวแปร คุณใช้พารามิเตอร์ data type ไหนก็ได้ เช่น string, bool, int, array และอื่นๆ! พารามิเตอร์หลายตัวใน method ต้องคั่นด้วยจุลภาคเสมอ

Program.cs 
int diff = 0;
if (Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12)
{
    Console.WriteLine("Invalid GMT");
}

สังเกตว่าคุณไม่ต้องประกาศตัวแปร newGMT และ currentGMT เพราะมัน ถูกประกาศไว้แล้วใน method signature คุณยังไม่ต้อง initialize ตัวแปรเหล่านั้นด้วย เพราะ method สมมติว่าผู้เรียกจะส่ง argument ที่มีค่ากำหนดไว้แล้วมาให้เสมอ

ในขั้นตอนนี้ คุณสร้าง int diff เก็บส่วนต่างของเวลา แล้วเช็คว่าค่า GMT ที่ให้มา อยู่ระหว่าง -12 ถึง 12 — ใช้ Math.Abs หาค่าสัมบูรณ์ของตัวเลข ดังนั้นค่า GMT จะ ไม่ถูกต้องถ้ามากกว่า 12

Program.cs 
int diff = 0;
if (Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12)
{
    Console.WriteLine("Invalid GMT");
}
else if (newGMT <= 0 && currentGMT <= 0 || newGMT >= 0 && currentGMT >= 0)
{
    diff = 100 * (Math.Abs(newGMT) - Math.Abs(currentGMT));
}
else
{
    diff = 100 * (Math.Abs(newGMT) + Math.Abs(currentGMT));
}

for (int i = 0; i < times.Length; i++)
{
    int newTime = (times[i] + diff) % 2400;
    Console.WriteLine($"{times[i]} -> {newTime}");
}

เรียก method:

Program.cs 
int[] schedule = {800, 1200, 1600, 2000};
DisplayAdjustedTimes(schedule, 6, -6);

void DisplayAdjustedTimes(int[] times, int currentGMT, int newGMT)
{
    int diff = 0;
    if (Math.Abs(newGMT) > 12 || Math.Abs(currentGMT) > 12)
    {
        Console.WriteLine("Invalid GMT");
    }
    else if (newGMT <= 0 && currentGMT <= 0 || newGMT >= 0 && currentGMT >= 0)
    {
        diff = 100 * (Math.Abs(newGMT) - Math.Abs(currentGMT));
    }
    else
    {
        diff = 100 * (Math.Abs(newGMT) + Math.Abs(currentGMT));
    }

    for (int i = 0; i < times.Length; i++)
    {
        int newTime = (times[i] + diff) % 2400;
        Console.WriteLine($"{times[i]} -> {newTime}");
    }
}
Output
800 -> 2000
1200 -> 0
1600 -> 400
2000 -> 800

สังเกตว่าทั้งตัวแปรและ literal ส่งเป็น argument ให้ method ได้ ด้วยการใช้พารามิเตอร์ method จึงไม่ถูกจำกัดให้ใช้แค่ค่าของตัวแปร global เท่านั้น

29.3 ลงมือ: ทำความเข้าใจ Method Scope

for loop, if-else statement, และ method ล้วนเป็น code block คนละ ชนิดกัน แต่ละ code block มี "scope" ของตัวเอง — "scope" คือขอบเขตของโปรแกรมที่ข้อมูลบางอย่าง เข้าถึงได้ ตัวแปรที่ประกาศข้างใน method หรือ code block ใดๆ เข้าถึงได้แค่ในขอบเขตนั้นเท่านั้น เมื่อโปรแกรมซับซ้อนขึ้น แพทเทิร์นนี้ช่วยให้นักพัฒนาใช้ชื่อตัวแปรที่ชัดเจนสม่ำเสมอ และดูแล รักษาโค้ดให้อ่านง่ายได้

ทดสอบ Scope ของตัวแปร

statement ที่ประกาศนอก code block ใดๆ เรียกว่า top-level statement ตัวแปรที่ประกาศใน top-level statement เรียกว่า "global variable" global variable ไม่ถูกจำกัดด้วย scope ใดๆ ใช้ที่ไหนก็ได้ตลอดทั้งโปรแกรม global variable มีประโยชน์สำหรับ method ต่างๆ ที่ต้องเข้าถึง ข้อมูลเดียวกัน อย่างไรก็ตาม สำคัญมากที่ต้องระวังชื่อตัวแปรใน scope ต่างกัน

Program.cs 
string[] students = {"Jenna", "Ayesha", "Carlos", "Viktor"};

DisplayStudents(students);
DisplayStudents(new string[] {"Robert","Vanya"});

void DisplayStudents(string[] students)
{
    foreach (string student in students)
    {
        Console.Write($"{student}, ");
    }
    Console.WriteLine();
}
Output
Jenna, Ayesha, Carlos, Viktor, 
Robert, Vanya,

ในโค้ดนี้ คุณสร้าง global array students และ method DisplayStudents ที่รับพารามิเตอร์ชื่อเดียวกัน สังเกตว่าพารามิเตอร์ students ของ method มีความ สำคัญเหนือกว่า global array students — สำคัญมากที่ต้องระมัดระวังและตั้งใจว่า method ของคุณจะใช้ global variable ตัวไหนบ้าง

⚠️ ตัวแปรใน method หนึ่งเข้าไม่ถึงจาก method อื่น พิจารณาโค้ดนี้:
Program.cs (ผิด — compile error)
PrintCircleArea(12);
double circumference = 2 * pi * radius;

void PrintCircleArea(int radius)
{
    double pi = 3.14159;
    double area = pi * (radius * radius);
    Console.WriteLine($"Area = {area}");
}
โค้ดนี้จะแสดง error บอกว่าชื่อ pi และ radius ไม่มีอยู่ใน scope ปัจจุบัน เพราะตัวแปรเหล่านั้นมีอยู่แค่ใน scope ของ method PrintCircleArea เท่านั้น

แชร์ตัวแปรระหว่าง Method ด้วย Global Variable

สร้าง method อีกตัวที่คำนวณเส้นรอบวง:

Program.cs 
void PrintCircleCircumference(int radius)
{
    double pi = 3.14159;
    double circumference = 2 * pi * radius;
    Console.WriteLine($"Circumference = {circumference}");
}

เพราะตัวแปร pi ถูกตั้งค่าคงที่เท่ากันเสมอ และใช้ในทั้งสอง method ค่านี้จึงเหมาะ สำหรับเป็น global variable ในตัวอย่างนี้ radius ไม่ใช่ global variable เพื่อให้คุณเรียก method ด้วยค่า radius ต่างกันได้โดยไม่ต้องอัปเดตตัวแปรทุกครั้ง

Program.cs 
double pi = 3.14159;

PrintCircleArea(12);
PrintCircleCircumference(12);

void PrintCircleArea(int radius)
{
    double area = pi * (radius * radius);
    Console.WriteLine($"Area = {area}");
}

void PrintCircleCircumference(int radius)
{
    double circumference = 2 * pi * radius;
    Console.WriteLine($"Circumference = {circumference}");
}
Output
Area = 452.38896
Circumference = 75.39815999999999

ตอนนี้ทั้งสอง method อ้างอิงค่า pi เดียวกันได้ โดยไม่ต้องนิยามซ้ำเลย

Method เรียก Method อื่นได้

คุณอาจเดาได้แล้วว่า method เรียก method อื่นได้ โดยทั่วไป ตราบใดที่ method ถูกนิยามอยู่ใน scope ของโปรแกรมคุณ มันถูกเรียกจากที่ไหนก็ได้

Program.cs 
double pi = 3.14159;
PrintCircleInfo(12);
PrintCircleInfo(24);

void PrintCircleInfo(int radius)
{
    Console.WriteLine($"Circle with radius {radius}");
    PrintCircleArea(radius);
    PrintCircleCircumference(radius);
}

void PrintCircleArea(int radius)
{
    double area = pi * (radius * radius);
    Console.WriteLine($"Area = {area}");
}

void PrintCircleCircumference(int radius)
{
    double circumference = 2 * pi * radius;
    Console.WriteLine($"Circumference = {circumference}");
}
Output
Circle with radius 12
Area = 452.38896
Circumference = 75.39815999999999
Circle with radius 24
Area = 1809.55584
Circumference = 150.79631999999998

ในโค้ดนี้ คุณสร้าง method ใหม่ PrintCircleInfo ที่เรียก method ที่มีอยู่แล้ว ค่า radius ถูกส่งต่อไปยังแต่ละ method ด้วย การสร้าง method ที่แยกเป็นโมดูลแบบนี้ ช่วยให้โค้ดของคุณจัดระเบียบและอ่านง่ายขึ้น

29.4 ลงมือ: Value Type และ Reference Type Parameter

ใน C# ตัวแปรแบ่งเป็น 2 ประเภทหลัก คือ value type และ reference type (ทบทวนจาก บทที่ 21) ประเภทเหล่านี้อธิบายว่าตัวแปรเก็บค่าของมันยังไง

value type อย่าง int, bool, float, double, และ char เก็บค่าโดยตรง reference type อย่าง string, array, และ object (เช่น instance ของ Random) ไม่ได้เก็บค่าของมันโดยตรง แต่เก็บ address ที่ ค่าของมันถูกเก็บอยู่แทน

พารามิเตอร์แบบ Pass-by-value และ Pass-by-reference

ตอนส่ง argument เข้า method ตัวแปรชนิด value จะถูกก็อปปี้ค่าเข้าไปใน method ตัวแปร แต่ละตัวมีสำเนาของค่าเป็นของตัวเอง ดังนั้นตัวแปรต้นฉบับจึงไม่ถูกแก้ไข

สำหรับ reference type, address ของค่านั้นถูกส่งเข้า method ตัวแปรที่ส่งให้ method อ้างอิงไปยัง ค่าที่ address นั้น ดังนั้นการดำเนินการกับตัวแปรนั้นส่งผลต่อค่าที่ถูกอ้างอิงโดยตัวแปรอื่นด้วย

ทดสอบ Pass by Value

Program.cs 
int a = 3;
int b = 4;
int c = 0;

Multiply(a, b, c);
Console.WriteLine($"global statement: {a} x {b} = {c}");

void Multiply(int a, int b, int c)
{
    c = a * b;
    Console.WriteLine($"inside Multiply method: {a} x {b} = {c}");
}
Output
inside Multiply method: 3 x 4 = 12
global statement: 3 x 4 = 0

ตัวแปร a, b, และ c ถูกส่งให้ method Multiply ค่าของตัวแปรถูกพิมพ์ระหว่าง method ทำงาน แล้วพิมพ์อีกครั้งหลัง method ทำงานเสร็จ — integer เป็น value type ซึ่งถูกก็อปปี้ค่าตอนส่งเข้า method สังเกตว่าค่าของ c ถูกแก้ไขแค่ข้างใน method Multiply เท่านั้น นอกเหนือจากนั้น c ยังคงค่าเดิมของมัน

ทดสอบ Pass by Reference

Program.cs 
int[] array = {1, 2, 3, 4, 5};

PrintArray(array);
Clear(array);
PrintArray(array);

void PrintArray(int[] array)
{
    foreach (int a in array)
    {
        Console.Write($"{a} ");
    }
    Console.WriteLine();
}

void Clear(int[] array)
{
    for (int i = 0; i < array.Length; i++)
    {
        array[i] = 0;
    }
}
Output
1 2 3 4 5 
0 0 0 0 0

array เป็น reference type — reference type เก็บ address ของค่าในหน่วยความจำ สังเกตว่า array ยังคงถูกแก้ไขอยู่นอก scope ของ method Clear เพราะ method Clear อัปเดตค่าที่เก็บอยู่ที่แต่ละ address โดยตรง (ทบทวนแนวคิดนี้จาก บทที่ 21 หัวข้อ 21.5c)

ทดสอบกับ String

ก่อนหน้านี้คุณเรียนแล้วว่า string เป็นชนิด immutable (เปลี่ยนแปลงไม่ได้) แม้ string จะเป็น reference type แต่ค่าของมันเปลี่ยนแปลงไม่ได้หลังถูกกำหนดค่า ต่างจาก array — คุณอาจ สังเกตเห็นเรื่องนี้แล้วถ้าเคยใช้เมธอดอย่าง string.Replace หรือ string.ToUpper ในหัวข้อนี้ คุณจะเรียนแก้ไข error ที่พบบ่อยเวลาทำงานกับ string

Program.cs 
string status = "Healthy";

Console.WriteLine($"Start: {status}");
SetHealth(status, false);
Console.WriteLine($"End: {status}");

void SetHealth(string status, bool isHealthy)
{
    status = (isHealthy ? "Healthy" : "Unhealthy");
    Console.WriteLine($"Middle: {status}");
}
Output
Start: Healthy
Middle: Unhealthy
End: Healthy

ถ้า method SetHealth ไม่ได้แสดงค่า status ออกมาด้วย คุณอาจคิดว่า method ทำงาน ผิดพลาด แต่จริงๆ แล้ว string ใหม่ที่มีค่า "Unhealthy" ถูกสร้างขึ้น แล้วก็หายไปใน scope ของ method นั้นเอง

แก้ปัญหานี้ได้ด้วยการเปลี่ยน SetHealth ให้ใช้ตัวแปร status แบบ global แทน:

Program.cs 
string status = "Healthy";

Console.WriteLine($"Start: {status}");
SetHealth(false);
Console.WriteLine($"End: {status}");

void SetHealth(bool isHealthy)
{
    status = (isHealthy ? "Healthy" : "Unhealthy");
    Console.WriteLine($"Middle: {status}");
}
Output
Start: Healthy
Middle: Unhealthy
End: Unhealthy

ในโค้ดนี้ คุณเขียนทับตัวแปร global status ด้วยค่า string ใหม่ ตอนนี้ค่าที่ อัปเดตแล้วถูกเก็บและบันทึกไว้อย่างถูกต้อง

ℹ️ สรุปตาราง value/reference type parameter
Data Typeประเภทmethod แก้ไขค่าต้นฉบับได้ไหม

arrayReference typeได้ — แก้ไขค่าที่ address เดียวกัน

Check ★ กำหนด method signature void SetHealth(string health) — ทำไมการดำเนินการข้างใน method จึงไม่ส่งผลต่อ string health ต้นฉบับ?

  • Aเพราะ string data type เป็น pass by value
  • Bเพราะโค้ดใน method ต้องผิดพลาดแน่นอน
  • Cstring เปลี่ยนแปลงค่าไม่ได้หลังถูกกำหนดค่า มันแค่ถูกเขียนทับด้วยค่าใหม่เท่านั้น
เฉลย: ข้อ C. string เป็น reference type (ไม่ใช่ pass by value ตามข้อ A ที่ผิด) แต่เป็น immutable — การ "แก้ไข" string จริงๆ แล้วคือการสร้าง string ใหม่ ทั้งก้อนเสมอ ไม่ใช่แก้ไขของเดิม string ใหม่นั้นจึงหายไปเมื่อ method จบทำงาน ไม่ใช่ code ผิด แต่อย่างใด

29.5 ลงมือ: Named และ Optional Parameter

ภาษา C# รองรับ named parameter และ optional parameter — parameter ชนิดนี้ให้คุณเลือกได้ว่า จะส่ง argument ตัวไหนให้ method บ้าง คุณจึงไม่ถูกจำกัดด้วยโครงสร้างที่กำหนดไว้ใน method signature เท่านั้น

named argument ให้คุณระบุค่าของพารามิเตอร์ด้วยชื่อของมัน แทนที่จะใช้ตำแหน่ง optional parameter ให้คุณละเว้น argument นั้นตอนเรียก method ได้

สร้างแอปตอบรับคำเชิญงานอีเวนต์ (RSVP)

Program.cs 
string[] guestList = {"Rebecca", "Nadia", "Noor", "Jonte"};
string[] rsvps = new string[10];
int count = 0;

void RSVP(string name, int partySize, string allergies, bool inviteOnly)
{
    if (inviteOnly)
    {
        // search guestList before adding rsvp
    }

    rsvps[count] = $"Name: {name}, \tParty Size: {partySize}, \tAllergies: {allergies}";
    count++;
}

void ShowRSVPs()
{
    Console.WriteLine("\nTotal RSVPs:");
    for (int i = 0; i < count; i++)
    {
        Console.WriteLine(rsvps[i]);
    }
}

เพิ่มโค้ดค้นหา guest list ใน method RSVP:

Program.cs 
if (inviteOnly)
{
    bool found = false;
    foreach (string guest in guestList)
    {
        if (guest.Equals(name)) {
            found = true;
            break;
        }
    }
    if (!found)
    {
        Console.WriteLine($"Sorry, {name} is not on the guest list");
        return;
    }
}

โค้ดนี้เช็คว่าชื่อที่ให้มาตรงกับชื่อในรายชื่อแขกไหม ถ้าเจอ ตั้ง found เป็น true แล้ว break ออกจาก foreach loop ถ้า found เป็น false แสดงข้อความ แล้วใช้คีย์เวิร์ด return จบการทำงานของ method

เรียก method:

RSVP("Linh", 2, "none", false);
RSVP("Tony", 1, "Jackfruit", true);
RSVP("Noor", 4, "none", false);
RSVP("Jonte", 2, "Stone fruit", false);
ShowRSVPs();

ใช้ Named Argument

ตอนเรียก method ที่รับพารามิเตอร์หลายตัว การเข้าใจว่า argument แต่ละตัวแทนอะไรอาจทำได้ยาก การใช้ named argument ช่วยเพิ่มความอ่านง่ายของโค้ด ใช้ named argument ด้วยการระบุชื่อ พารามิเตอร์ตามด้วยค่า argument

Program.cs 
RSVP(name: "Linh", partySize: 2, allergies: "none", inviteOnly: false);

สังเกตว่าคุณระบุชื่อพารามิเตอร์ตามด้วยเครื่องหมายทวิภาคและค่า — syntax นี้เรียกว่า named argument ไม่จำเป็นต้องตั้งชื่อ argument ทุกตัว เช่น syntax ต่อไปนี้ก็ถูกต้องเหมือนกัน:

Program.cs
RSVP("Linh", 2, allergies: "none", inviteOnly: false);
RSVP("Linh", partySize: 2, "none", false);

named argument ที่ใช้ร่วมกับ positional argument ใช้ได้ถ้าอยู่ในตำแหน่งที่ถูกต้อง named argument ยังใช้ได้ตราบใดที่ไม่ตามด้วย positional argument ตัวอย่างเช่น การใส่ "Linh" และ 2 ไว้ท้ายสุดจะผิด:

Program.cs (ผิด — compile error)
RSVP(allergies: "none", inviteOnly: false, "Linh", 2);
error CS1738: Named argument 'allergies' is used out-of-position but is followed by an unnamed argument

named argument ไม่จำเป็นต้องเรียงตามลำดับเดิมด้วย:

Program.cs 
RSVP("Tony", inviteOnly: true, allergies: "Jackfruit", partySize: 1);

สังเกตว่า argument ที่ตั้งชื่อไม่จำเป็นต้องเรียงตามลำดับต้นฉบับ แต่ argument ที่ไม่ตั้งชื่อ อย่าง "Tony" เป็น positional argument จึงต้องอยู่ในตำแหน่งที่ตรงกันเสมอ

ประกาศ Optional Parameter

พารามิเตอร์กลายเป็น optional เมื่อมันถูกกำหนดค่า default ไว้ ถ้า optional parameter ถูกละไว้ จาก argument ค่า default จะถูกใช้ตอน method ทำงาน ในขั้นตอนนี้ คุณจะทำให้พารามิเตอร์ partySize, allergies, และ inviteOnly เป็น optional

Program.cs 
void RSVP(string name, int partySize = 1, string allergies = "none", bool inviteOnly = true)

สังเกต syntax นี้ — พารามิเตอร์ยังคั่นด้วยจุลภาคเหมือนเดิม แต่พารามิเตอร์ partySize, allergies, และ inviteOnly ถูกกำหนดค่าแต่ละ ตัวไว้

Program.cs 
RSVP("Rebecca");
RSVP("Nadia", 2, "Nuts");
RSVP(name: "Linh", partySize: 2, inviteOnly: false);
RSVP("Tony", allergies: "Jackfruit", inviteOnly: true);
RSVP("Noor", 4, inviteOnly: false);
RSVP("Jonte", 2, "Stone fruit", false);
Output
Sorry, Tony is not on the guest list

Total RSVPs:
Name: Rebecca,  Party Size: 1,  Allergies: none
Name: Nadia,    Party Size: 2,  Allergies: Nuts
Name: Linh,     Party Size: 2,  Allergies: none
Name: Noor,     Party Size: 4,  Allergies: none
Name: Jonte,    Party Size: 2,  Allergies: Stone fruit

ในแต่ละการเรียก method สังเกตว่า name ไม่เคยถูกละเว้นเลย เวลาเรียก method argument ที่จำเป็น (required) ต้องมีเสมอ แต่ argument ที่เป็น optional ละเว้นได้

💡 ข้อจำกัด: required parameter ต้องมาก่อน optional เสมอ ใน method signature พารามิเตอร์ที่ไม่มีค่า default (required) ต้องอยู่ก่อนพารามิเตอร์ ที่มีค่า default (optional) เสมอ — เช่น void RSVP(string name, int partySize = 1, ...) ถูกต้อง แต่ void RSVP(int partySize = 1, string name, ...) จะ compile ไม่ผ่าน

29.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
แก้ไข string ข้างใน method แล้วค่าข้างนอกไม่เปลี่ยนตามที่คาดหวัง ไม่ใช่บั๊ก — string เป็น immutable เสมอ การ "แก้ไข" คือสร้าง string ใหม่ทั้งก้อน ถ้า ต้องการให้ค่าข้างนอกเปลี่ยน ต้องเขียนทับตัวแปร global โดยตรง (ทบทวนหัวข้อ 29.4d) ไม่ใช่ พึ่ง parameter
แก้ไข array ข้างใน method แล้วค่าข้างนอกเปลี่ยนตามโดยไม่ตั้งใจ ไม่ใช่บั๊ก — array เป็น reference type การแก้ไข element ข้างใน method จะกระทบ array ต้นฉบับเสมอ ถ้าไม่ต้องการพฤติกรรมนี้ ต้องก็อปปี้ array แยกก่อนส่งเข้า method (ทบทวน เทคนิคจาก บทที่ 21 แบบฝึกหัดข้อ 3)
compile error "Named argument ... is used out-of-position" ใส่ named argument ไว้ก่อน positional argument — named argument ต้องไม่ตามด้วย positional argument เสมอ (ทบทวนหัวข้อ 29.5b)
compile error ตอนประกาศ optional parameter ก่อน required parameter required parameter (ไม่มีค่า default) ต้องอยู่ก่อน optional parameter (มีค่า default) ใน method signature เสมอ
ตัวแปรใน method ทับชื่อ global variable แล้วงงว่าทำไมค่าไม่ตรงที่คิด ไม่ใช่บั๊ก — พารามิเตอร์ที่ชื่อซ้ำกับ global variable จะมีความสำคัญเหนือกว่าเสมอ ข้างในตัว method นั้น (ทบทวนหัวข้อ 29.3a) ถ้าต้องการหลีกเลี่ยงความสับสน ควรตั้งชื่อ พารามิเตอร์ให้ต่างจาก global variable

2. กำหนด method signature void Print(string name, string number = "", bool member = false) ข้อใดใช้ named และ optional argument ได้ถูกต้อง?

  • BPrint(number: "555", member: false)
  • CPrint("Tony", false)
เฉลย: ข้อ A. "Tony" เป็น positional argument ให้ name (required parameter — ต้องมีเสมอ) แล้วข้าม number (optional) ไปตั้งค่า member ด้วย named argument — ถูกต้องตามกฎทั้งหมด ข้อ B ผิดเพราะไม่ได้ส่งค่า name เลย (เป็น required parameter ละเว้นไม่ได้) ข้อ C ผิดเพราะ false ในตำแหน่งที่สองจะถูกตีความเป็นค่าของ number ซึ่งเป็น string ไม่ใช่ bool — ชนิดข้อมูลไม่ตรงกัน

3. กำหนด method signature void SetHealth(string health) ทำไมการดำเนินการข้างใน method จึงไม่ส่งผลต่อ string health ต้นฉบับ?

  • Astring data type เป็น pass by value
  • Bโค้ดใน method ต้องผิดพลาดแน่นอน
  • Cstring เปลี่ยนแปลงค่าไม่ได้หลังถูกกำหนดค่า มันถูกเขียนทับด้วยค่าใหม่ได้เท่านั้น
เฉลย: ข้อ C. ตรงกับคำถาม Check ★ ข้อ 29-2 ทุกประการ — string เป็น reference type ที่ immutable ไม่ใช่ pass by value

ข้อ 5ยาก

ดัดแปลงแอป RSVP จากหัวข้อ 29.5 ให้เพิ่ม optional parameter ใหม่ชื่อ vip (ค่า default false) — ถ้า vip เป็น true ให้ข้ามการตรวจสอบ guestList ไปเลย (VIP เข้าได้เสมอไม่ว่า จะอยู่ในรายชื่อหรือไม่) ทดสอบเรียก RSVP("Tony", vip: true)

ดูเฉลย
Program.cs (ส่วนที่แก้)
void RSVP(string name, int partySize = 1, string allergies = "none", bool inviteOnly = true, bool vip = false)
{
    if (inviteOnly && !vip)
    {
        bool found = false;
        foreach (string guest in guestList)
        {
            if (guest.Equals(name))
            {
                found = true;
                break;
            }
        }
        if (!found)
        {
            Console.WriteLine($"Sorry, {name} is not on the guest list");
            return;
        }
    }

    rsvps[count] = $"Name: {name}, \tParty Size: {partySize}, \tAllergies: {allergies}";
    count++;
}

เปลี่ยนเงื่อนไขจาก if (inviteOnly) เป็น if (inviteOnly && !vip) — ถ้า vip เป็น true เงื่อนไขทั้งก้อนเป็น false ทันที ข้ามการตรวจสอบ guest list ไปเลย ไม่ว่า inviteOnly จะเป็นอะไร

ข้อ 6ท้าทาย

ดัดแปลงเฉลยท้าทาย (หัวข้อ 29.6) ให้ตรวจสอบว่า username ที่ได้ (2 ตัวอักษรแรก + นามสกุล) ซ้ำกับพนักงานคนอื่นในรายชื่อเดียวกันหรือไม่ ถ้าซ้ำ ให้เติมตัวเลขต่อท้าย (เช่น "sibright2") — ทดสอบด้วยการเพิ่ม "Simone Bright" เข้าไปใน corporate (จะได้ username "sibright" ซ้ำกับ "Simon Bright" พอดี)

💡 คำใบ้

ต้องเก็บ username ที่สร้างไปแล้วไว้ใน array หรือ list แยกต่างหาก แล้วเช็คก่อนแสดงผลทุกครั้งว่าเคยมี username นี้แล้วหรือยัง — ทบทวนแพทเทิร์น "นับก่อน สร้างทีหลัง" จาก บทที่ 23

ดูเฉลย
Program.cs
string[,] corporate =
{
    {"Robert", "Bavin"}, {"Simon", "Bright"},
    {"Simone", "Bright"},
    {"Kim", "Sinclair"}, {"Aashrita", "Kamath"},
    {"Sarah", "Delucchi"}, {"Sinan", "Ali"}
};

string[] usedNames = new string[20];
int usedCount = 0;

for (int i = 0; i < corporate.GetLength(0); i++)
{
    DisplayEmail(first: corporate[i,0], last: corporate[i,1]);
}

void DisplayEmail(string first, string last, string domain = "contoso.com")
{
    string baseName = (first.Substring(0, 2) + last).ToLower();
    string email = baseName;

    int suffix = 2;
    bool isDuplicate = true;
    while (isDuplicate)
    {
        isDuplicate = false;
        for (int i = 0; i < usedCount; i++)
        {
            if (usedNames[i] == email)
            {
                isDuplicate = true;
                email = baseName + suffix;
                suffix++;
                break;
            }
        }
    }

    usedNames[usedCount] = email;
    usedCount++;

    Console.WriteLine($"{email}@{domain}");
}

"Simon Bright" ได้ username "sibright" ก่อน พอถึง "Simone Bright" ระบบเจอว่า "sibright" ถูกใช้แล้ว จึงเติม suffix เป็น "sibright2" — ใช้ while loop วนเช็คซ้ำเรื่อยๆ เผื่อกรณีชนกันหลายรอบ (เช่น "sibright2" ก็ถูกใช้แล้วด้วย จะขยับเป็น "sibright3" ต่อ)

📌 สรุปบทที่ 29

เป้าหมายของคุณคือเรียนรู้การใช้พารามิเตอร์ใน method เชิงลึกขึ้น และทำความเข้าใจ method scope คุณเรียนเรื่อง value type กับ reference type และข้อมูลถูกกระทบยังไงข้างใน method คุณยังเรียน ใช้ named argument และ optional argument เพื่อขยายความสามารถของ method

Cheat Sheet — บทที่ 29

Syntaxความหมาย
void M(int max) { }พารามิเตอร์ = ตัวแปรใน signature
M(5);argument = ค่าที่ส่งตอนเรียก
ตัวแปรนอกทุก methodglobal variable — เข้าถึงได้ทุกที่
ตัวแปรใน methodlocal — scope แค่ใน method นั้น
int/bool/double/char เป็น parameterpass by value — ก็อปปี้ค่า ไม่กระทบต้นฉบับ
array เป็น parameterpass by reference — แก้ไขกระทบต้นฉบับ
string เป็น parameterreference แต่ immutable — พฤติกรรมเหมือน pass by value
M(name: value)named argument
void M(string a, int b = 1)optional parameter (ต้องมาหลัง required เสมอ)
