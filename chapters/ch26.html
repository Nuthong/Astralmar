26.1 สถานการณ์และสเปก

สมมติคุณเป็นนักพัฒนาที่ชอบช่วยเหลือชุมชนท้องถิ่น คุณกับเพื่อนเริ่มธุรกิจที่ช่วยหาบ้านใหม่ให้ แมวและสุนัขจรจัดหรือถูกทอดทิ้ง ธุรกิจของคุณเริ่มต้นเล็กๆ มีสัตว์แค่ไม่กี่ตัว แต่ตอนนี้กำลัง เติบโตขึ้น เพื่อนของคุณพัฒนาแอปเริ่มต้นที่รองรับการกรอกและแสดงข้อมูลสัตว์ที่พร้อมให้อุปการะแล้ว พวกเขาขอให้คุณช่วยตรวจสอบการเพิ่มฟีเจอร์ที่ช่วยจับคู่สัตว์ในความดูแลกับคนที่กำลังมองหาสัตว์ เลี้ยงตัวใหม่

ทีมของคุณพบว่าการค้นหาข้อมูลสัตว์เพื่อระบุตัวที่อาจจับคู่ได้ตามลักษณะที่เจ้าของในอนาคตต้องการ เป็นเรื่องสำคัญ นอกจากนี้ ทีมยังต้องการเพิ่มฟีเจอร์ระดมทุน รวมข้อมูลเงินบริจาคที่แนะนำ และ แสดงข้อมูลสัตว์ด้วยจำนวนบรรทัด output ที่น้อยลง

สเปกของฟีเจอร์ใหม่

ค้นหาลักษณะสุนัข:

  • รวบรวม input คำค้นหาลักษณะของสัตว์เลี้ยง
  • วนผ่าน array ของสัตว์ ระบุตัวที่เป็น "สุนัข"
  • สำหรับสุนัขแต่ละตัว รวมคำอธิบายทางกายภาพและนิสัยเข้าด้วยกันเพื่อใช้ค้นหา
  • ค้นหาคำที่ตรงกันในคำอธิบายที่รวมแล้ว
  • แสดงสุนัขที่มีคำตรงกัน

ข้อมูลเงินบริจาคแนะนำ:

  • กำหนดตัวแปร string suggestedDonation
  • ขยาย array ourAnimals ให้เก็บ suggestedDonation ได้ พร้อมสร้าง ข้อมูลตัวอย่างสำหรับมัน
  • ทำให้ทุกจุดที่ใช้ array ourAnimals รองรับข้อมูล suggestedDonation ที่เพิ่มเข้ามา
  • แสดง suggestedDonation พร้อมสัญลักษณ์สกุลเงินตามภูมิภาค ($, €, ¥, ...)
💡 นี่คือ MVP (Minimum Viable Product) ฟีเจอร์ค้นหาในบทนี้เป็น "MVP" — ต้นแบบพื้นฐานที่ทำงานได้จริง เน้นส่งมอบเร็วและง่าย ไม่ใช่ ผลิตภัณฑ์ขั้นสุดท้าย จุดประสงค์คือช่วยทดสอบไอเดียและรวบรวมความต้องการเพิ่มเติมต่อไป — สังเกต ว่าฟีเจอร์ค้นหารับแค่ "คำเดียว" เท่านั้น ยังไม่รองรับหลายคำ (จะไปทำในบทที่ 27 Challenge Project)

26.2 ทบทวน Starter Code

starter code รอบนี้คล้ายกับ Contoso Pets จากบทที่ 19 มาก แต่มีจุดต่าง: ข้อมูลตัวอย่างเปลี่ยน ไปเล็กน้อย (น้ำหนัก d1 เป็น 45 ปอนด์ ไม่ใช่ 65, ชื่อเล่นเปลี่ยนเป็น gus/snow/lion) และเมนูมี แค่ 2 ตัวเลือก:

Welcome to the Contoso PetFriends app. Your main menu options are:
 1. List all of our current pet information
 2. Display all dogs with a specified characteristic

Enter your selection number (or type Exit to exit the program)

เมนู 1 ทำงานได้แล้วในโค้ดตั้งต้น เมนู 2 เป็นแค่ placeholder ข้อความ "UNDER CONSTRUCTION" — เป้าหมายของคุณคือ implement เมนู 2 ให้สมบูรณ์ พร้อมเพิ่มข้อมูลเงินบริจาคเข้าไปในเมนู 1 ด้วย

ℹ️ nullable type ทบทวนอีกครั้ง โค้ดตั้งต้นมีบรรทัด string? readResult; — เครื่องหมาย ? เปลี่ยน variable type ที่ปกติไม่รับค่า null (int, string, bool, ...) ให้รองรับ nullable type ได้ แนวทางปฏิบัติที่ดีเสมอเวลาอ่านค่าด้วย Console.ReadLine() คือใช้ nullable string type แบบนี้ เพื่อไม่ให้ compiler แสดง warning ตอน build (ทบทวนจาก บทที่ 18)

ทดสอบรัน starter code: เลือกเมนู 1 → เห็นข้อมูลสัตว์ตัวอย่าง 4 ตัวแสดงครบ เลือกเมนู 2 → เห็น ข้อความ "UNDER CONSTRUCTION" พิมพ์ "exit" → โปรแกรมจบการทำงาน

26.3 เพิ่มข้อมูลเงินบริจาคแนะนำ

เพิ่มตัวแปรและขยาย Array

เพิ่มตัวแปร suggestedDonation ต่อจาก animalNickname:

Program.cs 
// #1 the ourAnimals array will store the following:
string animalSpecies = "";
string animalID = "";
string animalAge = "";
string animalPhysicalDescription = "";
string animalPersonalityDescription = "";
string animalNickname = "";
string suggestedDonation = "";

ขยาย array ourAnimals จากเดิม 6 "คอลัมน์" เป็น 7 คอลัมน์ เพื่อรองรับข้อมูล เงินบริจาค:

Program.cs 
// #3 array used to store runtime data, there is no persisted data
string[,] ourAnimals = new string[maxPets, 7];

เพิ่มค่าเงินบริจาคในข้อมูลตัวอย่าง

ตรวจสอบข้อมูลด้วย TryParse()

ตัวแปร suggestedDonation ตั้งใจให้เป็นค่าตัวเลข แต่ถูกเก็บเป็น string ลองพิจารณากรณีในอนาคตที่ต้องตรวจสอบว่า suggestedDonation แทนค่า decimal ได้จริง และแปลงเป็น decimal ได้ เพื่อใช้คำนวณด้านบัญชีต่อไป เพื่อป้องกัน error เวลาผู้ใช้กรอกตัวเลข เป็นตัวอักษร เช่น twenty ต้องใช้ TryParse ตรวจสอบ (ทบทวนจาก บทที่ 22)

ประกาศตัวแปร decimalDonation ในกลุ่มตัวแปรสนับสนุนการกรอกข้อมูล:

Program.cs 
// #2 variables that support data entry
int maxPets = 8;
string? readResult;
string menuSelection = "";
decimal decimalDonation = 0.00m;

ท้าย for loop ที่สร้างข้อมูลตัวอย่าง (หลังกำหนดค่า ourAnimals[i, 5] แล้ว) เพิ่มการตรวจสอบและกำหนดค่า default:

Program.cs 
if (!decimal.TryParse(suggestedDonation, out decimalDonation)){
    decimalDonation = 45.00m; // if suggestedDonation NOT a number, default to 45.00
}
ourAnimals[i, 6] = $"Suggested Donation: {decimalDonation:C2}";

ถ้าตัวแปร suggestedDonation แปลงเป็น decimal ไม่ได้ (เช่น เป็น empty string) โค้ดกำหนดค่า default decimalDonation = 45.00m; ถ้าแปลงสำเร็จ TryParse กำหนดค่าให้ decimalDonation เอง ไม่ว่าทางไหน decimalDonation ก็เป็นค่า decimal ที่ถูกต้องเสมอ — สังเกตว่าใช้ string interpolation ผสม currency format specifier :C2 (ทบทวนจาก บทที่ 24) จัดรูปแบบผลลัพธ์ให้มีสัญลักษณ์สกุลเงินและทศนิยม 2 ตำแหน่ง เสมอ

⚠️ ตำแหน่งของโค้ดสำคัญมาก โค้ดตรวจสอบ TryParse ต้องอยู่ข้างใน for loop ของการสร้างข้อมูลตัวอย่าง (หลัง switch statement จบ แต่ก่อนปีกกาปิดของ for) ไม่ใช่ข้างนอก loop — เพราะต้องคำนวณ decimalDonation ใหม่ทุกครั้งที่วนไปสัตว์ตัวถัดไป ถ้าวางผิด ตำแหน่ง ค่าจะไม่อัปเดตตามสัตว์แต่ละตัว

อัปเดตเมนู 1 ให้แสดงคอลัมน์ที่ 7

เมนู 1 ยังวน inner loop แค่ 6 คอลัมน์เดิม (j < 6) ต้องเพิ่มเป็น 7 เพื่อให้ แสดง Suggested Donation ด้วย:

Program.cs 
case "1":
    // list all pet info
    for (int i = 0; i < maxPets; i++)
    {
        if (ourAnimals[i, 0] != "ID #: ")
        {
            Console.WriteLine();
            for (int j = 0; j < 7; j++) // เพิ่มจาก 6 เป็น 7
            {
                Console.WriteLine(ourAnimals[i, j]);
            }
        }
    }
    Console.WriteLine("\n\rPress the Enter key to continue");
    readResult = Console.ReadLine();
    break;

สังเกตสัตว์ตัวสุดท้าย (c4) — suggestedDonation เป็น empty string เพราะไม่ได้ ตั้งค่าไว้ในข้อมูลตัวอย่าง TryParse() จึงคืน false และค่า default $45.00 ถูกใช้แทน ตรงตามที่ออกแบบไว้

Check ★ ข้อใดอธิบายจุดประสงค์ของ TryParse() ได้ดีที่สุด?

  • Aแยกประโยคออกเป็นคำเก็บใน array
  • Bทดสอบการแคสต์ค่าอย่างปลอดภัย
  • Cหา substring ภายใน string ที่ใหญ่กว่า
เฉลย: ข้อ B. TryParse() พยายามแปลง (cast) ค่าอย่างปลอดภัย โดยไม่ throw exception ถ้าแปลงไม่สำเร็จ — ไม่เกี่ยวกับการแยกคำ (นั่นคือ Split()) หรือการค้นหา substring (นั่นคือ IndexOf()/Contains())

26.4 เพิ่มฟีเจอร์ค้นหาสุนัข

รับ Input คำค้นหาจากผู้ใช้

ลบข้อความ "UNDER CONSTRUCTION" ออกจาก case "2": แล้วเพิ่มโค้ดรับ input:

Program.cs 
case "2":
    // Display all dogs with a specified characteristic
    string dogCharacteristic = "";

    while (dogCharacteristic == "")
    {
        Console.WriteLine($"\nEnter one desired dog characteristics to search for");
        readResult = Console.ReadLine();
        if (readResult != null)
        {
            dogCharacteristic = readResult.ToLower().Trim();
        }
    }
    Console.WriteLine("Press the Enter key to continue.");
    readResult = Console.ReadLine();
    break;

จุดสำคัญของโค้ดนี้:

  • ตัวแปร string dogCharacteristic = ""; ถูก scope ไว้แค่ใน case "2": เท่านั้น — เข้าถึงจากนอก case นี้ไม่ได้ (ทบทวน scope จาก บทที่ 15)
  • หลัง Console.ReadLine() รับ input มาเป็น dogCharacteristic โค้ดตรวจว่าไม่ใช่ null แล้วแปลงเป็นตัวพิมพ์เล็กและตัดช่องว่างรอบข้างด้วย .ToLower().Trim() (ทบทวน Trim จาก บทที่ 18)
  • ถ้าผู้ใช้กด Enter เฉยๆ (ค่าว่าง) loop จะวนถามซ้ำจนกว่าจะได้ค่าจริง

ระบุว่าสัตว์ตัวไหนเป็นสุนัข

เพิ่มโค้ดวนหาสุนัขไว้ท้าย case "2": ก่อนบรรทัด "Press the Enter key" (ก่อน break;):

Program.cs 
// #6 loop through the ourAnimals array to search for matching animals
for (int i = 0; i < maxPets; i++)
{
    if (ourAnimals[i, 1].Contains("dog"))
    {
        // #7 Search combined descriptions and report results
    }
}

โค้ดกรองหา "สุนัข" ด้วย ourAnimals[i, 1] ซึ่งเป็นตำแหน่งที่เก็บข้อมูล animalSpecies ถ้า animalSpecies เก็บค่า "dog" ไว้ โค้ดจะเข้าไปทำงาน ข้างในปีกกาของ if ที่จะค้นหาคำอธิบายที่รวมกันแล้วต่อไป

รวมคำอธิบายทางกายภาพและนิสัยเข้าด้วยกัน

ทีมพิจารณาแล้วว่ามีคำอธิบาย 2 อย่าง คือ animalPhysicalDescription และ animalPersonalityDescription — ทีมตัดสินใจว่าการรวมคำอธิบายทั้งสองเข้าด้วยกัน เหมาะสมกว่าสำหรับการค้นหา

⚠️ Scope Creep นักพัฒนาบางคนเรียกการเพิ่มข้อกำหนดระหว่างพัฒนาแบบนี้ว่า "scope creep" แม้การรวมคำอธิบายจะไม่ใช่ งานหนักมาก แต่ก็ยังเพิ่มเวลาและความซับซ้อนอยู่ดี ด้วยเหตุนี้ คุณควรแจ้งทีมว่าข้อกำหนดที่เพิ่มขึ้น มักทำให้โปรเจกต์เสร็จช้าลง

ประกาศตัวแปร dogDescription ก่อนโค้ดข้อ #6:

Program.cs 
string dogDescription = "";

เติมค่าให้ dogDescription หลัง comment #7:

Program.cs 
dogDescription = ourAnimals[i, 4] + "\n" + ourAnimals[i, 5];

ค้นหาและแสดงผลลัพธ์

เพิ่ม if statement ตรวจว่าเจอคำที่ค้นหาในคำอธิบายที่รวมแล้วหรือไม่:

Program.cs 
if (dogDescription.Contains(dogCharacteristic))
{
    Console.WriteLine($"\nOur dog {ourAnimals[i, 3]} is a match!");
    Console.WriteLine(dogDescription);
}

ยังต้องจัดการข้อความ "ไม่พบที่ตรงกัน" ด้วย — เพิ่มตัวแปรติดตามสถานะก่อน comment #6:

Program.cs 
bool noMatchesDog = true;

ตอนนี้คุณติดตามได้ว่ายังไม่เจอที่ตรงกันเลยด้วยตัวแปรนี้ — ค่า default เป็น true หมายถึง "จริงที่ว่าไม่มีสุนัขตรงกับคำค้นหาเลย" พอเจอสุนัขที่ตรงกัน ก็ "พลิก" noMatchesDog จาก true เป็น false

Program.cs 
if (dogDescription.Contains(dogCharacteristic))
{
    Console.WriteLine($"\nOur dog {ourAnimals[i, 3]} is a match!");
    Console.WriteLine(dogDescription);

    noMatchesDog = false;
}

สุดท้าย เพิ่มโค้ดตัดสินว่าควรพิมพ์ข้อความ "ไม่พบที่ตรงกัน" หรือไม่ — วางไว้ท้าย case "2": ก่อนบรรทัด "Press the Enter key" (ก่อน break;):

Program.cs 
if (noMatchesDog)
{
    Console.WriteLine("None of our dogs are a match found for: " + dogCharacteristic);
}

26.6 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
IndexOutOfRangeException ตอนแสดงเมนู 1 ลืมขยาย inner loop จาก j < 6 เป็น j < 7 ทั้งที่ขยาย array เป็น 7 คอลัมน์ไปแล้ว หรือในทางกลับกัน — ต้องปรับทั้งสองจุดให้ตรงกันเสมอ
ค้นหาสุนัขแล้วไม่เจอผลลัพธ์ที่ควรจะเจอ ลืม .ToLower() ที่ฝั่งใดฝั่งหนึ่ง (input ผู้ใช้ หรือคำอธิบายในข้อมูล) — Contains() เป็น case-sensitive ต้องแปลงทั้งสองฝั่งให้ตัวพิมพ์เดียวกันก่อนเทียบเสมอ
ค้นหาแมวไม่ได้ ทั้งที่ตั้งใจให้ค้นหาได้ทุกสัตว์ ไม่ใช่บั๊ก — สเปกกำหนดให้ค้นหาเฉพาะสุนัขเท่านั้น (เช็ค ourAnimals[i, 1].Contains("dog")) เป็นไปตามที่ทีมออกแบบไว้
เงินบริจาคของสัตว์ทุกตัวแสดง $45.00 เหมือนกันหมด โค้ด TryParse + ค่า default วางอยู่นอก for loop สร้างข้อมูลตัวอย่าง จึงคำนวณ แค่ครั้งเดียวแล้วใช้ค่าเดิมซ้ำ ต้องย้ายเข้าไปในลำดับที่ถูกต้องข้างในลูป (ทบทวนหัวข้อ 26.3c)
noMatchesDog เป็น false ตลอด ทั้งที่ค้นหาไม่เจอจริง ลืมประกาศ bool noMatchesDog = true; ใหม่ทุกครั้งที่เข้า case "2": (ถ้า scope ผิดจุดอาจค้างค่าจากรอบก่อน) — ตรวจว่าประกาศอยู่ ข้างในเมนู 2 ทุกครั้งที่ทำงาน ไม่ใช่ตัวแปรระดับแอปที่ตั้งค่าแค่ครั้งเดียว

26.7 ❓ Knowledge Check

  • Astring ที่แทนตัวเลข
  • Bค่า Boolean
  • Cdecimal
เฉลย: ข้อ C. myConvert คือ out parameter ที่ชนิดตรงกับ เมธอดที่เรียก — เพราะเรียก decimal.TryParse() ค่าที่ได้จึงเป็น decimal เสมอ ส่วนค่า Boolean คือค่าที่เมธอด return กลับมา (ไม่ใช่ค่าใน out parameter) ทบทวนความแตกต่างนี้จาก บทที่ 22

ข้อ 2ง่าย

ข้อ 4กลาง

เพิ่มโค้ดคำนวณผลรวมของเงินบริจาคที่แนะนำทั้งหมด (เฉพาะสัตว์ที่มีข้อมูลแล้ว) แล้วแสดงผล เป็นสกุลเงิน — ใช้ในเมนู 1 หลังแสดงข้อมูลสัตว์ทั้งหมด

ดูเฉลย
Program.cs (เพิ่มท้าย case "1":)
decimal totalDonations = 0m;
for (int i = 0; i < maxPets; i++)
{
    if (ourAnimals[i, 0] != "ID #: ")
    {
        string donationText = ourAnimals[i, 6].Replace("Suggested Donation: ", "");
        decimal.TryParse(donationText, System.Globalization.NumberStyles.Currency, null, out decimal amount);
        totalDonations += amount;
    }
}
Console.WriteLine($"\nTotal suggested donations: {totalDonations:C2}");

ใช้ Replace() (ทบทวนจาก บทที่ 25) ตัด prefix "Suggested Donation: " ออกก่อน แล้วใช้ TryParse() overload ที่รองรับ การ parse string ที่มีสัญลักษณ์สกุลเงินติดมาด้วย (NumberStyles.Currency)

ข้อ 5ยาก

ปัจจุบันถ้าผู้ใช้ค้นหาคำว่า "medium sized" (มีช่องว่าง) จะยังทำงานถูกต้องไหม? วิเคราะห์ โดยไม่ต้องรันจริง แล้วอธิบายเหตุผล จากนั้นทดสอบจริงเพื่อยืนยัน

ดูเฉลย

ทำงานถูกต้อง — เพราะ Contains() ค้นหา substring ได้ ไม่ว่าจะมีช่องว่าง อยู่ในคำค้นหาหรือไม่ก็ตาม ตราบใดที่ลำดับตัวอักษรตรงกันทุกตัวรวมช่องว่างด้วย คำอธิบายของ lola มีข้อความ "medium sized cream colored..." ซึ่งมี "medium sized" อยู่ต่อเนื่องกัน พอดี จึงยังคงเจอผลลัพธ์เหมือนเดิม — นี่เป็นข้อดีของการค้นหาแบบ substring match ที่ไม่ ต้องแยกคำก่อนค้นหาแต่อย่างใด

ข้อ 6ท้าทาย

สเปกบอกว่าต้องแสดงเงินบริจาคด้วย "สัญลักษณ์สกุลเงินตามภูมิภาค" — อธิบายว่าโค้ดในบทนี้ทำ ตามข้อกำหนดนี้ได้ยังไงโดยไม่ต้องเขียนโค้ดตรวจสอบภูมิภาคเองเลยแม้แต่บรรทัดเดียว

ดูเฉลย

เพราะใช้ format specifier :C2 (ทบทวนจาก บทที่ 24 หัวข้อ 24.3a) ซึ่งดึงสัญลักษณ์สกุลเงินจาก culture setting ของเครื่องที่รัน โปรแกรมโดยอัตโนมัติ — ถ้าเครื่องตั้งเป็น en-US จะได้ $ ถ้าตั้งเป็น fr-FR จะได้ € โดย อัตโนมัติ ไม่ต้องเขียน if-else ตรวจสอบภูมิภาคเองเลย นี่คือพลังของการใช้ built-in format specifier แทนการต่อ string เอง

คุณอัปเดตแอปจับคู่สัตว์เลี้ยงในบทนี้ ให้รองรับฟีเจอร์ค้นหาด้วยคำเดียว ปรับปรุงความอ่านง่ายของ output และเพิ่มเงินบริจาคแนะนำเข้าไปในคำอธิบาย

ในโมดูลนี้ คุณฝึกความสามารถในการ: ใช้ iteration statement รวบรวม input ข้อมูล, ประมวลผลข้อมูล, จัดรูปแบบ output ของข้อมูล, เลือก data type ที่ถูกต้องและแปลง data type อย่างปลอดภัย, สร้าง array สองมิติของตัวเลขและ string, ค้นหาข้อมูลใน array เพื่อแสดงหรืออัปเดตข้อมูล, และแก้ไข/ ประกอบ string ที่ซับซ้อนจากหลายแหล่งข้อมูล พร้อมจัดรูปแบบสำหรับแสดงผลข้ามภูมิภาค

คุณส่งมอบฟีเจอร์ให้ทีม Contoso Pets ได้แก่: รวบรวม input คำค้นหาลักษณะสัตว์, วนผ่าน array ของสัตว์และระบุ "สุนัข", ค้นหาคำอธิบายของสุนัขแต่ละตัวหาคำที่ตรงกัน, แสดงสุนัขที่มีคำตรงกัน, และแสดงข้อมูลเงินบริจาคแนะนำที่จัดรูปแบบด้วยสกุลเงินท้องถิ่น
