ประเมิน Boolean Expression เพื่อตัดสินใจ

Evaluate Boolean Expressions to Make Decisions

  • ใช้เมธอดสำเร็จรูปของคลาส string ประเมินสตริงได้แม่นยำขึ้น

14.1 ทำไมต้องรู้จัก Boolean Expression ให้ลึกซึ้ง

ตรรกะการตัดสินใจตั้งอยู่บน expression ที่เรียกว่า Boolean expression ซึ่งประเมินได้เป็น "true" หรือ "false" นักพัฒนาใช้ตัวดำเนินการหลากหลายชนิดสร้าง Boolean expression ให้ตรงกับ ความต้องการ พอ expression ถูกประเมินแล้ว การทำงานของโค้ดจะแตกสาขาตามผลลัพธ์ C# รองรับ ตัวดำเนินการหลากหลาย (เช่น equality, comparison, Boolean operator) แต่ละแบบมีจุดประสงค์ เฉพาะตัวตอนสร้างตรรกะการตัดสินใจ

สมมติคุณถูกเลือกให้ทำงานกับชุดแอป C# หลายตัวที่ใช้ประมวลผลข้อมูลลูกค้าและอินพุตจากผู้ใช้ แต่ละแอปต้องมีตรรกะการตัดสินใจที่ตอบโจทย์ข้อกำหนดและกฎธุรกิจที่ต่างกันไป เช่น แอปประมวลผล คำสั่งซื้ออาจต้องเช็คสถานะลูกค้าก่อนดำเนินการ เพื่อเตรียมตัวสำหรับงานนี้ คุณจะฝึกฝนด้วย กิจกรรมที่ใช้ Boolean expression และตัวดำเนินการของ C#

ในบทนี้ คุณจะเรียนเรื่อง Boolean expression และใช้ตัวดำเนินการหลายแบบประเมิน expression เพื่อทดสอบความเท่ากัน ความไม่เท่ากัน และการเปรียบเทียบ คุณจะได้เรียนใช้ตัวดำเนินการเงื่อนไข (conditional operator) ซึ่งเป็นเวอร์ชัน inline พิเศษของ if ที่ให้ผลแบบ "อย่างใดอย่างหนึ่ง"

14.2 ลงมือ: ความเท่ากัน ไม่เท่ากัน และการเปรียบเทียบ

Expression คืออะไร

expression คือการรวมกันของค่า (literal หรือตัวแปร) ตัวดำเนินการ และเมธอด ที่คืนค่า เดียวออกมา ส่วน statement คือคำสั่งสมบูรณ์หนึ่งชุดใน C# ซึ่งประกอบด้วย expression ตั้งแต่หนึ่งตัวขึ้นไป เช่น if statement นี้มี expression เดียวที่คืนค่าเดียว:

ตัวอย่าง
if (myName == "Luiz")

expression บางตัวคืนตัวเลขหรือ string แต่เวลาใช้ในเงื่อนไข if จะเป็น expression ที่คืนค่า true หรือ false เท่านั้น — เรียกว่า Boolean expression Boolean expression สำคัญมาก เพราะโค้ดใช้มันตัดสินว่าจะรัน code block ไหน

เตรียมโปรเจกต์

Terminal 
dotnet new console -o ch14-boolean

ตัวดำเนินการความเท่ากัน (==) และไม่เท่ากัน (!=)

ตัวดำเนินการความเท่ากัน == คืนค่า true ถ้าค่าทั้งสองข้างเท่ากัน ตัวดำเนินการความไม่เท่ากัน != คืนค่า true ถ้าค่าทั้งสองข้าง ไม่เท่ากัน:

Program.cs 
Console.WriteLine("a" == "a");
Console.WriteLine("a" == "A");
Console.WriteLine(1 == 2);

string myValue = "a";
Console.WriteLine(myValue == "a");
Output
True
False
False
True

ปรับปรุงการเทียบ String ให้แม่นยำขึ้น

คุณอาจแปลกใจว่า "a" == "A" ได้ false — เพราะเทียบ string คำนึงตัวพิมพ์เล็ก-ใหญ่ด้วย และถ้ามีช่องว่างเกินมา เช่น "a" == "a " ก็จะได้ false เช่นกัน

บางกรณีช่องว่างหน้า-หลังหรือตัวพิมพ์ต่างกันอาจยอมรับได้ ถ้าต้องการให้จับคู่แบบไม่เป๊ะ เกินไป ต้อง "massage" ข้อมูลก่อน (ทำความสะอาดก่อนเทียบ) ตัวอย่างเช่น ถามผู้ใช้ว่า "ต้องการทำต่อไหม (Y/N)?" ผู้ใช้อาจพิมพ์ y หรือ Y ก็ได้ คุณอยากให้โค้ดตีความทั้งสองแบบเหมือนกัน แม้ y จะไม่เท่ากับ Y ตรงๆ ก็ตาม

ก่อนเทียบ string สองค่า โดยเฉพาะถ้ามาจากผู้ใช้ ควร:

  • ทำให้ทั้งสองค่าเป็นตัวพิมพ์ใหญ่หรือเล็กทั้งหมด ด้วย ToUpper() หรือ ToLower()
  • ตัดช่องว่างหน้า-หลังทิ้ง ด้วย Trim()

ปรับปรุงการเทียบ string ได้โดย chain สองเมธอดนี้เข้าด้วยกันทั้งสองฝั่ง:

Program.cs 
string value1 = " a";
string value2 = "A ";
Console.WriteLine(value1.Trim().ToLower() == value2.Trim().ToLower());
Output
True

ตัวดำเนินการความไม่เท่ากัน (!=)

Program.cs 
Console.WriteLine("a" != "a");
Console.WriteLine("a" != "A");
Console.WriteLine(1 != 2);

string myValue = "a";
Console.WriteLine(myValue != "a");
Output
False
True
True
False

ตามคาด ผลลัพธ์เมื่อใช้ตัวดำเนินการความไม่เท่ากัน จะตรงข้ามกับตอนใช้ความเท่ากัน — โค้ดของคุณ ก็จะแตกสาขาไปในทางตรงข้ามเช่นกัน ซึ่งบางครั้งก็เป็นสิ่งที่คุณต้องการพอดี

ตัวดำเนินการเปรียบเทียบ

เวลาทำงานกับข้อมูลตัวเลข อาจอยากรู้ว่าค่าหนึ่งมากกว่าหรือน้อยกว่าอีกค่าหนึ่ง ใช้ตัวดำเนินการ เหล่านี้:

ตัวดำเนินการความหมาย
>มากกว่า
<น้อยกว่า
>=มากกว่าหรือเท่ากับ
<=น้อยกว่าหรือเท่ากับ
Program.cs 
Console.WriteLine(1 > 2);
Console.WriteLine(1 < 2);
Console.WriteLine(1 >= 1);
Console.WriteLine(1 <= 1);
Output
False
True
True
True

เมธอดที่คืนค่า Boolean

บางเมธอดคืนค่า bool (true/false) เมธอดของคลาส string หลายตัวคืน bool รวมถึง Contains(), StartsWith(), และ EndsWith() (ทบทวน StartsWith ได้ที่ บทที่ 10):

Program.cs 
string pangram = "The quick brown fox jumps over the lazy dog.";
Console.WriteLine(pangram.Contains("fox"));
Console.WriteLine(pangram.Contains("cow"));
Output
True
False

การนิเสธเชิงตรรกะ (Logical Negation)

logical negation คือตัวดำเนินการนิเสธ (unary) ! บางคนเรียกว่า "not operator" เวลาวาง ! ไว้หน้า conditional expression มันบังคับให้โค้ดกลับ ผลการประเมิน — ถ้า operand เป็น false จะได้ true ถ้า operand เป็น true จะได้ false

สองบรรทัดนี้ให้ผลลัพธ์เหมือนกัน บรรทัดที่สองกระชับกว่า:

ตัวอย่าง 
// สองบรรทัดนี้ให้ผลลัพธ์เดียวกัน
Console.WriteLine(pangram.Contains("fox") == false);
Console.WriteLine(!pangram.Contains("fox"));
Program.cs 
string pangram = "The quick brown fox jumps over the lazy dog.";
Console.WriteLine(!pangram.Contains("fox"));
Console.WriteLine(!pangram.Contains("cow"));
Output
False
True
⚠️ อย่าสับสน != กับ ! ตัวดำเนินการความไม่เท่ากัน != มีเครื่องหมาย ! อยู่ แต่ไม่ใช่ logical negation — != คืน true ถ้า operandสองตัวไม่เท่ากัน ส่วน ! กลับผลของ expressionตัวเดียว สำหรับ built-in type แล้ว x != y ให้ผลเหมือนกับ !(x == y) ทุกประการ (เป็นตัวอย่างการใช้ logical negation) แต่ทั้งสองไม่ใช่ตัวดำเนินการตัวเดียวกัน
ตัวอย่าง
int a = 7;
int b = 6;
Console.WriteLine(a != b); // output: True
string s1 = "Hello";
string s2 = "Hello";
Console.WriteLine(s1 != s2); // output: False

Check ★ ข้อใดคือรายการตัวดำเนินการเปรียบเทียบที่ถูกต้องครบถ้วน?

  • A==, ~=, >, <, >=, <=
  • B==, <>, >, <, >=, <=
  • C==, !=, >, <, >=, <=
เฉลย: ข้อ C. ~= และ <> ไม่ใช่ตัวดำเนินการ ของ C# (บางภาษาอย่าง SQL/VB ใช้ <> แทนความไม่เท่ากัน แต่ C# ใช้ != เท่านั้น)

Check ★ โค้ดข้อใดใช้ logical negation?

  • AConsole.WriteLine(myValue != true);
  • BConsole.WriteLine(!myValue);
  • CConsole.WriteLine(myValue == false);
เฉลย: ข้อ B. มีแค่ ! วางหน้า operand เท่านั้นที่เป็น logical negation operator จริงๆ ข้อ A ใช้ inequality operator ข้อ C ใช้ equality operator เทียบกับ false — ทั้งสองให้ผลคล้ายกันในทางปฏิบัติ แต่ไม่ใช่ "ตัวดำเนินการนิเสธ" ตามนิยาม

Check ★ แอปมีตัวแปร string ชื่อ myValue1 กับ myValue2 ผู้ใช้กรอกค่า "Y " และ " y" ตามลำดับ ข้อใดคืน false?

  • A(myValue1 != myValue2)
  • B(myValue1.Trim().ToLower() != myValue2.Trim().ToLower())
  • C(myValue1.Trim().ToLower() == myValue2.Trim().ToLower())
เฉลย: ข้อ B. "Y " กับ " y" ต่างกันทั้งตัวพิมพ์และตำแหน่งช่องว่าง ข้อ A เทียบดิบๆ จึงได้ true (ไม่เท่ากันจริง) ข้อ C หลัง massage แล้วทั้งคู่เป็น "y" เหมือนกัน เทียบด้วย == จึงได้ true ส่วนข้อ B หลัง massage แล้วเท่ากัน เทียบด้วย != (ไม่เท่ากัน) จึงได้ false — นี่คือคำตอบที่โจทย์ถาม

14.3 ลงมือ: ตัวดำเนินการเงื่อนไข (?:)

สมมติต้องเช็คเร็วๆ ว่าคำสั่งซื้อของลูกค้าเข้าเงื่อนไขรับส่วนลดโปรโมชันไหม รายละเอียดคือ ถ้ายอดซื้อมากกว่า 1000 ยูโร ได้ส่วนลด 100 ยูโร ถ้ายอดซื้อ 1000 ยูโรหรือน้อยกว่า ได้ส่วนลด 50 ยูโร

จะใช้ if...elseif...else ก็ได้ แต่ใช้ conditional operator อาจเป็น ทางเลือกที่ดีกว่า เพราะรูปแบบกระชับกว่า ประหยัดบรรทัด และอาจสื่อเจตนาชัดเจนกว่าด้วย

Conditional Operator คืออะไร

conditional operator ?: ประเมิน Boolean expression แล้วคืนผลลัพธ์ หนึ่งในสองแบบ ตามว่า expression เป็น true หรือ false — มักถูกเรียกว่า ternary conditional operator รูปแบบพื้นฐาน:

รูปแบบ
<ประเมินเงื่อนไขนี้> ? <ถ้าจริง คืนค่านี้> : <ถ้าเท็จ คืนค่านี้>
Program.cs 
int saleAmount = 1001;
int discount = saleAmount > 1000 ? 100 : 50;
Console.WriteLine($"Discount: {discount}");
Output
Discount: 100

ใช้ Conditional Operator แบบ Inline

ตัดตัวแปรกลาง discount ทิ้งได้เลย ย่อโค้ดให้กระชับขึ้นอีก:

Program.cs 
int saleAmount = 1001;
Console.WriteLine($"Discount: {(saleAmount > 1000 ? 100 : 50)}");
Output
Discount: 100

สังเกตว่าต้องล้อม conditional operator ทั้งชุดด้วยวงเล็บ () เพื่อให้ runtime เข้าใจเจตนาว่าต้องการแสดงผลลัพธ์ของเงื่อนไข ไม่ใช่แค่ผลของ saleAmount > 1000 เฉยๆ

⚠️ กระชับไม่ได้แปลว่าอ่านง่ายเสมอไป ตัวอย่างข้างบนแม้จะกระชับและแสดงว่าทำอะไรได้บ้าง แต่ก็อ่านยากขึ้นเล็กน้อย การรวมบรรทัดโค้ด เข้าด้วยกันไม่ใช่ความคิดที่ดีเสมอไป โดยเฉพาะถ้ากระทบความอ่านง่ายของโค้ด (ทบทวนหลักการนี้ได้ ที่ บทที่ 11) — นี่เป็นการตัดสินใจที่ค่อนข้างเป็นดุลยพินิจส่วนตัว

Check ★ โค้ดข้อใดใช้ conditional operator ได้ถูกต้อง?

  • Aint bonus = amount >= 100 ? 10 : 5;
  • Bint bonus = amount >= 100 : 10 ? 5;
  • Cint bonus = amount >= 100 ? 10, 5;
เฉลย: ข้อ A. ต้องเป็นรูปแบบ เงื่อนไข ? ค่าจริง : ค่าเท็จ ข้อ B สลับตำแหน่ง ? กับ : ผิด ข้อ C ใช้จุลภาคแทนโคลอนผิดไวยากรณ์

14.4 ท้าทายที่ 1: จำลองเหรียญหัว-ก้อย

โจทย์ตามต้นฉบับ MS Learn

สร้างโค้ดจำลองการ "โยนเหรียญ" แสดงผลเป็น heads หรือ tails ข้อกำหนด:

  1. ใช้คลาส Random สุ่มค่าออกมา (พิจารณาช่วงตัวเลขที่ต้องการให้ดี)
  2. ใช้ conditional operator ตัดสินว่าจะแสดง heads หรือ tails จากค่าที่สุ่มได้ — ต้องมีโอกาสออก heads/tails เท่ากันที่ 50%
  3. โค้ดควรอ่านง่าย แต่ใช้บรรทัดให้น้อยที่สุด — ทำให้จบได้ใน3 บรรทัด
💡 ขอคำใบ้

ทบทวน overload ของ Random.Next() จาก บทที่ 8 — overload ที่รับพารามิเตอร์เดียวคืนค่าตั้งแต่ 0 ถึงต่ำกว่าค่านั้น (exclusive) ต้องการค่าแค่ 2 แบบ (0 กับ 1) ควรส่งอะไรเป็นพารามิเตอร์?

🔓 ดูเฉลย
Program.cs 
Random coin = new Random();
int flip = coin.Next(0, 2);
Console.WriteLine((flip == 0) ? "heads" : "tails");
Output (สุ่มทุกครั้ง)
heads

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ — ตัดตัวแปรกลาง flip ทิ้งได้เหมือนกัน ด้วยการเรียก Next() ไว้ข้างในตัว Boolean expression เลย:

Program.cs — เวอร์ชันย่อกว่า 
Random coin = new Random();
Console.WriteLine((coin.Next(0, 2) == 0) ? "heads" : "tails");

แต่โค้ดแบบนี้แน่นเกินไปหน่อย อาจทำให้เข้าใจยากขึ้นว่ากำลังทำอะไรอยู่

14.5 ท้าทายที่ 2: ตรรกะสิทธิ์การเข้าถึง

โจทย์ตามต้นฉบับ MS Learn

เริ่มจากโค้ดนี้ (ต้องใช้ตัวแปรทั้งสองในคำตอบ):

Program.cs — บังคับใช้
string permission = "Admin|Manager";
int level = 55;

ใช้เมธอด Contains() เช็คว่า permission มีคำว่า "Admin" หรือ "Manager" อยู่หรือไม่ (เช่น permission.Contains("Admin") จะได้ true) กฎธุรกิจ:

  • เป็น Admin และ level มากกว่า 55 → Welcome, Super Admin user.
  • เป็น Admin และ level น้อยกว่าหรือเท่ากับ 55 → Welcome, Admin user.
  • เป็น Manager และ level มากกว่าหรือเท่ากับ 20 → Contact an Admin for access.
  • เป็น Manager และ level น้อยกว่า 20 → You do not have sufficient privileges.
  • ไม่ใช่ทั้ง Admin และ Manager → You do not have sufficient privileges.

ทดสอบด้วยค่าตั้งต้น (permission="Admin|Manager", level=55) ควรได้:

ผลลัพธ์ที่ต้องได้จากค่าตั้งต้น
Welcome, Admin user.

จากนั้นลองเปลี่ยนค่า permission/level แล้วรันซ้ำ เพื่อ ทดสอบให้ครบทุกกฎ

💡 ขอคำใบ้

โครงสร้างนี้เหมาะกับ if ซ้อน if (nested) แบบเดียวกับที่ เรียนใน บทที่ 9 — เช็คบทบาท (Admin/Manager) ที่ชั้นนอกก่อน แล้วเช็ค level ที่ชั้นในของแต่ละบทบาท

🔓 ดูเฉลย
Program.cs 
string permission = "Admin|Manager";
int level = 53;

if (permission.Contains("Admin"))
{
    if (level > 55)
    {
        Console.WriteLine("Welcome, Super Admin user.");
    }
    else
    {
        Console.WriteLine("Welcome, Admin user.");
    }
}
else if (permission.Contains("Manager"))
{
    if (level >= 20)
    {
        Console.WriteLine("Contact an Admin for access.");
    }
    else
    {
        Console.WriteLine("You do not have sufficient privileges.");
    }
}
else
{
    Console.WriteLine("You do not have sufficient privileges.");
}
Output (level=53)
Welcome, Admin user.

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ บางกรณีใช้ Boolean expression ต่างออกไปก็ได้ผลลัพธ์เดียวกัน สังเกตว่าเช็คบทบาท "Admin" ก่อน "Manager" เสมอ — เพราะ permission ในตัวอย่างมีทั้งสองคำปนกัน ("Admin|Manager") ลำดับการเช็คจึงมีผลว่ากฎไหนจะถูกใช้ก่อน (เหมือนหลักการเรียง if-elseif จากบทที่ 9)

14.6 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
เทียบ string จากผู้ใช้แล้วไม่ตรงทั้งที่ "ดูเหมือน" จะตรง มีช่องว่างหรือตัวพิมพ์เล็ก-ใหญ่ต่างกันแอบแฝงอยู่ — ใช้ .Trim().ToLower() ทั้งสองฝั่งก่อนเทียบเสมอเมื่อรับข้อมูลจากผู้ใช้
สับสน != กับ ! != เทียบสองค่า · ! กลับผลของ expression เดียว — คนละหน้าที่กัน
ใช้ conditional operator แบบ inline ใน string interpolation แล้ว error ลืมล้อมด้วยวงเล็บ () — ต้องเขียน {(เงื่อนไข ? a : b)} เสมอ ไม่ใช่ {เงื่อนไข ? a : b}
conditional operator ซ้อนกันหลายชั้นจนอ่านไม่ออก แม้จะทำได้ (เช่น a ? b : c ? d : e) แต่ผิดหลักความอ่านง่ายจากบทที่ 11 — ถ้าเงื่อนไขซับซ้อนเกิน 1 ชั้น ควรกลับไปใช้ if-elseif-else แทน

14.7 ❓ Knowledge Check

คำถามชุดนี้แปลจาก Microsoft Learn (4 ข้อฝังในเนื้อหา + 2 ข้อ Module Assessment)

1. โค้ดบรรทัดใดใช้ logical negation?

  • AConsole.WriteLine(!value);
  • BConsole.WriteLine(value != false);
  • CConsole.WriteLine(a != b);
เฉลย: ข้อ A. มีแค่ ! วางหน้าตัวแปรเท่านั้นที่เป็น logical negation operator โดยตรง ข้อ B และ C ใช้ตัวดำเนินการความไม่เท่ากัน (!=) ซึ่งเป็นคนละตัวดำเนินการกัน

2. โค้ดบรรทัดใดใช้ conditional operator ได้ถูกต้อง?

  • Aint value = amount >= 10 ? 10 : 20;
  • Bint value = amount >= 10 : 10 ? 20;
  • Cint value = amount >= 10 ? 10| 20;
เฉลย: ข้อ A. ต้องเรียง เงื่อนไข ? true-value : false-value เท่านั้น ข้อ B สลับตำแหน่งสัญลักษณ์ผิด ข้อ C ใช้ | แทน : ผิดไวยากรณ์

14.8 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

เขียนโค้ดเทียบตัวเลขสองตัว int a = 15, b = 20; พิมพ์ผลของ ==, !=, >, < ทั้ง 4 แบบ

ดูเฉลย
Program.cs
int a = 15, b = 20;
Console.WriteLine(a == b);
Console.WriteLine(a != b);
Console.WriteLine(a > b);
Console.WriteLine(a < b);
ข้อ 2ง่าย

ใช้ conditional operator เขียนโค้ดตรวจว่าตัวเลข int n = 17; เป็นเลขคู่หรือ เลขคี่ พิมพ์ผลลัพธ์เป็น "คู่" หรือ "คี่"

💡 คำใบ้

ใช้ % เช็คหารด้วย 2 เหลือเศษ (ทบทวนที่ บทที่ 4)

ดูเฉลย
Program.cs
int n = 17;
Console.WriteLine(n % 2 == 0 ? "คู่" : "คี่");
ข้อ 3ง่าย

ผู้ใช้กรอกคำตอบ string answer = " YES "; เขียนโค้ดเช็คว่าตรงกับ "yes" หรือไม่ (ไม่สนตัวพิมพ์เล็ก-ใหญ่ ไม่สนช่องว่างหน้า-หลัง) พิมพ์ผล true/false

ดูเฉลย
Program.cs
string answer = " YES ";
Console.WriteLine(answer.Trim().ToLower() == "yes");
ข้อ 4กลาง

เขียนโค้ดใช้ ! (logical negation) ตรวจว่าอีเมล string email = "somchai@example.com"; ไม่มีเครื่องหมาย @ อยู่หรือไม่ (ควรได้ false เพราะอีเมลนี้มี @ อยู่จริง)

ดูเฉลย
Program.cs
string email = "somchai@example.com";
Console.WriteLine(!email.Contains("@"));
ข้อ 5กลาง

ดัดแปลงโจทย์ 14.5 (ตรรกะสิทธิ์) ให้เพิ่มบทบาทใหม่ "Guest" — ถ้า permission มีคำว่า "Guest" ให้แสดง "Read-only access." เสมอ ไม่ต้องเช็ค level เลย (ทดสอบด้วย permission = "Guest";)

💡 คำใบ้

เพิ่ม else if (permission.Contains("Guest")) ก่อนบรรทัด else สุดท้ายของเฉลยเดิม

ดูเฉลย
Program.cs (ส่วนที่เพิ่ม)
else if (permission.Contains("Guest"))
{
    Console.WriteLine("Read-only access.");
}
else
{
    Console.WriteLine("You do not have sufficient privileges.");
}
ข้อ 6ท้าทาย

เขียนโปรแกรมจำลอง "ทอยลูกเต๋า 3 ครั้ง" (1-6 แต่ละครั้ง) แล้วใช้ conditional operator อย่างเดียว (ห้ามใช้ if/else if/else เลย) พิมพ์ว่าแต้มรวมเป็น "สูง" (≥12) หรือ "ต่ำ" (<12) ในบรรทัดเดียว — ใบ้: ต้องซ้อน conditional operator ไว้ในตัว string interpolation

💡 คำใบ้

เก็บผลรวมไว้ในตัวแปรก่อน แล้วค่อยใช้ conditional operator ประเมินแค่ครั้งเดียวตอนพิมพ์ผล จะอ่านง่ายกว่าใส่นิพจน์การทอยเข้าไปในตัวมันเองตรงๆ

ดูเฉลย
Program.cs
Random dice = new Random();
int total = dice.Next(1, 7) + dice.Next(1, 7) + dice.Next(1, 7);
Console.WriteLine($"แต้มรวม {total}: {(total >= 12 ? "สูง" : "ต่ำ")}");

📌 สรุปบทที่ 14

เป้าหมายของบทนี้คือพัฒนา decision statement สำหรับสถานการณ์ต่างๆ ด้วย Boolean expression และตัวดำเนินการของ C# คุณเขียนโค้ดประเมินความเท่ากัน เปรียบเทียบว่าค่าหนึ่งมากกว่าหรือ น้อยกว่า (หรือเท่ากับ) อีกค่าหนึ่ง คุณเทียบ string โดย massage ข้อมูลก่อน เพื่อลดปัญหาเรื่อง ตัวพิมพ์และช่องว่างที่อาจรบกวนผลลัพธ์ คุณใช้ logical negation กลับค่าเพื่อเปรียบเทียบ และ ใช้ผลลัพธ์จากเมธอดใน Boolean expression ได้ สุดท้าย คุณใช้ conditional operator ประเมิน เงื่อนไขแบบกระชับและคืนผลลัพธ์ได้

ถ้าไม่มีตัวดำเนินการและเทคนิคชุดนี้ครบ คุณจะสร้าง decision statement ได้จำกัดมาก เพราะ ตรรกะธุรกิจทุกอย่างต้องอาศัย Boolean expression — คุณเพิ่งเพิ่มเครื่องมือที่มีค่ามากเข้าไป ในกล่องเครื่องมือเขียนโปรแกรมของคุณแล้ว
