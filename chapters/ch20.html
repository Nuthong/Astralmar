20.1 สถานการณ์และสเปก

แอปพลิเคชันมักใช้ selection และ iteration statement ผสมกันเพื่อสร้าง path การทำงานของโค้ด นอกจากนี้ input จากผู้ใช้และการคำนวณต่างๆ ยังส่งผลต่อ flow ของแอปด้วย การสร้าง user interface ที่ implement ตามสเปกที่กำหนดไว้อาจเป็นเรื่องท้าทาย

สมมติคุณเป็นนักพัฒนาที่กำลังทำงานต่อบนแอป Contoso Pets ที่ใช้หาบ้านใหม่ให้สัตว์จรจัดหรือถูก ทอดทิ้ง งานพัฒนาบางส่วนเสร็จไปแล้ว (จากบทที่ 19) — เมนูหลักของแอปและโค้ดที่ใช้บันทึกข้อมูล สัตว์ตัวใหม่พัฒนาเสร็จแล้ว อย่างไรก็ตาม ข้อมูลบางอย่างไม่ได้มีครบเสมอตอนสัตว์ตัวใหม่ถูกบันทึก เข้าระบบ คุณต้องพัฒนาฟีเจอร์ที่ทำให้มั่นใจว่าชุดข้อมูลของสัตว์แต่ละตัวในความดูแลสมบูรณ์ ครบถ้วน

ในบทนี้ คุณจะพัฒนาฟีเจอร์ต่อไปนี้ของแอป Contoso Pets:

  • ฟีเจอร์ที่ทำให้มั่นใจว่าอายุและคำอธิบายทางกายภาพของสัตว์สมบูรณ์ครบถ้วน (เมนู 3)
  • ฟีเจอร์ที่ทำให้มั่นใจว่าชื่อเล่นและคำอธิบายนิสัยของสัตว์สมบูรณ์ครบถ้วน (เมนู 4)

จบบทนี้ แอป Contoso Pets ของคุณจะรับประกันว่าทุก element ใน array ourAnimals สมบูรณ์ครบถ้วน

สเปกของเมนู 3 — ตรวจอายุและลักษณะทางกายภาพ

ฟีเจอร์นี้ต้อง:

  • ทำงานอยู่ใน code branch ที่ถูกต้อง (ห้ามเขียนทับโค้ดใน code branch ของเมนู 2)
  • ข้ามสัตว์ตัวใดๆ ใน ourAnimals ที่ยังมีค่า pet ID เป็นค่า default
  • แสดงค่า pet ID และถามผู้ใช้ให้กรอกค่าอัปเดต ถ้าข้อมูลใน ourAnimals ขาดหายหรือ ไม่สมบูรณ์
  • รับประกันว่า animalAge ของสัตว์ทุกตัวที่มีข้อมูลแล้วเป็นค่าตัวเลขที่ถูกต้อง
  • รับประกันว่า animalPhysicalDescription ของสัตว์ทุกตัวที่มีข้อมูลแล้วเป็น string ที่ถูกต้อง
  • กฎตรวจสอบของ animalAge: ต้องแปลงเป็นชนิดตัวเลขได้
  • กฎตรวจสอบของ animalPhysicalDescription: ห้ามเป็น null, ห้ามมีความยาวศูนย์ ตัวอักษร (ข้อจำกัดเพิ่มเติมแล้วแต่ผู้พัฒนา)
  • แจ้งผู้ใช้เมื่อข้อมูลครบตามที่กำหนดทุกอย่างแล้ว พร้อมหยุดแอปไว้ให้เห็นข้อความนั้น

สเปกของเมนู 4 — ตรวจชื่อเล่นและนิสัย

ฟีเจอร์นี้ต้อง:

  • ทำงานอยู่ใน code branch ที่ถูกต้อง (ห้ามเขียนทับโค้ดของเมนู 2)
  • ข้ามสัตว์ตัวใดๆ ที่ยังมีค่า pet ID เป็นค่า default
  • แสดงค่า pet ID และถามผู้ใช้ให้กรอกค่าอัปเดต ถ้าข้อมูลขาดหายหรือไม่สมบูรณ์
  • รับประกันว่า animalNickname ของสัตว์ทุกตัวที่มีข้อมูลแล้วเป็น string ที่ ถูกต้อง
  • รับประกันว่า animalPersonalityDescription ของสัตว์ทุกตัวที่มีข้อมูลแล้วเป็น string ที่ถูกต้อง
  • กฎตรวจสอบ: ห้ามเป็น null, ห้ามมีความยาวศูนย์ตัวอักษร (ข้อจำกัดเพิ่มเติมแล้วแต่ผู้พัฒนา)
  • แจ้งผู้ใช้เมื่อข้อมูลครบตามที่กำหนดทุกอย่างแล้ว พร้อมหยุดแอปไว้ให้เห็นข้อความนั้น
💡 ก่อนดูเฉลย ลองเองก่อน! หยิบ Program.cs จากบทที่ 19 หัวข้อ 19.7 มาต่อยอด แล้วลองเติมโค้ด ให้ case "3": และ case "4": เองตามสเปกข้างบน — ให้เวลาตัวเอง 20-30 นาทีต่อเมนู ก่อนเลื่อนไปดูเฉลยในหัวข้อถัดไป การลองผิดลองถูกด้วยตัวเองคือส่วนสำคัญที่สุดของ Challenge Project แบบนี้

20.2 🔓 เฉลยของผม — เมนู 3 (อายุ + ลักษณะทางกายภาพ)

แนวคิดหลัก: วนผ่านสัตว์ทุกตัวใน ourAnimals ด้วย for (เหมือนที่ทำใน บทที่ 19 หัวข้อ 19.4) ข้ามตัวที่ยังไม่มีข้อมูล แล้วสำหรับสัตว์ แต่ละตัวที่เหลือ เช็คว่าฟิลด์ Age ยังเป็นเครื่องหมาย "?" (ค่า default ที่บอกว่า "ยังไม่รู้อายุ" จาก หัวข้อ 19.6b) หรือฟิลด์ Physical description ยังว่างเปล่าอยู่หรือไม่ ถ้าใช่ ก็วน do-while ถามผู้ใช้จนกว่าจะได้ค่าที่ถูกต้อง — แพทเทิร์นเดียวกับที่ใช้ตอนกรอกข้อมูลสัตว์ตัวใหม่ในเมนู 2 เป๊ะ แค่เปลี่ยนจาก "กรอกใหม่ทั้งหมด" เป็น "เติมเฉพาะช่องที่ขาด"

Program.cs (ใน case "3":) 
case "3":
    // Ensure animal ages and physical descriptions are complete
    for (int i = 0; i < maxPets; i++)
    {
        if (ourAnimals[i, 0] == "ID #: ")
        {
            continue;
        }

        string petID = ourAnimals[i, 0];

        // ensure animalAge is a valid numeric value
        if (ourAnimals[i, 2] == "Age: ?")
        {
            bool validAge = false;
            int petAge = 0;
            do
            {
                Console.WriteLine($"Enter an age for {petID}");
                readResult = Console.ReadLine();
                if (readResult != null)
                {
                    validAge = int.TryParse(readResult, out petAge);
                }
            } while (validAge == false);

            ourAnimals[i, 2] = "Age: " + petAge.ToString();
        }

        // ensure animalPhysicalDescription is a valid non-empty string
        if (ourAnimals[i, 4] == "Physical description: ")
        {
            string petPhysicalDescription = "";
            do
            {
                Console.WriteLine($"Enter a physical description for {petID} (size, color, breed, gender, weight, housebroken)");
                readResult = Console.ReadLine();
                if (readResult != null)
                {
                    petPhysicalDescription = readResult;
                }
            } while (petPhysicalDescription == "");

            ourAnimals[i, 4] = "Physical description: " + petPhysicalDescription;
        }
    }

    Console.WriteLine("Age and physical description fields are complete for all of our friends.");
    Console.WriteLine("Press the Enter key to continue");
    readResult = Console.ReadLine();
    break;

ทดสอบตามสเปก: พิมพ์ "one" (ไม่ใช่ตัวเลข) → ระบบถามซ้ำ (เพราะ int.TryParse() คืน false) พิมพ์ 1 → ยอมรับ ต่อด้วย กด Enter เฉยๆ (ค่าว่าง) สำหรับลักษณะทางกายภาพ → ระบบถามซ้ำ (เพราะเงื่อนไข petPhysicalDescription == "") พิมพ์คำอธิบายจริง → ยอมรับและจบด้วยข้อความ ยืนยัน — ตรงกับพฤติกรรมที่สเปกต้องการทุกจุด

ทำไมต้องเช็ค "Age: ?" แบบตรงตัว (exact match)

สังเกตว่าเงื่อนไข if (ourAnimals[i, 2] == "Age: ?") ใช้เทียบ string ทั้งก้อน ตรงๆ ไม่ใช่ int.TryParse() กับ ourAnimals[i, 2] ตรงๆ — เพราะค่าที่ เก็บจริงในช่องนี้คือ "Age: 2" หรือ "Age: ?" (มี prefix "Age: " ติดมาด้วยเสมอ) ถ้าเอาทั้งก้อนไปเข้า TryParse() ตรงๆ จะ parse ไม่ผ่านเสมอ (เพราะมีตัวอักษร "Age: " ปนอยู่) เราจึงต้องอาศัยรู้ว่า "?" คือ marker เดียวที่แอปนี้ใช้แทน "อายุยังไม่ทราบ" (ทบทวนจาก บทที่ 19 หัวข้อ 19.6b) แล้วเช็คตรงๆ ว่า string เท่ากับ "Age: ?" พอดีหรือไม่

⚠️ continue กับ for-loop ในบริบทนี้ continue; ที่ใช้ในหัวข้อนี้ทำงานเหมือนที่เรียนใน บทที่ 18 ทุกประการ — ข้ามไปที่ iterator ของ for loop (i++) ทันที โดยไม่รันโค้ดที่เหลือใน iteration นั้น เหมาะมากสำหรับ "ข้ามสัตว์ที่ ยังไม่มีข้อมูล" เพราะเขียนสั้นกว่าการครอบทุกอย่างที่เหลือด้วย if { } ก้อนใหญ่

20.3 🔓 เฉลยของผม — เมนู 4 (ชื่อเล่น + นิสัย)

โครงสร้างเหมือนเมนู 3 ทุกประการ ต่างแค่ 2 ฟิลด์ที่ตรวจ (Nickname กับ Personality) และไม่มีการ validate เป็นตัวเลข — แค่ "ห้ามว่างเปล่า" เท่านั้น

Program.cs (ใน case "4":) 
case "4":
    // Ensure animal nicknames and personality descriptions are complete
    for (int i = 0; i < maxPets; i++)
    {
        if (ourAnimals[i, 0] == "ID #: ")
        {
            continue;
        }

        string petID = ourAnimals[i, 0];

        // ensure animalNickname is a valid non-empty string
        if (ourAnimals[i, 3] == "Nickname: ")

        }

สังเกตว่าโค้ดของเมนู 3 กับ 4 ไม่แตะ case "2": เลย — ตรงตามข้อกำหนด "must not overwrite the code in the code branch for menu option 2" ทั้งสองเมนูอ่านและแก้ไข เฉพาะ element ของ ourAnimals ที่มีอยู่แล้วเท่านั้น ไม่ได้เพิ่มแถวใหม่หรือยุ่ง กับ petCount แต่อย่างใด

💡 ทำไมสัตว์ตัวอย่าง d1, d2, c3 ไม่โดนถามอะไรเลย ทบทวนข้อมูลตัวอย่างจาก บทที่ 19 หัวข้อ 19.3a: d1, d2, c3 ถูกสร้าง มาพร้อมอายุ ลักษณะทางกายภาพ นิสัย และชื่อเล่นครบทุกฟิลด์ตั้งแต่แรก มีแค่ c4 ตัวเดียวที่ตั้งใจ เว้นข้อมูลไว้ไม่ครบ (อายุเป็น "?" ที่เหลือเป็นค่าว่าง) — ทั้งเมนู 3 และเมนู 4 จึงถามแค่ข้อมูลของ c4 เท่านั้น ตรงตามที่ Microsoft Learn ออกแบบไว้ในชุดข้อมูลตัวอย่าง

20.4 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
เมนู 3 วนถามอายุของสัตว์ที่มีอายุอยู่แล้วด้วย เช็คเงื่อนไขผิด เช่นเผลอใช้ != แทน == หรือลืม prefix "Age: " ตอนเทียบ string
เขียนทับโค้ดของเมนู 2 โดยไม่ตั้งใจ วางโค้ดเมนู 3/4 ผิด case — ตรวจให้แน่ใจว่าอยู่ใน case "3": และ case "4": เท่านั้น ไม่ใช่แทรกอยู่กลาง case "2":
สัตว์ตัวใหม่จากเมนู 2 ที่มี "tbd" ไม่ถูกถามซ้ำในเมนู 4 ทั้งที่ยังไม่รู้นิสัยจริง ไม่ใช่บั๊ก — เป็นไปตามสเปก ("ห้ามว่างเปล่า" เท่านั้น) "tbd" ถือว่าเป็น string ที่ถูกต้องแล้ว ถ้าต้องการ validate เข้มกว่านี้ (เช่น ห้ามเป็น "tbd" ด้วย) ต้องเพิ่มเงื่อนไขเอง — สเปกเปิดช่องให้ "Any further restriction is up to the developer"
infinite loop ตอนถามอายุ ถ้าผู้ใช้กด Enter เฉยๆ โดยไม่พิมพ์อะไร ไม่ใช่บั๊ก — เป็นพฤติกรรมที่ถูกต้อง เพราะ string ว่างแปลงเป็น int ไม่ได้ (TryParse คืน false) loop จึงถามซ้ำไปเรื่อยๆ จนกว่าจะได้ตัวเลขจริง ตรงตามสเปก "must be possible to convert the value entered to numeric data type"
ทดสอบเมนู 3 ซ้ำสองรอบ (รันแอปใหม่ไม่ได้) แล้วเจอ error อย่าลืมว่า ourAnimals เป็น runtime data ไม่ได้ persist ข้าม session (ตามที่ comment ในโค้ดบอกไว้ตั้งแต่บทที่ 19) — ทุกครั้งที่ dotnet run ใหม่ ข้อมูลจะรีเซ็ตกลับไปเป็นชุดตัวอย่างเดิมเสมอ เป็นเรื่องปกติ

1. นักพัฒนากำลังเขียนแอปใน Visual Studio Code เซฟการ เปลี่ยนแปลงในไฟล์ Program.cs แล้วรันคำสั่ง dotnet build ใน Terminal panel ข้อความ Error และ Warning ที่รายงานกลับมาให้ข้อมูลอะไรบ้าง?

  • Aคำแนะนำหนึ่งอย่างหรือมากกว่าว่าจะแก้ปัญหา syntax ที่ตรวจพบได้อย่างไร
  • Bหมายเลขบรรทัดและข้อมูลว่าอะไรเป็นสาเหตุของ error
  • Cลิงก์ไปยังเอกสารช่วยเหลือ (help documentation)
เฉลย: ข้อ B. ทบทวนจาก บทที่ 19 หัวข้อ 19.3a: build error บอกหมายเลขบรรทัดและประเภทของปัญหา (เช่น "error CS1002: ; expected") แต่ไม่ได้ แนะนำวิธีแก้ให้ตรงๆ และไม่มีลิงก์เอกสารแนบมาด้วย ผู้พัฒนาต้องตีความข้อความเองแล้วไปแก้ไข

2. นักพัฒนาต้องสร้าง iteration statement ตัวหนึ่ง ในเงื่อนไขแบบไหนที่ while statement เป็นตัวเลือกที่ดีกว่า do statement?

  • Aเมื่อค่าของ expression ที่ iteration statement ประเมิน ยังไม่รู้ล่วงหน้าก่อนเข้า iteration code block
  • Bเมื่อค่าของ expression ที่ iteration statement ประเมิน รู้อยู่แล้วล่วงหน้าก่อนเข้า iteration code block
  • Cเมื่อนักพัฒนาสร้าง nested do หรือ while loop
เฉลย: ข้อ B. ตรงกับตัวอย่าง while (anotherPet == "y" && petCount < maxPets) ใน บทที่ 19 หัวข้อ 19.5c — ตอนนั้นรู้ค่า petCount อยู่แล้วก่อนเข้า loop (จากการนับล่วงหน้า) จึงเลือก while ไม่ใช่ do-while ทบทวนหลักการเลือกเพิ่มเติมได้ที่ บทที่ 18 หัวข้อ 18.4

20.6 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

ในเฉลยเมนู 3 ทำไมเราไม่ใช้ if (ourAnimals[i, 2] == "Age: ?") กับ else block ที่ทำอะไรบางอย่างเมื่ออายุครบแล้ว? ลองอธิบายด้วยคำพูดตัวเอง

ดูเฉลย

เพราะสเปกไม่ได้ต้องการให้ทำอะไรกับสัตว์ที่มีอายุครบแล้ว — แค่ "ข้าม" ไปเฉยๆ ก็พอ การไม่ ใช้ else (ปล่อยให้ไม่มีอะไรเกิดขึ้นถ้าเงื่อนไขเป็นเท็จ) คือพฤติกรรม default ของ if อยู่แล้ว ไม่จำเป็นต้องเขียน else { } ว่างๆ เพิ่ม (เพิ่มโค้ดที่ไม่มีประโยชน์ ขัดกับหลัก "ไม่เพิ่มโค้ดเกินจำเป็น")

ข้อ 2กลาง

เพิ่มกฎ validate ให้เข้มขึ้นในเมนู 3: อายุที่กรอกต้องเป็นค่าระหว่าง 0-30 เท่านั้น (สัตว์ อายุติดลบหรือเกิน 30 ปีไม่สมเหตุสมผล) ถ้าไม่อยู่ในช่วงนี้ให้ถามใหม่ พร้อมข้อความแจ้งเตือน

ดูเฉลย
Program.cs (ส่วนที่แก้)
bool validAge = false;
int petAge = 0;
do
{
    Console.WriteLine($"Enter an age for {petID}");
    readResult = Console.ReadLine();
    if (readResult != null)
    {
        validAge = int.TryParse(readResult, out petAge);
        if (validAge && (petAge < 0 || petAge > 30))
        {
            Console.WriteLine("Age must be between 0 and 30. Please try again.");
            validAge = false;
        }
    }
} while (validAge == false);

ใช้ && รวมเงื่อนไขว่า parse สำเร็จและอยู่นอกช่วงที่ยอมรับได้ ถ้าเข้า เงื่อนไขนี้ ตั้ง validAge = false กลับ เพื่อบังคับให้ loop วนถามใหม่

ข้อ 3กลาง

สเปกบอกว่า physical description "ห้าม null" — แต่โค้ดเฉลยของเราดูจะไม่มีทางเป็น null ได้เลยตั้งแต่แรก อธิบายว่าทำไม (คำใบ้: ดูตัวแปร readResult และ petPhysicalDescription อีกที)

ดูเฉลย

petPhysicalDescription เริ่มต้นด้วยค่า "" (ไม่ใช่ null) เสมอ และโค้ดใน do loop กำหนดค่าให้มันเฉพาะตอน readResult != null เท่านั้น (ทบทวน nullable string pattern จาก บทที่ 18) ดังนั้น petPhysicalDescription จึงเป็น string ปกติที่ไม่มีทาง null ได้เลยตลอดทั้งลูป — การเช็ค "ห้าม null" ในสเปกจึงถูกป้องกันไว้แล้วโดยโครงสร้างโค้ด ไม่ต้องเขียนเช็คซ้ำอีกชั้น

ข้อ 4ยาก

ท้าทายจริง — implement เมนู 5 "Edit an animal's age" เอง: ให้ผู้ใช้พิมพ์ pet ID ที่ต้องการแก้ (เช่น "d1") แล้วถามอายุใหม่ (ต้องเป็นตัวเลขที่ถูกต้อง) แล้วอัปเดตลง ourAnimals ถ้าไม่เจอ pet ID ที่พิมพ์ ให้แจ้งเตือนแล้วกลับเมนูหลัก

💡 คำใบ้

ใช้ for loop วนหา index ที่ ourAnimals[i, 0] เท่ากับ "ID #: " + ค่าที่ผู้ใช้พิมพ์ เก็บ index นั้นไว้ (เริ่มที่ -1 แทน "ยังไม่เจอ") แล้วค่อยถามอายุใหม่ด้วยแพทเทิร์นเดียวกับเมนู 3

ดูเฉลย
Program.cs (ใน case "5":)
case "5":
    // Edit an animal's age
    Console.WriteLine("Enter the pet ID of the animal you want to edit (example: d1)");
    readResult = Console.ReadLine();

    int foundIndex = -1;
    if (readResult != null)
    {
        string searchID = "ID #: " + readResult.ToLower();
        for (int i = 0; i < maxPets; i++)
        {
            if (ourAnimals[i, 0] == searchID)
            {
                foundIndex = i;
            }
        }
    }

    if (foundIndex == -1)
    {
        Console.WriteLine("Sorry, we couldn't find that pet ID.");
    }
    else
    {
        bool validAge = false;
        int newAge = 0;
        do
        {
            Console.WriteLine($"Enter a new age for {ourAnimals[foundIndex, 0]}");
            readResult = Console.ReadLine();
            if (readResult != null)
            {
                validAge = int.TryParse(readResult, out newAge);
            }
        } while (validAge == false);

        ourAnimals[foundIndex, 2] = "Age: " + newAge.ToString();
        Console.WriteLine("Age updated successfully.");
    }

    Console.WriteLine("Press the Enter key to continue.");
    readResult = Console.ReadLine();
    break;
ข้อ 5ยาก

รวมเมนู 3 กับ 4 เข้าเป็น case เดียว (สมมติว่าออกแบบแอปใหม่ให้เป็นเมนู "Complete all missing data" เมนูเดียว) โดยยังคงตรวจครบทั้ง 4 ฟิลด์ (age, physical, nickname, personality) ในการวน loop รอบเดียว

ดูเฉลย
Program.cs
for (int i = 0; i < maxPets; i++)
{
    if (ourAnimals[i, 0] == "ID #: ")
    {
        continue;
    }

    string petID = ourAnimals[i, 0];

    if (ourAnimals[i, 2] == "Age: ?")
    {
        bool validAge = false;
        int petAge = 0;
        do
        {
            Console.WriteLine($"Enter an age for {petID}");
            readResult = Console.ReadLine();
            if (readResult != null) validAge = int.TryParse(readResult, out petAge);
        } while (validAge == false);
        ourAnimals[i, 2] = "Age: " + petAge.ToString();
    }

    if (ourAnimals[i, 4] == "Physical description: ")
    {
        string val = "";
        do
        {
            Console.WriteLine($"Enter a physical description for {petID}");
            readResult = Console.ReadLine();
            if (readResult != null) val = readResult;
        } while (val == "");
        ourAnimals[i, 4] = "Physical description: " + val;
    }

    if (ourAnimals[i, 3] == "Nickname: ")
    {
        string val = "";
        do
        {
            Console.WriteLine($"Enter a nickname for {petID}");
            readResult = Console.ReadLine();
            if (readResult != null) val = readResult;
        } while (val == "");
        ourAnimals[i, 3] = "Nickname: " + val;
    }

    if (ourAnimals[i, 5] == "Personality: ")
    {
        string val = "";
        do
        {
            Console.WriteLine($"Enter a personality description for {petID}");
            readResult = Console.ReadLine();
            if (readResult != null) val = readResult;
        } while (val == "");
        ourAnimals[i, 5] = "Personality: " + val;
    }
}

Console.WriteLine("All fields are complete for all of our friends.");
Console.WriteLine("Press the Enter key to continue.");
readResult = Console.ReadLine();

สังเกตว่า for loop ชั้นนอกวนแค่รอบเดียวต่อสัตว์หนึ่งตัว แต่ข้างในตรวจครบ ทั้ง 4 ฟิลด์ก่อนขยับไปสัตว์ตัวถัดไป — เป็นการรวม logic จากทั้งเมนู 3 และ 4 เข้าด้วยกัน โดยไม่ต้องวน array ซ้ำสองรอบ (ประหยัดกว่าเรียกทั้งสอง case แยกกัน)

ข้อ 6ท้าทาย

วิเคราะห์: ถ้าลืมเขียน ourAnimals[i, 2] = "Age: " + petAge.ToString(); (บรรทัดบันทึกค่ากลับ) ในเฉลยเมนู 3 จะเกิดอะไรขึ้นถ้าผู้ใช้เลือกเมนู 3 สองครั้งติดกัน?

ดูเฉลย

ถ้าไม่มีการบันทึกค่ากลับลง ourAnimals ค่าที่ผู้ใช้กรอกจะหายไปทันทีที่ case "3": จบ (เพราะ petAge เป็นตัวแปรท้องถิ่นที่ scope อยู่แค่ใน iteration นั้น) พอผู้ใช้เลือกเมนู 3 อีกครั้ง เงื่อนไข ourAnimals[i, 2] == "Age: ?" จะยังเป็นจริงเหมือนเดิม (เพราะค่าจริงใน array ไม่เคยถูกอัปเดต) ระบบจะถามอายุของ c4 ซ้ำไปเรื่อยๆ ทุกครั้งที่เลือกเมนู 3 ไม่มีวัน "จบสมบูรณ์" ได้จริง — นี่แสดงให้เห็นว่าทำไมการเขียนค่ากลับลง array (ไม่ใช่แค่ ตัวแปรชั่วคราว) เป็นขั้นตอนที่ขาดไม่ได้

เป้าหมายของคุณคือแสดงความสามารถในการพัฒนาฟีเจอร์ของแอปพลิเคชันให้บรรลุตามสเปกที่ออกแบบไว้ คุณต้องเลือกและ implement ชนิดของ iteration และ selection statement ที่เหมาะสม เพื่อให้ตรง ตามข้อกำหนดที่ระบุไว้
