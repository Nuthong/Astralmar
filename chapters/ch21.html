21.1 ทำไมต้องเข้าใจ Data Type ให้ลึกขึ้น

ภาษา C# พึ่งพา data type อย่างมาก data type จำกัดชนิดของค่าที่เก็บในตัวแปรหนึ่งๆ ได้ ซึ่งช่วย ให้เขียนโค้ดที่ปราศจากข้อผิดพลาดได้ง่ายขึ้น ในฐานะนักพัฒนา คุณมั่นใจในการดำเนินการกับตัวแปร ของคุณได้ เพราะรู้ล่วงหน้าว่ามันเก็บได้แค่ค่าที่ถูกต้องเท่านั้น

สมมติงานของคุณคือสร้างแอปใหม่ที่ต้อง ดึง จัดการ และเก็บข้อมูลหลายชนิดมาก รวมถึงค่าตัวเลขเดี่ยว และลำดับของค่าตัวเลขกับข้อความ การเลือก data type ที่ถูกต้องเป็นสิ่งสำคัญมากต่อความสำเร็จของ งานพัฒนาซอฟต์แวร์ของคุณ แต่คุณมีตัวเลือกอะไรบ้าง และควรใช้เกณฑ์อะไรตัดสินใจ เมื่อเจอ data type หลายตัวที่ดูคล้ายกัน?

ในบทนี้ คุณจะเรียนรู้ว่าแอปของคุณเก็บและประมวลผลข้อมูลยังไง คุณจะเรียนว่า data type มี 2 ประเภทหลักที่สอดคล้องกับ 2 วิธีที่ข้อมูลถูกประมวลผล คุณจะเขียนโค้ดที่หาค่าสูงสุดและต่ำสุดที่ numeric data type แต่ละชนิดเก็บได้ และเรียนเกณฑ์การเลือกระหว่าง numeric data type หลายตัวสำหรับ แอปของคุณ

21.2 ข้อมูลคืออะไร และ Value กับ Reference Type ต่างกันยังไง

ข้อมูลคืออะไรจริงๆ

ในงานพัฒนาซอฟต์แวร์ ข้อมูลก็คือค่าที่ถูกเก็บในหน่วยความจำของคอมพิวเตอร์เป็นลำดับของ bit bit คือสวิตช์ไบนารีง่ายๆ แทนด้วย 0 หรือ 1 (คือ "off" กับ "on") bit เดียวดูไม่มีประโยชน์เท่าไร แต่พอรวม 8 bit เข้าด้วยกันเป็นลำดับ มันจะกลายเป็น byte เมื่อใช้ในหนึ่ง byte แต่ละ bit จะมีความหมายตามตำแหน่งของมัน อันที่จริงคุณแทนค่าได้ถึง 256 รูปแบบด้วยแค่ 8 bit ถ้าใช้ระบบเลขฐานสอง (binary)

ตัวอย่างเช่น ในระบบเลขฐานสอง คุณแทนเลข 195 ด้วย 11000011 ได้ ตารางข้างล่างช่วยให้เห็นภาพ: แถวแรกมี 8 คอลัมน์ แทนตำแหน่งใน byte แต่ละตำแหน่งแทนค่าตัวเลขที่ ต่างกัน แถวที่สองเก็บค่าของแต่ละ bit (0 หรือ 1)

1286432168421
11000011

ถ้าบวกเลขจากแถวแรกที่ตรงกับ 1 ในแถวสอง คุณจะได้ค่าเทียบเท่าฐานสิบของค่าเลขฐานสอง นี้: 128 + 64 + 2 + 1 = 195

ถ้าจะทำงานกับค่าที่ใหญ่กว่า 255 คอมพิวเตอร์ต้องเก็บ byte มากขึ้น (ปกติ 32-bit หรือ 64-bit) ถ้าคุณทำงานกับตัวเลขจำนวนมากในบริบททางวิทยาศาสตร์ อาจต้องพิจารณาให้รอบคอบว่าใช้ data type ไหน เพราะโค้ดของคุณอาจต้องการหน่วยความจำมากขึ้น

💡 แล้วข้อมูลข้อความล่ะ ถ้าคอมพิวเตอร์เข้าใจแค่ 0 กับ 1 แล้วมันให้เราทำงานกับข้อความได้ยังไง? ด้วยระบบอย่าง ASCII (American Standard Code for Information Interchange) คอมพิวเตอร์ใช้ byte เดียวแทนตัวอักษรพิมพ์ใหญ่-เล็ก ตัวเลข tab backspace newline และสัญลักษณ์ทางคณิตศาสตร์อีก มากมายได้ ตัวอย่างเช่น ตัวอักษร a พิมพ์เล็กเทียบเท่าค่าฐานสิบ 97 (64 + 32 + 1 = 97) จึงเก็บเป็นเลขฐานสอง 8 bit ได้เป็น 01100001 — คุณแทบไม่ต้องแปลงแบบนี้ด้วยตัวเองเลยในการทำงานจริง แต่การเข้าใจมุมมองของคอมพิวเตอร์ต่อข้อมูล เป็นพื้นฐานสำคัญ โดยเฉพาะตอนพิจารณาเรื่อง data type

Data Type คืออะไร

data type คือวิธีที่ภาษาโปรแกรมกำหนดว่าจะจองหน่วยความจำไว้เท่าไรสำหรับค่าหนึ่งๆ ภาษา C# มี data type มากมายให้ใช้กับแอปพลิเคชันและขนาดข้อมูลที่หลากหลาย สำหรับแอปส่วนใหญ่ ที่คุณสร้างตลอดอาชีพการทำงาน คุณจะใช้แค่ส่วนย่อยเล็กๆ ของ data type ทั้งหมดที่มี แต่ก็ยังสำคัญ ที่จะรู้ว่ามีตัวอื่นอยู่ด้วย และทำไม

Value Type vs Reference Type

บทนี้เน้นที่ data type 2 ประเภทหลักใน C#: reference type และ value type

ตัวแปรของ reference type เก็บ การอ้างอิง (reference) ไปยังข้อมูลของมัน (object) — คือมันชี้ไปยังค่าที่เก็บอยู่ที่อื่น ในทางกลับกัน ตัวแปรของ value type เก็บข้อมูลของมันโดยตรง เมื่อคุณเรียนรู้ C# มากขึ้น รายละเอียดใหม่ๆ ที่เกี่ยวกับความแตกต่างพื้นฐานนี้จะค่อยๆ ปรากฏขึ้น

Simple value type คือชุดของ type ที่กำหนดไว้ล่วงหน้าโดย C# ในรูปคีย์เวิร์ด คีย์เวิร์ด เหล่านี้เป็น alias (ชื่อเล่น) ของ type ที่กำหนดไว้ใน .NET Class Library เช่น คีย์เวิร์ด int ของ C# เป็น alias ของ value type ที่กำหนดไว้ใน .NET Class Library ในชื่อ System.Int32

simple value type รวมถึง data type ที่คุณอาจเคยใช้แล้วอย่าง char และ bool และยังมี integral กับ floating-point value type อีกหลายตัว ที่แทนตัวเลขจำนวนเต็มและเลขทศนิยมได้หลากหลายช่วงค่า

Check ★ ข้อใดอธิบายวิธีที่ bit แทนค่า on/off ได้ถูกต้อง ที่สุด?

  • Abit แทนด้วยตัวอักษร "x" หรือ "o"
  • Bbit แทนด้วยสัญลักษณ์ "+bit" หรือ "-bit"
  • Cbit เป็นเลขฐานสอง แทนด้วยตัวเลข "1" หรือ "0"
เฉลย: ข้อ C. bit คือสวิตช์ไบนารี แทนด้วยตัวเลข 1 (on) หรือ 0 (off) เท่านั้น

21.3 Integral Types — ตัวเลขจำนวนเต็ม

integral type คือ simple value type ที่แทนจำนวนเต็มไม่มีเศษ (เช่น -1, 0, 1, 2, 3) ตัวที่นิยมที่สุดในกลุ่มนี้คือ int

integral type แบ่งเป็น 2 กลุ่มย่อย: signed (มีเครื่องหมายบวก-ลบ) และ unsigned (ไม่มีเครื่องหมาย)

Signed Integral Types

signed type ใช้ bit ของมันแทนทั้งจำนวนบวกและลบในสัดส่วนเท่าๆ กัน

Program.cs 
Console.WriteLine("Signed integral types:");

Console.WriteLine($"sbyte  : {sbyte.MinValue} to {sbyte.MaxValue}");
Console.WriteLine($"short  : {short.MinValue} to {short.MaxValue}");
Console.WriteLine($"int    : {int.MinValue} to {int.MaxValue}");
Console.WriteLine($"long   : {long.MinValue} to {long.MaxValue}");
Output
Signed integral types:
sbyte  : -128 to 127
short  : -32768 to 32767
int    : -2147483648 to 2147483647
long   : -9223372036854775808 to 9223372036854775807

สำหรับแอปทั่วไปที่ไม่ใช่งานวิทยาศาสตร์ คุณมักต้องใช้แค่ int เท่านั้น ส่วนใหญ่แล้ว คุณไม่ต้องการมากกว่าช่วง -2.14 พันล้าน ถึง +2.14 พันล้าน

Unsigned Integral Types

unsigned type ใช้ bit ของมันแทนแค่จำนวนบวกเท่านั้น

Program.cs (เพิ่มต่อจากด้านบน) 
Console.WriteLine("");
Console.WriteLine("Unsigned integral types:");

Console.WriteLine($"byte   : {byte.MinValue} to {byte.MaxValue}");
Console.WriteLine($"ushort : {ushort.MinValue} to {ushort.MaxValue}");
Console.WriteLine($"uint   : {uint.MinValue} to {uint.MaxValue}");
Console.WriteLine($"ulong  : {ulong.MinValue} to {ulong.MaxValue}");
Output
Signed integral types:
sbyte  : -128 to 127
short  : -32768 to 32767
int    : -2147483648 to 2147483647
long   : -9223372036854775808 to 9223372036854775807

Unsigned integral types:
byte   : 0 to 255
ushort : 0 to 65535
uint   : 0 to 4294967295
ulong  : 0 to 18446744073709551615

data type หนึ่งใช้ได้กับหลายกรณี แต่จากข้อเท็จจริงที่ byte แทนค่าได้ตั้งแต่ 0 ถึง 255 เห็นได้ชัดว่ามันถูกออกแบบมาให้เก็บค่าที่แทน 1 byte ของข้อมูลพอดี ข้อมูลที่เก็บ ในไฟล์หรือส่งผ่านอินเทอร์เน็ตมักอยู่ในรูปแบบไบนารี เวลาทำงานกับข้อมูลจากแหล่งภายนอกแบบนี้ คุณมักต้องรับข้อมูลเป็น array ของ byte แล้วค่อยแปลงเป็น string — เมธอดจำนวนมากใน .NET Class Library ที่เกี่ยวกับ encoding/decoding ข้อมูล ต้องการให้คุณจัดการกับ byte array

Check ★ data type ไหนมีช่วงจำนวนเต็มระหว่าง 0 ถึง 65535 ในโค้ด C#?

  • Asbyte
  • Bushort
  • Cbyte
เฉลย: ข้อ B. ushort มีช่วง 0 ถึง 65535 พอดี ส่วน byte มีช่วงแค่ 0-255 และ sbyte มีช่วง -128 ถึง 127 (ไม่ใช่บวกล้วน)

21.4 Floating-Point Types — ตัวเลขทศนิยม

floating point คือ simple value type ที่แทนตัวเลขทางขวาของจุดทศนิยม ต่างจากตัวเลข integral ตรงที่มีเรื่องต้องพิจารณามากกว่าแค่ค่าสูงสุด-ต่ำสุดที่เก็บได้

ก่อนอื่นต้องพิจารณา digits of precision (จำนวนหลักความละเอียด) ที่แต่ละ type รองรับ — precision คือจำนวนตำแหน่งค่าที่เก็บได้หลังจุดทศนิยม

สองคือต้องพิจารณาวิธีที่ค่าถูกเก็บ และผลกระทบต่อความแม่นยำของค่า ตัวอย่างเช่น ค่า float และ double ถูกเก็บภายในแบบเลขฐานสอง (base 2) ในขณะที่ decimal ถูกเก็บแบบเลขฐานสิบ (base 10) ทำไมเรื่องนี้ถึงสำคัญ?

การคำนวณทางคณิตศาสตร์กับค่า binary floating-point อาจให้ผลลัพธ์ที่คุณคาดไม่ถึง ถ้าคุณคุ้นกับ คณิตศาสตร์แบบฐานสิบ (decimal) บ่อยครั้ง binary floating-point math เป็นแค่ค่าประมาณของ ค่าจริง ดังนั้น float และ double จึงมีประโยชน์เพราะเก็บตัวเลขจำนวน มากได้ด้วยหน่วยความจำน้อย แต่ควรใช้เฉพาะตอนที่ค่าประมาณเพียงพอแล้วเท่านั้น เช่น การคำนวณการ กระเด็นของลูกบอลหิมะในวิดีโอเกม คลาดเคลื่อนไปสองสามในพันก็ยังถือว่าใกล้เคียงพอ

เมื่อคุณต้องการคำตอบที่แม่นยำกว่านั้น ควรใช้ decimal ค่าแต่ละค่าของชนิด decimal ใช้พื้นที่หน่วยความจำค่อนข้างมาก แต่การคำนวณทางคณิตศาสตร์ให้ผลลัพธ์ที่ แม่นยำกว่า ดังนั้นคุณควรใช้ decimal เมื่อทำงานกับข้อมูลทางการเงิน หรือสถานการณ์ ใดๆ ที่ต้องการผลลัพธ์การคำนวณที่แม่นยำ

Program.cs 
Console.WriteLine("");
Console.WriteLine("Floating point types:");
Console.WriteLine($"float  : {float.MinValue} to {float.MaxValue} (with ~6-9 digits of precision)");
Console.WriteLine($"double : {double.MinValue} to {double.MaxValue} (with ~15-17 digits of precision)");
Console.WriteLine($"decimal: {decimal.MinValue} to {decimal.MaxValue} (with 28-29 digits of precision)");
Output
Floating point types:
float  : -3.402823E+38 to 3.402823E+38 (with ~6-9 digits of precision)
double : -1.79769313486232E+308 to 1.79769313486232E+308 (with ~15-17 digits of precision)
decimal: -79228162514264337593543950335 to 79228162514264337593543950335 (with 28-29 digits of precision)

สังเกตว่า float กับ double ใช้ notation ต่างจาก decimal ตอนแทนค่าสูงสุด-ต่ำสุดของมัน แต่ notation นี้หมายความว่าอะไร?

ถอดรหัส Floating-Point แบบ E Notation

เพราะ floating-point type เก็บตัวเลขขนาดใหญ่พร้อม precision ได้ ค่าของมันจึงแทนด้วย "E notation" ซึ่งเป็นรูปแบบ scientific notation ที่แปลว่า "คูณด้วย 10 ยกกำลัง" ดังนั้นค่าอย่าง 5E+2 จะมีค่าเท่ากับ 500 เพราะเทียบเท่ากับ 5 × 102

⚠️ float/double vs decimal — ต่างกันในระดับ compiler มีความแตกต่างพื้นฐานในวิธีที่ compiler และ runtime จัดการ decimal เทียบกับ float หรือ double โดยเฉพาะตอนตัดสินว่าต้องการความแม่นยำแค่ไหนจากการ คำนวณทางคณิตศาสตร์ — จำไว้ง่ายๆ ว่า: เงิน → decimal เสมอ ตำแหน่ง/ฟิสิกส์/ วิทยาศาสตร์ที่รับค่าประมาณได้ → float/double

  • Bfloat
  • Cdouble
เฉลย: ข้อ A. ข้อมูลทางการเงินต้องการความแม่นยำสูงสุด ไม่ใช่ค่าประมาณ — decimal เก็บแบบฐาน 10 และให้ผลคำนวณที่แม่นยำกว่า float/double ซึ่งเก็บแบบฐาน 2 และมักมี ค่าคลาดเคลื่อนเล็กน้อยจากการปัดเศษ

21.5 Reference Types — Stack กับ Heap

reference type รวมถึง array, class, และ string reference type ถูกจัดการต่างจาก value type ในแง่ของวิธีเก็บค่าตอนแอปกำลังทำงาน

Reference Type ต่างจาก Value Type ยังไง

ตัวแปร value type เก็บค่าของมันโดยตรงในพื้นที่เก็บข้อมูลที่เรียกว่า stack — stack คือ หน่วยความจำที่ถูกจัดสรรให้กับโค้ดที่กำลังทำงานอยู่บน CPU ในขณะนั้น (เรียกอีกอย่างว่า stack frame หรือ activation frame) เมื่อ stack frame ทำงานเสร็จ ค่าใน stack จะถูกลบทิ้ง

ตัวแปร reference type เก็บค่าของมันในพื้นที่หน่วยความจำแยกต่างหากที่เรียกว่า heap — heap คือพื้นที่หน่วยความจำที่ใช้ร่วมกันระหว่างหลายแอปพลิเคชันที่รันบนระบบปฏิบัติการพร้อมกัน .NET Runtime สื่อสารกับระบบปฏิบัติการเพื่อหาว่า memory address ไหนว่างอยู่ แล้วขอ address ที่จะเก็บค่านั้นไว้ .NET Runtime เก็บค่านั้น แล้วส่ง memory address กลับไปให้ตัวแปร เมื่อโค้ด ของคุณใช้ตัวแปรนั้น .NET Runtime จะค้นหา address ที่เก็บอยู่ในตัวแปรอย่างราบรื่น แล้วดึงค่าที่ เก็บอยู่ที่นั่นออกมา

สร้างตัวแปร Reference Type

Program.cs 
int[] data;

โค้ดข้างบนประกาศตัวแปรที่เก็บค่าชนิด int array ได้ ตอนนี้ data เป็น แค่ตัวแปรที่อาจจะเก็บ reference (memory address) ของค่าใน heap ได้ เพราะมันยังไม่ได้ชี้ ไปยัง memory address ใดๆ เลย จึงเรียกว่า null reference

สร้าง instance ของ int array ด้วยคีย์เวิร์ด new:

Program.cs 
int[] data;
data = new int[3];

คีย์เวิร์ด new บอก .NET Runtime ให้สร้าง instance ของ int array แล้วประสานงานกับระบบปฏิบัติการเพื่อเก็บ array ขนาด 3 ค่า int ในหน่วยความจำ .NET Runtime ทำตาม แล้วคืน memory address ของ int array ตัวใหม่ สุดท้าย memory address นั้นถูกเก็บไว้ในตัวแปร data element ของ int array จะมีค่า default เป็น 0 เพราะนั่นคือค่า default ของ int

สองบรรทัดข้างบนมักย่อเหลือบรรทัดเดียว ทั้งประกาศตัวแปรและสร้าง instance พร้อมกัน:

Program.cs 
int[] data = new int[3];
💡 แล้ว string ล่ะ ทำไมไม่ต้องใช้ new string data type ก็เป็น reference type เหมือนกัน คุณอาจสงสัยว่าทำไมไม่เห็นใช้ new ตอนประกาศ string เลย — นี่เป็นความสะดวกที่นักออกแบบ C# มอบให้ เพราะ string ถูกใช้บ่อยมาก จึงเขียนแบบนี้ได้เลย:
ตัวอย่าง
string shortenedString = "Hello World!";
Console.WriteLine(shortenedString);
เบื้องหลัง ระบบสร้าง instance ใหม่ของ System.String และกำหนดค่าเริ่มต้นเป็น "Hello World!" ให้อยู่ดี แค่ไม่ต้องให้คุณพิมพ์ new เอง

ข้อควรระวังในทางปฏิบัติ: Value Type vs Reference Type

ตัวอย่างที่ 1 — Value Type (int): val_A และ val_B เป็น integer value type

Program.cs 
int val_A = 2;
int val_B = val_A;
val_B = 5;

Console.WriteLine("--Value Types--");
Console.WriteLine($"val_A: {val_A}");
Console.WriteLine($"val_B: {val_B}");
Output
--Value Types--
val_A: 2
val_B: 5

ตอน val_B = val_A ทำงาน ค่าของ val_A จะถูกก็อปปี้และเก็บใน val_B ดังนั้นเมื่อ val_B ถูกเปลี่ยน val_A จะไม่ได้รับ ผลกระทบเลย

ตัวอย่างที่ 2 — Reference Type (array): ref_A และ ref_B เป็น array reference type

Program.cs 
int[] ref_A = new int[1];
ref_A[0] = 2;
int[] ref_B = ref_A;
ref_B[0] = 5;

Console.WriteLine("--Reference Types--");
Console.WriteLine($"ref_A[0]: {ref_A[0]}");
Console.WriteLine($"ref_B[0]: {ref_B[0]}");
Output
--Reference Types--
ref_A[0]: 5
ref_B[0]: 5

ตอน ref_B = ref_A ทำงาน ref_B จะชี้ไปยัง memory location เดียวกัน กับ ref_A ดังนั้นเมื่อ ref_B[0] ถูกเปลี่ยน ref_A[0] ก็เปลี่ยนตามไปด้วย เพราะทั้งคู่ชี้ไปยัง memory location เดียวกัน — นี่คือความแตกต่างสำคัญ ระหว่าง value type กับ reference type

⚠️ กับดักที่พบบ่อยที่สุดของมือใหม่เรื่อง reference type หลายคนคาดว่า ref_B = ref_A จะ "ก็อปปี้" array เหมือนตอนก็อปปี้ int แต่ไม่ใช่เลย — มันแค่ก็อปปี้ memory address ทำให้ตัวแปรทั้งสองชี้ไปยัง array ตัวเดียวกัน ถ้าต้องการ array คนละชุดจริงๆ ต้องสร้าง new int[...] แยกกันชัดเจน แล้วก็อปปี้ element ทีละตัว (เช่นด้วย foreach) ไม่ใช่แค่กำหนดตัวแปรเท่ากัน

Check ★ ใน C# ตอนใช้คีย์เวิร์ด new สร้าง instance ของ class หนึ่งตัว หน่วยความจำถูกจัดสรรที่ไหน?

  • AStack
  • BHeap
  • CVariable
เฉลย: ข้อ B. class เป็น reference type เสมอ instance ของมันถูกเก็บใน heap ตัวแปรบน stack เก็บแค่ memory address ที่ชี้ไปยัง heap เท่านั้น

21.6 เลือก Data Type ให้ถูกต้อง

คุณรู้จักความแตกต่างระหว่าง value type กับ reference type แล้ว รวมถึง integral กับ floating-point type ด้วย สมมติงานของคุณคือสร้างแอปใหม่ที่ ดึง จัดการ และเก็บข้อมูลหลายชนิด — คุณจะใช้ data type ไหน?

บางกรณีก็เลือกง่าย เช่น เวลาทำงานกับข้อความ คุณมักใช้ string เป็นค่า default เว้นแต่ต้องทำการต่อ string (concatenation) จำนวนมาก แต่แล้วข้อมูลตัวเลขล่ะ มีตัวเลือกถึง 11 แบบ จะเลือก data type ที่ถูกต้องได้ยังไง?

เลือก Data Type ที่ตรงกับช่วงค่าที่แอปต้องการ

การเลือก data type ช่วยกำหนดขอบเขตขนาดข้อมูลที่คุณจะเก็บในตัวแปรนั้นได้ ตัวอย่างเช่น ถ้ารู้ว่า ตัวแปรหนึ่งควรเก็บแค่ตัวเลขระหว่าง 1 ถึง 10,000 (นอกเหนือจากนี้ถือว่าผิดขอบเขตที่คาดไว้) คุณ มักหลีกเลี่ยง byte และ sbyte เพราะช่วงค่าของมันต่ำเกินไป

ยิ่งไปกว่านั้น คุณอาจไม่ต้องการ int, long, uint, และ ulong เพราะเก็บข้อมูลได้มากเกินความจำเป็น เช่นเดียวกัน คุณอาจข้าม float, double, และ decimal ถ้าไม่ต้องการค่าทศนิยม คุณอาจเลือกเหลือแค่ short กับ ushort ซึ่งทั้งคู่ก็ใช้ได้ ถ้ามั่นใจ ว่าค่าติดลบไม่มีความหมายในแอปของคุณ อาจเลือก ushort (จำนวนเต็มบวกไม่มีเครื่องหมาย 0 ถึง 65,535) ตอนนี้ ค่าใดๆ ที่กำหนดให้ตัวแปรชนิด ushort ที่อยู่นอกขอบเขต 0 ถึง 65535 จะ throw exception ทันที ซึ่งช่วยบังคับให้เกิดการตรวจสอบความสมเหตุสมผลในแอปของคุณโดย ปริยาย

เลือก Data Type ให้เหมาะกับข้อมูล (ไม่ใช่เพื่อ optimize performance)

คุณอาจถูกล่อใจให้เลือก data type ที่ใช้ bit น้อยที่สุดในการเก็บข้อมูล คิดว่าจะช่วยเพิ่ม performance ของแอป แต่คำแนะนำที่ดีที่สุดข้อหนึ่งเกี่ยวกับ performance ของแอป (คือแอปทำงานเร็ว แค่ไหน) คือ อย่า "optimize ก่อนเวลาอันควร" (premature optimization) คุณควรอดใจไม่เดาว่าส่วน ไหนของโค้ด รวมถึงการเลือก data type จะกระทบ performance

หลายคนคิดว่า data type ที่เก็บข้อมูลน้อยกว่าต้องใช้ CPU และหน่วยความจำน้อยกว่า data type ที่ เก็บข้อมูลมากกว่าเสมอ แต่ที่จริงคุณควรเลือกให้เหมาะกับข้อมูลก่อน แล้วค่อยวัด performance ของ แอปด้วยซอฟต์แวร์เฉพาะทางที่ให้ข้อมูลเชิงประจักษ์เกี่ยวกับส่วนที่กระทบ performance จริงๆ ในภายหลัง

เลือก Data Type ตาม Input/Output ของ Library Function ที่ใช้

สมมติคุณต้องทำงานกับช่วงปีระหว่างสองวันที่ เพราะแอปเป็นแอปธุรกิจ คุณอาจตัดสินใจว่าต้องการแค่ ช่วงตั้งแต่ปี 1960 ถึง 2200 คุณอาจคิดจะใช้ byte เพราะแทนค่าได้ 0-255

แต่พอดูเมธอด built-in บน class System.TimeSpan และ System.DateTime คุณจะพบว่าส่วนใหญ่รับค่าชนิด double และ int ถ้าคุณเลือก sbyte คุณจะต้อง cast ไปมาระหว่าง byte กับ double หรือ int ตลอดเวลา ในกรณีนี้ เลือก int ถ้าไม่ต้องการความละเอียดระดับ เสี้ยววินาที และเลือก double ถ้าต้องการ อาจสมเหตุสมผลกว่า

เลือก Data Type ตามผลกระทบต่อระบบอื่น

บางครั้งคุณต้องพิจารณาว่าข้อมูลจะถูกใช้โดยแอปหรือระบบอื่นยังไง เช่นฐานข้อมูล ตัวอย่างเช่น ระบบ type ของ SQL Server ต่างจากระบบ type ของ C# ผลก็คือต้องมีการ mapping ระหว่างสองระบบก่อน จะบันทึกข้อมูลลงฐานข้อมูลได้

ถ้าจุดประสงค์ของแอปคือเชื่อมต่อกับฐานข้อมูล คุณต้องพิจารณาว่าข้อมูลถูกเก็บยังไงและมากแค่ไหน การเลือก data type ที่ใหญ่กว่าอาจกระทบปริมาณ (และค่าใช้จ่าย) ของพื้นที่จัดเก็บทางกายภาพที่ ต้องใช้เก็บข้อมูลทั้งหมดที่แอปของคุณสร้างขึ้น

เมื่อไม่แน่ใจ ให้ยึดพื้นฐาน

แม้จะพิจารณาหลายเรื่องแล้ว แต่ตอนเริ่มต้น เพื่อความง่าย คุณควรเลือกใช้ data type พื้นฐานกลุ่ม เล็กๆ ก่อน:

  • int สำหรับตัวเลขจำนวนเต็มส่วนใหญ่
  • decimal สำหรับตัวเลขที่แทนเงิน
  • bool สำหรับค่า true/false
  • string สำหรับค่าตัวอักษร/ตัวเลขผสม

เลือก Complex Type เฉพาะทางสำหรับสถานการณ์พิเศษ

อย่าคิดค้น data type ใหม่ ถ้ามี data type ที่มีอยู่แล้วสำหรับจุดประสงค์นั้น ตัวอย่าง .NET data type เฉพาะทางที่มีประโยชน์:

  • byte: ทำงานกับข้อมูลที่ถูก encode มาจากระบบคอมพิวเตอร์อื่น หรือใช้ character set ต่างกัน
  • double: ใช้กับงานเรขาคณิตหรือวิทยาศาสตร์ — double ถูกใช้บ่อยตอน สร้างเกมที่เกี่ยวกับการเคลื่อนไหว
  • System.DateTime สำหรับค่าวันที่และเวลาที่เจาะจง
  • System.TimeSpan สำหรับช่วงเวลา ปี/เดือน/วัน/ชั่วโมง/นาที/วินาที/มิลลิวินาที

21.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
ใช้ float หรือ double คำนวณเงิน แล้วผลรวมเพี้ยนไปนิดหน่อย (เช่น 0.1 + 0.2 ≠ 0.3 พอดี) float/double เก็บค่าแบบฐาน 2 ซึ่งแทนเศษส่วนฐาน 10 บางค่าไม่ได้แม่นยำ 100% ต้องใช้ decimal กับข้อมูลการเงินเสมอ
คิดว่าก็อปปี้ array ด้วย arr2 = arr1; แล้วแก้ arr2 ไม่กระทบ arr1 array เป็น reference type — การกำหนดค่าแบบนี้แค่ก็อปปี้ address ทั้งสองตัวแปรชี้ไปยัง array ตัวเดียวกัน ถ้าต้องการ array แยกจริงๆ ต้องสร้าง new แล้วก็อปปี้ element ทีละตัว
OverflowException ตอนกำหนดค่าเกินขอบเขตให้ตัวแปรชนิด byte/short/ushort เป็นพฤติกรรมที่ถูกต้อง (ไม่ใช่บั๊ก) — ค่าที่เกินช่วง MinValue-MaxValue ของ type นั้น ทำให้เกิด exception ตามที่ตั้งใจ (ใช้เป็นการ sanity-check โดยปริยายได้)
เลือก byte/sbyte เพราะคิดว่า "เล็กกว่า เร็วกว่า" ทั้งที่ข้อมูลจริงอาจเกินขอบเขต อย่า optimize ก่อนเวลาอันควร — เลือก data type ให้พอดีกับข้อมูลก่อน ไม่ใช่เพื่อ performance ที่ยังไม่ได้วัดจริง

  • Cint
เฉลย: ข้อ C. เป็นตัวเลขจำนวนเต็ม (whole number) ไม่มีเศษ ไม่จำเป็นต้อง ใช้ floating-point type เลย int ครอบคลุมช่วง ±1,000,000 ได้สบายๆ (ช่วงจริงของ int คือ ±2.1 พันล้าน) และเป็นตัวเลือกที่เหมาะสมที่สุดตามหลัก "เมื่อไม่แน่ใจ ให้ยึดพื้นฐาน"

2. โค้ดของเกมต้องเก็บค่าทศนิยมจำนวนมากที่แทนตำแหน่ง x, y, z ในพื้นที่ 3 มิติขนาดใหญ่ น่าจะต้องคำนวณฟิสิกส์เรื่องวิถีการเคลื่อนที่ต่างๆ ไม่จำเป็น ต้องแม่นยำสมบูรณ์แบบ แต่สำคัญที่โปรแกรมต้องทำงานได้อย่างมีประสิทธิภาพที่สุด data type ไหน ดีที่สุด?

  • Afloat
  • Bdecimal
  • Cint
เฉลย: ข้อ A. ค่าตำแหน่งเป็นทศนิยม (int ตัดออก) ไม่ต้องการความแม่นยำ สมบูรณ์แบบและเน้นประสิทธิภาพ (ตัดการใช้ decimal ที่แม่นยำแต่หนักและช้ากว่าออก) float ใช้ หน่วยความจำน้อยกว่า double (4 byte เทียบ 8 byte) เหมาะกับค่าจำนวนมากในพื้นที่ 3 มิติที่เน้น ความเร็วมากกว่าความละเอียด

3. ข้อความใดต่อไปนี้ ถูกต้อง?

  • AReference type ถูกเก็บใน stack
  • BValue type เก็บได้แค่ตัวเลขเท่านั้น
  • Cใช้ตัวดำเนินการ new สร้าง instance ใหม่ของ reference type แล้วคืน address ของมันให้ตัวแปร
เฉลย: ข้อ C. ตรงกับหัวข้อ 21.5b ทุกประการ ข้อ A ผิดเพราะ reference type ถูกเก็บใน heap (ตัวแปรบน stack เก็บแค่ address) ข้อ B ผิดเพราะ value type มีทั้ง bool, char, และ struct อื่นๆ ที่ไม่ใช่ตัวเลข ไม่ใช่แค่ตัวเลข เท่านั้น

21.9 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

เขียนโค้ดพิมพ์ MinValue และ MaxValue ของ char (ใบ้: char ก็มี MinValue/MaxValue เหมือน numeric type)

ดูเฉลย
Program.cs
Console.WriteLine($"char: {(int)char.MinValue} to {(int)char.MaxValue}");

ต้อง cast เป็น (int) ก่อนพิมพ์ ไม่งั้นจะได้ตัวอักษรที่มองไม่เห็น (control character) แทนที่จะเห็นตัวเลข

ข้อ 2ง่าย

ตอบคำถามสั้นๆ: ตัวแปรที่เก็บ "อายุของคน" (0-120 ปี) ควรใช้ data type ไหนในกลุ่ม integral ที่ประหยัดหน่วยความจำที่สุด ตามเกณฑ์หัวข้อ 21.6a?

ดูเฉลย

byte (0-255) ครอบคลุมช่วง 0-120 ได้พอดีและประหยัดที่สุดในบรรดา integral type ทั้งหมด — แต่ในทางปฏิบัติ นักพัฒนาส่วนใหญ่มักเลือก int อยู่ดีตามหลัก "เมื่อไม่แน่ใจ ให้ยึดพื้นฐาน" (หัวข้อ 21.6e) เว้นแต่มีเหตุผลเฉพาะเจาะจงจริงๆ ที่ต้อง ประหยัดหน่วยความจำ (เช่น เก็บอายุคนนับล้านคนพร้อมกัน)

ข้อ 3กลาง

เขียนโค้ดสร้าง int[] scores = new int[3]; กำหนดค่า scores[0] = 10; จากนั้นสร้างตัวแปรใหม่ backup ที่เป็น array แยกจาก scores จริงๆ (แก้ backup ไม่กระทบ scores) โดยก็อปปี้ค่าทีละ element ด้วย for loop (ห้ามใช้ backup = scores; ตรงๆ)

ดูเฉลย
Program.cs
int[] scores = new int[3];
scores[0] = 10;

int[] backup = new int[scores.Length];
for (int i = 0; i < scores.Length; i++)
{
    backup[i] = scores[i];
}

backup[0] = 999;

Console.WriteLine($"scores[0]: {scores[0]}");
Console.WriteLine($"backup[0]: {backup[0]}");

ผลลัพธ์: scores[0]: 10 และ backup[0]: 999 — เพราะ backup เป็น array คนละตัวที่มี memory address ของตัวเอง แม้เนื้อหาข้างใน จะเหมือนกันตอนแรกก็ตาม

ข้อ 4กลาง

เขียนโค้ดที่พยายามกำหนดค่า 300 ให้ตัวแปรชนิด byte แล้วอธิบายว่า เกิดอะไรขึ้นและทำไม (ทบทวนหัวข้อ 21.3b)

ดูเฉลย
Program.cs (compile error)
byte myByte = 300;

เกิด compile-time error: error CS0031: Constant value '300' cannot be converted to a 'byte' — เพราะ byte เก็บได้แค่ 0-255 เท่านั้น 300 อยู่นอก ขอบเขตนี้ นี่คือตัวอย่างของ "sanity checking โดยปริยาย" ที่หัวข้อ 21.6a พูดถึง — compiler จับปัญหานี้ให้คุณตั้งแต่ก่อนรันโปรแกรมด้วยซ้ำ

ข้อ 5ยาก

เขียนโค้ดเปรียบเทียบผลบวก 0.1f + 0.2f (float) กับ 0.1m + 0.2m (decimal — ใส่ m suffix บอกว่าเป็น decimal literal) แล้วพิมพ์ทั้งสองผลลัพธ์ ออกมา สังเกตความต่าง

ดูเฉลย
Program.cs 
float floatResult = 0.1f + 0.2f;
decimal decimalResult = 0.1m + 0.2m;

Console.WriteLine($"float:   {floatResult}");
Console.WriteLine($"decimal: {decimalResult}");
float:   0.3
decimal: 0.3

ในกรณีนี้ C# ปัด float ให้แสดงเป็น 0.3 พอดีตอน WriteLine (เพราะ default formatting ปัดตำแหน่งที่ไม่มีนัยสำคัญออก) แต่ถ้าเทียบค่าด้วย == แบบตรงๆ หรือคำนวณต่อหลายรอบ ความคลาดเคลื่อนเล็กๆ ของ float จะเริ่มสะสมและแสดงผลชัดขึ้น เรื่อยๆ นี่คือเหตุผลที่ควรใช้ decimal กับการคำนวณการเงินเสมอ ไม่ใช่ float/double

ข้อ 6ท้าทาย

ให้เหตุผลว่าทำไม System.DateTime และ System.TimeSpan (จาก หัวข้อ 21.6f) น่าจะเป็น reference type หรือ value type — ลองเดาจาก พฤติกรรมที่คุณคาดหวังตอนใช้งานจริง (เช่น ก็อปปี้ตัวแปรวันที่แล้วแก้ค่า ควรกระทบตัวต้นฉบับ หรือไม่) แล้วถ้าอยากได้คำตอบจริง ลองค้นหา "C# DateTime struct" ดู

ดูเฉลย

DateTime และ TimeSpan เป็น value type (โดยเฉพาะเป็น struct — โครงสร้างข้อมูลชนิดหนึ่งที่ยังไม่ได้เรียนในบทนี้) เหตุผลเชิง ปฏิบัติ: ถ้าคุณก็อปปี้ตัวแปร DateTime ไปอีกตัวแล้วแก้ไขค่าใหม่ (เช่น เปลี่ยนวันที่) คุณคงไม่อยากให้ตัวแปรต้นฉบับเปลี่ยนตามไปด้วยโดยไม่ตั้งใจ — พฤติกรรมแบบ "ก็อปปี้ค่าจริง แยกกันเด็ดขาด" แบบ value type จึงเหมาะกับแนวคิดของวันที่/เวลามากกว่า พฤติกรรมแบบ reference type ที่ใช้ "ชี้ตำแหน่งเดียวกัน"

📌 สรุปบทที่ 21

การเลือก data type ที่ถูกต้องสำหรับแอปของคุณเป็นทักษะการเขียนโปรแกรมที่สำคัญมาก เป้าหมายของ คุณคือเข้าใจความแตกต่างระหว่าง data type แต่ละตัว เพื่อตัดสินใจเลือก data type ในโค้ดของคุณ ได้อย่างมีข้อมูลรองรับ

คุณเริ่มสร้างแบบจำลองทางความคิดว่าข้อมูลถูกเก็บยังไงตอนแอปของคุณทำงาน คุณมีประสบการณ์ทำงานกับ integral และ floating point data type ใหม่ๆ คุณมีเกณฑ์ที่ใช้ตัดสินใจว่าจะเลือก data type ไหนในโค้ดของคุณ และสุดท้าย คุณเข้าใจว่าทำไมต้องใช้คีย์เวิร์ด new ตอนสร้าง instance ของ reference type
