เรียกใช้เมธอดจาก .NET Class Library

Call Methods From the .NET Class Library Using C#

8.1 ทำไมต้องรู้จัก .NET Class Library

ภาษา C# มาพร้อมกับคลังฟังก์ชันสำเร็จรูปขนาดใหญ่ ที่ช่วยให้คุณสร้างแอป เข้าถึงข้อมูลจากไฟล์ หรืออินเทอร์เน็ต ทำการคำนวณทางคณิตศาสตร์ขั้นสูง และอีกมากมาย การรู้จักนำทางคลังฟังก์ชันนี้ เป็นทักษะสำคัญที่ช่วยให้คุณสร้างแอปที่มีฟีเจอร์เยอะได้เร็วขึ้นมาก

สมมติคุณต้องสร้างรายงานประจำวันจากไฟล์ข้อมูลนับพันไฟล์ เพื่อประหยัดเวลา โค้ดของคุณสุ่ม เลือกไฟล์บางส่วนมาคำนวณผลประมาณแทนที่จะวิเคราะห์ทุกไฟล์ จะสุ่มตัวเลขได้ยังไง? C# รองรับไหม? ถ้ารองรับ จะกำหนดช่วงค่า สุ่ม แล้วดึงผลลัพธ์ออกมาได้ยังไง?

ในบทนี้คุณจะเรียนเรื่องคลาสไลบรารี เขียนโค้ดเรียกเมธอดใน .NET Class Library เรียนรู้ว่า เมธอดมีคุณสมบัติยังไง และทำไมเมธอดใน .NET Class Library ถึงถูกออกแบบต่างกันไปในแต่ละส่วน ที่สำคัญที่สุด คุณจะเขียนโค้ดใช้เมธอดของไลบรารีเพื่อทำงานเฉพาะให้สำเร็จ และใช้เครื่องมือ ในตัวกับเอกสารออนไลน์ช่วยหาข้อมูลเมธอดที่ต้องการ

8.2 รู้จัก .NET Class Library

การสร้างแอป C# ไม่ใช่แค่เรียงบรรทัดโค้ดต่อกัน คุณต้องพึ่ง .NET Runtime ที่โฮสต์และ จัดการโค้ดของคุณตอนรันบนเครื่องผู้ใช้ และพึ่ง .NET Class Library คลังทรัพยากรโค้ด สำเร็จรูปที่ใช้ในแอปของคุณได้เลย

.NET Class Library คืออะไร

เวลาต้องการหาหนังสือ ห้องสมุดสาธารณะคือที่ที่ดีในการมองหา เพราะมีหนังสือเป็นพันเป็นหมื่น เล่ม จัดหมวดหมู่ไว้ช่วยให้หาเจอง่าย เวลาต้องทำงานเขียนโปรแกรมบางอย่าง .NET Class Library ก็เป็นที่ที่ดีในการมองหาเช่นกัน เพราะเป็นคลังทรัพยากรโปรแกรมมิ่งที่จัดระเบียบไว้อย่างดี

.NET Class Library คือกลุ่มคลาสนับพันคลาส ที่รวมเมธอดนับหมื่นเมธอดไว้ข้างใน เช่น คลาส Console สำหรับนักพัฒนาที่ทำแอป console มีเมธอดสำหรับรับ-ส่งข้อมูลอย่าง Write(), WriteLine(), Read(), ReadLine() และอื่นๆ — คุณคุ้นเคยกับโค้ดแบบนี้อยู่แล้ว: Console.WriteLine("Hello, World!")

คิดว่าคลาสคือ "ภาชนะ" เก็บเมธอด เหมือนหมวดหมู่ในห้องสมุด นักพัฒนามักเก็บเมธอดที่เกี่ยวข้อง กันไว้ในคลาสเดียวกัน อย่างที่เห็น เมธอดที่รับ-ส่งข้อมูลกับหน้าต่างคอนโซล ถูกรวมอยู่ในคลาส System.Console

บางคลาสช่วยให้สร้างแอปเฉพาะแบบได้ เช่น เว็บแอปแบบไดนามิก แอปเดสก์ท็อป หรือเชื่อมต่อฐานข้อมูล บางคลาสก็เป็นเครื่องมือทั่วไปที่ใช้ได้กับทุกแพลตฟอร์ม เช่น อ่าน/เขียนไฟล์ หรือคำนวณตรีโกณมิติ/ แคลคูลัส — ไม่ว่าจะสร้างแอปสำหรับเว็บ เดสก์ท็อป มือถือ หรือคลาวด์ ก็มีคลาสรองรับ

แม้แต่ชนิดข้อมูลก็เป็นส่วนหนึ่งของ .NET Class Library

ชนิดข้อมูล C# อย่าง string และ int จริงๆ แล้วก็มาจากคลาสใน .NET Class Library เช่นกัน — ภาษา C# แค่ซ่อนความเชื่อมโยงนี้ไว้เพื่อให้ใช้งานง่ายขึ้น เบื้องหลังชนิดข้อมูลถูกสร้างเหมือนคลาสอื่นๆ ทุกประการ ทำให้ตัวแปรธรรมดาของคุณมีเมธอด สำเร็จรูปในตัวด้วย เช่น คลาส string มีเมธอดแปลงเป็นตัวพิมพ์ใหญ่/เล็ก (ToUpper, ToLower)

หาสิ่งที่ต้องการใน .NET Class Library ยังไง

คลาสและเมธอดมีเยอะมาก จะหาสิ่งที่ต้องการเจอได้ยังไง?

  1. ไม่จำเป็นต้องรู้ทุกอย่าง — เหมือนไม่มีใครอ่านหนังสือครบทุกเล่มในห้องสมุด คุณจะคุ้นเคยกับบางส่วนมากกว่าส่วนอื่นตามประเภทโปรเจกต์ที่ทำ แม้แต่คนที่ทำงานที่ Microsoft ก็ไม่มีใครรู้ทุกอย่างใน .NET Class Library
  2. ความจำเป็นจะพาไปเจอเอง — คนไปห้องสมุดตอนต้องการหาหนังสือ ไม่ใช่ไปดูว่าหาเจอกี่เล่ม ใช้เสิร์ชเอนจินหาบทความ บล็อก หรือฟอรัมที่นักพัฒนาคนอื่นเคยเจอปัญหาคล้ายกันได้
  3. เอกสารอ้างอิงของ Microsoft — มีคู่มืออ้างอิงภาษาและการเขียนโปรแกรม C# ให้ค้นหาได้ ทีมเอกสารทำงานใกล้ชิดกับทีมพัฒนา .NET Class Library เพื่อความแม่นยำ นี่คือ "แหล่งความจริง (source of truth)"
  4. ทดลองทำโปรเจกต์เล็กๆ — ยิ่งลองมาก ยิ่งเข้าใจลึกว่าคลาส/เมธอดทำงานยังไง

นักพัฒนาทุกคนใช้กระบวนการคล้ายกันนี้เวลาเข้าสู่พื้นที่ที่ไม่คุ้นเคย — เป็นกระบวนการค้นพบ ที่สนุก แม้จะท้าทายก็ตาม

Check ★ หาข้อมูลเกี่ยวกับคลาส/เมธอด .NET ที่กำลังใช้ได้จากที่ไหน?

  • A.NET Class Library เอกสารอย่างเดียว
  • Bเว็บไซต์ของนักพัฒนาอย่างเดียว
  • Cเอกสาร .NET Class Library, การค้นหาผ่าน Google, และเว็บไซต์นักพัฒนา
เฉลย: ข้อ C. ควรใช้ทั้ง 3 แหล่งประกอบกัน — เอกสารทางการเป็น source of truth ส่วนบล็อก/ฟอรัมช่วยให้เห็นตัวอย่างการใช้งานจริงจากปัญหาที่คนอื่นเคยเจอ

8.3 ลงมือ: เรียกใช้เมธอดของคลาสใน .NET

ตั้งแต่แอป "Hello, World!" แอปแรก คุณก็เรียกเมธอด C# มาตลอดโดยไม่รู้ตัว — แอปนั้นใช้ เมธอด WriteLine() ของคลาส Console แต่ไม่ใช่ทุกคลาส/เมธอดจะถูก implement แบบเดียวกัน หัวข้อนี้จะพาดูรูปแบบที่พบบ่อยที่สุด

วิธีเรียกเมธอดใน .NET Class Library

จากประสบการณ์กับ Console.WriteLine() คุณรู้พื้นฐานอยู่แล้ว:

  • พิมพ์ชื่อคลาส — ในที่นี้คือ Console
  • ใส่ตัวเชื่อมเข้าถึงสมาชิก — เครื่องหมาย .
  • ใส่ชื่อเมธอด — ในที่นี้คือ WriteLine
  • ใส่ตัวเรียกใช้เมธอด — วงเล็บ ()
  • ระบุอาร์กิวเมนต์ (ถ้ามี) ในวงเล็บ

เตรียมโปรเจกต์

เปิด VS Code → File → Open Folder → เลือกโฟลเดอร์ CsharpProjects (ที่สร้างไว้ตั้งแต่บทที่ 7) → เปิด Terminal → สร้างโปรเจกต์ใหม่สำหรับบทนี้:

Terminal 
dotnet new console -o ch08-methods

เปิดโฟลเดอร์ ch08-methods เลือก Program.cs แล้วลบโค้ดเดิมทั้งหมด ทำแบบนี้ทุกครั้งที่บทนี้บอกให้ "ลบโค้ดเดิม แล้วพิมพ์ใหม่" ตลอดทั้งบท

เรียกใช้เมธอดหลายแบบ

พิมพ์โค้ดจำลองการทอยลูกเต๋า:

Program.cs 
Random dice = new Random();
int roll = dice.Next(1, 7);
Console.WriteLine(roll);
Output (ค่าสุ่มระหว่าง 1-6 ทุกครั้งที่รัน)
4

Save แล้วคลิกขวาโฟลเดอร์ ch08-methods เลือก Open in Integrated Terminal รัน dotnet run — จะเห็นเลข 1 ถึง 6 (แต้มลูกเต๋า) แบบสุ่มทุกครั้งที่รัน

สังเกตว่าโค้ดใช้เทคนิคเข้าถึงเมธอด ต่างกัน ระหว่าง dice.Next(1, 7) กับ Console.WriteLine(roll) — เพราะเมธอดบางตัว "มีสถานะ (stateful)" บางตัว "ไม่มีสถานะ (stateless)"

Stateful กับ Stateless เมธอด

ในงานพัฒนาซอฟต์แวร์ คำว่า state (สถานะ) หมายถึงสภาพของสภาพแวดล้อมการทำงาน ณ ขณะใด ขณะหนึ่ง ขณะโค้ดรันไปทีละบรรทัด ค่าต่างๆ ถูกเก็บในตัวแปร สถานะปัจจุบันของแอปคือ ค่าทั้งหมดที่ถูกเก็บไว้ในหน่วยความจำ ณ ตอนนั้น

เมธอดบางตัวไม่พึ่งสถานะของแอปเลยก็ทำงานได้ เรียกว่า stateless method (หรือ static method) เช่น Console.WriteLine() ไม่พึ่งค่าใดๆ ในหน่วยความจำ ทำงานเสร็จโดยไม่กระทบสถานะแอปเลย

เมธอดอื่นๆ ต้องเข้าถึงสถานะของแอปถึงจะทำงานถูกต้อง เรียกว่า stateful method (หรือ instance method) — สร้างขึ้นให้พึ่งค่าที่บรรทัดก่อนหน้าเก็บไว้ในหน่วยความจำ หรือ แก้ไขสถานะโดยอัปเดต/เก็บค่าใหม่ เมธอดแบบ stateful เก็บสถานะไว้ใน field ซึ่งเป็นตัวแปรที่นิยามไว้บนคลาส แต่ละ instance ใหม่ของคลาสจะได้สำเนา field ของตัวเอง ไว้เก็บสถานะ

คลาสเดียวรองรับได้ทั้งเมธอดแบบ stateful และ stateless แต่เวลาเรียกเมธอด stateful ต้องสร้าง instance ของคลาสก่อนเสมอ ถึงจะให้เมธอดเข้าถึงสถานะได้

สร้าง Instance ของคลาส

instance ของคลาสเรียกว่า object การสร้าง instance ใหม่ ใช้ตัวดำเนินการ new:

Program.cs
Random dice = new Random();

จากนั้นทุกครั้งที่โค้ดอ้างอิงถึง object dice .NET Runtime จะค้นหาเบื้องหลังให้ เสมือนคุณทำงานกับ object นั้นตรงๆ โค้ดของคุณใช้ dice เหมือนตัวแปรที่เก็บสถานะ ของคลาส Random พอเรียก Next() บน dice เมธอดจะใช้ สถานะที่เก็บไว้ในนั้นสร้างเลขสุ่ม

ℹ️ ทางลัดสร้าง instance (.NET รุ่นใหม่) .NET รุ่นล่าสุดให้สร้าง instance โดยไม่ต้องพิมพ์ชื่อชนิดซ้ำได้ (target-typed constructor invocation) เช่น Random dice = new(); ก็สร้าง instance ของ Random ได้เหมือนกัน — เพื่อให้อ่านง่ายขึ้น ต้องมีวงเล็บเสมอเวลาเขียนแบบนี้

ทำไม Next() ต้องมีสถานะ

คอมพิวเตอร์เก่งเรื่องทำตามคำสั่งเป๊ะๆ เพื่อให้ได้ผลลัพธ์ที่คาดเดาได้และทำซ้ำได้เหมือนเดิม เพื่อสร้างภาพลวงตาของความสุ่ม ผู้พัฒนาเมธอด Next() เลือกจับเวลาวันที่/เวลา ละเอียดถึงเสี้ยวมิลลิวินาที มาใช้เป็น seed ป้อนอัลกอริทึมที่สร้างเลขต่างกันทุกครั้ง แม้จะ ไม่สุ่มแท้ๆ 100% แต่ก็เพียงพอสำหรับแอปส่วนใหญ่ สถานะที่ถูกเก็บและคงอยู่ตลอดอายุของ object dice คือค่า seed นี้เอง

ไม่จำเป็นต้องเข้าใจกลไกเบื้องหลังก็ใช้ Random.Next() ได้ สิ่งสำคัญคือรู้ว่า เมธอดบางตัวต้องสร้าง instance ก่อนเรียก บางตัวไม่ต้อง

รู้ได้ยังไงว่าเมธอดไหนต้องสร้าง instance ก่อน

วิธีหนึ่งคือดูเอกสาร ซึ่งจะมีตัวอย่างโค้ดบอกว่าต้องเรียกจาก instance หรือเรียกจากคลาสตรงๆ อีกวิธีคือลองเข้าถึงเมธอดจากชื่อคลาสตรงๆ ดูเลย — ถ้าใช้ได้ แปลว่า stateless ถ้าใช้ไม่ได้ แย่สุดก็แค่เจอ compile error

Program.cs — ลองผิดดูก่อน
int result = Random.Next();
Output
(1,14): error CS0120: An object reference is required for the non-static field, method, or property 'Random.Next()'

error นี้ยืนยันว่า Next() เป็น stateful ต้องสร้าง instance ก่อนถึงจะเรียกได้:

Program.cs — แก้ถูกต้อง 
Random dice = new Random();
int roll = dice.Next();

Check ★ ข้อใดสร้าง instance ของคลาสได้ถูกต้อง?

  • ARandom dice = new Random.Next();
  • BRandom dice = new Random();
  • CString dice = new Random();
เฉลย: ข้อ B. ข้อ A ผิดเพราะเอา new ไปวางหน้าการเรียกเมธอด แทนที่จะเรียก constructor ของคลาส ข้อ C ผิดเพราะกำหนดชนิดตัวแปรกับ instance ที่สร้าง คนละชนิดกัน (String ≠ Random)

Check ★ สมมติสร้าง instance ของ Random ชื่อ coins แล้ว จะเรียก Next() ยังไง?

  • Aint money = new coins.Next();
  • Bint money = Random.Next();
  • Cint money = coins.Next();
เฉลย: ข้อ C. เรียกผ่านชื่อ instance ตรงๆ ไม่ต้องมี new ซ้ำอีก (instance สร้างไปแล้วครั้งเดียวตอนประกาศ) ข้อ B ผิดเพราะ Next() เป็น stateful เรียกจากชื่อคลาสตรงๆ ไม่ได้

8.4 ลงมือ: Return Value และ Parameter ของเมธอด

สถานการณ์ทอยลูกเต๋ายังสอนแนวคิดสำคัญอื่นๆ ได้อีก: การจัดการค่าที่เมธอดคืนกลับมา พารามิเตอร์ของเมธอดและการส่งอาร์กิวเมนต์ และการเลือกเมธอด overload

Return Value (ค่าที่คืนกลับ)

บางเมธอดทำงานเสร็จแล้ว "เงียบๆ" ไม่คืนค่าอะไรกลับมา เรียกว่า void method บางเมธอด ถูกออกแบบให้คืนค่าเมื่อทำงานเสร็จ — ค่าที่คืนมักเป็นผลลัพธ์ของการดำเนินการ เป็นวิธีหลัก ที่เมธอดใช้สื่อสารกลับมายังโค้ดที่เรียกมัน

Random.Next() คืนค่าชนิด int ที่เป็นเลขสุ่ม แต่เมธอดออกแบบให้ คืนค่าชนิดไหนก็ได้ แม้แต่คลาสอื่นก็คืนได้ เช่น คลาส String มีทั้งเมธอดที่คืน string, int, และ bool

เวลาเรียกเมธอดที่คืนค่า มักจะเก็บค่าไว้ในตัวแปรเพื่อใช้ทีหลัง:

Program.cs
int roll = dice.Next(1, 7);

หรือใช้ค่าที่คืนโดยตรง ไม่ต้องเก็บลงตัวแปร:

Program.cs
Console.WriteLine(dice.Next(1, 7));

แม้เมธอดจะคืนค่า ก็เรียกโดยไม่สนใจค่าที่คืนได้เช่นกัน (แต่ในกรณีนี้ก็ไม่มีประโยชน์อะไร เพราะจุดประสงค์การเรียก Next() ก็เพื่อเอาค่าที่สุ่มได้มาใช้):

Program.cs
dice.Next(1, 7);

Parameter กับ Argument

เวลาเรียกเมธอด คุณส่งค่าเข้าไปให้เมธอดใช้ทำงานได้ ค่าที่ส่งเข้าไปเรียกว่า argument (อาร์กิวเมนต์) เมธอดใช้อาร์กิวเมนต์กำหนดค่าให้ parameter (พารามิเตอร์) ที่นิยาม ไว้ใน method signature ของมัน เมธอดหนึ่งอาจต้องการพารามิเตอร์หนึ่งหรือหลายตัว หรือไม่ต้องการ เลยก็ได้

ℹ️ สองคำนี้มักใช้แทนกัน แต่จริงๆ ต่างกัน parameter คือตัวแปรที่ถูกใช้ข้างในเมธอด (นิยามใน signature) — argument คือค่าที่ถูกส่งเข้าไปตอนเรียกเมธอด

เมธอดส่วนใหญ่ถูกออกแบบให้รับพารามิเตอร์หนึ่งหรือหลายตัว บางตัวใช้พารามิเตอร์กำหนดวิธีทำงาน บางตัวก็นำพารามิเตอร์ไปใช้ตรงๆ เช่น Random.Next() ใช้พารามิเตอร์กำหนดขอบเขต บนล่างของค่าที่คืน ส่วน Console.WriteLine() ใช้พารามิเตอร์ตรงๆ โดยพิมพ์ค่า นั้นออกคอนโซล

เมธอดใช้ method signature กำหนดจำนวนและชนิดข้อมูลของพารามิเตอร์ที่รับ คำสั่งที่เรียก เมธอดต้องตรงตามข้อกำหนดของ signature นั้น ผู้เรียกต้องส่งอาร์กิวเมนต์ที่เข้ากันได้กับชนิด พารามิเตอร์ (ชื่อของอาร์กิวเมนต์ไม่จำเป็นต้องตรงกับชื่อพารามิเตอร์)

Program.cs
Random dice = new Random();
int roll = dice.Next(1, 7);
Console.WriteLine(roll);

บรรทัดแรกสร้าง instance ชื่อ dice บรรทัดที่สองใช้ dice.Next(1, 7) กำหนดค่าสุ่มให้ roll — สังเกตว่าส่งอาร์กิวเมนต์ 2 ตัวคั่นด้วย , method signature ของ Next() เวอร์ชันนี้รับพารามิเตอร์ 2 ตัวชนิด int ใช้กำหนด ขอบเขตล่าง-บนของเลขสุ่ม บรรทัดสุดท้ายพิมพ์ค่า roll ออกคอนโซล

ℹ️ ชนิดข้อมูลต้องตรง อาร์กิวเมนต์ที่ส่งเข้าไปต้องเป็นชนิดข้อมูลเดียวกับพารามิเตอร์ที่เมธอดกำหนดไว้ ถ้าส่งผิดชนิด คอมไพเลอร์ C# จะจับได้และบังคับให้แก้ก่อนถึงจะคอมไพล์ผ่าน — เป็นวิธีที่ C# และ .NET ป้องกัน ไม่ให้ผู้ใช้เจอ error ตอน runtime · เมธอดบางตัวก็ไม่ต้องการพารามิเตอร์เลย เช่น Console.Clear() ที่ล้างข้อความบนคอนโซล ไม่ต้องมีพารามิเตอร์ก็ทำงานได้

Check ★ return value คืออะไร?

  • Aค่าที่เมธอดคืนกลับมาให้เมื่อทำงานเสร็จ
  • Bอาร์กิวเมนต์ในการเรียกเมธอด ถูกเรียกว่า return value ข้างในเมธอด
  • Cค่าที่เป็น string เท่านั้น
เฉลย: ข้อ A. return value คือผลลัพธ์ที่เมธอดส่งกลับมาเมื่อทำงานเสร็จ เป็นชนิดข้อมูลอะไรก็ได้ ไม่ใช่แค่ string (ข้อ C ผิด) และไม่ใช่สิ่งเดียวกับอาร์กิวเมนต์ (ข้อ B สลับความหมายกัน)

Check ★ method parameter คืออะไร?

  • Aตัวแปรที่ถูกใช้ข้างในเมธอด
  • Bค่าที่เมธอดคืนกลับมา
  • Cตัวแปรที่ถูกส่งเข้าไปในเมธอดโดยคำสั่งที่เรียก
เฉลย: ข้อ C. พารามิเตอร์คือตัวแปรใน method signature ที่รับค่าจาก อาร์กิวเมนต์ตอนถูกเรียก ข้อ A กว้างเกินไป (ตัวแปรท้องถิ่นธรรมดาก็ "ถูกใช้ข้างในเมธอด" เหมือนกันแต่ไม่ใช่พารามิเตอร์) ข้อ B คือคำนิยามของ return value ไม่ใช่พารามิเตอร์

Overloaded Method (เมธอดแบบโอเวอร์โหลด)

เมธอดหลายตัวใน .NET Class Library มี method signature แบบโอเวอร์โหลด ทำให้เรียกเมธอดนั้น ได้หลายแบบ ทั้งแบบมี/ไม่มีอาร์กิวเมนต์ หรือส่งข้อมูลคนละชนิดก็ได้

overloaded method คือเมธอดที่นิยามด้วย method signature หลายแบบ ให้เรียกเมธอดได้ หลายวิธี หรือส่งข้อมูลคนละชนิดก็ได้ บางกรณี overload ต่างกันที่ชนิดข้อมูลของพารามิเตอร์ เช่น Console.WriteLine() มี overload ถึง 19 แบบ:

Program.cs 
int number = 7;
string text = "seven";

Console.WriteLine(number);
Console.WriteLine();
Console.WriteLine(text);
Output
7

seven

ตัวอย่างนี้เรียก WriteLine() ที่ overload ต่างกันถึง 3 แบบ: แบบรับพารามิเตอร์ int, แบบไม่รับพารามิเตอร์เลย, และแบบรับพารามิเตอร์ string

บางกรณี overload ต่างกันที่จำนวนพารามิเตอร์ พารามิเตอร์เสริมช่วยควบคุมผลลัพธ์ได้ ละเอียดขึ้น เช่น Random.Next() มี overload หลายแบบ:

Program.cs 
Random dice = new Random();
int roll1 = dice.Next();
int roll2 = dice.Next(101);
int roll3 = dice.Next(50, 101);

Console.WriteLine($"First roll: {roll1}");
Console.WriteLine($"Second roll: {roll2}");
Console.WriteLine($"Third roll: {roll3}");
Output (ตัวเลขสุ่มทุกครั้ง)
First roll: 342585470
Second roll: 43
Third roll: 89
overloadพารามิเตอร์ช่วงค่าที่คืน
Next()ไม่มี0 ถึง 2,147,483,647 (ค่าสูงสุดของ int)
Next(maxValue)int maxValue0 ถึง ต่ำกว่า maxValue (exclusive)
Next(minValue, maxValue)int minValue, int maxValueminValue (inclusive) ถึงต่ำกว่า maxValue

Check ★ overloaded method คืออะไร?

  • Aเมธอดที่คืนค่าเป็น value type
  • Bเมธอดที่มีพารามิเตอร์มากกว่า 5 ตัว
  • Cเมธอดที่รองรับการเรียกได้หลายแบบ แต่ละแบบมี method signature ของตัวเอง
เฉลย: ข้อ C. คำนิยามตรงตัว — ไม่เกี่ยวกับชนิดค่าที่คืน (ข้อ A) และไม่มีเกณฑ์จำนวนพารามิเตอร์ตายตัว (ข้อ B)

ใช้ IntelliSense

VS Code มีฟีเจอร์ IntelliSense ขับเคลื่อนด้วย language service — ให้คำแนะนำโค้ด อัตโนมัติตามความหมายของภาษาและการวิเคราะห์ซอร์สโค้ดของคุณ เพราะ IntelliSense อยู่ในตัว editor เอง คุณเรียนรู้เกี่ยวกับเมธอดได้เยอะโดยไม่ต้องออกจากหน้าต่างเขียนโค้ดเลย

ลองพิมพ์ทีละตัวอักษรช้าๆ ใน VS Code:

  1. พิมพ์ d, i, c ทีละตัวช้าๆ — จะเห็น popup IntelliSense โผล่มา พอพิมพ์ครบ dic ตัวแปร dice ควรขึ้นอันดับ บนสุด กด Tab เพื่อเติมคำให้เต็ม
  2. พิมพ์ . — popup จะโผล่แสดงรายการเมธอด/สมาชิกทั้งหมดของคลาส
  3. พิมพ์ N — รายการกรองเหลือ Next เป็นตัวเลือกอันดับแรก กด Tab เติมคำ
  4. พิมพ์ ( — วงเล็บปิดถูกเติมให้อัตโนมัติ IntelliSense จะแสดงข้อมูลละเอียด ของ Random.Next()

Popup จะแสดง int Random.Next() ด้านบน และ "Returns a non-negative random integer." ด้านล่าง — int คือชนิดข้อมูลที่คืนกลับ ด้านซ้ายจะขึ้น 1/3 แปลว่ากำลังดู method signature อันที่ 1 จาก 3 แบบ กดลูกศรขึ้น-ลงเพื่อดู overload อื่นได้:

#สิ่งที่ IntelliSense แสดง
1/3ไม่มีพารามิเตอร์ — "Returns a non-negative random integer."
2/3int maxValue — ขอบเขตบนแบบ exclusive (ค่าที่คืนน้อยกว่า maxValue เสมอ)
3/3int minValue, int maxValue — minValue เป็นขอบเขตล่างแบบ inclusive
💡 ทำไม dice.Next(1, 7) แต้มสูงสุดถึงเป็น 6 เพราะ maxValue เป็นขอบเขตแบบ exclusive (ไม่รวมค่านั้น) ค่าที่คืนจะ "น้อยกว่า" 7 เสมอ สูงสุดคือ 6 พอดี — เหมาะกับลูกเต๋า 6 หน้า

ใช้ learn.microsoft.com ค้นข้อมูล Overload

ในส่วน Parameters จะบอกว่า maxValue คือ "exclusive upper bound" และ "maxValue must be greater than or equal to 0" ถ้าฝ่าฝืน จะได้ ArgumentOutOfRangeException ตามที่ระบุในส่วน Exceptions

8.5 ท้าทาย: หาเมธอดที่คืนค่ามากกว่าระหว่างตัวเลขสองตัว

โจทย์ตามต้นฉบับ MS Learn

เริ่มจากโค้ดนี้ (ห้ามแก้ 4 บรรทัดนี้ แต่เพิ่มโค้ดตรงกลางได้):

Program.cs — บังคับใช้
int firstValue = 500;
int secondValue = 600;
int largerValue;

Console.WriteLine(largerValue);

ใช้ IntelliSense หรือ learn.microsoft.com หาเมธอดของคลาส System.Math ที่คืนค่ามากกว่าระหว่างตัวเลขสองตัว แล้วใช้เมธอดนั้นกำหนดค่าให้ตัวแปร largerValue — ต้องส่งค่า firstValue และ secondValue เป็นอาร์กิวเมนต์ให้เมธอดนั้นได้ และเมธอดต้องคืนค่าชนิด int

ผลลัพธ์ที่ต้องได้
600
💡 ขอคำใบ้

ลองพิมพ์ Math. ใน VS Code แล้วดู IntelliSense แนะนำเมธอดที่ขึ้นต้นด้วย คำว่า "Max" — ชื่อเมธอดสื่อความหมายตรงตัวอยู่แล้ว

8.6 เฉลยและวิเคราะห์

Program.cs — เฉลยตัวอย่าง 
int firstValue = 500;
int secondValue = 600;
int largerValue;
largerValue = Math.Max(firstValue, secondValue);
Console.WriteLine(largerValue);
Output
600

เมธอด Math.Max() มี overload ถึง 13 แบบ รองรับชนิดข้อมูลต่างกัน เวอร์ชันที่ เรียกในโค้ดนี้รับพารามิเตอร์ทั้งสองเป็น int และคืนค่ามากกว่าเป็น int กลับมา

สังเกตว่า Math.Max() เป็นเมธอด stateless — เรียกจากชื่อคลาส Math ตรงๆ ได้เลย ไม่ต้องสร้าง new Math() ก่อน ต่างจาก Random.Next() ที่ต้องสร้าง instance ก่อนเสมอ นี่คือตัวอย่างจริงที่ตอกย้ำ บทเรียนเรื่อง stateless/stateful จากหัวข้อ 8.3

8.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
Random.Next() โดยไม่สร้าง instance CS0120 — เมธอดนี้เป็น stateful ต้อง new Random() ก่อนเสมอ
สร้าง new Math() ก่อนเรียก Max() ไม่จำเป็น — Math.Max() เป็น stateless เรียกจากชื่อคลาสตรงๆ ได้เลย
สับสนคำว่า parameter กับ argument parameter = ตัวแปรในนิยามเมธอด · argument = ค่าจริงที่ส่งตอนเรียก
คิดว่า dice.Next(1, 7) จะได้แต้มสูงสุด 7 maxValue เป็นขอบเขตแบบ exclusive ค่าที่คืนน้อยกว่า 7 เสมอ (สูงสุดคือ 6)
ไม่รู้ว่ามี overload ให้ใช้แบบสั้นกว่า เปิด IntelliSense ดู (พิมพ์ "(" แล้วดูเลขมุมซ้าย เช่น 1/3, 2/3) หรือเช็ค learn.microsoft.com หัวข้อ Overloads เสมอก่อนเขียนโค้ดยาวเกินจำเป็น

เฉลย: ข้อ C. object คือ instance ของคลาสหนึ่งๆ ที่ถูกสร้างด้วย new — ที่อยู่หน่วยความจำ (ข้อ A) เป็นแค่ส่วนหนึ่งของกลไกเบื้องหลัง การอ้างอิง object เท่านั้น ไม่ใช่คำนิยามของ object เอง

2. ข้อความใดถูกต้อง?

  • A.NET Class Library นิยาม overload ให้ทุกเมธอดเสมอ
  • B.NET Class Library มีนิยามของชนิดข้อมูลที่ใช้ใน C# ด้วย
  • C.NET Class Library มีคลาสเยอะจนทำให้พัฒนาช้าลง
เฉลย: ข้อ B. ชนิดข้อมูลอย่าง string/int จริงๆ มาจากคลาสใน .NET Class Library (หัวข้อ 8.2) ข้อ A ผิดเพราะไม่ใช่ทุกเมธอดจะมี overload ข้อ C ผิดเพราะ คลังฟังก์ชันขนาดใหญ่ช่วยประหยัดเวลาพัฒนา ไม่ใช่ทำให้ช้าลง

3. สัญลักษณ์ใดคือตัวเรียกใช้เมธอด (method invocation operator)?

  • A.
  • B{}
  • C()
เฉลย: ข้อ C. วงเล็บ () คือตัวเรียกใช้เมธอด ต้องมีเสมอ เวลาจะเรียกเมธอด — . คือตัวเชื่อมเข้าถึงสมาชิก (ทบทวนบทที่ 1) และ {} ใช้กับ interpolation หรือ code block (ทบทวนบทที่ 3)

8.9 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

เขียนโค้ดสุ่มเลข 1-100 (ใช้ overload ที่รับพารามิเตอร์ตัวเดียว) แล้วพิมพ์ค่าที่ได้

ดูเฉลย
Program.cs
Random rng = new Random();
int number = rng.Next(101);
Console.WriteLine(number);

ใช้ 101 เพราะขอบเขตบนเป็นแบบ exclusive ต้องการค่าสูงสุด 100 จึงต้องส่ง 101

ข้อ 2ง่าย

ใช้ Math.Min() หาค่าน้อยกว่าระหว่าง 45 กับ 12 แล้วพิมพ์ผล (ค้นดูจาก IntelliSense หรือคาดเดาจากชื่อเมธอดที่คล้าย Math.Max())

ดูเฉลย
Program.cs
int smaller = Math.Min(45, 12);
Console.WriteLine(smaller);
ข้อ 3ง่าย

โค้ดนี้ error หาสาเหตุและแก้ไข:

Program.cs (ผิด)
int result = Random.Next(1, 10);
Console.WriteLine(result);
ดูเฉลย

error CS0120 — Next() เป็น stateful เรียกจากชื่อคลาส Random ตรงๆ ไม่ได้ ต้องสร้าง instance ก่อน:

Program.cs (ถูก)
Random rng = new Random();
int result = rng.Next(1, 10);
Console.WriteLine(result);
ข้อ 4กลาง

ใช้ IntelliSense หรือ learn.microsoft.com ค้นหาเมธอดของคลาส string ที่แปลงข้อความเป็นตัวพิมพ์ใหญ่ทั้งหมด แล้วใช้กับตัวแปร string name = "somchai"; ให้ได้ผลลัพธ์ SOMCHAI

💡 คำใบ้

บทที่ 8.2 พูดถึงเมธอดนี้ไว้แล้วเป็นตัวอย่าง ชื่อเมธอดขึ้นต้นด้วย "To"

ดูเฉลย
Program.cs
string name = "somchai";
Console.WriteLine(name.ToUpper());

สังเกตว่า ToUpper() เป็น stateful — เรียกผ่านตัวแปร name ตรงๆ ได้เลย เพราะ string ก็เป็น instance ของคลาสอยู่แล้วตั้งแต่ตอน สร้างค่า literal (ทบทวนหัวข้อ 8.2 เรื่อง "แม้แต่ชนิดข้อมูลก็เป็นส่วนหนึ่งของ .NET Class Library")

ข้อ 5กลาง

อธิบายว่าทำไม Console.WriteLine() ถึงเป็น stateless ทั้งที่มันต้อง "รู้" ว่าต้องพิมพ์ไปที่หน้าต่างคอนโซลไหนของโปรแกรม (ไม่ต้องเขียนโค้ด ตอบเป็นข้อความ)

ดูเฉลย

ความเป็น stateless หมายถึงเมธอดไม่พึ่งพา/แก้ไขค่าที่โปรแกรมของคุณเก็บไว้ในตัวแปร ระหว่างการทำงาน ไม่ได้แปลว่าเมธอดทำงานแบบไม่มีบริบทเลย — คอนโซลที่จะพิมพ์ไปนั้นถูก จัดการโดยระบบปฏิบัติการ/runtime อยู่เบื้องหลัง ไม่ใช่ state ที่โค้ดของคุณต้องสร้าง หรือดูแลเอง

ข้อ 6ท้าทาย

เขียนโปรแกรมจำลอง "ทอยลูกเต๋า 2 ลูก" (ค่า 1-6 แต่ละลูก) แล้วใช้ Math.Max() หาว่าลูกไหนแต้มสูงกว่า พิมพ์ผลทั้งสองแต้มและแต้มที่สูงกว่า ให้ได้ผลลัพธ์ทำนองนี้ (ตัวเลขจะสุ่มต่างกันทุกครั้ง):

ลูกเต๋าลูกที่ 1: 4
ลูกเต๋าลูกที่ 2: 6
แต้มสูงสุด: 6
💡 คำใบ้

สร้าง Random instance ตัวเดียว แล้วเรียก Next(1, 7) สองครั้งเก็บใส่ตัวแปรคนละตัว จากนั้นส่งทั้งสองตัวแปรให้ Math.Max()

ดูเฉลย
Program.cs
Random dice = new Random();
int die1 = dice.Next(1, 7);
int die2 = dice.Next(1, 7);
int higher = Math.Max(die1, die2);

Console.WriteLine($"ลูกเต๋าลูกที่ 1: {die1}");
Console.WriteLine($"ลูกเต๋าลูกที่ 2: {die2}");
Console.WriteLine($"แต้มสูงสุด: {higher}");

📌 สรุปบทที่ 8

เป้าหมายของบทนี้คือเรียกใช้เมธอดที่นิยามไว้ใน .NET Class Library เพื่อทำงานอย่างสุ่มตัวเลข หรือคำนวณทางคณิตศาสตร์ คุณเรียกเมธอดหลายแบบด้วยไวยากรณ์ C#: เมธอดที่คืนค่า เมธอดที่รับ พารามิเตอร์หลายตัว และเมธอดที่เก็บสถานะ คุณใช้ IntelliSense ของ VS Code และ learn.microsoft.com ค้นคว้าข้อมูลเมธอด และเข้าใจลึกซึ้งขึ้นว่าแต่ละเมธอดทำงานยังไง — นี่คือก้าวสำคัญที่ทำให้คุณเข้าใจว่านักพัฒนาซอฟต์แวร์สร้างแอปจริงกันยังไง
