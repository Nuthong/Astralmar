27.1 สถานการณ์และสเปก

สมมติคุณเป็นหนึ่งในนักพัฒนาที่ทำงานบนแอป Contoso Pets ที่ช่วยหาบ้านใหม่ให้สัตว์เลี้ยง แอป เวอร์ชันเริ่มต้นของคุณ (จากบทที่ 26) รับคำค้นหาแค่คำเดียว ใช้ค้นหา คำอธิบายของสุนัข การค้นหาคำเดียวมีประโยชน์ แต่ feedback จากทีมบอกว่าแอปต้องการความสามารถ ค้นหาที่มากกว่านี้ ทีมต้องการให้คุณขยายฟีเจอร์ค้นหาให้รองรับหลายคำค้นหาพร้อมกัน นอกจากนี้ ทีมยังต้องการทดลองอัปเดต animation "สถานะการค้นหา" ที่แสดงความคืบหน้าด้วย

ในโปรเจกต์ท้าทายนี้ คุณจะประยุกต์ใช้ความรู้และทักษะข้อมูล C# ของคุณกับ:

  • สร้าง string array ด้วยการแยก string
  • จัดการข้อมูลใน array วนผ่าน element และเรียงลำดับข้อมูลใน array
  • แก้ไขและประกอบ string จากหลายแหล่งข้อมูล

สรุปสั้นๆ คุณจะ:

  • พัฒนาฟีเจอร์ค้นหาหลายคำสำหรับการค้นหา "สุนัข"
  • อัปเดต animation "สถานะการค้นหา" ข้อมูล และการนับถอยหลัง

สเปกฟีเจอร์ค้นหาหลายคำ

รวบรวมคำค้นหาหลายคำจากผู้ใช้:

  • ให้ผู้ใช้กรอกคำค้นหาหลายคำได้ตอนค้นหาสุนัข
  • ผู้ใช้ต้องได้รับคำแนะนำให้ "กรอกคำค้นหาคั่นด้วยจุลภาค"
  • แยกคำค้นหาแต่ละคำออกจาก string ที่ผู้ใช้กรอก แล้วเก็บเป็นค่าใน array
  • เรียงคำใน array ตามลำดับ alphanumeric

ระบุสุนัขที่คำอธิบายตรงกับคำค้นหาหนึ่งคำหรือมากกว่า:

  • เมื่อระบุสุนัขใน array ของสัตว์ได้แล้ว ค้นหาว่าตรงกับคำค้นหาแต่ละคำที่ผู้ใช้กรอกหรือไม่
  • ถ้าคำตรงกัน แสดงข้อความชื่อสุนัขพร้อมคำที่ตรงกัน เช่น: "Our dog Jake is a match for your search for sheppard!"
  • เมื่อค้นหาครบทุกคำสำหรับสุนัขตัวปัจจุบันแล้ว: ถ้าตรงกันอย่างน้อยหนึ่งคำ แสดงชื่อเล่นและ คำอธิบายของสุนัขตัวนั้น และติดตามไว้ว่ามีการตรงกันเกิดขึ้นแล้ว (เพื่อไม่ให้แสดงข้อความ "ไม่พบที่ตรงกันเลย" ทีหลัง)
  • หลังค้นหาสุนัขทุกตัวเสร็จ ถ้าไม่มีตัวไหนตรงกันเลย ให้แสดงข้อความ "No matches found for any available dogs"

กฎตรวจสอบความถูกต้อง: ค่าห้ามเป็น null, ค่าห้ามมีความยาวศูนย์ตัวอักษร, ข้อจำกัดเพิ่มเติมแล้วแต่ผู้พัฒนา

สเปกแอนิเมชันการค้นหา

  • ปรับ string[] searchingIcons = {". ", ".. ", "..."}; ให้เป็นไอคอนที่ จำลองการหมุน (เหมือน spinner)
  • animation "searching..." ต้องถูกเขียนทับ (overwrite) หลังแต่ละเฟรมจบ เพื่อให้อยู่บรรทัด เดิมเสมอ และต้องไม่ค้างแสดงหลัง animation จบแล้ว
  • เพิ่มการนับถอยหลังในแอนิเมชัน: จาก "2" ไป "1" แล้วไป "0"
💡 ออกแบบแอนิเมชันเองได้ ไม่ต้องเหมือนต้นฉบับเป๊ะ MS Learn บอกไว้ตรงๆ ว่า "You can design the searching animation to display spinning to work differently than displayed in the animated image" — คุณออกแบบรูปแบบการหมุนเองได้ตามใจ ขอแค่ มี spinner + countdown 2→1→0 ตามสเปก

27.2 🔓 เฉลยของผม — ค้นหาหลายคำ

แนวคิดหลัก: รับ input เป็น string เดียวคั่นด้วยจุลภาค (เหมือนรูปแบบที่เจอใน บทที่ 23) ใช้ Split(',') แยกเป็น array แล้ว Trim().ToLower() แต่ละคำ กรองคำว่างทิ้ง แล้ว Array.Sort() เรียง ตามตัวอักษร — จากนั้นวนผ่านสุนัขแต่ละตัวเหมือนเดิมจากบทที่ 26 แต่เปลี่ยนจากเช็คคำเดียวเป็น วนเช็คทุกคำในคำค้นหา

Program.cs (ใน case "2":) 
case "2":
    // Display all dogs with a specified characteristic (multi-term search)
    string searchInput = "";

    while (searchInput == "")
    {
        Console.WriteLine("\nEnter dog characteristics to search for separated by commas");
        readResult = Console.ReadLine();
        if (readResult != null)
        {
            searchInput = readResult.Trim();
        }
    }

    // #1 แยกคำค้นหาเป็น array แล้ว trim + lowercase แต่ละคำ กรองคำว่างทิ้ง
    string[] rawTerms = searchInput.Split(',');
    int validCount = 0;
    foreach (string term in rawTerms)
    {
        if (term.Trim() != "") validCount += 1;
    }

    string[] searchTerms = new string[validCount];
    int idx = 0;
    foreach (string term in rawTerms)
    {
        string cleaned = term.Trim().ToLower();
        if (cleaned != "")
        {
            searchTerms[idx] = cleaned;
            idx += 1;
        }
    }

    // #2 เรียงคำค้นหาตามลำดับตัวอักษร
    Array.Sort(searchTerms);

    // #3 วนหาสุนัข แล้วเช็คทุกคำค้นหากับคำอธิบายที่รวมแล้ว
    bool noMatchesDog = true;

    for (int i = 0; i < maxPets; i++)
    {
        if (ourAnimals[i, 1].Contains("dog"))
        {
            string dogDescription = ourAnimals[i, 4] + "\n" + ourAnimals[i, 5];
            bool dogMatched = false;

            foreach (string term in searchTerms)
            {
                if (dogDescription.Contains(term))
                {
                    Console.WriteLine($"Our dog {ourAnimals[i, 3]} matches your search for {term}");
                    dogMatched = true;
                }
            }

            if (dogMatched)
            {
                Console.WriteLine($"{ourAnimals[i, 3]} ({ourAnimals[i, 0]})");
                Console.WriteLine(ourAnimals[i, 4]);
                Console.WriteLine(ourAnimals[i, 5]);
                Console.WriteLine();
                noMatchesDog = false;
            }
        }
    }

    if (noMatchesDog)
    {
        Console.WriteLine("None of our dogs are a match for: " + string.Join(", ", searchTerms));
    }

    Console.WriteLine("\nPress the Enter key to continue");
    readResult = Console.ReadLine();
    break;

สังเกตลำดับคำที่ตรงกัน: คำค้นหาที่ผู้ใช้กรอก "large, cream, golden" ถูกเรียง ใหม่เป็น cream, golden, large (ตามลำดับตัวอักษร) ก่อนเริ่มค้นหา — สำหรับ lola (คำอธิบาย "medium sized cream colored... golden retriever...") คำว่า "cream" ตรวจเจอก่อน ตามด้วย "golden" ส่วน "large" ไม่ตรงเลย (เพราะ lola ตัวขนาด "medium" ไม่ใช่ "large") — สำหรับ gus (คำอธิบาย "large reddish-brown... golden retriever...") คำว่า "cream" ไม่ตรง แต่ "golden" ตรงก่อน ตามด้วย "large" — ลำดับการแสดงผลจึงตรงกับลำดับที่เรียงไว้ใน searchTerms เป๊ะ

ทดสอบรัน — ค้นหา "big, grey, stripes" (ไม่เจอเลย)

💡 ทำไมต้อง Trim() ก่อน Sort() เสมอ ถ้าผู้ใช้พิมพ์ "large, cream, golden" (มีช่องว่างหลังจุลภาค) การ Split(',') ตรงๆ จะได้ "large", " cream" (มีช่องว่าง นำหน้า!), " golden" — ถ้าไม่ Trim() ก่อน Sort() ช่องว่างนำหน้าจะถูกนับเป็นตัวอักษรด้วย และในตาราง ASCII ช่องว่างมีค่าน้อยกว่าตัวอักษรทุกตัว (ทบทวนแนวคิด ASCII จาก บทที่ 21) ทำให้คำที่มีช่องว่างนำหน้าถูกเรียง มาก่อนเสมอ ไม่ว่าตัวอักษรจริงจะเป็นอะไรก็ตาม — ผลลัพธ์การเรียงจึงผิดเพี้ยนไปจากที่ตั้งใจ

27.3 🔓 เฉลยของผม — แอนิเมชันหมุนพร้อมนับถอยหลัง

ใช้ 4 สัญลักษณ์คลาสสิกที่จำลองการหมุนของ spinner: | / - \ วนซ้ำ พร้อมนับถอยหลัง จาก 2 ลงมา 0 คู่กับแต่ละสัญลักษณ์ ใช้ \r (carriage return) เขียนทับบรรทัดเดิม แทนการขึ้นบรรทัดใหม่ทุกครั้ง (ทบทวน escape sequence จาก บทที่ 3) — เพิ่มโค้ดนี้ไว้ก่อนเช็ค dogDescription.Contains(term) ในแต่ละรอบของ foreach (string term in searchTerms) จากหัวข้อ 27.2

Program.cs (แทรกก่อน if (dogDescription.Contains(term))) 
string[] searchingIcons = { "|", "/", "-", "\\" };

for (int count = 2; count >= 0; count--)
{
    foreach (string icon in searchingIcons)
    {
        Console.Write($"\rsearching our dog {ourAnimals[i, 3]} for {term} {icon} {count}   ");
        System.Threading.Thread.Sleep(120);
    }
}

// ล้างบรรทัดแอนิเมชันทิ้งก่อนพิมพ์ผลลัพธ์จริง
Console.Write("\r" + new string(' ', 60) + "\r");

เพราะ searchingIcons ประกาศไว้นอก loop การค้นหาสุนัข มันถูกสร้างแค่ครั้งเดียว ส่วน for (int count = 2; count >= 0; count--) วนนับถอยหลัง 3 รอบ (2, 1, 0) แต่ ละรอบวนแสดงสัญลักษณ์ทั้ง 4 ตัวติดกันเป็น "การหมุน" หนึ่งรอบ — \r ที่ต้นข้อความ ทำให้ cursor กลับไปต้นบรรทัดก่อนพิมพ์ทับของเดิม แทนที่จะขึ้นบรรทัดใหม่ (สังเกตช่องว่างท้าย string " " ไว้เผื่อ "ลบ" ตัวอักษรเก่าที่อาจยาวกว่าข้อความใหม่)

หลังจบ animation ของคำค้นหานั้น เขียนช่องว่างทับทั้งบรรทัดแล้วกลับไปต้นบรรทัดอีกครั้ง เพื่อ "ล้าง" ข้อความ animation ก่อนพิมพ์ข้อความผลลัพธ์จริงตามปกติ — ตรงตามสเปกที่บอกว่า "ต้องไม่ค้างแสดงหลัง animation จบแล้ว"

ℹ️ ตัวอย่างเฟรมของแอนิเมชัน (จำลองบนกระดาษ — ในเทอร์มินัลจริงจะเขียนทับกัน) เพราะ \r เขียนทับบรรทัดเดิมในเทอร์มินัลจริง หนังสือเล่มนี้แสดงผลลัพธ์แบบ static ไม่ได้ แต่ถ้าดูทีละเฟรม (เหมือนถ่ายภาพหน้าจอทุก 120 มิลลิวินาที) จะเห็นบรรทัดเดียวเปลี่ยนไป เรื่อยๆ แบบนี้:
เฟรมที่ 1-4 (คำค้นหา "golden", สุนัข lola)
searching our dog Nickname: lola for golden | 2
searching our dog Nickname: lola for golden / 2
searching our dog Nickname: lola for golden - 2
searching our dog Nickname: lola for golden \ 2
searching our dog Nickname: lola for golden | 1
   ... (วนต่อจนครบ count = 0) ...
searching our dog Nickname: lola for golden \ 0
พอรันจริงในเทอร์มินัล คุณจะเห็นแค่บรรทัดเดียวที่ตัวเลขนับถอยหลังและสัญลักษณ์หมุนเปลี่ยนไปเรื่อยๆ อยู่กับที่ ไม่ใช่หลายบรรทัดแบบนี้
⚠️ Thread.Sleep() ทำให้โปรแกรมหยุดชั่วคราวจริงๆ System.Threading.Thread.Sleep(120) สั่งให้โปรแกรมหยุดทำงาน 120 มิลลิวินาทีจริงๆ (ไม่ใช่แค่ simulate) ทั้งโปรแกรมจะค้างระหว่างนั้น ถ้าตั้งเวลานานเกินไปหรือมีคำค้นหา/สุนัข หลายตัว โปรแกรมอาจดูเหมือนค้างนานผิดปกติ ควรตั้งค่าให้พอเหมาะ (100-150 มิลลิวินาทีต่อเฟรม ถือว่าดูเป็นธรรมชาติ) และจำนวนสุนัข × จำนวนคำค้นหา × 3 รอบนับถอยหลัง × 4 เฟรมสัญลักษณ์ ควร อยู่ในระดับที่ผู้ใช้รอไหว

27.4 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
ลืม Trim() คำค้นหาแต่ละคำหลัง Split(',') แล้วเรียงลำดับเพี้ยน ช่องว่างนำหน้า (จากการพิมพ์ "term1, term2" มีช่องว่างหลังจุลภาค) มีค่า ASCII น้อยกว่า ตัวอักษรทุกตัว ทำให้คำที่มีช่องว่างนำหน้าถูกเรียงมาก่อนเสมอ ต้อง Trim() ก่อน Sort() ทุกครั้ง (ทบทวนหัวข้อ 27.2)
ค้นหาแล้วได้คำว่างเปล่าติดมาด้วย (เช่น พิมพ์ "large,,golden" มีจุลภาคติดกัน) Split(',') สร้าง element ว่างเปล่าตรงกลาง — ต้องกรองคำว่างทิ้งก่อนใช้งานเสมอ ตรงตาม กฎ "values can't have zero characters" ในสเปก
แอนิเมชันเขียนทับไม่สนิท มีตัวอักษรเก่าค้างอยู่ท้ายบรรทัด ข้อความใหม่สั้นกว่าข้อความเก่า (เช่น "0" สั้นกว่า "golden") การเขียนทับด้วย \r เขียนทับแค่ความยาวของข้อความใหม่ ตัวอักษรเก่าที่ยาวกว่าจึงโผล่ค้างท้าย บรรทัด — ต้องเติมช่องว่างท้ายข้อความให้พอ (หรือล้างทั้งบรรทัดก่อนเขียนใหม่ทุกครั้ง)
โปรแกรมค้างนานผิดปกติตอนค้นหาหลายคำกับสุนัขหลายตัว เวลารวมของ animation คูณกันตามจำนวนสุนัข × คำค้นหา × รอบนับถอยหลัง × เฟรม — ถ้าตั้ง Thread.Sleep() นานเกินไป เวลารวมจะยาวเกินจำเป็น ควรคำนวณเวลารวมสูงสุดที่เป็นไปได้ ก่อนตั้งค่า
คำที่ตรงกันหลายคำแสดงซ้ำ ทั้งที่สุนัขตัวเดียวควรแสดงคำอธิบายแค่ครั้งเดียว ใช้ตัวแปร dogMatched (bool) แยกจาก noMatchesDog เสมอ — ตัวแรก ติดตามสถานะ "ตรงกันไหม" ต่อสุนัขหนึ่งตัว ตัวหลังติดตามสถานะ "ตรงกันไหม" ของ การค้นหาทั้งหมด ถ้าใช้ตัวแปรเดียวปนกันจะพิมพ์คำอธิบายซ้ำทุกครั้งที่มีคำตรงกัน

27.5 ❓ Knowledge Check

คำถามชุดนี้แปลจาก Module Assessment ของ Microsoft Learn

1. ตอนเรียง string array ทำไมการใช้เมธอด String.Trim() กับแต่ละ element ก่อนเรียงจึงสำคัญ?

  • Aเฉพาะ array ที่ trim แล้วเท่านั้นที่เรียงได้
  • BString.Trim() ตัดช่องว่างนำหน้าที่จะถูกเรียงมาก่อนตัวเลขและตัวอักษรทิ้ง
  • Cการเรียงเร็วขึ้นอย่างเห็นได้ชัดเมื่อใช้ String.Trim() กับแต่ละ element
เฉลย: ข้อ B. ตรงกับที่อธิบายในหัวข้อ 27.2 — ช่องว่างมีค่า ASCII น้อยกว่าตัวอักษรทุกตัว ถ้าไม่ Trim() ก่อน คำที่มีช่องว่างนำหน้าจะถูกเรียงมาก่อนเสมอ ทำให้ ผลการเรียงผิดเพี้ยนจากที่ตั้งใจ ไม่เกี่ยวกับความเร็วในการเรียงเลย (ข้อ C ผิด) และ array ที่ไม่ trim ก็เรียงได้ปกติ แค่ผลลัพธ์อาจไม่ตรงตามคาด (ข้อ A ผิด)

2. ทั้ง foreach และ for เป็น ตัวเลือกที่ดีสำหรับวน array มิติเดียวขนาดเล็ก เช่น {"cat", "fox", "dog", "snake", "eagle"} แต่เมื่อไรที่ควรใช้ for loop ดีที่สุด?

  • Aเมื่อ element เรียงตามลำดับตัวอักษรอยู่แล้ว
  • Bเพื่อค้นหาใน element แต่ละตัวของ array
  • Cเพื่อประเมินช่วง (range) ที่เจาะจงของ element
เฉลย: ข้อ C. ตรงกับหลักการที่เรียนใน บทที่ 17 — for ให้ควบคุม index ได้ละเอียด จึงเหมาะกับการเข้าถึงช่วง element เฉพาะเจาะจง (เช่น element ที่ 2 ถึง 4 เท่านั้น) ซึ่ง foreach ทำไม่ได้เพราะมันวนทุก element เสมอ ส่วนการค้นหา (ข้อ B) และการเรียงตามลำดับตัวอักษร (ข้อ A) ไม่ใช่เหตุผลที่ต้องเลือก for โดยเฉพาะ — foreach ก็ค้นหาได้เหมือนกัน

27.6 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

เขียนโค้ดแยกและเรียง string " Zebra ,apple, Mango,banana " ด้วย Split + Trim + ToLower + Sort แล้วพิมพ์ผลลัพธ์ทีละบรรทัด

ดูเฉลย
Program.cs
string input = "  Zebra ,apple,  Mango,banana ";
string[] items = input.Split(',');

for (int i = 0; i < items.Length; i++)
{
    items[i] = items[i].Trim().ToLower();
}

Array.Sort(items);

foreach (string item in items)
{
    Console.WriteLine(item);
}

ผลลัพธ์: apple, banana, mango, zebra (เรียงถูกต้องแม้ input จะมีช่องว่างและตัวพิมพ์ ใหญ่-เล็กปนกัน)

ข้อ 2ง่าย

เขียน spinner แอนิเมชันง่ายๆ ที่หมุน 3 รอบ (ไม่ต้องนับถอยหลัง) ใช้สัญลักษณ์ | / - \ เขียนทับบรรทัดเดิมด้วย \r

ดูเฉลย
Program.cs
string[] icons = { "|", "/", "-", "\\" };

for (int round = 0; round < 3; round++)
{
    foreach (string icon in icons)
    {
        Console.Write($"\rLoading {icon}   ");
        System.Threading.Thread.Sleep(150);
    }
}
Console.Write("\r" + new string(' ', 20) + "\r");
Console.WriteLine("Done!");
ข้อ 3กลาง

ในเฉลยหัวข้อ 27.2 ทำไมต้องแยกตัวแปร dogMatched ออกจาก noMatchesDog? ลองอธิบายด้วยคำพูดตัวเอง แล้วยกตัวอย่างสถานการณ์ที่ถ้าใช้ ตัวแปรเดียวจะเกิดปัญหา

ดูเฉลย

dogMatched ต้องรีเซ็ตเป็น false ใหม่ทุกครั้งที่เริ่มตรวจ สุนัขตัวใหม่ (เพราะแค่ต้องการรู้ว่า "สุนัขตัวนี้" ตรงกับคำค้นหาไหม) ส่วน noMatchesDog ต้องคงค่าอยู่ตลอดการวนสุนัขทุกตัว (เพราะต้องการรู้ว่า "มีสุนัขตัวไหนเลยไหม" ที่ตรงกัน) ถ้าใช้ตัวแปรเดียวปนกัน เช่น ใช้แค่ noMatchesDog แล้วรีเซ็ตเป็น true ทุกครั้งที่เริ่มสุนัขตัว ใหม่ พอสุนัขตัวที่สองไม่ตรงกับคำค้นหาเลย ตัวแปรจะถูกรีเซ็ตกลับเป็น true ทับค่า false ที่ตัวแรกตั้งไว้ (ทั้งที่สุนัขตัวแรกเจอที่ตรงกันแล้ว) ทำให้ ข้อความ "ไม่พบที่ตรงกันเลย" แสดงผิดพลาดทั้งที่จริงๆ เจอผลลัพธ์แล้ว

ข้อ 4กลาง

ดัดแปลงเฉลยหัวข้อ 27.2 ให้จำกัดจำนวนคำค้นหาไม่เกิน 5 คำ ถ้าผู้ใช้กรอกเกิน 5 คำ ให้แสดง ข้อความเตือนและใช้แค่ 5 คำแรกเท่านั้น (ทบทวน Array.Resize จาก บทที่ 23)

ดูเฉลย
Program.cs (ส่วนที่เพิ่ม หลังสร้าง searchTerms)
if (searchTerms.Length > 5)
{
    Console.WriteLine("You entered more than 5 terms. Only the first 5 will be used.");
    Array.Resize(ref searchTerms, 5);
}

วางโค้ดนี้ก่อน Array.Sort(searchTerms); เพื่อให้ตัดคำเกินออกก่อนเรียง (ถ้าเรียงก่อนตัด จะตัดคำผิดตัวไป เพราะลำดับเปลี่ยนไปแล้ว)

ข้อ 5ยาก

เขียนโค้ดนับว่าคำค้นหาแต่ละคำ (ไม่ใช่แค่สุนัขแต่ละตัว) ตรงกับสุนัขกี่ตัว แล้วแสดงสรุปท้าย การค้นหา เช่น "cream: 1 dog, golden: 2 dogs, large: 1 dog"

ดูเฉลย
Program.cs
int[] termMatchCounts = new int[searchTerms.Length];

for (int i = 0; i < maxPets; i++)
{
    if (ourAnimals[i, 1].Contains("dog"))
    {
        string dogDescription = ourAnimals[i, 4] + "\n" + ourAnimals[i, 5];

        for (int t = 0; t < searchTerms.Length; t++)
        {
            if (dogDescription.Contains(searchTerms[t]))
            {
                termMatchCounts[t] += 1;
            }
        }
    }
}

string summary = "";
for (int t = 0; t < searchTerms.Length; t++)
{
    summary += $"{searchTerms[t]}: {termMatchCounts[t]} dog(s), ";
}
Console.WriteLine("\n" + summary.TrimEnd(',', ' '));

ใช้ array คู่ขนาน termMatchCounts (ทบทวนแนวคิด array คู่ขนานจาก บทที่ 12) เก็บจำนวนที่ตรงกันของแต่ละคำ index เดียวกับ searchTerms — ต้องวนผ่านสุนัขทั้งหมดแยกต่างหาก (ไม่ปนกับ loop หลักที่ แสดงผลลัพธ์) เพื่อความชัดเจนของโค้ด

ข้อ 6ท้าทาย

วิเคราะห์: สเปกบอกว่า "ค้นหาคำที่ตรงกันหนึ่งคำหรือมากกว่า" (OR logic — ตรงคำไหนก็ได้) — ถ้าทีมเปลี่ยนใจอยากให้เป็น "ต้องตรงกับทุกคำที่ค้นหา" (AND logic) แทน จะต้องแก้โค้ด ตรงไหนบ้าง? ลองเขียนเวอร์ชัน AND logic ออกมา

ดูเฉลย
Program.cs (เปลี่ยนจาก OR เป็น AND)
for (int i = 0; i < maxPets; i++)
{
    if (ourAnimals[i, 1].Contains("dog"))
    {
        string dogDescription = ourAnimals[i, 4] + "\n" + ourAnimals[i, 5];
        bool matchesAllTerms = true;

        foreach (string term in searchTerms)
        {
            if (!dogDescription.Contains(term))
            {
                matchesAllTerms = false;
                break;
            }
        }

        if (matchesAllTerms)
        {
            Console.WriteLine($"{ourAnimals[i, 3]} ({ourAnimals[i, 0]})");
            Console.WriteLine(ourAnimals[i, 4]);
            Console.WriteLine(ourAnimals[i, 5]);
            Console.WriteLine();
            noMatchesDog = false;
        }
    }
}

จุดต่างหลัก: ค่าเริ่มต้นเปลี่ยนจาก false (OR — เริ่มที่ "ยังไม่เจอ") เป็น true (AND — เริ่มที่ "ตรงทุกคำ") แล้วพอเจอคำที่ไม่ตรงคำแรก ให้ตั้ง เป็น false ทันทีและ break ออกจาก loop เลย (ไม่ต้องเช็คคำที่ เหลือต่อ เพราะรู้แล้วว่าไม่ผ่านเงื่อนไข AND) — ไม่มีการพิมพ์ "matches your search for..." ทีละคำแบบเดิมด้วย เพราะ AND logic ต้องรอครบทุกคำก่อนถึงจะสรุปได้ว่าตรงหรือไม่

📌 สรุปบทที่ 27

ความท้าทายของคุณคืออัปเดตแอปให้รองรับการค้นหาหลายคำ และปรับปรุงข้อมูลแอนิเมชัน "สถานะการ ค้นหา" ในโมดูลนี้ คุณพัฒนาโค้ดที่รวม: วน iteration รับ input ข้อมูล, ประมวลผลข้อมูล, จัดรูปแบบ output ของข้อมูล, เลือก data type ที่ถูกต้องและแปลง data type อย่างปลอดภัย, สร้างและจัดการ string array รวมถึงเรียงลำดับข้อมูลใน array, และแก้ไข/ประกอบ string ที่ซับซ้อนจากหลายแหล่ง ข้อมูลพร้อมจัดรูปแบบสำหรับแสดงผล

คุณส่งมอบฟีเจอร์ให้ทีม Contoso Pets ได้แก่: รวบรวมคำค้นหาหลายคำจากผู้ใช้, เก็บคำค้นหาไว้ใน array ที่เรียงลำดับแล้ว, แสดงสุนัขที่มีคำตรงกัน, และแอนิเมชันสถานะการค้นหาที่ปรับปรุงแล้วพร้อม การนับถอยหลัง
