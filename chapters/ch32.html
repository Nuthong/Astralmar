32.1 สถานการณ์และสเปก

การสร้างเกมของตัวเองเป็นวิธีที่น่าตื่นเต้นในการฝึกทักษะการเขียนโปรแกรม เกมพึ่งพาการประมวลผล input จากผู้ใช้อย่างมาก เพื่อตัดสินใจแบบไดนามิก เกมทุกเกมยังต้องมีชุดกฎที่กำหนดไว้ชัดเจน ที่ตัดสินการกระทำและเหตุการณ์ในเกม

สมมติคุณอยากสร้างเกมของตัวเอง คุณอาจยังไม่พร้อมพัฒนาเกมที่มีฟีเจอร์ครบเต็มรูปแบบ จึงตัดสินใจ เริ่มจากเล็กที่สุดเท่าที่จะทำได้ คุณอยากขยับตัวละครไปทั่วหน้าจอ และทำให้มันกินวัตถุได้ วัตถุที่ กินเข้าไปส่งผลต่อสถานะของผู้เล่นได้ เพื่อให้เกมดำเนินต่อไปได้ คุณอยากให้วัตถุนั้น regenerate (สร้างใหม่) ในตำแหน่งใหม่หลังถูกกินไปแล้ว คุณตัดสินใจว่าต้องใช้ method จัดระเบียบโค้ดเกมของคุณ

ในโมดูลนี้ คุณจะพัฒนาฟีเจอร์ต่อไปนี้ของแอปมินิเกม:

  • ฟีเจอร์ตัดสินว่าผู้เล่นกินอาหารหรือไม่
  • ฟีเจอร์อัปเดตสถานะผู้เล่นตามอาหารที่กิน
  • ฟีเจอร์หยุดความเร็วการเคลื่อนที่ชั่วคราวตามอาหารที่กิน
  • ฟีเจอร์สร้างอาหารใหม่ในตำแหน่งใหม่
  • ตัวเลือกจบเกมถ้ากดปุ่มที่ไม่รองรับ
  • ฟีเจอร์จบเกมถ้าหน้าต่าง Terminal ถูกปรับขนาด

สเปกจาก MS Learn (คำบรรยาย starter code)

โค้ดตั้งต้นตามคำบรรยายของ MS Learn ประกอบด้วย:

  • ตัวแปร: ขนาดหน้าต่าง Terminal, ตำแหน่งของผู้เล่นและอาหาร, array states และ foods เก็บรูปลักษณ์ที่เป็นไปได้ของผู้เล่นและอาหาร, ตัวแปรติดตามรูปลักษณ์ปัจจุบันของผู้เล่นและอาหาร
  • Method ที่มีอยู่แล้ว: เช็คว่าหน้าต่าง Terminal ถูกปรับขนาดไหม, แสดงรูปลักษณ์อาหารสุ่ม ที่ตำแหน่งสุ่ม, เปลี่ยนรูปลักษณ์ผู้เล่นให้ตรงกับอาหารที่กิน, หยุดการเคลื่อนที่ของผู้เล่น ชั่วคราว, ขยับผู้เล่นตาม input ทิศทาง, ตั้งค่าสถานะเริ่มต้นของเกม
  • สิ่งที่ยังขาด (งานของคุณ): เช็คว่าผู้เล่นกินอาหารที่แสดงอยู่หรือไม่, เช็คว่าอาหารที่ กินควรหยุดการเคลื่อนที่ของผู้เล่นไหม, เช็คว่าอาหารที่กินควรเพิ่มความเร็วการเคลื่อนที่ไหม, เพิ่มความเร็วการเคลื่อนที่, แสดงอาหารใหม่หลังถูกกิน, จบการทำงานถ้ากดปุ่มที่ไม่รองรับ, จบ การทำงานถ้า terminal ถูกปรับขนาด

สเปกรายละเอียดเพิ่มเติมจาก 3 แบบฝึกหัดของโมดูลนี้:

  • จบเกมถ้าปรับขนาดหน้าต่าง: เช็คว่า terminal ถูกปรับขนาดก่อนให้เกมทำงานต่อ ล้างหน้าจอ และจบเกมถ้าปรับขนาด แสดงข้อความ "Console was resized. Program exiting." ก่อนจบโปรแกรม
  • เพิ่มตัวเลือกจบเกม: ปรับ method Move ที่มีอยู่แล้วให้รองรับ optional parameter — ถ้าเปิดใช้งาน parameter นี้ควรตรวจจับปุ่มที่ไม่ใช่ทิศทาง ถ้าเจอปุ่มแบบนั้น ให้เกมจบได้
  • ตรวจว่าผู้เล่นกินอาหารหรือไม่: สร้าง method ใช้ตัวแปรตำแหน่งของผู้เล่นและอาหารที่มี อยู่แล้ว method ต้องคืนค่า หลังผู้เล่นขยับ เรียก method นี้ตัดสินว่าควรเรียก method เปลี่ยนรูปลักษณ์ผู้เล่นและ method แสดงอาหารใหม่หรือไม่
  • ตรวจว่าผู้เล่นควรหยุดนิ่ง: สร้าง method เช็คว่ารูปลักษณ์ผู้เล่นปัจจุบันคือ (X_X) ไหม (เกิดจากกินอาหารค่า #####) method ต้องคืนค่า ก่อน ยอมให้ผู้เล่นขยับ เรียก method นี้ตัดสินว่าควรเรียก method หยุดการเคลื่อนที่หรือไม่ (หยุด แค่ชั่วคราวเท่านั้น ผู้เล่นต้องขยับต่อได้หลังจากนั้น)
  • เพิ่มตัวเลือกเพิ่มความเร็ว: ปรับ method Move ให้รองรับ optional parameter ความเร็วการเคลื่อนที่ ใช้เพิ่ม/ลดความเร็วซ้าย-ขวาทีละ 3 สร้าง method เช็คว่า รูปลักษณ์ผู้เล่นปัจจุบันคือ (^-^) ไหม แล้วเรียก method นี้ตัดสินว่า Move ควรใช้พารามิเตอร์ความเร็วหรือไม่
💡 นี่คือ Challenge Project — ลองออกแบบเองก่อน แม้บทนี้จะไม่มีโค้ดตั้งต้นให้ก็ตาม ลองปิดหนังสือแล้วร่างโครงสร้างเกมของคุณเองดูก่อนก็ได้ — ลอง คิดว่าคุณจะเก็บตำแหน่งผู้เล่น/อาหารยังไง จะรับ input ทิศทางยังไง (ใบ้: Console.ReadKey()) และจะตรวจจับการปรับขนาดหน้าต่างยังไง (ใบ้: Console.WindowWidth/ WindowHeight)

32.2 🔓 การออกแบบของผม — โครงสร้างเกมและ Method ที่มีอยู่แล้ว

ผมออกแบบเกมให้เป็น ASCII art ง่ายๆ บนหน้าจอ Terminal — ตัวละครผู้เล่นเป็นหน้ายิ้มแบบ text เช่น ('-') เคลื่อนที่ด้วยปุ่มลูกศร อาหารเป็น string สัญลักษณ์ เช่น ##### ปรากฏที่ตำแหน่งสุ่มบนจอ

Program.cs (ตัวแปรตั้งต้น) 
int windowWidth = Console.WindowWidth;
int windowHeight = Console.WindowHeight;

int playerRow;
int playerCol;
int foodRow;
int foodCol;

string[] foods  = { "*****", "#####", "+++++" };
string[] states = { "('-')", "(X_X)", "(^-^)" };

string currentState = states[0];
int currentFoodIndex = 0;

bool gameOver = false;

ผมออกแบบ foods กับ states เป็น array คู่ขนาน (parallel array — ทบทวนจาก บทที่ 12) — index เดียวกันแทนความสัมพันธ์กัน:

Indexfoods[i]states[i]ผลเมื่อกิน
0*****('-')ปกติ ไม่มีผลพิเศษ
1#####(X_X)หยุดนิ่งชั่วคราว
2+++++(^-^)เคลื่อนที่ซ้าย-ขวาเร็วขึ้น

ต่อไปนี้คือ method ที่ผมถือว่า "มีอยู่แล้ว" ตามที่สเปกบรรยายไว้ (เขียนขึ้นเองให้ตรงตามคำอธิบาย):

Program.cs (method ที่ "มีอยู่แล้ว") 
// เช็คว่าหน้าต่าง Terminal ถูกปรับขนาดไหม
bool IsResized()
{
    return Console.WindowWidth != windowWidth || Console.WindowHeight != windowHeight;
}

// แสดงรูปลักษณ์อาหารสุ่มที่ตำแหน่งสุ่ม
void DisplayFood()
{
    Random random = new Random();
    currentFoodIndex = random.Next(foods.Length);
    foodRow = random.Next(1, windowHeight - 1);
    foodCol = random.Next(1, windowWidth - foods[currentFoodIndex].Length - 1);

    Console.SetCursorPosition(foodCol, foodRow);
    Console.Write(foods[currentFoodIndex]);
}

// เปลี่ยนรูปลักษณ์ผู้เล่นให้ตรงกับอาหารที่กิน
void ChangeAppearance(int foodIndex)
{
    currentState = states[foodIndex];
}

// หยุดการเคลื่อนที่ของผู้เล่นชั่วคราว
void FreezePlayer()
{
    Console.SetCursorPosition(0, 0);
    Console.Write("Frozen!   ");
    System.Threading.Thread.Sleep(1500);
    Console.SetCursorPosition(0, 0);
    Console.Write("          ");
}

// ขยับผู้เล่นตาม input ทิศทาง
void Move(ConsoleKey key)
{
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(new string(' ', currentState.Length));

    switch (key)
    {
        case ConsoleKey.UpArrow:
            playerRow = Math.Max(1, playerRow - 1);
            break;
        case ConsoleKey.DownArrow:
            playerRow = Math.Min(windowHeight - 1, playerRow + 1);
            break;
        case ConsoleKey.LeftArrow:
            playerCol = Math.Max(0, playerCol - 1);
            break;
        case ConsoleKey.RightArrow:
            playerCol = Math.Min(windowWidth - currentState.Length, playerCol + 1);
            break;
    }

    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}

// ตั้งค่าสถานะเริ่มต้นของเกม
void Setup()
{
    Console.Clear();
    Console.CursorVisible = false;
    playerRow = windowHeight / 2;
    playerCol = windowWidth / 2;
    DisplayFood();
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}
ℹ️ Console.SetCursorPosition คืออะไร Console.SetCursorPosition(col, row) ย้าย cursor ของ Terminal ไปยังตำแหน่งคอลัมน์ และแถวที่กำหนด (ทั้งสองค่าเริ่มนับที่ 0) — บรรทัดถัดไปที่ Console.Write() ทำงาน จะเขียนทับตำแหน่งนั้นแทนที่จะขึ้นบรรทัดใหม่แบบปกติ นี่คือกลไกหลักที่ทำให้ตัวละคร "เคลื่อนที่" บนหน้าจอได้ — เขียนช่องว่างทับตำแหน่งเก่าก่อน (ลบภาพเดิม) แล้วค่อยเขียนตัวละครที่ตำแหน่งใหม่

32.3 🔓 เฉลยของผม — จบเกมเมื่อ Resize หรือกดปุ่มไม่ถูกต้อง

งานแรกคือให้เกมจบได้ 2 ทาง: (1) หน้าต่าง Terminal ถูกปรับขนาด (2) ผู้เล่นกดปุ่มที่ไม่ใช่ปุ่ม ทิศทาง — งานแรกเช็คใน main loop ตรงๆ งานที่สองต้องปรับ Move() ให้รองรับ optional parameter

Program.cs (ปรับ Move ให้รองรับ checkTermination) 
void Move(ConsoleKey key, bool checkTermination = true)
{
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(new string(' ', currentState.Length));

    switch (key)
    {
        case ConsoleKey.UpArrow:
            playerRow = Math.Max(1, playerRow - 1);
            break;
        case ConsoleKey.DownArrow:
            playerRow = Math.Min(windowHeight - 1, playerRow + 1);
            break;
        case ConsoleKey.LeftArrow:
            playerCol = Math.Max(0, playerCol - 1);
            break;
        case ConsoleKey.RightArrow:
            playerCol = Math.Min(windowWidth - currentState.Length, playerCol + 1);
            break;
        default:
            if (checkTermination)
            {
                gameOver = true;
            }
            break;
    }

    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}

สังเกตว่าผมเพิ่มแค่ default: case เข้าไปใน switch เดิม (ทบทวนหลัก การ switch จาก บทที่ 16) — ถ้าปุ่มที่กดไม่ตรงกับ 4 ทิศทางเลย และ checkTermination เป็น true (ค่า default) จะตั้ง global variable gameOver เป็น true

ต่อไป main loop ที่เช็ค resize ก่อน ประมวลผลการเคลื่อนที่ทุกครั้ง:

Program.cs 
Setup();

while (!gameOver)
{
    if (IsResized())
    {
        Console.Clear();
        Console.WriteLine("Console was resized. Program exiting.");
        break;
    }

    ConsoleKeyInfo keyInfo = Console.ReadKey(true);
    Move(keyInfo.Key);
}

สังเกตว่าใช้ Console.ReadKey(true) — argument true บอกว่าไม่ต้อง echo ตัวอักษรที่กดกลับไปที่หน้าจอ (ไม่งั้นตัวอักษรจะไปรบกวนภาพเกม) เมธอดนี้บล็อกโปรแกรมรอ จนกว่าผู้เล่นจะกดปุ่มใดปุ่มหนึ่ง — คืน ConsoleKeyInfo ที่มี property .Key เป็นค่า enum ConsoleKey บอกว่ากดปุ่มไหน

💡 ทดสอบเปิด/ปิด optional parameter ทดสอบตามสเปก: เปิดใช้งาน — เรียก Move(keyInfo.Key) ตรงๆ (ใช้ค่า default true) กดปุ่มที่ไม่ใช่ทิศทาง เกมควรจบ — ปิดใช้งาน — เปลี่ยนเป็น Move(keyInfo.Key, false) กดปุ่มที่ไม่ใช่ทิศทาง เกมควรทำงานต่อ (ไม่มีอะไรเกิดขึ้น เพราะไม่เข้าเงื่อนไข switch ไหนเลย) แต่ยังคงจบเกมได้ถ้าปรับขนาดหน้าต่าง เพราะ IsResized() เช็คแยกจากพารามิเตอร์นี้โดยสิ้นเชิง

32.4 🔓 เฉลยของผม — ให้ผู้เล่นกินอาหารได้

ตอนนี้เกมจบได้แล้ว แต่ผู้เล่นยังกินอาหารไม่ได้เลย — สร้าง method เช็คว่าผู้เล่นอยู่ตำแหน่ง เดียวกับอาหารหรือไม่:

Program.cs 
bool ConsumedFood()
{
    bool sameRow = playerRow == foodRow;
    bool overlapsCol = playerCol >= foodCol && playerCol < foodCol + foods[currentFoodIndex].Length;
    return sameRow && overlapsCol;
}

เพราะทั้งผู้เล่นและอาหารเป็น string หลายตัวอักษร (ไม่ใช่จุดเดียว) ผมเช็คว่าผู้เล่นอยู่แถว เดียวกับอาหาร (sameRow) และตำแหน่งคอลัมน์ของผู้เล่นอยู่ในช่วงความกว้างของ string อาหาร (overlapsCol) — ถือว่า "กิน" ถ้าทั้งสองเงื่อนไขเป็นจริงพร้อมกัน

เชื่อม method นี้เข้ากับ main loop หลังผู้เล่นขยับทุกครั้ง:

Program.cs 
Setup();

while (!gameOver)
{
    if (IsResized())
    {
        Console.Clear();
        Console.WriteLine("Console was resized. Program exiting.");
        break;
    }

    ConsoleKeyInfo keyInfo = Console.ReadKey(true);
    int eatenFoodIndex = currentFoodIndex;

    Move(keyInfo.Key);

    if (gameOver) break;

    if (ConsumedFood())
    {
        ChangeAppearance(eatenFoodIndex);
        DisplayFood();
    }
}
⚠️ ทำไมต้องเก็บ eatenFoodIndex ไว้ก่อน Move() สังเกตว่าผมเก็บค่า currentFoodIndex ไว้ในตัวแปร eatenFoodIndex ก่อนเรียก Move() — เพราะถ้าผู้เล่นกินอาหารสำเร็จ โค้ดจะเรียก DisplayFood() ซึ่งเปลี่ยนค่า currentFoodIndex เป็นอาหารชิ้นใหม่ทันที ถ้าเรียก ChangeAppearance(currentFoodIndex) ตรงๆ หลัง DisplayFood() จะได้รูปลักษณ์ของอาหารชิ้นใหม่ (ที่ยังไม่ถูกกิน) ไม่ใช่อาหารชิ้นที่เพิ่งกินไป — ต้องเก็บค่าดักไว้ก่อนเสมอเมื่อค่านั้นจะถูกเปลี่ยนโดย method ที่เรียกทีหลัง (ทบทวนแนวคิด execution order จาก บทที่ 28)

32.5 🔓 เฉลยของผม — ปรับการเคลื่อนที่ตามอาหารที่กิน

ตอนนี้เกมเล่นได้ กินอาหารได้ เปลี่ยนรูปลักษณ์ได้ — แต่รูปลักษณ์ยังไม่ส่งผลอะไรต่อการเล่นเลย งานสุดท้ายคือทำให้อาหาร ##### (สถานะ (X_X)) หยุดผู้เล่นชั่วคราว และอาหาร +++++ (สถานะ (^-^)) เพิ่มความเร็วซ้าย-ขวา

Program.cs 
bool ShouldFreeze()
{
    return currentState == "(X_X)";
}

bool ShouldSpeedUp()
{
    return currentState == "(^-^)";
}

ปรับ Move() อีกครั้ง เพิ่ม optional parameter ความเร็ว:

Program.cs (Move ฉบับสมบูรณ์) 
void Move(ConsoleKey key, bool checkTermination = true, int speed = 1)
{
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(new string(' ', currentState.Length));

    switch (key)
    {
        case ConsoleKey.UpArrow:
            playerRow = Math.Max(1, playerRow - 1);
            break;
        case ConsoleKey.DownArrow:
            playerRow = Math.Min(windowHeight - 1, playerRow + 1);
            break;
        case ConsoleKey.LeftArrow:
            playerCol = Math.Max(0, playerCol - speed);
            break;
        case ConsoleKey.RightArrow:
            playerCol = Math.Min(windowWidth - currentState.Length, playerCol + speed);
            break;
        default:
            if (checkTermination)
            {
                gameOver = true;
            }
            break;
    }

    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}

สเปกบอกว่า "เพิ่ม/ลดความเร็วซ้าย-ขวาทีละ 3" — ผมตีความว่าหมายถึง speed เพิ่มขึ้นจากค่าปกติ 1 เป็น 1+3 = 4 ตอนสถานะเป็น (^-^) เท่านั้น (ไม่กระทบการขยับขึ้น-ลง)

อัปเดต main loop ให้เช็คทั้งสองสถานะก่อนเรียก Move():

Program.cs (ฉบับสมบูรณ์) 
Setup();

while (!gameOver)
{
    if (IsResized())
    {
        Console.Clear();
        Console.WriteLine("Console was resized. Program exiting.");
        break;
    }

    if (ShouldFreeze())
    {
        FreezePlayer();
    }

    ConsoleKeyInfo keyInfo = Console.ReadKey(true);
    int eatenFoodIndex = currentFoodIndex;

    int moveSpeed = ShouldSpeedUp() ? 4 : 1;
    Move(keyInfo.Key, checkTermination: true, speed: moveSpeed);

    if (gameOver) break;

    if (ConsumedFood())
    {
        ChangeAppearance(eatenFoodIndex);
        DisplayFood();
    }
}

สังเกตว่าผมใช้ named argument (ทบทวนจาก บทที่ 29) ตอนเรียก Move(keyInfo.Key, checkTermination: true, speed: moveSpeed) — ทำให้อ่านโค้ด เข้าใจง่ายขึ้นมาก ว่า argument แต่ละตัวคืออะไร แทนที่จะพึ่ง positional argument ล้วนๆ ซึ่งอาจ สับสนได้ง่ายเมื่อมีพารามิเตอร์ประเภทเดียวกันหลายตัว (ในที่นี้คือ bool กับ int ซึ่งไม่ชนกัน แต่การตั้งชื่อชัดๆ ก็ยังช่วยความอ่านง่ายอยู่ดี)

ตรวจสอบว่า ShouldFreeze() ทำให้ผู้เล่นหยุดแค่ชั่วคราวจริง (ไม่ใช่ค้างถาวร) — เพราะ FreezePlayer() ใช้ Thread.Sleep(1500) แค่หน่วงเวลาไว้ 1.5 วินาทีแล้วปล่อยให้โปรแกรมทำงานต่อตามปกติ พอ loop วนกลับมาอ่าน key ใหม่ ผู้เล่นก็ขยับต่อได้ เหมือนเดิม ไม่ค้างตลอดไป

💡 ทดสอบเปิด/ปิด Speed Boost ทดสอบตามสเปก: เปิดใช้งาน — moveSpeed = ShouldSpeedUp() ? 4 : 1; ทำงานตามปกติ สถานะ (^-^) ควรขยับซ้าย-ขวาได้ไกลกว่าปกติต่อการกดหนึ่งครั้ง — ปิดใช้งาน — เปลี่ยน เป็น int moveSpeed = 1; ตรงๆ (ไม่เรียก ShouldSpeedUp() เลย) ความเร็ว ควรเป็นปกติเสมอไม่ว่าสถานะจะเป็นอะไร

32.6 🔓 โค้ดฉบับเต็ม (Program.cs)

🔓 ดู Program.cs ฉบับเต็ม
Program.cs 
int windowWidth = Console.WindowWidth;
int windowHeight = Console.WindowHeight;

int playerRow;
int playerCol;
int foodRow;
int foodCol;

string[] foods  = { "*****", "#####", "+++++" };
string[] states = { "('-')", "(X_X)", "(^-^)" };

string currentState = states[0];
int currentFoodIndex = 0;

bool gameOver = false;

Setup();

while (!gameOver)
{
    if (IsResized())
    {
        Console.Clear();
        Console.WriteLine("Console was resized. Program exiting.");
        break;
    }

    if (ShouldFreeze())
    {
        FreezePlayer();
    }

    ConsoleKeyInfo keyInfo = Console.ReadKey(true);
    int eatenFoodIndex = currentFoodIndex;

    int moveSpeed = ShouldSpeedUp() ? 4 : 1;
    Move(keyInfo.Key, checkTermination: true, speed: moveSpeed);

    if (gameOver) break;

    if (ConsumedFood())
    {
        ChangeAppearance(eatenFoodIndex);
        DisplayFood();
    }
}

bool IsResized()
{
    return Console.WindowWidth != windowWidth || Console.WindowHeight != windowHeight;
}

void DisplayFood()
{
    Random random = new Random();
    currentFoodIndex = random.Next(foods.Length);
    foodRow = random.Next(1, windowHeight - 1);
    foodCol = random.Next(1, windowWidth - foods[currentFoodIndex].Length - 1);

    Console.SetCursorPosition(foodCol, foodRow);
    Console.Write(foods[currentFoodIndex]);
}

void ChangeAppearance(int foodIndex)
{
    currentState = states[foodIndex];
}

void FreezePlayer()
{
    Console.SetCursorPosition(0, 0);
    Console.Write("Frozen!   ");
    System.Threading.Thread.Sleep(1500);
    Console.SetCursorPosition(0, 0);
    Console.Write("          ");
}

void Move(ConsoleKey key, bool checkTermination = true, int speed = 1)
{
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(new string(' ', currentState.Length));

    switch (key)
    {
        case ConsoleKey.UpArrow:
            playerRow = Math.Max(1, playerRow - 1);
            break;
        case ConsoleKey.DownArrow:
            playerRow = Math.Min(windowHeight - 1, playerRow + 1);
            break;
        case ConsoleKey.LeftArrow:
            playerCol = Math.Max(0, playerCol - speed);
            break;
        case ConsoleKey.RightArrow:
            playerCol = Math.Min(windowWidth - currentState.Length, playerCol + speed);
            break;
        default:
            if (checkTermination)
            {
                gameOver = true;
            }
            break;
    }

    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}

void Setup()
{
    Console.Clear();
    Console.CursorVisible = false;
    playerRow = windowHeight / 2;
    playerCol = windowWidth / 2;
    DisplayFood();
    Console.SetCursorPosition(playerCol, playerRow);
    Console.Write(currentState);
}

bool ConsumedFood()
{
    bool sameRow = playerRow == foodRow;
    bool overlapsCol = playerCol >= foodCol && playerCol < foodCol + foods[currentFoodIndex].Length;
    return sameRow && overlapsCol;
}

bool ShouldFreeze()
{
    return currentState == "(X_X)";
}

bool ShouldSpeedUp()
{
    return currentState == "(^-^)";
}

32.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
ตัวละครวาดเป็นเส้นยาวลงมาเรื่อยๆ แทนที่จะเคลื่อนที่อยู่ตำแหน่งเดียว ลืมเรียก Console.SetCursorPosition() ก่อน Console.Write() ทุกครั้ง — ถ้าไม่ตั้งตำแหน่ง cursor ก่อน มันจะเขียนต่อจากตำแหน่งเดิมแล้วขึ้นบรรทัดใหม่ ตามปกติของ console ธรรมดา
รูปลักษณ์ผู้เล่นเปลี่ยนเป็นอาหารชิ้นถัดไปแทนที่จะเป็นชิ้นที่เพิ่งกิน เรียก ChangeAppearance(currentFoodIndex) หลัง DisplayFood() เปลี่ยนค่า currentFoodIndex ไปแล้ว — ต้องเก็บ ค่าดักไว้ในตัวแปรก่อนเสมอ (ทบทวนหัวข้อ 32.4)
ผู้เล่นค้างนิ่งตลอดไปหลังกินอาหาร ##### ไม่ใช่บั๊ก ถ้าดีไซน์ถูกต้อง — FreezePlayer() ใช้แค่ Thread.Sleep() หน่วงเวลาชั่วคราว ไม่ได้ตั้ง flag ค้างถาวรใดๆ ถ้าค้างจริง ให้ตรวจว่าไม่มีโค้ดอื่นตั้งค่า currentState เป็น (X_X) ซ้ำ อยู่เรื่อยๆ
IndexOutOfRangeException ตอนแสดงอาหารใกล้ขอบจอ สุ่มตำแหน่ง foodCol ไม่ได้เผื่อความยาวของ string อาหารไว้ — ต้องใช้ random.Next(1, windowWidth - foods[currentFoodIndex].Length - 1) ไม่ใช่ random.Next(1, windowWidth - 1) เฉยๆ
เกมไม่จบทั้งที่ปรับขนาดหน้าต่างแล้ว เช็ค IsResized() วางอยู่หลัง Console.ReadKey() ซึ่ง เป็นคำสั่งที่บล็อกโปรแกรมรอ input — ต้องเช็คก่อนรอ input ทุกรอบของ loop เพื่อให้จับได้ เร็วที่สุด (แม้จะจับได้ "รอบถัดไป" อยู่ดีเพราะ ReadKey บล็อกอยู่ ก็ควรวางเช็คไว้จุดแรก สุดของ loop เสมอเป็นหลักปฏิบัติที่ดี)

1. นักพัฒนาต้องการสร้าง method เปรียบเทียบค่า 2 ค่า ข้อใดเป็น data type ที่ดีที่สุดให้ method นี้คืนค่า?

  • Aค่า double
  • Bไม่คืนอะไรเลย ควรเป็น void
  • Cค่า bool
เฉลย: ข้อ C. การเปรียบเทียบธรรมชาติแล้วให้ผลลัพธ์แบบ "จริงหรือเท็จ" (เช่น เท่ากันไหม มากกว่าไหม) bool จึงเป็น return type ที่เหมาะสมที่สุด ตรงกับ method อย่าง ShouldFreeze() และ ShouldSpeedUp() ในบทนี้

2. นักพัฒนาต้องการสร้าง method ที่คืนค่าหนึ่งค่าใน array ข้อใดเป็น method signature ที่ดี?

  • Astring GetValueAtIndex(string[] array, int index)
  • Bbool GetValueAtIndex(string[] array, int index)
  • Cint GetValueAtIndex(int index)
เฉลย: ข้อ A. ต้องรับทั้ง array และ index มาเป็นพารามิเตอร์ (ข้อ C ขาด array เข้าไปเลย ไม่มีทางรู้ว่าจะดึงค่าจาก array ไหน) และ return type ต้องตรงกับชนิด element ใน array (string[] จึงควรคืน string ไม่ใช่ bool แบบข้อ B)

ข้อ 4กลาง

ดัดแปลง ConsumedFood() ให้เป็น method ที่ทดสอบได้ง่ายขึ้น โดยรับตำแหน่ง ผู้เล่นและอาหารเป็นพารามิเตอร์แทนที่จะอ่านจากตัวแปร global โดยตรง (เขียน signature ใหม่ พร้อมปรับจุดที่เรียกใช้ให้ตรงกัน)

ดูเฉลย
Program.cs
bool ConsumedFood(int pRow, int pCol, int fRow, int fCol, int fLength)
{
    bool sameRow = pRow == fRow;
    bool overlapsCol = pCol >= fCol && pCol < fCol + fLength;
    return sameRow && overlapsCol;
}

// จุดที่เรียกใช้:
if (ConsumedFood(playerRow, playerCol, foodRow, foodCol, foods[currentFoodIndex].Length))

    DisplayFood();

ข้อดีของการรับพารามิเตอร์แทนอ่าน global ตรงๆ คือทดสอบ method นี้แยกได้ง่ายขึ้นมาก (ป้อนค่าตำแหน่งสมมติเข้าไปตรวจผลลัพธ์ได้ โดยไม่ต้องรันเกมจริง) แต่ก็ต้องแลกกับการพิมพ์ argument ยาวขึ้นทุกครั้งที่เรียก — เป็น trade-off ที่นักพัฒนาต้องชั่งน้ำหนักเอง

ข้อ 6ท้าทาย

วิเคราะห์: โค้ดของผมเช็ค IsResized() ก่อน Console.ReadKey() ทุกรอบของ loop แต่ Console.ReadKey() เป็นคำสั่งที่บล็อกโปรแกรมรอ input ผู้ใช้ — ถ้าผู้ใช้ปรับขนาดหน้าต่างแล้วไม่กดปุ่มอะไรต่อเลย เกมจะจบทันทีไหม หรือต้องรอให้กดปุ่มก่อน? อธิบายเหตุผล แล้วลองเสนอวิธีแก้ถ้าต้องการให้เกมจบทันทีที่ resize (ไม่ต้องรอกดปุ่ม)

ดูเฉลย

เกมจะไม่จบทันที — ต้องรอให้ผู้ใช้กดปุ่มก่อน เพราะ Console.ReadKey() เป็นคำสั่ง blocking ที่หยุดโปรแกรมไว้ตรงนั้นจนกว่าจะมี key event เข้ามา โค้ดที่เช็ค IsResized() จะไม่ได้ทำงานอีกครั้งจนกว่า ReadKey() รอบปัจจุบัน จะคืนค่ากลับมา (คือหลังกดปุ่มแล้ว) — วิธีแก้จริงต้องใช้เทคนิคขั้นสูงกว่านี้ เช่น รันการ เช็ค resize บน background thread แยกต่างหาก (ใช้ System.Threading.Tasks หรือ Timer) ที่ตรวจสอบทุกๆ ช่วงเวลาสั้นๆ โดยไม่ขึ้นกับว่า main thread กำลังรอ ReadKey() อยู่หรือไม่ — เนื้อหานี้อยู่นอกขอบเขตของ Foundational C# แต่เป็นตัวอย่างที่ดีว่าเมื่อโปรแกรมโตขึ้น บางครั้งก็ต้องพึ่งแนวคิดเรื่อง concurrency (การทำงานพร้อมกันหลาย thread) ด้วย

เป้าหมายของคุณคือแสดงความสามารถในการพัฒนาฟีเจอร์ของแอปพลิเคชันให้บรรลุตามสเปกที่ออกแบบไว้ คุณ ต้องถอดรหัสโค้ดเกมที่มีอยู่แล้ว (หรือในกรณีของบทนี้ ออกแบบมันขึ้นเองจากคำบรรยาย) เพื่อตัดสินใจ ปรับแก้และเพิ่มเติมโค้ดอย่างมีข้อมูลรองรับ

ด้วยการสร้าง method ใหม่ เพิ่ม optional parameter และใช้โค้ดที่มีอยู่แล้ว คุณสร้างมินิเกมที่ ทำงานได้จริงและสนุกขึ้นมาสำเร็จ! ความสามารถในการ implement ฟีเจอร์ของแอปมินิเกมนี้ตามสเปกการ ออกแบบ แสดงให้เห็นว่าคุณสร้างและเรียกใช้ method ได้อย่างแท้จริงแล้ว
