7.1 ทำไมต้องใช้ IDE

การพัฒนาซอฟต์แวร์ไม่ใช่แค่การเขียนโค้ด แต่เป็นกระบวนการ โปรเจกต์ใหญ่ๆ อาจใช้เวลา เป็นเดือนหรือเป็นปีและซับซ้อนมาก กระบวนการเขียน ดีบั๊ก ทดสอบ อัปเดต/versioning และปล่อย โค้ด เป็นงานใหญ่มาก เพื่อช่วยกระบวนการนี้ นักพัฒนาใช้เครื่องมือเฉพาะทางที่เรียกว่า Integrated Development Environment (IDE)

IDE มักมีชุดเครื่องมือที่รองรับกระบวนการพัฒนาซอฟต์แวร์ตั้งแต่ต้นจนจบ (เรียกว่า development lifecycle) ช่วยให้นักพัฒนาคนเดียวหรือทีมทำงานได้มีประสิทธิภาพขึ้นมาก IDE ที่ดีคือเพื่อนคู่ใจของโปรแกรมเมอร์

สมมติคุณสนใจเริ่มพัฒนาแอป C# จริงจัง ขั้นแรกคือเลือกสภาพแวดล้อมการเขียนโปรแกรม หลังค้นข้อมูลออนไลน์ คุณพบว่า Visual Studio Code เป็นหนึ่งใน code editor ที่นิยม ที่สุดในหมู่นักพัฒนา C# ติดตั้งง่ายรวดเร็ว และรองรับ extension มากมายที่ช่วยเพิ่ม ประสิทธิภาพการทำงาน (ยังมี Visual Studio ตัวเต็มที่มีฟีเจอร์เยอะกว่าสำหรับมืออาชีพด้วย ทั้งสองตัวมีเวอร์ชันฟรีให้ใช้) ในบทนี้คุณจะติดตั้งและตั้งค่า VS Code ให้พร้อมใช้งานจริง

7.2 ลงมือ: ดาวน์โหลดและติดตั้ง VS Code

Visual Studio Code เป็น source code editor ที่เบาแต่ทรงพลัง ใช้ได้ทั้ง Windows, macOS, และ Linux รองรับ JavaScript/TypeScript/Node.js ในตัว และมี extension มากมายสำหรับภาษาอื่นๆ (C++, C#, Java, Python, PHP, Go, .NET)

ดาวน์โหลด

  1. เปิดเบราว์เซอร์ ไปที่ code.visualstudio.com
  2. กดปุ่ม Download for Windows (เว็บจะตรวจจับระบบปฏิบัติการให้อัตโนมัติ)
  3. รอไฟล์ติดตั้งดาวน์โหลดเสร็จ — ชื่อไฟล์จะคล้าย VSCodeUserSetup-x64-1.9x.x.exe

ติดตั้ง

  1. เปิด File Explorer ไปที่โฟลเดอร์ Downloads
  2. ดับเบิลคลิกไฟล์ติดตั้งที่ดาวน์โหลดมา
  3. ติ๊ก I accept the license agreement แล้วกด Next ไปเรื่อยๆ ใช้ค่าเริ่มต้นทั้งหมด
  4. ถ้าเปิด VS Code ขึ้นมาตอนจบการติดตั้ง ให้ปิดไปก่อน (จะมาสำรวจกันในหัวข้อถัดไป)
ℹ️ User Installer กับ System Installer ตอนติดตั้งอาจมีให้เลือก 2 แบบ — User Installer ติดตั้งให้แค่ผู้ใช้ปัจจุบัน (แนะนำ สำหรับคนส่วนใหญ่) ส่วน System Installer ติดตั้งให้ทุกบัญชีผู้ใช้ในเครื่อง

7.3 รู้จักหน้าตา VS Code

โดยพื้นฐาน VS Code คือ code editor ที่มี UI คล้ายกับ editor อื่นๆ ทั่วไป ฝั่งซ้ายเป็น side bar สำหรับเข้าถึงไฟล์/โฟลเดอร์ในโปรเจกต์ ฝั่งขวาเป็นพื้นที่ editor แสดงเนื้อหาไฟล์

ส่วนชื่อหน้าที่
AActivity Barแถบแนวตั้งซ้ายสุด สลับมุมมอง (Explorer, Extensions ฯลฯ) และตัวชี้บริบทอื่นๆ
BSide Barแสดงเครื่องมือ/ทรัพยากรตามมุมมองที่เลือกจาก Activity Bar
CEditorพื้นที่แก้ไขไฟล์ เปิดได้หลายไฟล์พร้อมกัน ทั้งแนวตั้งและแนวนอน
DPanelแสดงผลลัพธ์/ดีบั๊ก/error/warning หรือ terminal ที่ฝังในตัว
EStatus Barแถบแนวนอนล่างสุด แสดงข้อมูลโปรเจกต์และไฟล์ที่กำลังแก้
FMain Menuเมนูบนสุด ใช้บันทึก แก้ไข รันโค้ด และอื่นๆ

ตอนเริ่มต้น ส่วนที่สำคัญที่สุดที่ต้องจำคือ Activity Bar (เลือกกิจกรรม), Side Bar (เครื่องมือ/ตัวเลือก) และ Editor (แก้ไขโค้ด) — ส่วนอื่นๆ จะคุ้นเคยขึ้นเอง เมื่อใช้งานบ่อยขึ้น

7.4 ลงมือ: สำรวจหน้าตา VS Code

เปิด VS Code และหน้า Welcome

สำรวจ Activity Bar และ Side Bar

เอาเมาส์ไปวางบนไอคอนแต่ละอันใน Activity Bar จะเห็น label โผล่ขึ้นมา ไล่จากบนลงล่าง ไอคอนคือ: Explorer, Search, Source Control, Run and Debug, Extensions, Accounts, และ Manage

สำรวจเมนูบนสุด

ℹ️ Command Palette — เครื่องมือที่คุ้มค่าจำที่สุด เปิดเมนู View → Command Palette (หรือกด Ctrl+Shift+P) แล้วพิมพ์ชื่อคำสั่งที่ ต้องการ เช่น พิมพ์ help แล้วเลือก Help: Interactive Editor Playground จะเปิดหน้าฝึกใช้ฟีเจอร์ต่างๆ แบบอินเทอร์แอกทีฟ Command Palette คือทางลัดสู่แทบทุกคำสั่งของ VS Code ยิ่งใช้บ่อย ยิ่งเร็ว

7.5 ลงมือ: ติดตั้ง Extension สำหรับ C#

Extension คือส่วนเสริมที่เพิ่มความสามารถให้ VS Code มีทั้ง extension ภาษา, ธีม, และฟีเจอร์ ใหม่ๆ VS Code รองรับการพัฒนา C# ผ่าน C# language extension ร่วมกับ .NET SDK

.NET SDK กับ .NET Runtime ต่างกันยังไง

.NET เป็นแพลตฟอร์มพัฒนาข้ามระบบปฏิบัติการ (cross-platform) แบบโอเพนซอร์ส ใช้พัฒนาแอปได้ หลายแบบ เขียนได้ทั้ง C#, F#, Visual Basic รันได้ทั้ง Windows, macOS, Linux

.NET runtime คือไลบรารีที่จำเป็นสำหรับรันแอป C# (บางทีเรียก Common Language Runtime หรือ CLR) — ไม่จำเป็นสำหรับเขียนโค้ด แต่จำเป็นสำหรับรันแอปจริง ส่วน .NET SDK (ที่คุณติดตั้งไปแล้วในบทที่ 0) มี runtime รวมอยู่ในตัว บวกกับเครื่องมือ สำหรับสร้างแอปด้วย

ติดตั้ง C# Dev Kit

  1. เปิด VS Code → คลิก Extensions บน Activity Bar
  2. ช่องค้นหา พิมพ์ C#
  3. เลือก extension ชื่อ "C# Dev Kit — Official C# extension from Microsoft" (ผู้พัฒนา Microsoft)
  4. กด Install รอประมาณ 30–40 วินาที ปุ่มจะเปลี่ยนเป็น Installed
⚠️ ระหว่างติดตั้งอาจเจอ notification 2 อัน อันที่ให้ "log in" — ข้ามไปได้เลย · อันที่บอกว่า "The .NET SDK cannot be located" — ปิดไปได้ เพราะคุณติดตั้ง .NET SDK ไว้แล้วตั้งแต่บทที่ 0 (VS Code แค่ยังไม่เจอ จะเจอเองหลังรีสตาร์ต terminal หรือเปิดโปรเจกต์ใหม่)

การติดตั้ง C# Dev Kit จะติดตั้ง extension ย่อยมาด้วย 3 ตัว:

  • .NET Install Tool — ติดตั้งและจัดการเวอร์ชันต่างๆ ของ .NET SDK/Runtime
  • C# — รองรับไวยากรณ์พื้นฐานของภาษา C#
  • C# Dev Kit — extension หลักจาก Microsoft
💡 อย่าลงเยอะเกินจำเป็น ไม่มีรางวัลให้คนลง extension เยอะที่สุด มี extension ดีๆ เยอะมาก แต่รอจนกว่าจะต้องใช้จริง ค่อยลงก็ได้

7.6 ลงมือ: เช็คและติดตั้ง .NET SDK ผ่าน VS Code

C# Dev Kit ช่วยติดตั้ง .NET SDK ให้ได้เช่นกัน — ในบทนี้เราจะเช็คว่าสิ่งที่คุณติดตั้งไว้ ในบทที่ 0 ยังใช้ได้ดี และรู้จักอีกวิธีติดตั้ง/จัดการเวอร์ชัน .NET ผ่านตัว VS Code เอง

เช็คว่ามี .NET ติดตั้งอยู่หรือยัง

  1. เมนู Terminal → New Terminal
  2. พิมพ์ dotnet --version กด Enter
  3. ถ้าเจอเลขเวอร์ชัน (เช่น 10.0.100) แปลว่าติดตั้งอยู่แล้ว — ถ้าจากบทที่ 0 ควรเจอตรงนี้แน่นอน
ℹ️ ณ วันที่เขียนบทนี้ .NET 10 คือรุ่น LTS (Long-Term Support) ล่าสุด แนะนำให้ใช้รุ่นนี้หรือใหม่กว่า .NET 8/9 ก็ยังใช้งานร่วมกับหลักสูตรนี้ได้เช่นกัน

ติดตั้ง/อัปเดตผ่าน Command Palette (ถ้าต้องการ)

ถ้าอยากติดตั้งเวอร์ชันใหม่ หรือยังไม่มีเลย ทำได้ผ่าน VS Code โดยตรง:

  1. View → Command Palette (หรือ Ctrl+Shift+P)
  2. พิมพ์ .NET: Install แล้วเลือก .NET: Install New .NET SDK
  3. เลือก Latest (.NET 10) → กด Install
  4. รอจนติดตั้งเสร็จ (อาจใช้เวลาหลายนาที) แล้วปิด VS Code

เปิด VS Code ใหม่ เปิด Terminal ใหม่ พิมพ์ dotnet --version อีกครั้งเพื่อยืนยัน (ต้องเปิด terminal ใหม่ หลังติดตั้ง ไม่งั้นจะยังตรวจไม่เจอ)

7.7 ลงมือ: สร้าง Build และ Run แอปด้วย VS Code

.NET SDK มี command-line interface (CLI) ที่เรียกผ่าน Terminal ในตัว VS Code ได้เลย ตลอดหลักสูตรนี้คุณจะใช้คำสั่ง .NET CLI สร้างแอปใหม่ build โค้ด และรันแอป

ตัวอย่างคำสั่งสร้างแอป console ใหม่ในโฟลเดอร์ที่กำหนด:

PowerShell / Terminal
dotnet new console -o ./CsharpProjects/TestProject

โครงสร้างคำสั่ง CLI มี 3 ส่วน:

  • driver — dotnet
  • command — new console
  • command arguments — -o ./CsharpProjects/TestProject (ตัวเลือกเสริม)
ℹ️ argument เป็นตัวเลือก ไม่ใส่ -o ... ก็รันได้ แค่ dotnet new console เฉยๆ — จะสร้างแอปที่ ตำแหน่งโฟลเดอร์ปัจจุบันแทน

สร้างแอปในโฟลเดอร์ที่กำหนด

  1. เปิด VS Code → เมนู File → Open Folder
  2. เลือกโฟลเดอร์ Desktop (หรือที่เก็บโปรเจกต์ของคุณ) → Select Folder
  3. ถ้ามี dialog ถามว่าเชื่อถือผู้เขียนไหม (Trust) เลือก Yes
  4. เมนู Terminal → New Terminal
  5. พิมพ์คำสั่ง:
Terminal 
dotnet new console -o ./CsharpProjects/TestProject

คำสั่งนี้สร้างโฟลเดอร์ CsharpProjects และ TestProject ให้อัตโนมัติ และตั้งชื่อไฟล์โปรเจกต์ TestProject.csproj ตามชื่อโฟลเดอร์

ในมุมมอง EXPLORER ขยายโฟลเดอร์ CsharpProjects → จะเห็นโฟลเดอร์ TestProject มีไฟล์ 2 อัน: Program.cs (โค้ด C#) และ TestProject.csproj (ไฟล์โปรเจกต์) คลิก Program.cs ดู — เป็นแอป "Hello World!" แบบเดิม:

TestProject/Program.cs
// See https://aka.ms/new-console-template for more information
Console.WriteLine("Hello, World!");

แก้ไข Build และ Run

  1. ใน EXPLORER คลิกขวาที่โฟลเดอร์ TestProject → เลือก Open in Integrated Terminal (เพื่อให้ Terminal อยู่ในโฟลเดอร์โปรเจกต์พอดี — สำคัญมาก ก่อนสั่ง build/run ต้องเช็คว่า Terminal อยู่ถูกโฟลเดอร์เสมอ)
  2. แก้บรรทัดโค้ดเป็น:
Program.cs 
Console.WriteLine("Hello C#!");

ครั้งแรกที่แก้ไฟล์ .cs อาจมี prompt ถาม "add missing assets to build and debug" — เลือก Yes ได้เลย

🛑 อย่าลืม Save กด Ctrl+S (หรือ File → Save) เสมอหลังแก้โค้ด — คอมไพเลอร์เห็นแค่สิ่งที่บันทึกแล้ว เท่านั้น ถ้าลืม save แล้วรัน จะได้ผลลัพธ์เป็นโค้ดเก่าที่ยังไม่ได้แก้

Build โปรเจกต์:

Terminal 
dotnet build

dotnet build คอมไพล์โปรเจกต์และ dependency ทั้งหมดเป็นชุดไบนารี รวมถึงไฟล์ Intermediate Language (IL) นามสกุล .dll ถ้าอยากรู้ ไฟล์ TestProject.dll จะอยู่ที่ประมาณ TestProject\bin\Debug\net10.0\

รันแอป:

Terminal 
dotnet run
Output
Hello C#!

dotnet run รันซอร์สโค้ดโดยไม่ต้องสั่ง compile/launch แยก — สะดวกมากสำหรับ การพัฒนาแบบวนซ้ำเร็วๆ จากบรรทัดคำสั่ง (แต่เบื้องหลังยังพึ่ง dotnet build ทำงานอยู่ดี)

⚠️ เห็น "Hello, World!" แทน "Hello C#!" ไหม? แปลว่าคุณลืม save ไฟล์ก่อนสั่ง build/run — กลับไป save แล้วรันใหม่

7.8 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
รัน dotnet build/dotnet run แล้ว error "ไม่พบไฟล์โปรเจกต์" Terminal ไม่ได้อยู่ในโฟลเดอร์โปรเจกต์ — ใช้ "Open in Integrated Terminal" จากเมนูคลิกขวา บนโฟลเดอร์โปรเจกต์เสมอ
แก้โค้ดแล้วรันยังได้ผลลัพธ์เดิม ลืม Ctrl+S บันทึกไฟล์ก่อนสั่ง build/run
ขึ้น notification "The .NET SDK cannot be located" หลังลง C# Dev Kit ปกติ ปิดได้เลย ถ้าเคยติดตั้ง .NET SDK ไว้แล้ว (เช่นบทที่ 0) VS Code จะเจอเองหลัง เปิด terminal ใหม่
dotnet --version ใน terminal ของ VS Code ไม่เจอคำสั่ง ต้องเปิด terminal ใหม่หลังติดตั้ง .NET SDK เสมอ (terminal เก่ายังจำ path เดิมอยู่)

เฉลย: ข้อ C. Editor คือพื้นที่แก้ไขไฟล์โดยตรง ส่วน Explorer ใช้ เรียกดูไฟล์/โฟลเดอร์ และ Extensions ใช้จัดการส่วนเสริม ไม่ใช่ที่เขียนโค้ด

2. เครื่องมือใดจำเป็นสำหรับรันคำสั่ง CLI อย่าง dotnet run?

  • AVisual Studio Code
  • BC# Dev Kit
  • C.NET SDK
เฉลย: ข้อ C. คำสั่ง dotnet มาจาก .NET SDK โดยตรง — VS Code เป็นแค่ editor ที่มี terminal ฝังอยู่ (รันได้แม้ไม่มี VS Code ผ่าน PowerShell ตรงๆ แบบที่ทำมาตั้งแต่บทที่ 0) ส่วน C# Dev Kit เป็นแค่ extension ที่ช่วยอำนวยความสะดวก ไม่ใช่สิ่งที่ CLI ต้องพึ่งพา

7.10 ✍️ แบบฝึกหัดท้ายบท

ข้อ 1ง่าย

ใน VS Code สร้างโปรเจกต์ใหม่ชื่อ ch07-practice ด้วยคำสั่ง dotnet new console -o ch07-practice ผ่าน Terminal ที่ฝังอยู่ในตัว (ไม่ใช่ PowerShell แยก) แล้ว build+run ให้เห็น Hello, World!

ดูเฉลย

ไม่มีโค้ดให้เฉลย เป็นแบบฝึกหัดลงมือทำจริง — เช็คจากผลลัพธ์ที่เห็นในเทอร์มินัลว่าตรงกับ "Hello, World!" หรือไม่

ข้อ 2ง่าย

เปิด Command Palette (Ctrl+Shift+P) แล้วหาคำสั่งที่ใช้เปลี่ยนธีมสี (พิมพ์ "theme") ลองเปลี่ยนดูว่ามีธีมอะไรให้เลือกบ้าง

ดูเฉลย

คำสั่งที่ต้องการคือ Preferences: Color Theme

ข้อ 3ง่าย

แยกส่วนประกอบคำสั่งนี้ตามโครงสร้าง driver/command/argument: dotnet new console -o MyApp

ดูเฉลย

driver = dotnet · command = new console · argument = -o MyApp

ข้อ 4กลาง

รัน dotnet build ในโปรเจกต์ที่สร้างในข้อ 1 แล้วหาไฟล์ .dll ที่ถูกสร้างขึ้นใน EXPLORER — อยู่ที่โฟลเดอร์ย่อยอะไร?

ดูเฉลย

อยู่ที่ ch07-practice\bin\Debug\net10.0\ch07-practice.dll (เลขเวอร์ชัน net10.0 อาจต่างกันไปตามที่คุณติดตั้ง)

ข้อ 5กลาง

อธิบายว่าทำไมการคลิกขวาแล้วเลือก "Open in Integrated Terminal" ที่โฟลเดอร์โปรเจกต์ ปลอดภัยกว่าการเปิด Terminal เปล่าๆ แล้วพิมพ์ cd เอง

ดูเฉลย

ลดโอกาสพิมพ์ path ผิดหรือสะกดชื่อโฟลเดอร์ผิด — VS Code เติม path ที่ถูกต้องให้อัตโนมัติ ตรงจากตำแหน่งโฟลเดอร์ที่คลิก ลดข้อผิดพลาดจากมนุษย์

ข้อ 6ท้าทาย

สร้างโปรเจกต์ใหม่ แก้โค้ดให้พิมพ์ข้อความอะไรก็ได้ที่มีชื่อคุณอยู่ด้วย โดยตั้งใจไม่ save ไฟล์ก่อนสั่ง dotnet run — สังเกตผลลัพธ์ที่ได้ ว่าตรงกับสิ่งที่คุณเพิ่งแก้ไปหรือไม่ แล้วอธิบายว่าทำไม

ดูเฉลย

ผลลัพธ์จะเป็นโค้ดก่อนแก้ไข (เช่น "Hello, World!" เดิม) เพราะคอมไพเลอร์อ่านจาก ไฟล์บนดิสก์เท่านั้น ไม่ใช่จากสิ่งที่ยังค้างอยู่ใน editor ที่ยังไม่ได้บันทึก — นี่คือกับดักที่พบบ่อยมากตอนเพิ่งเริ่มใช้ IDE

📌 สรุปบทที่ 7

เป้าหมายของบทนี้คือติดตั้งและตั้งค่าสภาพแวดล้อมการพัฒนาที่ตอบโจทย์การเขียน C# คุณติดตั้ง Visual Studio Code และสำรวจ UI ที่มีโครงสร้างเป็นมาตรฐานอุตสาหกรรม ตั้งค่า extension ที่ทำให้ VS Code เป็นเครื่องมือพัฒนา C# ที่ทรงพลังขึ้น ติดตั้ง .NET SDK เพื่อรองรับการ คอมไพล์และรัน รวมถึงคำสั่ง .NET CLI ตอนนี้คุณพร้อมสร้างแอป C# ในสภาพแวดล้อมแบบที่ นักพัฒนามืออาชีพทั่วโลกใช้กันแล้ว
