24.1 สถานการณ์: จดหมายการตลาดส่วนบุคคล

สมมติคุณทำงานในแผนกขายและการตลาด ที่ส่งจดหมายส่วนบุคคลนับพันฉบับให้ลูกค้าเดิมของบริษัทที่เป็น นักลงทุนสถาบัน งานของทีมคุณคือโปรโมทผลิตภัณฑ์การเงินใหม่ให้ลูกค้า จดหมายแต่ละฉบับที่คุณส่งจะ รวมข้อมูลส่วนบุคคลของลูกค้าเข้าไปด้วย จดหมายเปรียบเทียบผลตอบแทนของพอร์ตปัจจุบันของลูกค้ากับ ผลตอบแทนที่คาดการณ์โดยใช้ผลิตภัณฑ์ใหม่ล่าสุด คุณจะรวมและจัดรูปแบบข้อมูลให้ถูกต้องได้ยังไง?

มองในภาพกว้าง นักพัฒนาซอฟต์แวร์ต้องสนใจ:

  • data input — รวมถึงข้อมูลที่ผู้ใช้พิมพ์จากคีย์บอร์ด ใช้เมาส์ อุปกรณ์ หรือจากระบบ ซอฟต์แวร์อื่นผ่าน network request
  • data processing — รวมถึงตรรกะการตัดสินใจ การจัดการข้อมูล และการคำนวณ
  • data output — รวมถึงการนำเสนอให้ผู้ใช้ปลายทางผ่านข้อความ command-line, หน้าต่าง, หน้าเว็บ หรือบันทึกข้อมูลที่ประมวลผลแล้วลงไฟล์ แล้วส่งไปยัง network service

เพื่อแก้ปัญหาทางธุรกิจใน C# คุณต้องทำงานกับข้อมูลหลายชนิด เช่น string และตัวเลข คุณยังต้อง ทำการดำเนินการต่างๆ กับข้อมูล เช่น การคำนวณ การเปรียบเทียบ หรือการแปลงค่า ในบทนี้ คุณแสดงผล ข้อมูล string และตัวเลขใน C# ด้วยตัวเลือกการจัดรูปแบบต่างๆ คุณยังสร้าง mockup ใบเสร็จและ ข้อความการตลาดส่วนบุคคลด้วยเทคนิคการรวมข้อมูล (data merging)

24.2 Composite Formatting vs String Interpolation

composite formatting ใช้ placeholder ที่มีหมายเลขกำกับอยู่ภายใน string ตอนรันจริง ทุกอย่างข้างในปีกกาจะถูกแทนที่ด้วยค่าที่ส่งเข้ามาตามตำแหน่งของมัน

string.Format() — ต้นแบบของ Composite Formatting

Program.cs 
string first = "Hello";
string second = "World";
string result = string.Format("{0} {1}!", first, second);
Console.WriteLine(result);
Output
Hello World!

มีจุดสำคัญที่ควรสังเกตในโค้ดนี้:

  • data type และตัวแปรของ data type นั้นๆ มี "helper method" สำเร็จรูปที่ทำให้งานบางอย่าง ง่ายขึ้น
  • literal string "{0} {1}!" คือ template ที่บางส่วนของมันจะถูกแทนที่ตอนรันจริง
  • token {0} ถูกแทนที่ด้วย argument ตัวแรกหลัง string template คือค่าของตัวแปร first
  • token {1} ถูกแทนที่ด้วย argument ตัวที่สอง คือค่าของตัวแปร second
💡 ทำไมเริ่มนับที่ 0 คุณอาจรู้สึกแปลกที่เริ่มนับจาก 0 แต่จริงๆ แล้วนี่เป็นเรื่องปกติมากในงานพัฒนาซอฟต์แวร์ — เมื่อไร ก็ตามที่มีลำดับของ item ที่ระบุด้วยตัวเลขได้ การนับมักเริ่มที่ 0 เสมอ (ทบทวน zero-based indexing ของ array จาก บทที่ 10)
Program.cs 
string first = "Hello";
string second = "World";
Console.WriteLine("{1} {0}!", first, second);
Console.WriteLine("{0} {0} {0}!", first, second);
Output
World Hello!
Hello Hello Hello!

สังเกตจากตัวอย่าง: statement แรกจัดเรียง token ในลำดับไหนก็ได้ ({1} มาก่อน {0}) statement ที่สองใช้ token ซ้ำได้ ({0} ปรากฏ 3 ครั้ง) และตัวแปร ตัวที่สอง (second) ไม่ถูกใช้เลยก็ยังรันได้ไม่มี error

String Interpolation — เวอร์ชันที่เรียบง่ายกว่า

string interpolation เป็นเทคนิคที่ทำให้ composite formatting ง่ายขึ้น แทนที่จะใช้ token ที่มีหมายเลขแล้วใส่ค่าตัวอักษรหรือชื่อตัวแปรในลิสต์ argument ของ String.Format() หรือ Console.WriteLine() คุณแค่ใส่ชื่อตัวแปรไว้ ข้างในปีกกาได้เลย

Program.cs 
string first = "Hello";
string second = "World";
Console.WriteLine($"{first} {second}!");
Console.WriteLine($"{second} {first}!");
Console.WriteLine($"{first} {first} {first}!");
Output
Hello World!
World Hello!
Hello Hello Hello!

ต้องเติม directive $ ไว้หน้า string เสมอถึงจะทำ interpolation ได้ — คุณคุ้นเคย กับเทคนิคนี้อยู่แล้วตั้งแต่ บทที่ 3 เพราะเป็นวิธีที่ใช้ตลอดทั้งเล่ม

ℹ️ ควรเลือกใช้แบบไหน ถ้าดูตัวอย่างโค้ดในหนังสือหรือบนอินเทอร์เน็ต คุณมักเห็นทั้ง composite formatting และ string interpolation ถูกใช้ปนกัน แต่โดยทั่วไป ควรเลือกใช้ string interpolation เป็นหลัก เพราะอ่านง่ายกว่า (เห็นชื่อตัวแปรตรงตำแหน่งที่จะแสดงผลเลย ไม่ต้องนับ index) — composite formatting ยังมีประโยชน์อยู่ในบางกรณี เช่น ตอนสร้าง template ที่ต้องใช้ตัวแปรตัวเดียวกันซ้ำ หลายครั้งในตำแหน่งต่างกัน หรือ template ที่จะถูกใช้ซ้ำกับชุดข้อมูลต่างๆ (จะเห็นตัวอย่างในหัวข้อ 24.6)

24.3 Format Specifier: สกุลเงิน ตัวเลข และเปอร์เซ็นต์

composite formatting และ string interpolation ใช้จัดรูปแบบค่าสำหรับแสดงผลตามภาษาและ culture ที่กำหนดได้ด้วย

จัดรูปแบบสกุลเงินด้วย :C

Program.cs 
decimal price = 123.45m;
int discount = 50;
Console.WriteLine($"Price: {price:C} (Save {discount:C})");
Output (en-US)
Price: $123.45 (Save $50.00)

สังเกตว่าเติม :C เข้าไปใน token ในปีกกา จัดรูปแบบตัวเลขเป็นสกุลเงินให้ ไม่ว่าจะ ใช้ int หรือ decimal ก็ตาม

Culture ส่งผลต่อการจัดรูปแบบยังไง

ถ้ารันโค้ดเดียวกันนี้บนคอมพิวเตอร์ที่ตั้งค่า Windows Display Language เป็นภาษาฝรั่งเศส (ประเทศฝรั่งเศส) คุณจะเห็นผลลัพธ์แบบนี้แทน:

Output (fr-FR)
Price: 123,45 € (Save 50,00 €)

เหตุผลของผลลัพธ์ "€" ข้างบนคือฟีเจอร์จัดรูปแบบสกุลเงินของ string ขึ้นอยู่กับการตั้งค่า culture ของเครื่องนั้นๆ ในบริบทนี้ คำว่า "culture" หมายถึงประเทศ/ภูมิภาคและภาษาของ ผู้ใช้ปลายทาง culture code คือ string 5 ตัวอักษรที่คอมพิวเตอร์ใช้ระบุตำแหน่งและภาษา ของผู้ใช้ปลายทาง culture code ช่วยรับประกันว่าข้อมูลอย่างวันที่และสกุลเงินจะถูกแสดงผล อย่างถูกต้อง

ตัวอย่างเช่น:

  • culture code ของคนพูดภาษาอังกฤษในสหรัฐฯ คือ en-US
  • culture code ของคนพูดภาษาฝรั่งเศสในฝรั่งเศส คือ fr-FR
  • culture code ของคนพูดภาษาฝรั่งเศสในแคนาดา คือ fr-CA

culture ส่งผลต่อระบบการเขียน ปฏิทินที่ใช้ ลำดับการเรียง string และการจัดรูปแบบวันที่กับตัวเลข (เช่น การจัดรูปแบบสกุลเงิน) น่าเสียดายที่การทำให้แน่ใจว่าโค้ดของคุณทำงานถูกต้องบนทุกเครื่อง ไม่ว่าประเทศ/ภูมิภาคหรือภาษาของผู้ใช้ปลายทางจะเป็นอะไรนั้นเป็นเรื่องท้าทายมาก กระบวนการนี้ เรียกว่า localization (หรือ globalization) การทำ localization ขึ้นอยู่กับหลายปัจจัยที่ ไม่ได้กล่าวถึงในบทนี้ แต่พูดง่ายๆ คือ syntax การจัดรูปแบบ string อาจใช้รูปแบบต่างกันไปตาม culture ของผู้ใช้

💡 ไม่รู้ culture ของเครื่อง จะได้สัญลักษณ์อะไร ถ้ารันโค้ดในโปรแกรมแก้ไข .NET แบบ "in-browser" (เช่น TryDotNet) คุณจะเห็นสัญลักษณ์ ¤ แทนสัญลักษณ์สกุลเงินของประเทศคุณ — นี่คือสัญลักษณ์ทั่วไปที่ใช้แทน "สกุลเงิน" โดยไม่ระบุประเภทที่แน่นอน เพราะโปรแกรมแก้ไขแบบ in-browser ไม่รู้ตำแหน่งปัจจุบันของคุณ

จัดรูปแบบตัวเลขด้วย :N

เวลาทำงานกับข้อมูลตัวเลข คุณอาจต้องการจัดรูปแบบให้อ่านง่ายขึ้น ด้วยการใส่จุลภาคคั่นหลัก (thousands, millions, billions ฯลฯ)

Program.cs 
decimal measurement = 123456.78912m;
Console.WriteLine($"Measurement: {measurement:N} units");
Output (en-US)
Measurement: 123,456.79 units

ค่า default ของ N format specifier แสดงแค่ 2 หลักหลังจุดทศนิยม ถ้าต้องการความ ละเอียดมากขึ้น เติมตัวเลขต่อท้าย specifier ได้ เช่น N4 แสดง 4 หลักหลังจุดทศนิยม:

Program.cs 
decimal measurement = 123456.78912m;
Console.WriteLine($"Measurement: {measurement:N4} units");
Output (en-US)
Measurement: 123,456.7891 units

จัดรูปแบบเปอร์เซ็นต์ด้วย :P

ใช้ P format specifier จัดรูปแบบเปอร์เซ็นต์ ปัดเศษ 2 ตำแหน่งทศนิยมเป็นค่า default เติมตัวเลขต่อท้ายเพื่อควบคุมจำนวนหลักหลังจุดทศนิยมที่แสดง

Program.cs 
decimal tax = .36785m;
Console.WriteLine($"Tax rate: {tax:P2}");
Output (en-US)
Tax rate: 36.79%
⚠️ :P คูณด้วย 100 ให้อัตโนมัติ สังเกตว่าค่า .36785m (ทศนิยม) กลายเป็น 36.79% — :P คูณค่าด้วย 100 และเติมเครื่องหมาย % ให้อัตโนมัติเสมอ ถ้าคุณคำนวณอัตราภาษีมาแล้วเก็บเป็นค่า "0.15" (15%) การใช้ :P ตรงๆ จะได้ผลถูกต้อง แต่ถ้าเผลอเก็บค่าไว้เป็น "15" (คิดว่า 15 คือ 15% แล้ว) การใช้ :P จะแสดงผลผิดเป็น "1,500.00%" แทน — ระวังจุดนี้ให้ดี

Check ★ Console.WriteLine($"Tax rate: {tax:P1}"); เมื่อ decimal tax = .12051m; ผลลัพธ์คืออะไร?

  • ATax rate: 12.05%
  • BTax rate: 12.10%
  • CTax rate: 12.1%
เฉลย: ข้อ C. 0.12051 × 100 = 12.051% — P1 แสดงแค่ 1 หลัก หลังจุดทศนิยม (ปัดเศษจาก 12.051 เป็น 12.1) ไม่ใช่ 2 หลักแบบ default

รวมเทคนิคการจัดรูปแบบเข้าด้วยกัน

ตัวแปร string เก็บ string ที่สร้างด้วยเทคนิคการจัดรูปแบบได้เหมือนกัน ตัวอย่างนี้จัดรูปแบบ ค่า decimal และผลการคำนวณ decimal แล้วเก็บไว้ใน string ชื่อ yourDiscount ด้วย composite formatting:

Program.cs 
decimal price = 67.55m;
decimal salePrice = 59.99m;

string yourDiscount = String.Format("You saved {0:C2} off the regular {1:C2} price. ", (price - salePrice), price);

Console.WriteLine(yourDiscount);
Output (en-US)
You saved $7.56 off the regular $67.55 price.

ต่อ string ที่จัดรูปแบบแล้วหลายอันเข้าด้วยกันได้ ต่อยอดจากโค้ดข้างบน โดยแทรก yourDiscount += $"A discount of {(price - salePrice)/price:P2}!"; เข้าไปก่อน บรรทัด Console.WriteLine():

Program.cs 
decimal price = 67.55m;
decimal salePrice = 59.99m;

string yourDiscount = String.Format("You saved {0:C2} off the regular {1:C2} price. ", (price - salePrice), price);

yourDiscount += $"A discount of {((price - salePrice)/price):P2}!";
Console.WriteLine(yourDiscount);
Output (en-US)
You saved $7.56 off the regular $67.55 price. A discount of 11.19%!
ℹ️ ไม่ต้องใช้ String.Format() คู่กับ interpolation สังเกตว่าบรรทัดที่เพิ่มเข้ามาใช้ string interpolation ($"...") ตรงๆ ไม่ต้องพึ่ง String.Format() เลย — สองเทคนิคนี้ผสมกันในโค้ดชิ้นเดียวได้ตามสะดวก

24.4 ตัวอย่าง: พิมพ์ใบเสร็จ

คุณต้องเขียนโค้ดพิมพ์ใบเสร็จให้ลูกค้าที่ซื้อหุ้นในผลิตภัณฑ์การลงทุน หุ้นถูกซื้ออัตโนมัติเมื่อ สิ้นปีตามชุดของการหักเงินจากบัญชีเงินเดือน ดังนั้นจำนวนหุ้นที่ซื้อมักมีเศษทศนิยม การพิมพ์ ใบเสร็จจึงต้องรวมข้อมูลหลายชนิด ทั้งค่าที่มีเศษ สกุลเงิน และเปอร์เซ็นต์ ให้ถูกต้องแม่นยำ

Program.cs 
int invoiceNumber = 1201;
decimal productShares = 25.4568m;
decimal subtotal = 2750.00m;
decimal taxPercentage = .15825m;
decimal total = 3185.19m;

Console.WriteLine($"Invoice Number: {invoiceNumber}");
Console.WriteLine($"   Shares: {productShares:N3} Product");
Console.WriteLine($"     Sub Total: {subtotal:C}");
Console.WriteLine($"           Tax: {taxPercentage:P2}");
Console.WriteLine($"     Total Billed: {total:C}");
Output (en-US)
Invoice Number: 1201
   Shares: 25.457 Product
     Sub Total: $2,750.00
           Tax: 15.83%
     Total Billed: $3,185.19

เพราะเก็บสัดส่วนหุ้นเป็นทศนิยมละเอียดถึง 1 ในหมื่น (0.0001) แต่แสดงผลแค่ 3 หลักหลังจุดทศนิยม (0.001) จึงใช้ :N3 แทน :N เฉยๆ (ซึ่ง default จะแสดงแค่ 2 หลัก) — ตัวเลขที่คุณเติมต่อท้าย format specifier มักคุมความละเอียดที่ต้องการแสดงเสมอ ไม่ว่าจะเป็น :N, :P, หรือ :C ก็ตาม

24.5 Padding และ Alignment

เมธอด string.Format() ที่คุณเห็นในหัวข้อ 24.2 อาจดูแปลกสักหน่อย เพราะคีย์เวิร์ด ที่แทน data type กลับมีเมธอดให้เรียกได้เหมือนที่คุณเรียกเมธอดบน Console class — ความจริงคือ string data type มีเมธอดสำเร็จรูปแบบนี้อีกหลายตัวที่ใช้กับ string literal หรือตัวแปรชนิด string ตัวไหนก็ได้

นี่คือรายการหมวดหมู่ของ built-in method เหล่านี้คร่าวๆ เพื่อให้เห็นภาพว่ามีอะไรทำได้บ้าง:

  • เมธอดที่เติมช่องว่างเพื่อจัดรูปแบบ (PadLeft(), PadRight())
  • เมธอดที่เปรียบเทียบ string สองอัน หรือช่วยในการเปรียบเทียบ (Trim(), TrimStart(), TrimEnd(), GetHashCode(), property Length)
  • เมธอดที่ช่วยตรวจสอบว่าข้างใน string มีอะไรอยู่ หรือแม้แต่ดึงบางส่วนของ string ออกมา (Contains(), StartsWith(), EndsWith(), Substring())
  • เมธอดที่เปลี่ยนเนื้อหาของ string ด้วยการแทนที่ แทรก หรือลบบางส่วน (Replace(), Insert(), Remove())
  • เมธอดที่แปลง string เป็น array ของ string หรือ char (Split(), ToCharArray())
💡 หลายเมธอดนี้เจอมาแล้วในบทก่อนๆ Contains(), Substring(), Split(), และ ToCharArray() คุณเจอมาแล้วใน บทที่ 14 และ บทที่ 23 — บทนี้เน้นที่ PadLeft() และ PadRight() ซึ่งยังไม่เคยแนะนำมาก่อน

เติมช่องว่างซ้าย-ขวาด้วย PadLeft() และ PadRight()

PadLeft() เติมช่องว่างที่ด้านซ้ายของ string จนกว่าจำนวนตัวอักษรทั้งหมดจะเท่ากับ argument ที่คุณส่งให้มัน

Program.cs 
string input = "Pad this";
Console.WriteLine(input.PadLeft(12));
Output ("Pad this" มี 8 ตัวอักษร → เติม 4 ช่องว่างซ้าย)
    Pad this

ใช้ PadRight() เติมช่องว่างหรืออักขระที่ด้านขวาแทน — ผลลัพธ์จะไม่เห็นความต่าง ด้วยตาเปล่าตอนพิมพ์ (เพราะช่องว่างอยู่ท้ายบรรทัด) แต่มันมีอยู่จริง

Overloaded Method — เติมอักขระอื่นแทนช่องว่างได้

ใน C# overloaded method คือเวอร์ชันอื่นของเมธอดตัวเดียวกันที่รับ argument ต่างกันหรือ เพิ่มเติม ปรับพฤติกรรมของเมธอดเล็กน้อย เหมือนกับเวอร์ชัน overload ของ PadLeft() — คุณเรียกเวอร์ชัน overload ที่สองได้ โดยส่งอักขระที่ต้องการใช้แทนช่องว่างเข้าไป:

Program.cs 
string input = "Pad this";
Console.WriteLine(input.PadLeft(12, '-'));
Console.WriteLine(input.PadRight(12, '-'));
Output
----Pad this
Pad this----

Check ★ กำหนด string myWords = "Learning C#"; คำอธิบายข้อไหนตรงกับผลลัพธ์ของ Console.WriteLine(myWords.PadLeft(12)); ที่สุด?

  • Aเติมช่องว่าง 1 ช่องที่หน้า string
  • Bเติมช่องว่าง 4 ช่องที่หน้า string
  • Cเติมช่องว่าง 12 ช่องที่หน้า string
เฉลย: ข้อ A. "Learning C#" มี 11 ตัวอักษร (นับรวมช่องว่างและ #) — PadLeft(12) เติมให้ครบ 12 ตัวอักษรทั้งหมด จึงเติมแค่ 1 ช่องว่างเท่านั้น ไม่ใช่ 12 ช่องว่าง ตรงๆ (12 คือความยาวรวมที่ต้องการ ไม่ใช่จำนวนช่องว่างที่จะเติม)

สถานการณ์จริง: ส่งข้อมูลให้ระบบ Mainframe รุ่นเก่า

สมมติคุณทำงานให้บริษัทประมวลผลการชำระเงินที่ยังรองรับระบบ mainframe รุ่นเก่าอยู่ ระบบเหล่านี้ มักต้องการให้ข้อมูลถูกป้อนในคอลัมน์ที่กำหนดตายตัว เช่น เก็บ Payment ID ในคอลัมน์ 1 ถึง 6 ชื่อผู้รับเงินในคอลัมน์ 7 ถึง 30 และจำนวนเงินในคอลัมน์ 31 ถึง 40 — และสำคัญคือ จำนวนเงินต้อง ชิดขวา (right-aligned)

คุณถูกขอให้สร้างแอปแปลงข้อมูลจากฐานข้อมูลเชิงสัมพันธ์ให้เป็นรูปแบบไฟล์ระบบเก่า เพื่อยืนยันว่า การเชื่อมต่อทำงานถูกต้อง ขั้นแรกคือยืนยันรูปแบบไฟล์โดยให้ตัวอย่าง output แก่ผู้ดูแลระบบเก่า

Program.cs 
string paymentId = "769C";
string payeeName = "Mr. Stephen Ortega";
string paymentAmount = "$5,000.00";

var formattedLine = paymentId.PadRight(6);
formattedLine += payeeName.PadRight(24);
formattedLine += paymentAmount.PadLeft(10);

Console.WriteLine("1234567890123456789012345678901234567890");
Console.WriteLine(formattedLine);
Output
1234567890123456789012345678901234567890
769C  Mr. Stephen Ortega       $5,000.00

สังเกต 3 จุดสำคัญ:

  • paymentId.PadRight(6) — Payment ID "769C" มี 4 ตัวอักษร เติม ช่องว่าง 2 ช่องด้านขวาให้ครบคอลัมน์ 1-6
  • payeeName.PadRight(24) — ชื่อผู้รับเงินเติมช่องว่างด้านขวาให้ครบ 24 ตัวอักษร (คอลัมน์ 7-30)
  • paymentAmount.PadLeft(10) — จำนวนเงินใช้ PadLeft() แทน (ไม่ใช่ PadRight()) เพราะโจทย์กำหนดให้ต้องชิดขวา
  • ใช้ += ต่อ string เข้ากับตัวแปร formattedLine ทีละส่วน — เทียบ เท่ากับ formattedLine = formattedLine + payeeName.PadRight(24);

บรรทัดตัวเลข 1234567890... ที่พิมพ์ไว้ด้านบนช่วยให้นับคอลัมน์ตรงตามที่ต้องการได้ ง่ายขึ้น เป็นเทคนิคที่มีประโยชน์เวลาต้องยืนยันความถูกต้องของ fixed-width format กับทีมอื่น

ย่อหน้าแรกใช้ string interpolation ธรรมดา ส่วนตารางเปรียบเทียบด้านล่างต้องสร้างทีละ บรรทัดด้วยการต่อ string (+=) ผสม String.Format() กับ format specifier (:P, :C) และ PadRight() — สังเกตว่าจำนวนหุ้น currentShares เป็น int แต่ต้องแสดงเป็น 2,975,000.00 (มีทศนิยม 2 ตำแหน่ง) ทั้งที่เป็นจำนวนเต็ม — format specifier ตัวไหนทำแบบนั้นได้?

🔓 ดูเฉลย (เฉลยทางการจาก Microsoft Learn)
Program.cs 
string customerName = "Ms. Barros";

string currentProduct = "Magic Yield";
int currentShares = 2975000;
decimal currentReturn = 0.1275m;
decimal currentProfit = 55000000.0m;

string newProduct = "Glorious Future";
decimal newReturn = 0.13125m;
decimal newProfit = 63000000.0m;

Console.WriteLine($"Dear {customerName},");
Console.WriteLine($"As a customer of our {currentProduct} offering we are excited to tell you about a new financial product that would dramatically increase your return.\n");
Console.WriteLine($"Currently, you own {currentShares:N} shares at a return of {currentReturn:P}.\n");
Console.WriteLine($"Our new product, {newProduct} offers a return of {newReturn:P}.  Given your current volume, your potential profit would be {newProfit:C}.\n");

Console.WriteLine("Here's a quick comparison:\n");

string comparisonMessage = "";

comparisonMessage = currentProduct.PadRight(20);
comparisonMessage += String.Format("{0:P}", currentReturn).PadRight(10);
comparisonMessage += String.Format("{0:C}", currentProfit).PadRight(20);

comparisonMessage += "\n";
comparisonMessage += newProduct.PadRight(20);
comparisonMessage += String.Format("{0:P}", newReturn).PadRight(10);
comparisonMessage += String.Format("{0:C}", newProfit).PadRight(20);

Console.WriteLine(comparisonMessage);
Output
Dear Ms. Barros,
As a customer of our Magic Yield offering we are excited to tell you about a new financial product that would dramatically increase your return.

Currently, you own 2,975,000.00 shares at a return of 12.75%.

Our new product, Glorious Future offers a return of 13.13%.  Given your current volume, your potential profit would be $63,000,000.00.

Here's a quick comparison:

Magic Yield         12.75%   $55,000,000.00      
Glorious Future     13.13%   $63,000,000.00

นี่เป็นเพียงหนึ่งในหลายวิธีที่แก้โจทย์นี้ได้ — ขึ้นอยู่กับว่าคุณเลือก implement ตรรกะยังไง ขอแค่ใช้เทคนิคที่เรียนในบทนี้ (จัดรูปแบบ string, เติม padding ฯลฯ) และผลลัพธ์ ตรงกับที่โจทย์กำหนดก็ถือว่าสำเร็จแล้ว

สังเกตว่า currentShares เป็น int แต่ใช้แค่ :N เฉยๆ (ไม่ใช่ :N0) ก็ยังแสดงทศนิยม 2 ตำแหน่งเป็น 2,975,000.00 ได้ เพราะ :N แสดง 2 ตำแหน่งทศนิยมเป็นค่า default เสมอ ไม่ว่า data type ต้นฉบับจะเป็นจำนวนเต็มหรือไม่ก็ตาม (ทบทวนหัวข้อ 24.3c)

ส่วนตารางเปรียบเทียบ สร้างทีละส่วนด้วยการต่อ string (+=) — แต่ละแถวประกอบ ด้วย 3 ส่วน: ชื่อผลิตภัณฑ์ (PadRight(20)), เปอร์เซ็นต์ผลตอบแทน (PadRight(10)), และกำไร (PadRight(20)) — สังเกตว่าทุกส่วนใช้ PadRight() ไม่มี PadLeft() เลย เพราะโจทย์นี้ไม่ได้กำหนดให้ ชิดขวาแบบตัวอย่าง mainframe ในหัวข้อก่อน

24.7 ⚠️ กับดักที่พบบ่อย

อาการสาเหตุ / วิธีแก้
:P แสดงผล 1,500.00% ทั้งที่ต้องการ 15% ค่าที่เก็บไว้เป็น 15 (คิดว่าคือ 15% แล้ว) แต่ :P คูณด้วย 100 ให้อัตโนมัติเสมอ — ต้อง เก็บอัตราส่วนเป็นทศนิยม 0-1 (เช่น 0.15) ก่อนใช้ :P เสมอ
ผลลัพธ์สกุลเงินแสดงสัญลักษณ์ที่ไม่คาดคิด (เช่น € แทน $) ไม่ใช่บั๊ก — ขึ้นอยู่กับ culture setting ของเครื่องที่รันโค้ด ถ้าต้องการบังคับ culture เฉพาะ ต้องตั้งค่า CultureInfo เองอย่างชัดเจน (ทบทวนจาก บทที่ 22 เรื่องการตั้งค่า en-US)
PadLeft(n) ไม่เติมช่องว่างเลย ทั้งที่คาดว่าจะเติม ถ้า string เดิมยาวเท่ากับหรือมากกว่า n อยู่แล้ว PadLeft()/PadRight() จะไม่ทำอะไรเลย (คืนค่าเดิมกลับมาโดยไม่ตัดทอนหรือ error) — n คือความยาวรวมเป้าหมาย ไม่ใช่ จำนวนอักขระที่จะเติมเพิ่ม
ใช้ PadRight() แต่มองไม่เห็นผลต่างในผลลัพธ์ ไม่ใช่บั๊ก — ช่องว่างที่เติมด้านขวาอยู่ท้ายบรรทัด มองด้วยตาเปล่าจากหน้าจอไม่เห็น แต่มี อยู่จริง (ลองใช้ PadRight(n, '-') ชั่วคราวเพื่อยืนยัน)
ลืมว่า string.Format() กับ Console.WriteLine() composite formatting ใช้ syntax token เดียวกัน ทั้งคู่รับ template string ตามด้วย argument list แบบเดียวกัน — สลับใช้แทนกันได้ตาม ต้องการ (String.Format() คืนค่า string ให้เก็บไว้ใช้ต่อ ส่วน Console.WriteLine() พิมพ์ออกจอทันที)

24.8 ❓ Knowledge Check

คำถามชุดนี้แปลจาก Module Assessment ของ Microsoft Learn

1. โค้ด Console.WriteLine("C110".PadLeft(6, '0')); ผลลัพธ์ที่คาดว่าจะได้คือข้อใด?

  • AC11000
  • BC110000000
  • C00C110
เฉลย: ข้อ C. "C110" มี 4 ตัวอักษร PadLeft(6, '0') เติม '0' ที่ด้าน ซ้ายจนครบความยาวรวม 6 ตัวอักษร ได้ "00C110" — ไม่ใช่เติมด้านขวา (นั่นคือพฤติกรรมของ PadRight)

2. format specifier ไหนแสดงค่า decimal ในรูปแบบ 12,345.67 สำหรับผู้ชม en-US?

  • A0:C
  • B0:H
  • C0:N2
เฉลย: ข้อ C. N2 จัดรูปแบบตัวเลขพร้อมจุลภาคคั่นหลักและทศนิยม 2 ตำแหน่ง พอดี — C จะเติมสัญลักษณ์สกุลเงินซึ่งไม่ตรงกับผลลัพธ์ที่ต้องการ ส่วน H ไม่ใช่ format specifier ที่มีอยู่จริงใน C#

3. ต้องใช้อักขระตัวไหนเป็น directive เพื่อทำ string interpolation?

  • A$
  • B@
  • C%
เฉลย: ข้อ A. $ คือ directive ของ string interpolation — @ เป็น directive ของ verbatim string literal (ทบทวนจาก บทที่ 3) ซึ่งเป็นคนละเรื่องกัน

ข้อ 1ง่าย

ประกาศ decimal salary = 55000m; แล้วพิมพ์ออกมาในรูปแบบสกุลเงิน (:C)

Program.cs
decimal salary = 55000m;

ข้อ 2ง่าย

ใช้ PadRight() จัดคำว่า "ID" ให้กว้าง 10 ตัวอักษร ต่อด้วยคำว่า "Name" ให้กว้าง 15 ตัวอักษร แล้วพิมพ์เป็นบรรทัดหัวตาราง

ดูเฉลย

ข้อ 3กลาง

ทำนายผลลัพธ์ของโค้ดนี้ก่อนรันจริง แล้วเทียบว่าตรงไหม:

Program.cs
decimal rate = 1.5m;
Console.WriteLine($"Rate: {rate:P0}");
ดูเฉลย
ผลลัพธ์จริง 
decimal rate = 1.5m;
Console.WriteLine($"Rate: {rate:P0}");
Rate: 150%

1.5 × 100 = 150% — P0 แสดง 0 หลักหลังจุดทศนิยม (จำนวนเต็มพอดี) เป็นตัวอย่างที่ดีว่า :P คูณ 100 เสมอไม่ว่าค่าตั้งต้นจะมากกว่า 1 หรือไม่ก็ตาม (กับดักจากหัวข้อ 24.3d ในอีกรูปแบบหนึ่ง)

ข้อ 4กลาง

ใช้ composite formatting (string.Format()) สร้างข้อความ "3 + 4 = 7" จากตัวแปร int a = 3, b = 4; โดยใช้ token {0} และ {1} เท่านั้น (ห้ามใช้ string interpolation)

ดูเฉลย
Program.cs
int a = 3, b = 4;
string result = string.Format("{0} + {1} = {2}", a, b, a + b);
Console.WriteLine(result);
ข้อ 5ยาก

สร้างตารางราคาสินค้า 3 รายการ (ชื่อ, ราคา) โดยจัดคอลัมน์ชื่อให้กว้าง 15 ตัวอักษร (ชิดซ้าย) และคอลัมน์ราคาให้กว้าง 10 ตัวอักษร (ชิดขวา แสดงเป็นสกุลเงิน) ใช้ข้อมูล: ("Apple", 1.5m), ("Bread", 3.25m), ("Milk", 2.99m)

ดูเฉลย
Program.cs
string[] names = ["Apple", "Bread", "Milk"];
decimal[] prices = [1.5m, 3.25m, 2.99m];

for (int i = 0; i < names.Length; i++)
{
    string line = names[i].PadRight(15);
    line += String.Format("{0:C}", prices[i]).PadLeft(10);
    Console.WriteLine(line);
}
ข้อ 6ท้าทาย

ดัดแปลงเฉลยท้าทาย (หัวข้อ 24.6) ให้รองรับผลิตภัณฑ์ที่ 3 ชื่อ "Steady Growth" ผลตอบแทน 0.095m กำไร 40000000.0m เพิ่มเป็นแถวที่ 3 ในตาราง เปรียบเทียบ โดยยังคงจัดคอลัมน์ให้ตรงกันกับ 2 แถวเดิม

ดูเฉลย
Program.cs (ส่วนตารางเปรียบเทียบ)
string thirdProduct = "Steady Growth";
decimal thirdReturn = 0.095m;
decimal thirdProfit = 40000000.0m;

string comparisonMessage = "";

comparisonMessage = currentProduct.PadRight(20);
comparisonMessage += String.Format("{0:P}", currentReturn).PadRight(10);
comparisonMessage += String.Format("{0:C}", currentProfit).PadRight(20);

comparisonMessage += "\n";
comparisonMessage += newProduct.PadRight(20);
comparisonMessage += String.Format("{0:P}", newReturn).PadRight(10);
comparisonMessage += String.Format("{0:C}", newProfit).PadRight(20);

comparisonMessage += "\n";
comparisonMessage += thirdProduct.PadRight(20);
comparisonMessage += String.Format("{0:P}", thirdReturn).PadRight(10);
comparisonMessage += String.Format("{0:C}", thirdProfit).PadRight(20);

Console.WriteLine(comparisonMessage);

เพิ่มแถวที่ 3 ด้วยแพทเทิร์นเดียวกับ 2 แถวแรกทุกประการ (PadRight 20/10/20 เท่ากัน) เพราะใช้ความกว้างคอลัมน์เดิม ตารางจึงยังคงจัดตรงกันสวยงาม

📌 สรุปบทที่ 24

บริษัทของคุณต้องสร้างข้อความการตลาดส่วนบุคคลเพื่อโปรโมทผลิตภัณฑ์การเงินใหม่ให้ลูกค้า ด้วย C# คุณเขียนโค้ดที่รวมข้อมูล string และตัวเลขเกี่ยวกับลูกค้าปัจจุบันของคุณได้สำเร็จ

คุณฝึกใช้เทคนิคต่างๆ ในการรวม string template เข้ากับตัวแปร ทั้ง composite formatting และ string interpolation format specifier ต่างๆ ช่วยให้คุณจัดรูปแบบตัวเลขจำนวนมาก สกุลเงิน และ เปอร์เซ็นต์ได้อย่างถูกต้อง built-in method บนตัวแปรชนิด string ช่วยให้คุณเติม padding จัด ตำแหน่งข้อมูลชิดซ้ายและชิดขวาได้

ลองจินตนาการดูว่าจะต้องทำงานเพิ่มขึ้นแค่ไหน ถ้าไม่มีเครื่องมือและเทคนิคจัดรูปแบบ string และ ตัวเลขที่หลากหลายใน C# แบบนี้ คุณอาจต้องพยายามใช้ string concatenation ทุกที่ ซึ่งอาจทำให้ ดูแลรักษาหรืออัปเดตโค้ดได้ยากขึ้นมาก

เทคนิคและเครื่องมือจัดรูปแบบ string และข้อมูลตัวเลขมีการใช้งานได้กว้างขวางมาก เช่น คุณใช้ เทคนิคเหล่านี้แสดงข้อมูลบนหน้าจอ และจัดรูปแบบข้อมูลเพื่อส่งต่อระหว่างระบบที่ต่างกันได้
